# M1 — the read slice, plus the pre-cutover edit surface

Campaign `admin-window`. Slice definition: `agenticflow/docs/vision/ROADMAP.md`.
Behavior: `agenticflow/docs/vision/SPEC.md` (F1–F8).
Acceptance authority: `contracts/admin-build.md`, read 2026-09-01 — its test
numbers are cited as **[test N]**.

**M1 carries zero schema.** No migration in this repo, no DDL from app code, no
dependency on the two §9 handoff artifacts. If a criterion below appears to
require installed schema, it is mis-authored — report it, do not install
anything.

**Preconditions (human-owned).** Live criteria cannot be graded until
`STAGING_SUPABASE_URL` and `STAGING_SUPABASE_SERVICE_ROLE_KEY` exist in `.env`
(names only in `.env.example`) and the staging Supabase project is declared in
`agenticflow/docs/SERVICES.md`. An unset name is a refusal, never a fallback;
no secret value ever appears in a file, transcript, ticket, or evidence note.

## Exit criteria

### EC1 — the repo's bars are green [test 1]

`npm run lint` and `npm run build` each exit 0 with zero errors, and the
campaign's test suite passes. The suite is **offline by default**: with no
`STAGING_SUPABASE_*` names set it still passes, and its staging tests are
skipped behind an explicit live marker rather than failing or falling back.

- Machine-checkable: `npm run lint`; `npm run build`; the suite command,
  run once with the staging names unset (green, live tests skipped) and once
  with them set (green, live tests run).

### EC2 — no deprecated surface survives [test 1, spec §3]

Overview, Analytics, Data Management (including the completeness gap list) and
the Database table browser are gone — no route serves them, no navigation links
them, and no code exists that only they used. The events editor is removed
rather than converted: from Browse's recent-events view, an event's record page
offers **no editable field**.

- Machine-checkable: an HTTP request to each retired route returns 404 (not a
  redirect to a working page); a repo grep finds no surviving component whose
  only consumer was a retired page.

### EC3 — the window is six pages, and the investigation never leaves it [spec §4]

Dashboard, Queues, Claims, Sources, Cycles & runs and Browse each exist at
their own URL and are reachable from the navigation. Walked end to end: from
**Dashboard**, an attention count opens **Queues**; a queue row opens its
**review-item detail**; the detail reaches its **claims**, its **source**, and
the affected record; from **Browse**, an event row reaches that record's edit
surface. No step in that chain leaves the app or dead-ends.

### EC4 — every page's numbers equal the database's [test 2]

For each of the six pages, a live parity check asserts the rendered numbers
against direct SQL on staging — dashboard counts, queue counts, cycle rows,
source rows — and passes.

- Machine-checkable: the live-marked parity tests, one per page, green.

### EC5 — Claims parity, and `in_window` nowhere [test 3]

On **Claims**, rendered bucket counts equal the classification view's, per
bucket and per source filter. The string `in_window` appears nowhere in the
UI — not as a bucket, not as an empty bucket, not as a filter option. The
standing-disagreements subset is reachable as its own tab.

- Machine-checkable: the per-bucket / per-source-filter parity test; a scan of
  the rendered HTML of every page for `in_window` finds zero occurrences.

### EC6 — Queues split by kind, and the filters are exact [test 4]

**Queues** shows two queues of equal standing — decision and signal — open
items first, ordered severity then age, with settled items browsable. The three
shapes classify as decision (`data_conflict` fact), decision (`entity_link`
fact) and signal (`entity_link` source-pattern). Each shape filter and each
queue filter returns **exactly** the matching items — no extras, none missing.

- Machine-checkable: for every filter value, the returned id set equals the SQL
  id set.

### EC7 — a review item's detail resolves its evidence [test 5]

Opening any review item from **Queues**: every id in `evidence` renders as its
observation row showing **value, source, tier and `observed_at`**, with the
fact's **current canonical value and its provenance** beside them. The header
carries the summary sentence, severity, age and `folded_count`. Each of the
three shapes renders its own typed view (the source-pattern item's evidence
renders as its folded-record list with the per-source dial beside it). The
recommendation slot renders nothing.

- Walked once per shape, screenshotted.
- **No settle control is present in M1** — the close is M2's.

### EC8 — the six gauges render, each answering its knob [test 11]

Six gauges render from staging rows: cycle health, resolution latency, pending
claims, queue health, standing disagreements, settled values — the "one glance
shows" content of spec §5, each on the page whose data it judges (per-source
trends on **Sources**). Every gauge is a server-side query in this app.

- Machine-checkable: the repo contains no new migration and no new database
  view; each gauge's query runs read-only.

### EC9 — Browse: recent events [test 10]

**Browse** ships exactly one curated view, **recent events**: newest first,
carrying the spot-verification columns (title, description, poster image, date,
venue) **and the source(s) behind the row read from `field_provenance`**. The
runtime column selector shows and hides **exactly** the configured set — every
configured column is offered, and nothing outside it is.

- Machine-checkable: the rendered order matches SQL's `order by` newest-first;
  the selector's option set equals the configured column set.
- No whole-table browser, no SQL runner, no second curated view.

### EC10 — the edit surface obeys its config map, pre-cutover half [test 7]

One hand-written `{table → editable columns}` map drives the surface. On a
**groups** record and an **idols** record: a column present in the map edits
and the value persists after reload; a column absent from the map is not
editable, and a **forged request naming it is refused server-side** (not merely
hidden). `events` and `venues` render read-only, and no write path to them
exists from Admin.

- Machine-checkable: a request to the edit route naming an unmapped column
  returns a refusal and leaves the row unchanged; a repo scan finds no write
  path to `events` / `venues` / `event_performers`; zero inserts or deletes of
  catalog rows from Admin; `scraped_events` untouched.

### EC11 — graceful absence [test 9]

Pointed at a database lacking the resolver's tables and views, every ecosystem
page renders its **not-provisioned state** naming what is missing, and nothing
throws — the process stays up and the rest of the app still works.

- Machine-checkable: the absence-mode test asserts a 200 and the
  not-provisioned marker on each of the six pages, and zero unhandled errors.

### EC12 — auth holds and no key leaks [test 12]

An unauthenticated request to **every** new page and every new route redirects
to login. A scan of the built client bundles finds no service-role key and no
`STAGING_SUPABASE_SERVICE_ROLE_KEY` value.

- Machine-checkable: an unauthenticated request per route asserts the redirect;
  a build-artifact scan over `.next`'s client output finds zero matches.

### EC13 — zero residue [test 13]

After the final live run, staging carries no campaign leftovers: every row a
live test wrote is swept. Production was never a target, the deployed Railway
service was never repointed, and no `.env` value appears in any commit, ticket,
receipt, or evidence file.

- Machine-checkable: a post-run sweep query returns zero campaign-written rows;
  `git log -p` over the milestone's commits contains no secret value.

### EC14 — the campaign's own bars [acceptance doc, "Reviewed after the build"]

At milestone close the following exist for Ben's review:

- `docs/build_judgments.md` — at most fifteen entries, each naming the contract
  location that was silent.
- **Screenshots of every page and of the groups/idols edit flow**, captured at
  close (the human eye on rendered UI the factory cannot judge).
- The cross-directory report: every scraper-side commit is a declared handoff
  or a noted minor edit, and no ticket's touch scope named a scraper path.
- Any contract gap hit during M1 is a **blocked ticket**, not a silent
  judgment call — including the five already named in SPEC.md.
