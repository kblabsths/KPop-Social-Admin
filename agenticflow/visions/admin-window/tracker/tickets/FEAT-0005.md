# Claims, Sources, and Cycles and runs

## Description
VISION: "Six pages ... each showing real staging rows whose numbers match what the database says" and "who keeps being wrong". SPEC F5. Contracts read 2026-09-01: admin-observability.md §4 (Claims, Sources, Cycles and runs); resolver.md §7 (the classification view and its buckets), §4 (standing disagreements), §6 (resolution_runs columns), §11; data-model.md (source registry config and state). Claims renders the pending-claims classification view as buckets with counts and age, filterable by source, domain and bucket, with the standing-disagreements subset as its own tab. The in_window bucket is not rendered at all — it is empty by rule while corroboration windows stay parked. A claim links to its source and to the provenance of its fact. Sources renders the sources state rows: lifecycle (candidate, trial, active, paused, retired), current tier, checkpoint, last run, with the per-source gauge trends beside them. Cycles and runs renders resolution_runs and the adapter framework runs newest first, with the run counts as columns (facts_examined, applied, held, escalated, entities_created, claims_linked, claims_rerejected, errors) and error_summary inline; a still-running cycle (ended_at null) and a skipped cycle are each legible as such.
