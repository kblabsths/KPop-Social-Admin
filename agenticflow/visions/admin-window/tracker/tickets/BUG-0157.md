# The folded-records table prints the dash-meaning line with no dash on screen: a record's own em-dash reference is explained as "a value this row does not carry"

## Description
Found attacking BUG-0156 on the landed tree (run/admin-window @ 886dd1a, offline vitest + cheerio, no device, no network, 2026-09-09). BUG-0156 gave `sourceColumn` a condition that is the one its cell branches on; `recordColumn` kept the old shape and still diverges from its own cell.

Expected (`src/components/review/shape-views.tsx:225-233`, and the landed rule at `src/components/review/evidence-cells.tsx:100-125`: "Each column now states its own condition, and each states exactly the one its cell uses"): the dash-meaning line is printed "only while one is on screen", and what it says of that dash is true — "A - is a value this row does not carry".

Found, on the `entity_link_source_pattern` item's folded-records table (the one view carrying `recordColumn`, `shape-views.tsx:526`), rendered through the real page:

 1. observation with `entity_id: null`, `external_ref: "—"` -> the record cell is `<span data-record="—">—</span>` (the SOURCE's own reference, verbatim ink); `[aria-label="no value"]` inside `[data-surface="evidence"]` = 0; `[data-absence-note="dash"]` = 1. The page explains a dash that is the producer's value - BUG-0156's own untruth, one column over.
 2. same with `external_ref: "​"` -> the cell is `<span data-record="​">​</span>`: an evidence cell with nothing in it and no absence element at all (the rendering BUG-0152/BUG-0154 were filed to remove), and the note is printed for a dash that is not on screen.

Where it comes from: `src/components/review/evidence-cells.tsx:344-347` - `absent: (row) => isAbsent(entityId-when-linked else externalRef)` - while the cell (`evidence-cells.tsx:348-357`) draws the app's dash only by RETURNING NULL, which it does only when neither identity is there (`entityId`/`recordHref` absent AND `externalRef === null`). The two expressions coincide in that one case only; for every ink-less or em-dash `external_ref` they disagree. Same class as BUG-0156 (a predicate answering a rendering's question, LESSONS 4/11), and it PREDATES the BUG-0156 fix: the pre-fix `value` accessor run through `isAbsent` gives the same two verdicts, so this is not a regression of that diff.

Not filed, for the record: a third arm (`entityId` present but ink-less, with a `recordHref`) renders `<a href="/records/events/" data-record="">` - an anchor with nothing to read or click - but `recordHref` (`src/lib/records/routes.ts:49`) refuses an empty id, so reaching it needs a whitespace-only uuid. Unreachable, so no claim is made on it.

Reach: `observations.external_ref` is plain `text` with NO check constraint (`kspace Scraper/supabase/migrations/20260818000000_the_schema_arrives_as_one_snapshot.sql:3827`), i.e. LESS constrained than the `sources.source` name BUG-0156 was priced on (`CHECK (source ~ '^[a-z0-9_]+$')`). Staging holds no such row. P3 for that reach; inside it, a false sentence about a value the row does carry, plus an unreadable cell.

Pins (landed on run/admin-window by qa-0156, `it.fails` while the divergence stands - THE FIX FLIPS BOTH TO PLAIN `it`), both watched RED first as plain `it` on this exact tree, in `tests/offline/review-item/page.test.ts`, describe "an evidence cell with nothing in it":
