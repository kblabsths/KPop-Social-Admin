# Take the SIBLING-READING handoff guards out of the every-builder suite: a new opt-in vitest project

## Description
RULED by the architect 2026-09-12, from the M3 queue (QA's BUG-0213 residual: 'a fourth trigger in one file today').

THE PROBLEM, stated as a property rather than as four anecdotes: a check whose RED is produced by a LEGITIMATE event in a repo we do not own sits in the suite every builder must have green before pushing. Four triggers landed on tests/offline/handoff/settle-review-item.test.ts inside one campaign (BUG-0207, BUG-0212, BUG-0213 and the sibling's own next code allocation), and every one of them made npm test red for every builder in this repo at a moment when nothing here was wrong — twice at the exact moment the campaign SUCCEEDED (the handoff landing next door). LESSONS 9 names the class; this ticket takes the input out of the suite instead of hardening the guard a fourth time.

THE CUT — by INPUT OWNERSHIP, not by subject:
- STAYS in the offline project (deterministic, every input owned by this repo): everything that grades OUR artifact — the handoff notes under agenticflow/tracker/for-human/, SQL block balance, dollar quotes, ALTER TABLE targets, forbidden constructs, ACL/privilege math, and the code->meaning declarations of the codes THIS campaign allocates. These are the guards that catch an authoring slip before Ben pastes, and they must keep firing for every builder.
- MOVES to a new project: every case that READS the sibling checkout (SIBLING_ROOT, SIBLING_PRESENT, ksRaisesUnder, the registry read at tests/offline/handoff/settle-review-item.test.ts:1236-1250, and anything else reaching outside this repo). New home tests/handoff/, new vitest project named 'handoff', new script 'npm run test:handoff'. It is NOT in npm test, so it is not in ci_command either (run.yaml's ci_command runs lint, tsc and npm test — untouched by this ticket, and nothing in this ticket edits run.yaml).
- WHO RUNS IT: the verifier at a milestone close, and whoever prepares or re-checks a handoff (LESSONS 9). A red there is a cross-repo FINDING to route, never a bar a builder in this repo must clear before pushing.

SIBLING_ROOT stays an ABSOLUTE path (it already is, :135). Do not make it relative: receipt and build worktrees live under agenticflow/.worktrees/, where '../kspace Scraper' resolves INSIDE this repo and the guard silently scans nothing (this is the same vacuity that made BUG-0209's stored check 3 pass unconditionally). Keep the runIf(SIBLING_PRESENT) skip so a machine without the checkout skips loudly rather than greening.

WHILE YOU ARE IN THERE: tests/offline/handoff/__probe.test.ts is UNTRACKED RESIDUE in the primary checkout (BUG-0213's repro probe, pointing at a scratch replica that no longer exists) and it IS collected by the offline glob there — delete it. It is invisible in receipts, which run at HEAD; that asymmetry is exactly why it survived.

NOT IN SCOPE, and it is not ours to write: the reciprocal rule next door (the sibling raising one of OUR codes without a registry change passes in both repos). That is an admission rule in kspace Scraper, which this repo may not edit — it is a handoff for Ben, filed at agenticflow/tracker/for-human/M3-sibling-code-admission-for-ben.md.

## Acceptance criteria
1. npm test COLLECTS NO TEST THAT READS THE SIBLING CHECKOUT. No tracked file under tests/offline names SIBLING_ROOT or otherwise opens a path outside this repo, and the offline project's own toolchain assertions (tests/offline/toolchain.test.ts) are updated to state the new project boundary rather than being loosened.

2. THE MOVED CASES STILL RUN, opt-in, and pass: the 'handoff' vitest project exists in vitest.config.mts with its own include glob rooted at tests/handoff/, npm run test:handoff runs it, and every case that read the sibling before this ticket still exists, unweakened, with the same assertions — a case deleted or softened is a criterion failed, not a simplification.

3. THE OUR-ARTIFACT GUARDS STAY IN THE EVERY-BUILDER SUITE: the offline project still grades this campaign's handoff artifacts (block balance, quoting, ALTER targets, forbidden constructs, ACL math, our own code->meaning declarations) and is still red if one of those is broken. Prove it red-then-green on one of them.

4. A MACHINE WITHOUT THE SIBLING CHECKOUT SKIPS LOUDLY, never greens silently: the runIf(SIBLING_PRESENT) guard survives the move, SIBLING_ROOT stays an absolute path (ARCHITECTURE §1.2), and a run where the sibling is absent reports the skip.

5. The untracked probe residue tests/offline/handoff/__probe.test.ts is gone from the working tree.

6. THE TREE MATCHES THE CONTRACT THE ARCHITECT ALREADY WROTE: ARCHITECTURE §10's 2026-09-12 bullet names the project 'handoff', its home tests/handoff/**, its script npm run test:handoff, and the input-ownership cut. Land exactly that. If a measurement makes a different name or layout right, do NOT edit ARCHITECTURE.md — say so in your handoff note and let the architect amend it; that file has one writer.
