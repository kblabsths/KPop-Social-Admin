# Retire the interim groups/idols walk-write exception from the walk docs

## Description
**The interim walk-write exception is dead, and the docs still teach it.** Ben's amendment of 2026-09-08 struck "groups/idols edit directly within it" from VISION: *"admin edits catalog tables only through the observation pipeline; do not re-implement direct edits."* `STACK.md` §5 step 3's first branch still instructs a walker, whenever `walk_sandbox` is absent from staging, to *"edit one field of one existing `groups`/`idols` row, note the original, restore it in a `finally`, and run the residue sweep"* — and `agenticflow/tracker/for-human/TASK-0034.md` §1 tells Ben the same thing in his own copy. A walker who reads either today writes a real row of a catalog three repos share, under a rule the human has withdrawn.

**The retirement is now the AMENDMENT's, not the paste's.** The old wording made the exception end when `public.walk_sandbox` appears. It ends now, whether or not the table exists, and that is the whole substance of this ticket.

**What is true after it, and must be said plainly:** until Ben pastes the sandbox table, **a save-path walk has no write surface at all.** That is the honest state — a walker states it in the walk report as a narrowed walk and moves on. It is not a licence to write `events` or `venues` (never was), not a licence to insert or delete anywhere, and not a reason to build a workaround, a fixture writer, or a second sandbox. TASK-0037 proves the sandbox once he pastes; that ticket now carries the whole of the save-path walk, which is why it went to P1.

**Retire in place, do not delete.** Replace the interim branches with a dated retirement line naming the 2026-09-08 amendment, so a walker who half-remembers the old permission finds its withdrawal rather than silence. Keep everything the retirement does not touch: the absence test itself (run `tests/walk/reset-sandbox.mts`, read which refusal it gave — that is still how a walker learns which state staging is in, and nothing here flips on a date), the sandbox's paste-ready SQL block and its uuid ids byte-identical, and the two-branch structure of step 3.

**Say the rule once.** The "do not re-implement direct edits" rule belongs to the architect's 2026-09-08 entry in `agenticflow/docs/DECISIONS.md` and its ARCHITECTURE rule, written the same day. Cite it. Only if that entry does not itself retire the walk exception may this ticket add one dated line to DECISIONS superseding the 2026-09-03 ruling — one line, never a restatement of the rule.

**Do not touch:** `.env.example`, port 8771, the sandbox SQL, `VISION.md`, or any code. This is a documentation reconciliation and nothing else.
