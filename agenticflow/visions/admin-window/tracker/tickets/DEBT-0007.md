# a fact identifier is hand-spelled ${domain}.${field} in four places, one of them now load-bearing for the reference rule

## Description
**Expected** (ARCHITECTURE.md §13.7, quoted by BUG-0087's own builder note: "a helper several tickets need is seeded before them, or it becomes N copies that drift"; the same doctrine `settlePath` and `recordFieldApiPath` exist for — "two spellings of a path is two chances for one of them to be wrong in a way nothing catches"): the app's spelling of a fact identifier, `domain.field`, is produced in ONE place.

**Found**: four independent spellings on the landed tree (154503f), grepped:

    src/app/queues/[reviewItemId]/page.tsx:236          `${observation.domain}.${observation.field}`  -> EvidenceRow.fact
    src/components/claims/claim-list.tsx:144            `${row.domain}.${row.field}`                  -> the rendered identifier
    src/components/review/close/conflict-actions.tsx:80 `${fact.domain}.${fact.field}`                -> factName(), for `supplies` and the notice
    src/lib/verdict/decision.ts:240                     `${domain}.${field}`                          -> isReferenceField's lookup key

BUG-0087's builder flagged three of these in the handoff note and did not fix them; the fourth is the one that ticket added, and it is the one that changed the stakes. `isReferenceField` (`decision.ts:240`) builds the key it looks up in `REFERENCE_FIELDS`, and `factName` (`conflict-actions.tsx:80`) builds the identifier the withheld-control notice renders and the supply control's `supplies` carries. Those two must agree for the reference rule to hold at all: the predicate that decides whether a `venue_id` fact may be settled with typed text is a string built by hand, four lines of code away from another hand-built copy of the same string. Today they agree because both are the obvious two-part template; nothing tests that they will.

**Why it is DEBT and not a BUG**: no divergence is observable today. All four spellings produce the same string for every row the resolver can file — `tests/offline/review-item/conflict-actions.test.ts` drives `REFERENCE_FIELDS` through both `isReferenceField` and `factName`, and the notice's `data-close-notice` attribute matches the constant's own spelling at every card count. This is the seam that makes a future divergence silent, not a present defect.

**The shape of the fix** (architect's call on where it lands): one exported helper — `factName(domain, field)` or the like — in the pure domain leaf the components already import (`src/lib/verdict/decision.ts`), with the four call sites above using it. `REFERENCE_FIELDS`'s entries then read as the same helper's output rather than as a second literal spelling. The one thing to keep: `decision.ts` is a leaf (ARCHITECTURE.md §4 rule 7, pinned by `tests/offline/db/layering.test.ts`) — the helper goes IN it, and nothing goes into it from outside.
