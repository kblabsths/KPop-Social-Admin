# STACK.md 5's walk caveat is false: the walker identity is allowlisted on staging and its saves land

## Description
Expected (agenticflow/docs/vision/STACK.md 5, 'Two caveats a walker must know', second bullet): "Staging's allowlist does not hold `walker@admin-window.local`, so a save from `EditableCell` gets a 403. Every read surface walks fine."

Found: the walker identity IS on staging's allowlist now, so its saves SUCCEED and write the shared staging catalog. Measured 2026-09-03 on run/admin-window at 1526051, against a walk instance launched exactly as 5 prescribes (staging names mapped, AUTH_URL=http://localhost:8771, port 8771):

  1. `node tests/walk/session-cookie.mts`  -> descriptor for walker@admin-window.local
  2. PATCH /api/admin/records/groups/<a real row id> with that cookie, body {"field":"bio","value":"<marker>"}
     -> **200 {"ok":true,...}**, and a direct service-role SELECT confirms the column now carries the marker.
     (The probe restored the original value in a finally; residue check: 0 rows carry the marker.)
  3. staging admin_allowed_emails holds 2 rows, and `.ilike('email','walker@admin-window.local')` MATCHES
     - which is exactly what src/lib/admin.ts:14-22 (requireAdmin) consults, so the gate passes.
  4. Earlier probe on a non-existent id answered 404 'no groups record with that id', not 403 - the same proof that the gate is passed, without a write.

Ben evidently answered the open question the architect left in TASK-0033's History (2026-09-03T21:17:28Z) by adding the labelled walker row. The doc was true when TASK-0033 landed and is false now.

Why this matters (walker-visible, and it is the dangerous direction): every M1 endgame walker - designer walk, user-sims, verifier - is told by this recipe that an edit-surface save cannot land. Following it, a walk of the edit surface will silently write real rows in the shared staging catalog and the walker will not know to restore them; conversely a walker that sees a save fail will suppress a genuine bug report because the doc told it 403 is correct.

Fix (a doc correction; the mint helper and its tests are correct and stay as they are): 5's second caveat must state the measured truth - the walker identity is allowlisted on staging, saves DO land, and a walk that drives EditableCell writes real staging rows and must confine itself to one field on one groups/idols row and restore it. The 'sign-in is never walked' caveat is unaffected. Whether staging keeps the walker row at all is Ben's call, not a builder's - if it is removed instead, the same bullet still needs rewriting to say so, so the ticket is a doc edit either way. No product code changes.
