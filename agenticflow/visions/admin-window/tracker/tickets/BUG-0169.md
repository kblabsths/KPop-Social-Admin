# the /cycles gauges render Empty at a counted zero while the live oracle grades them emptyAtZero:false, so cycles.live is red on the run branch

## Description
**Expected** (`tests/live/cycles.live.test.ts:282` `emptyAtZero: false` with `figure: "Cycles in this window"`, and LESSONS 7 — "An empty set still renders its labelled figure as a real 0", admin-window/BUG-0027): with zero rows in the gauge's window, `[data-surface="cycle_health"]` renders its OK state and the labelled figure reads 0.
**Found**: it renders its EMPTY card, and the live oracle throws. Same at `[data-surface="resolution_latency"]` (`tests/live/cycles.live.test.ts:313`).

**Repro (exact), from the repo root on run/admin-window @ 554dd78:**

```
npm run test:live -- tests/live/cycles.live.test.ts
```

exits 1 — `Tests 2 failed | 5 passed (7)` — run twice back to back, identical both times, so this is deterministic and NOT a staging race:

```
StateMismatchError: '[data-surface="cycle_health"]' rendered its EMPTY state, but this test counted 0 row(s) of 'resolution_runs', which is OK.
StateMismatchError: '[data-surface="resolution_latency"]' rendered its EMPTY state, but this test counted 0 row(s) of 'field_provenance', which is OK.
```

**Neither side is new.** `emptyAtZero: false` arrived with admin-window/TASK-0032 (76c2963); the components' empty branch with admin-window/DEBT-0004 (0543d42). The contradiction was latent while staging's resolver window held rows and became visible once it emptied. TASK-0075's diff does not reach this file (verified by QA on the landed tree).

**Cost while it stands:** `npm run test:live` is red on the run branch for every M3 lane and for the milestone's own full-suite pass, on a file no M3 ticket touches.

## The ruling — the ORACLE moves, at the GRAIN (architect, 2026-09-10; DECISIONS.md same date, ARCHITECTURE §10 amended)

**The component cannot move, and does not need to.**

1. The card at a counted zero is not a choice `cycle-health.tsx:105` or `latency.tsx:31` makes. `Distribution` and `TrendTable` replace themselves with `GaugeStateCard` whenever they hold no row — with or without an explicit `state` (`distribution.tsx:145-159`, `trend-table.tsx:87-100`) — and ARCHITECTURE §7 / admin-window/TASK-0030 made that mandatory: `rows: []` with no stated reason is unwritable and a header row over an empty body is unreachable by construction. "The component moves" therefore means unwriting a shared primitive six gauges obey, in order to render the one thing §7 made impossible. Not happening.
2. **LESSONS 7 is not violated here in the first place.** The four `GaugeCard`s render unconditionally beside the empty cards, and `tests/offline/cycles/page.test.ts` has asserted exactly that since DEBT-0004 — `says the window held nothing when the resolver has applied nothing` reads `readNumber(markup, "Applies in this window") === 0` over an empty `field_provenance`. The labelled figure IS a real 0 today.
3. What is false is the ORACLE's claim about the SURFACE. `emptyAtZero: false` says "this surface never draws an empty card" — which no surface containing a distribution can honour. `stateOf` attributes every `[data-state]` card inside `within` to the surface, so a BLOCK's emptiness is being read as the SURFACE's state.

**The rule (one derivation, both surfaces, and every gauge surface after them — LESSONS 11):** a surface's state is the state of the read behind its FIGURES; a state card rendered by a block inside it belongs to that block.

- **Product (one component):** `GaugeStateCard` (`src/components/gauges/state.tsx`) emits `data-gauge-block` on the card it renders — one spelling, one emitter (LESSONS 5). `Distribution`, `TrendTable` and `GaugeCard` reach it already; nothing else calls it. A SURFACE-level refusal is rendered by `StateOf` in `src/app/cycles/page.tsx`, which does not use `GaugeStateCard` and so carries no marker — that is what makes the exclusion incapable of silencing an error or a not-provisioned card (admin-window/BUG-0036's exact failure mode, and the reason the marker lives in exactly one place).
- **Oracle (two call sites):** both `gradeSurface` calls in `tests/live/cycles.live.test.ts` pass `excluding` for that marker — the device `/queues` already uses for `[data-gauge-queue]` (`queues.live.test.ts:98,419`) — and **keep `emptyAtZero: false`**. Both call sites read the selector from ONE shared constant in that file; two hand-typed selectors would be two rules.

**What this buys over the cheap fix.** Flipping `emptyAtZero` to `true` would also green the file, and it is wrong twice: it grades the surface `empty` at a counted zero and then RETURNS before comparing anything (the parity assertions stop running in exactly the state that reddened), and it says nothing about the same card appearing over a NON-empty window — a distribution with no rows beside figures that count rows, which is this bug again at `counted > 0`. Under this ruling the surface stays `ok` at a counted zero, `gradeSurface`'s `figure` clause still demands the labelled 0, and the case goes on to grade every figure it grades when the window is full.

**Do not** add a third assertion of the behaviour: the two failing cases ARE the pin (watched red twice on the landed tree), so they are extended, not duplicated. **Do not** touch the resolver, staging's data, or anything on `/cycles` outside the two gauge sections' oracle.

## Acceptance criteria
1. `npm run test:live -- tests/live/cycles.live.test.ts` exits 0 on the landed tree in staging's CURRENT state — zero rows in both gauges' windows, the state that reddens it today — and both gauges are decided the SAME way from one derivation (LESSONS 11): one shared selector constant in that file, passed as `excluding` at both `gradeSurface` call sites, with `emptyAtZero: false` kept at both. 2. The marker has ONE emitter and one spelling: `data-gauge-block` is emitted from `GaugeStateCard` in `src/components/gauges/state.tsx` — on the card element itself or on a wrapper that component renders — so every card a gauge BLOCK renders (Distribution, TrendTable, a stated GaugeCard) carries it, and no page, feature component or other block sets it (nothing under `src/app` or `src/components/cycles` spells it at all). 3. The exclusion cannot silence a refusal (admin-window/BUG-0036): an offline case over the existing not-provisioned and error fixtures for `/cycles` asserts the card or line the SURFACE renders in those states carries no `data-gauge-block`, so it still reaches `stateOf` — and the live file's existing not_provisioned/error handling is unchanged. 4. The losing side stays pinned, on both surfaces, offline, over a zero-window fixture: with zero `resolution_runs` in the window and with zero `field_provenance` applies, every labelled COUNT figure of each gauge reads exactly `0` — "Cycles in this window", "Facts examined", "Writes", "Errors"; "Applies in this window", "Unset by a human decision", "Applies with no claim found" — rendered as a real `0` and never as the absence dash, never missing, and the surface renders no card of its OWN in place of them (the median-wait card's dash stays an absence and is not graded as a zero). LESSONS 7's rule survives this ruling as a test, not as a comment. 5. The two-fact rule stays pinned the same way (LESSONS 3 / ARCHITECTURE §4.3): over the same zero fixture each block's Empty card still names what it holds AND the one thing that fills it, so the exclusion cannot quietly become "empty blocks are ungraded". 6. Nothing else moves: `src/components/cycles/cycle-health.tsx` and `src/components/cycles/latency.tsx` are BYTE-IDENTICAL (the components do not move — that is the ruling), no other file under `tests/live` changes, the five currently-green cases in cycles.live.test.ts still pass and still assert what they assert, `npm run lint` and `npm test` are green, and the closing History entry states which side moved and names the ruling it followed (DECISIONS 2026-09-10 / ARCHITECTURE §10, the block-grain rule).
