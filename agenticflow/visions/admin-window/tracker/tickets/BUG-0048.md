# Browse: the poster cell is a 24x24 thumbnail that navigates out of the app to the CDN

## Description
Found on the M1 endgame designer walk (2026-09-03), walk instance :8771 against staging, 1440x900.

The POSTER column on `/browse` renders `<a href="https://s1.ticketm.net/dam/a/..."><img …></a>`. Measured: the image is **24x24 CSS px**, and the anchor carries no `target`, so a click replaces the Admin tab with a raw image on the Ticketmaster CDN.

Two things against the file:

1. **Feel bar 10 — "The investigation never leaves the app."** Every other link on the page is a real in-app URL (`/records/events/<id>`). The poster is the one cell that navigates the operator out, with the browser's Back button as the only way home.

2. **24x24 cannot do the job the column exists for.** The column's own source comment says "Spot-verification is looking at the thing: a poster that belongs to" — at 24px the operator can see that an image EXISTS, not whether it is the right one. The Look sets no image rule (my taste fills the gap, licensed by VISION's "Browse (v1 view: recent events) ... whose numbers match what the database says" and the walk's spot-verification purpose), so I am not legislating a size — only recording that the present one answers a different question than the column asks.

The alt text is correct and present (the event title), so the accessibility side is clean.

Evidence: `agenticflow/tracker/evidence/designer-walk-m1/browse-light.png` (the POSTER column, all 50 rows).

Lowest priority of the walk: nothing is broken, nothing is wrong, and an operator who never clicks a poster never meets it.

**What this adds that BUG-0047 does not.** 0047 is the STARTS column's zone suffix and the row wrapping it causes; this is the POSTER column's link target and size. Same file, different column renderer, no shared line.

## Acceptance criteria
Clicking a poster does not navigate the Admin tab away from the app. Either the poster is not a link, or it opens outside the current tab — the operator's place in the browse list survives the click.

The poster is large enough that "is this the right poster for this event" is answerable from the row, or the column is honest about being a presence indicator. Say in the ticket History which of the two was chosen and the rendered size.

The `alt` stays the event title.

`tests/offline/browse/page.test.ts` asserts the poster cell's rendered markup — the anchor's target behaviour and the image's alt — so this cannot regress silently.

Human-check: on `/browse`, click a poster; you are still in Admin, on the same list, at the same scroll position. (human-checkable)
