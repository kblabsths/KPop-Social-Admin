# Three paging-leaf truths: a ceiling-false invariant, a stale test title, and a closure guard that stops at a barrel

## Description
**Modules:** `src/lib/paging/machine.ts` (comment only — no behaviour change), `tests/offline/paging/machine.test.ts`, `tests/offline/claims/read.test.ts`. Three small truth defects QA left on the TASK-0065 and BUG-0168 closes, none of which changes what the app does and all of which make a later reader believe something false. They are one ticket because they are one session's worth of reading and each is a sentence or a guard, not a behaviour.

**1. `requestPage`'s doc invariant is false at the ceiling.** Its closing paragraph says: "after any press, either `pageBound(String(held), deps.size)` is `ok` or the status is `exhausted` — `held` leaves the bound grid only on the final page." Measured on the landed code: `MAX_PAGE_OFFSET` is 100000, so from `held = 100000` with a window of 50 a FULL page appends, `held` becomes 100050, `exhausted` is false and the status is `idle`. `pageBound("100050", 50)` is refused (above the ceiling) with the status not exhausted — the invariant's second escape hatch, the ceiling, is not in the sentence. The BEHAVIOUR is right and must not change: `PageMore`'s arm 2 is exactly what stands there, and admin-window/TASK-0067's ruling of 2026-09-10 says so. Only the prose is wrong, and a false invariant in a leaf's header is what a later builder writes a "simplification" against. Rewrite it to state the rule that holds — `held` moves by one WINDOW on every continuing page, and it may sit off the grid in exactly two places, the final (short or empty) page and the ceiling, where the widget's limit arm is the honest answer — and cite `MAX_PAGE_OFFSET` so the reader can find the number.

**2. A stale test title, `tests/offline/paging/machine.test.ts` line 200.** "appends an ok answer in the order received and **grows the bound by the row count**". Since BUG-0168 a continuing page grows it by the WINDOW — a page whose row count is not the window is now refused, not appended. The assertions are right; the title describes the rule the ticket deleted.

**3. The leaf-closure guard stops silently at an unresolvable specifier** (`tests/offline/claims/read.test.ts`, "the claims leaf reaches nothing that can reach a database"). `importsOf` maps `@/x/y` to `src/x/y.ts` and hands it to `codeText`, whose `sourceText` returns **""** for ENOENT/EISDIR by design (a file that vanished mid-walk reads as empty). So a barrel import — `@/components/ui`, which is `src/components/ui/index.ts` and not `src/components/ui.ts` — walks into an empty string: the whole subtree behind it is never scanned, nothing fails, and the guard reports green over a closure it did not read. The leaf's three current imports all resolve, so this is latent, not live; it is exactly the shape of guard that greens the day it stops working. Resolve a directory specifier to its `index.ts`/`index.tsx`, and make an `src/` specifier that resolves to NO real file an assertion failure naming the importer and the specifier, rather than empty text. `tests/offline/db/layering.test.ts` owns the same rule for the registered leaf set — if the fix wants a shared resolver, it goes where that file can reach it, not copied (LESSONS 5).

Do not widen this ticket: no behaviour change in `src/lib/paging/**`, no new rule over the leaf set, no reorganisation of the two test files.

## Acceptance criteria
requestPage's header states an invariant that is true of the landed code, and the ceiling case is DRIVEN rather than asserted in prose: an offline test presses from held = MAX_PAGE_OFFSET with a full window and pins that the next state is status idle with held above the ceiling and pageBound(String(held), size) refused — the state PageMore answers with its limit arm — and the comment names MAX_PAGE_OFFSET as the second place held may sit off the grid. No behaviour in src/lib/paging/machine.ts changes: the offline paging suite is green with no assertion about rows, held, status or refusal weakened or removed.

The test at tests/offline/paging/machine.test.ts that appends an ok answer names what it proves — the bound grows by the WINDOW — and the phrase "grows the bound by the row count" appears nowhere in the file.

The leaf-closure guard in tests/offline/claims/read.test.ts reads every file in the closure it claims to walk: a directory specifier resolves to its index.ts/index.tsx, and an src/ specifier that resolves to no real file is an assertion FAILURE naming the importer and the specifier — never empty text that skips a subtree silently. Proved on two fixtures, one that must fail and one that must not: the resolver asked for a barrel (a directory with an index file) returns that index file, and the guard run over a fixture importer whose src/ specifier resolves nowhere fails. The guard still passes over the real leaf, and still fails on a leaf that reaches lib/db, supabase-js or process.env at depth — the existing negative fixture is unchanged.
