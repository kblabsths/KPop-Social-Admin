# the close's picker stays live while a settlement is in flight, and drops the row it is clicked with

## Description
**Expected** (`ChosenControl`'s own `disabled` contract, `src/components/review/close/form.tsx:254` — "A settlement is in flight, so this control may not start a second one" — and admin-window/BUG-0097's rule for the SAME shared panel, `src/components/records/entity-picker.tsx:266-283`, pinned for the record surface by `tests/offline/records/entity-picker.test.ts:267` "offers no option that would start a second write while one is saving"): while a settlement is in flight, no option in the open picker may act.

**Found**: every option acts. `ChosenControl` hands `PickerPanel` a hardcoded `status={{ kind: "idle" }}` (`form.tsx:285`), so `busy={status.kind === "saving"}` (`entity-picker.tsx:353`) is false and `disabled={busy}` (`entity-picker.tsx:283`) never fires. `disabled` reaches the control's TOGGLE only (`form.tsx:271`). Rendering `ChosenControl` with `open: true, disabled: true` — exactly what `CloseForm` passes while settling (`form.tsx:403,405`) — leaves all three window rows live: `["Olympic Hall 01920000-…a4", "Gocheok Sky Dome 01920000-…b1", "— 01920000-…b2"]` where `[]` is expected.

**Repro (operator path, an `entity_link` FACT item naming a whole `events.venue` fact, so both controls are offered — TASK-0056 criterion 1's fixture):**
1. Open the item's close; press **Link to an existing entity**. The panel opens (`choosing = 0`).
2. Without closing it, press **Settle & leave it held**. That button is live (nothing is in flight yet); `state` becomes `settling`, so `settling = true`.
3. The panel is STILL open and still live: `open={choosing === index}` and `disabled={settling}` are independent state and nothing clears `choosing` when a settlement starts (`form.tsx:400-419`; the settle button's `onClick` at `form.tsx:427` touches neither).
4. Click a venue row. `onChoose` closes the panel and calls `settle`, which returns at its in-flight guard (`form.tsx:334-336`) **without `setState`** — no refusal is shown, no status changes, the note is untouched.
5. The first settlement lands and the form is replaced by `SettledNotice` for `settle`. The operator's link choice is gone, and nothing on screen ever said so.

Two divergences in one: a control that LOOKS live while every sibling control is visibly disabled, and a click on it that is silently dropped. The second is why BUG-0097 made the rows go busy on the record surface rather than trusting the write path to refuse it later.

**Repro (test, deterministic)**: `tests/offline/review-item/link-actions.test.ts` > "the link control's picker" > "offers no live option while a settlement is in flight" — landed as a strict `it.fails` pin (admin-window/BUG-0102), observed RED as a plain `it` against the landed tree at 6a93776 before it was pinned. Flip `it.fails` back to `it` when fixing; strict means the pin reddens the day the divergence disappears.

**Not the fix**: `entity-picker.tsx` is correct and owns BUG-0097 — the defect is the close's re-use of it discarding the `status` the panel takes a parameter for. Whether the panel also CLOSES when a sibling control starts settling is the fixer's call; going busy is the contract.
