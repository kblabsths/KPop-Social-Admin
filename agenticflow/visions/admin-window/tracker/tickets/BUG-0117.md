# The review header's out-links draw half their own words in secondary ink, and three files retype the app's one link spelling instead of importing it

## Description
QA's residual from the BUG-0113 attack (2026-09-09), measured and filed by the architect on the same day's rulings pass. It is NOT the chip defect BUG-0115 carries — the chip guard cannot see it — so it gets its own ticket rather than a fold.

**Two halves, one file's worth of cause, both about the app's one link spelling.**

**Half 1 — a link whose ink stops halfway through its own words.** `src/components/review/item-header.tsx:97-106` renders each out-link as

    <a href={link.href} data-out={link.href} className="text-accent underline">
      {link.label}
      {link.value === undefined ? null : (
        <span className="type-data text-ink-secondary"> {link.value}</span>
      )}
    </a>

The value is part of the link's own words — `ItemLink.value`'s own docstring says it is "WHAT it is narrowed to, as the app names it — shown beside the label" — and it carries `text-ink-secondary`, which CSS gives priority over the inherited accent. So the anchor measures as a link while half of what a reader sees is drawn in secondary ink. It is the mechanism of BUG-0113 without the chip: there a fill also painted over the underline, so the link vanished entirely; here the underline survives and only the ink is broken. QA measured it in the browser on `/queues/<id>`: anchor `rgb(152, 16, 250)`, the source name inside it `rgb(74, 85, 101)`, same shape in dark.

**Measured, whole-window, by the architect before filing** (offline, the shared `loadSurfaces()` harness, `populatedScript`, every one of the eight routes, anchors filtered to those carrying `IN_PAGE_LINK`'s ink): exactly **two** re-inked links exist in this app, both on `/queues/<reviewItemId>`, both from this component —

    "/queues/<id>": ["Its claims events — text-ink-secondary",
                     "Its record events/01920000-0000-7000-800… — text-ink-secondary"]

and `[]` on `/`, `/queues`, `/claims`, `/sources`, `/cycles`, `/browse`, `/records/<table>/<id>`. So the repo-wide guard criterion 2 asks for is red today on exactly this defect and green everywhere else.

**Half 2 — three hand-written copies of the one link spelling.** `src/components/cycles/links.ts` says the app has exactly one — "a second spelling is a second answer to 'does this text go somewhere', and BUG-0099 is what the second answer cost" — and publishes it as `IN_PAGE_LINK` (`text-accent underline`). Three files write the literal instead of importing it:

- `src/components/review/item-header.tsx:98` (the anchors of half 1)
- `src/components/review/close/slot.tsx:316` (the verdict's observation-id link)
- `src/app/not-found.tsx:43` (the `next/link` back to the Dashboard)

They spell the same two classes today, so nothing renders wrong; that is precisely the state BUG-0099 was in the day before the spelling changed under three surfaces that had copied it. The existing source-tree guard in `tests/offline/ui/link-spelling.test.ts` forbids only the REJECTED spelling (`hover:text-accent`); nothing yet says the published one is imported rather than retyped.

**Why this depends on BUG-0115 rather than running beside it.** Both tickets land in `tests/offline/ui/link-spelling.test.ts`, and BUG-0115 builds the whole-window sweep this ticket's guard extends. Two lanes writing one destination file collide at merge, so they are chained at the destination, not merely at the source (ARCHITECTURE §13, and the architect's decomposition rule on consolidation-shaped work). Take BUG-0115's sweep as it lands and add a second assertion to the same loop; do not fork a second sweep.

## Acceptance criteria
1. **A link's spelling reaches the words a reader sees.** No anchor carrying `IN_PAGE_LINK`'s ink contains a descendant that re-inks any of its own words. On `/queues/<reviewItemId>` the two out-links of `ItemHeader` are the open instance; measured on the pre-fix tree there are exactly two in the whole window and none on the other seven routes.
2. **The guard is repo-wide and rides BUG-0115's sweep.** In `tests/offline/ui/link-spelling.test.ts` — the one owner of link spelling — the whole-window sweep BUG-0115 lands gains a second assertion over the same rendered routes: for every anchor whose classes carry `IN_PAGE_LINK`'s INK half, `expectLinkSpellingReachesTheGlyphs` (`tests/fixtures/link-spelling.ts`) holds. The ink filter is load-bearing and must be asserted as the predicate, not assumed: the Dashboard's `error_summary` links wear `text-broken` plus the decoration by ruling (BUG-0108 criterion 3) and are NOT this rule's subject — a guard that grades them reddens on correct work. Measured by the architect on the pre-fix tree, 2026-09-09: 2 hits, both on `/queues/<id>`, 0 on the other seven routes.
3. **Half 1's fix shape.** The value keeps its FACE and loses its INK: `type-data` stays (mono carries every value the database produced — ARCHITECTURE §7), `text-ink-secondary` goes, so the whole link is drawn in the link's one ink. The words are unchanged: the label and the value render exactly as they do today, in the same order, with the same space between them, and `data-out` is untouched. Moving the value OUT of the anchor is not this ticket's call — it changes what the link's words are, which is the designer's.
4. **Half 2's fix.** `src/components/review/item-header.tsx`, `src/components/review/close/slot.tsx` and `src/app/not-found.tsx` import `IN_PAGE_LINK` from `@/components/cycles/links` (through `@/components/cycles` where that is the file's idiom) instead of writing `text-accent underline`. The rendered classes are unchanged — this is a spelling-ownership change, not a restyle — and `slot.tsx`'s and `not-found.tsx`'s links keep every other class they carry (`type-data` on the observation id; `next/link` stays `next/link` on the 404, which is the shell's idiom and is not a link-spelling question).
5. **Nothing else moves.** No other file's classes change; no new link is created or removed; the review header's five badges, which sit beside the summary and inside no anchor, are untouched.
6. `npm run lint` and `tsc --noEmit` clean; the targeted offline files green (`ui/link-spelling`, `review-item/**`, `queues/verdict-log`, `shell/shell` — the suites that render the three files).
