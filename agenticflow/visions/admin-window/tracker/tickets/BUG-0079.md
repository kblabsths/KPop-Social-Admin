# decisionRefusals throws on an absent `value` key and mis-refuses two ordinary bodies (undefined vs null)

## Description
`decisionRefusals` (src/lib/verdict/decision.ts:206) tests three fields with `!== null` / `=== null` where the body it grades can carry an ABSENT key. `request.json()` never produces an explicit `null` for a key a client omitted, and TASK-0049 hands it exactly that body: 'the body is parsed into a VerdictDecision; then decisionRefusals — a refused decision is a 400 naming the refusal and never reaches the database'. One root cause, three symptoms, all measured on a971d37 (landed run/admin-window).

**Repro** — from the repo root, in any offline test importing the leaf (the three pins added by QA in tests/offline/verdict/decision.test.ts, block 'a body whose optional keys are absent, not null', reproduce each verbatim):

1. CRASH. `decisionRefusals({action:'supply_value', review_item_id:'2222…', actor:'admin@example.test', note:null})` (no `value` key).
   Expected (criterion 3, invariant 4 — 'value is present on the value-carrying actions'): `['value_required']`.
   Found: throws `TypeError: Cannot read properties of undefined (reading 'observation_id')` at src/lib/verdict/decision.ts:164 (`filled()` indexes `value` after line 234's `value === null` lets `undefined` through). The campaign's one pre-database guard raises where it owes a named refusal, so the settle route's 400 path becomes a 500.

2. FALSE REFUSAL, settle-only actions. `decisionRefusals({action:'settle', review_item_id:'2222…', actor:'…', note:null})` — the ordinary JSON for a settle, which carries no value at all.
   Expected: `[]`.
   Found: `['value_forbidden']` (src/lib/verdict/decision.ts:231, `value !== null`). Same for `keep_current`, `fixed`, `wont_fix`.

3. FALSE REFUSAL, the item-less override. `decisionRefusals({action:'override', actor:'…', note:null, value:{…}})` — no `review_item_id` key, which is precisely what 'null on override and ONLY on override' asks a client for.
   Expected: `[]`.
   Found: `['review_item_forbidden']` (src/lib/verdict/decision.ts:216, `review_item_id !== null`) — the refusal for CARRYING an item, returned for a body that carries none. This is the path F12's picker and TASK-0054's record surface submit on.

**Fix bar**: the guard grades an absent key exactly as it grades an explicit null (`== null` / an explicit undefined arm), and `filled()` is never reached with a non-object `value`. No new refusal name, no signature change, no import — the module stays a zero-import leaf.

**The pins**: QA added the three cases to tests/offline/verdict/decision.test.ts as `it.fails(...)` (vitest's strict xfail, tagged admin-window/BUG-XXXX), watched red before pinning. Removing `.fails` is part of the fix — leaving it after the fix turns the tests red and points back here.

**Not in scope of this BUG** (QA residual, architect's call): blank-but-non-null id slots (`value.ref = ''`, `value.observation_id = '   '`) are accepted, while a blank `review_item_id` is refused by the same module's own reasoning ('a blank string cannot satisfy a uuid FK').

## Acceptance criteria
1. `decisionRefusals` returns `['value_required']` — never throws — for a value-carrying decision whose `value` key is absent (undefined), for each of choose_claimed_value, supply_value, link_entity, override.
2. `decisionRefusals` returns `[]` for a settle-only decision (settle, keep_current, fixed, wont_fix) whose `value` key is absent, and still returns `['value_forbidden']` when a value object IS present.
3. `decisionRefusals` returns `[]` for an `override` whose `review_item_id` key is absent, and still returns `['review_item_forbidden']` when it carries a non-null id.
4. Explicit-null behaviour is unchanged: the 29 pre-existing tests in tests/offline/verdict/decision.test.ts stay green, and the three QA pins are converted from `it.fails` to plain `it`.
5. The module still imports nothing (tests/offline/db/layering.test.ts green) and exports nothing beyond the TASK-0042 contract.
6. `npm run lint` and `tsc --noEmit` clean.
