# Five live parity oracles still address their surfaces by POSITION (section:nth-of-type) — the class BUG-0056 fixed on one page only

## Description
This defect class has now shipped twice on run/admin-window (BUG-0056: /cycles, four live tests threw MarkupReadError; BUG-0061: /claims, filed alongside this). BUG-0056 fixed it for /cycles by giving Section an optional `surface` prop rendered as `data-surface` and naming that page's four surfaces. Five other live files were left addressing their surfaces positionally, and each is one added section — or one added <div> wrapper — away from the same break.

Expected: a live oracle addresses a surface by a NAME that does not move when the page is rearranged, as `src/components/ui/section.tsx:12-30` now documents and `tests/live/cycles.live.test.ts:62-77` now practises. `stateOf` (`tests/live/parity.ts:213-231`) requires the selector to match EXACTLY ONE element and throws MarkupReadError otherwise, so an added sibling section or a new wrapping <div> either duplicates a match or silently repoints the selector at the wrong surface.

Adjacent, deliberately excluded: `tests/live/queues.live.test.ts:325` addresses its surface as `section:not([data-queue] section)` — structural rather than positional, and failing for an unrelated reason (see the residual note on BUG-0056). Rule on it here or leave it; it is not a position.

Work: give the five pages' graded surfaces `data-surface` names through the `surface` prop that already exists (`src/components/ui/section.tsx:31`), and replace each selector above with its name, exactly as `tests/live/cycles.live.test.ts` now does — including the up-front "every hook present and unique" assertion (`cycles.live.test.ts:151-163`) and its offline twin (`tests/offline/cycles/page.test.ts`, describe "the surface hooks the live parity oracle addresses"). The offline twin is the part that matters for CI: `run.yaml` `ci_command` is `npm test`, which runs the offline and isolated projects only, so a live-only fix leaves this class invisible to every future ticket.

Watch the second check RED before fixing. It greps `tests/live/` for any remaining `nth-of-type`, excluding JSDoc comment lines, and currently reports exactly the eleven sites above (exit 1, measured 2026-09-03). It is the ratchet: with the work done, no live file addresses a surface by position.

Two facts a builder should not re-derive:
 1. The `surface` prop is byte-identical when omitted — rendered `Section` markup md5 `dbbf6f06bae0bfff49cee4b0ac69ae85` at both f85b43e and 193fe57 — so adding names to some pages is not a markup change for any page that keeps omitting it. `tests/offline/ui/primitives.test.ts` ("carries a data-surface only where a caller named one") pins both directions.
 2. A Section's name must not collide with a hand-written `data-surface` wrapper on the same page: `src/app/cycles/page.tsx:988` keeps `data-surface="runs"` and its enclosing Section deliberately takes NO name, because two elements answering `[data-surface="runs"]` would break `runs.live.test.ts` the same way.
