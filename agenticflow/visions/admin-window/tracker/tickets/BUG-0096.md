# The close sits 3,500px below the evidence it closes, so the operator scrolls four screenfuls to act

## Description
Measured on the M2 early walk, 2026-09-08, walk instance on 127.0.0.1:8771 against staging, bundled Chromium, viewport 1440x900, light theme, the one real review item `/queues/01a06287-5b67-7d1f-b4a5-d90aa93cb01a`.

**Expected** — LOOK_AND_FEEL, Key screens: "**Review item detail** — the evidence pair, **and the close beside it**. The operator must be able to decide without opening another tab: contenders, canonical, tiers, ages, and the note field."

**Found** — the close is not beside the evidence; it is under it, past the whole of it. Geometry of `[data-surface]` on that page, read from the rendered document:

- `what_happened`: y=84, height 128
- `evidence`:      y=256, height **3,483**  (106 rows: 91 folded records + the source's trend)
- `close`:         y=**3,781**, height 72
- document height: 3,869

So the close slot's top is 4.2 screenfuls below the fold at 1440x900, and the operator must scroll past 3,483px of evidence to reach the controls that settle the item. Nothing about the evidence needs to be read to the bottom first — it is 91 rows of the same fact folded 700 times, which is exactly the shape this queue is designed to produce (`×700` on the queue row).

Today the slot holds only the not-provisioned card, so the cost is a scroll to read one sentence. **FEAT-0010 builds three action controls into this same slot**, and FEAT-0013/TASK-0059 render a settled item's verdict there — after which the page's whole reason for existing sits below four screenfuls of raw payload. This is filed on the early walk precisely so the placement is settled before the controls land on top of it.

Not a duplicate: FEAT-0010 grades WHAT the close slot contains (criteria 1-4) and says nothing about where it renders; TASK-0059 and BUG-0092 grade the inline verdict block's own contents.

**The fix is not prescribed.** Beside the evidence (the evidence view already runs a `lg:grid-cols-[2fr_1fr]` grid whose right column holds the source dial), above it, or pinned — any of the three satisfies the bar. What the bar forbids is the operator reaching the decision only by exhausting the evidence.

## Acceptance criteria
1. On the staging signal item at 1440x900, the close slot is reachable without scrolling past the evidence: either `[data-surface="close"]` renders at y < 900 in the first viewport, or it precedes `[data-surface="evidence"]` in document order, or the two render in one row of the same grid.
2. Whichever placement is chosen, it holds for all three item shapes (a data_conflict fact item whose evidence is two cards, an entity_link fact item, and the source-pattern signal whose evidence is 100+ rows) — asserted on fixtures in the offline render suite, so a short evidence view and a long one place the close the same way.
3. The evidence view's own anatomy is unchanged: the evidence pair keeps its fixed order (contending claims left, canonical rightmost) and the source-pattern view keeps its table and its dial (LOOK_AND_FEEL, "The evidence pair").
4. The page still answers 200 with `verdicts` absent, the not-provisioned card still names `verdicts`, and nothing throws.
5. Human-check: at 1440x900 on `/queues/01a06287-5b67-7d1f-b4a5-d90aa93cb01a`, the close and the evidence are both on screen at once, or the close comes first. (human-checkable)
6. `npm run lint` and `tsc --noEmit` clean; the targeted offline files and the review-item live suite green.
