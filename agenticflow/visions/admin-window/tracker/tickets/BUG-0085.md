# the verdict log renders a present-but-blank note as an empty cell, not the mandated dash

## Description
**Expected** (LESSONS 1, and `src/components/ui/data-table.tsx`'s own promise "a null renders as an em dash … never blank"): every absence in a verdict row renders the app's one dash. `isAbsent` in `src/lib/format.ts` TRIMS before it decides, so `""` and an all-whitespace string are absences everywhere else in this app.

**Found**: the verdict log's `note` column returns a React ELEMENT (`<span title={shown.title}>{shown.text}</span>`, `src/components/queues/verdict-log.tsx` line ~166, the `note` column's `cell`), and `orDash` never looks inside an element (`isAbsent` returns false for a non-string ReactNode, `src/lib/format.ts:236`). A verdict whose `note` is `""` renders `<td class="…"><span title=""></span></td>` — a cell that says nothing. `"   "` renders three spaces. Measured on the landed tree (run/admin-window, 98c69c0).

This is the exact shape `tests/offline/absence/blank-cells.test.ts` exists to sweep ("a body that is a child COMPONENT element is never absent to it"), and that sweep cannot reach this surface: it renders ONE view per route and the verdict log is a TAB (`/queues?tab=verdict_log`), so the new table shipped outside the repo-wide blank-cell net.

**Exact repro** (offline, no database):

1. `cd app` (repo root).
2. Script `verdicts` with one row whose `note` is `""` and one whose `note` is `"   "` — `tests/offline/queues/verdict-log.test.ts`, the case `dashes a note that is present but blank, as every other absence is dashed`, does exactly this.
3. Render `QueuesPage({ searchParams: { tab: "verdict_log" } })` and read the note cell (column index 4).
4. Expected `—`; found `''` (and `'   '` for the whitespace row). The failure the pin produced before it was made strict: `AssertionError: expected '' to be '—'`.

**Reachability**: `src/app/api/admin/review-items/[reviewItemId]/settle/route.ts` forwards `body.note` VERBATIM (line 125) — the app's own control nulls a blank (`settleBody` in `src/components/review/close/actions.ts:107`), the route does not — and `decisionRefusals` refuses a blank note only on `wont_fix` (`src/lib/verdict/decision.ts`, invariant 3). `verdicts.note` is a nullable `text` with no CHECK (`agenticflow/tracker/for-human/M2-handoff-verdicts.md` line 95). So a settle carrying `"note": ""` stores `''` the day the handoff lands, and the one record of every admin data action then shows a row whose why is invisible.

**Where the fix belongs is not QA's call** — the log's column returning the `null` itself (the fix `/cycles`, `/sources`, `/claims` and `/browse` all took, per blank-cells.test.ts's own note), or the settle route normalising a blank note to null, or the handoff function's SQL doing it. One of them; not two.

**Pin**: `tests/offline/queues/verdict-log.test.ts` carries the case as a STRICT `it.fails` naming this ticket. When the fix lands the pin XPASSes and reddens — flip it to a plain `it(...)` in the same commit, the way admin-window/BUG-0067's pin was flipped in `tests/offline/cycles/page.test.ts`.
