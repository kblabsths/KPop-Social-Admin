# The canonical card's provenance line draws a blank source as an empty identifier box, announcing no absence — the claim line beside it draws the dash

## Description
Found while re-checking DEBT-0011 (QA r3, attack on the new ProvenanceSegment seam).

Expected: a provenance value with nothing visible in it draws the app's own absence element, exactly as the CLAIM LINE one card to its left already does for the same class of value — `ClaimValue` (`src/components/evidence/evidence-pair.tsx:112-115`) passes `claim.source` through `isAbsent`/`orDash` and renders `<span aria-label="no value">` (admin-window/BUG-0151 and its pinned test "draws a %s source as the app's absence element, not an empty isolated box"; the absence rule is BUG-0134).

Found: `ProvenancePart` (`src/components/evidence/evidence-pair.tsx:139-157`) wraps `segment.identifier` in `<Identifier muted>` UNCONDITIONALLY, with no absence guard. Measured offline (vitest, `tests/offline/ui/evidence-pair.test.ts`, cheerio over the rendered markup, 2026-09-09):

  provenance: [{ identifier: "" }, { identifier: "official", after: "at apply" }, "applied 3d ago"]
  renders    <span class="type-data text-ink-secondary"><span dir="ltr" class="type-data text-ink-secondary"></span> · <span dir="ltr" class="type-data text-ink-secondary">official</span> at apply · applied 3d ago</span>

  i.e. an EMPTY isolated box, `[aria-label="no value"]` count 0, and the line reads " ·  at apply · applied 3d ago" — a silent gap where the winning source belongs. Identical on all three shapes `isAbsent` calls empty: "" , "   ", and "​‮" (ink-less).

Repro (offline, no device, no network):
  1. cd "kspace Admin"
  2. ./node_modules/.bin/vitest run --project=offline tests/offline/ui/evidence-pair.test.ts
  3. The three `it.fails` cases "draws a {empty,blank,ink-less} provenance value as the app's absence element, not an empty isolated box" pass as EXPECTED FAILURES — flip `it.fails.each` to `it.each` and they go red with `expected [ "", "official" ] to not include ""`.

Reachability: `canonicalCard` (`src/app/queues/[reviewItemId]/page.tsx:339`) builds `{ identifier: source }` from `canonicalSideOf`'s `sources.get(decision.source_id)?.source ?? decision.source_id` (`src/lib/db/review-item.ts:530-533`) — the source's own NAME out of the scraper-owned `sources` registry, which is `string` with no blankness guard. A registry row whose name is empty or whitespace produces this.

NOT a regression from DEBT-0011: the pre-sweep line concatenated the same empty string into the sentence and drew the same nothing, so criterion 3 (rendered text unchanged) holds. What DEBT-0011 changed is that the gap now has a BOX around it, and that the sibling line on the same card gained the guard this one did not. P3: two lines of one card disagree about how they announce a missing value, on a path that needs a blank registry name to reach.

Fix shape (for the builder, not binding): route `segment.identifier` through the same `isAbsent`/`orDash` pair `ClaimValue` uses — an absent value is the app's own absence element, never a machine identifier's box, so it must NOT be wrapped. Then convert the `it.fails.each` in `tests/offline/ui/evidence-pair.test.ts` to a strict `it.each`.
