# A refusal that lands on a panel focus has slipped out of leaves focus on the document

## Description
DEBT-0013's criterion 3 is false on the landed tree (run/admin-window, a0ba886).

**Expected** (DEBT-0013 criterion 3): "Focus is never dropped to the document:
after a refusal, after a save that lands, and after a save that is superseded by
another widget, focus is on a real focusable element of this widget."

**Found**: focus is on `document.body` after a refusal, and after a supersession,
whenever the operator's focus left the panel's controls at any moment during the
write. `pickerFocus`'s no-transition branch rescues focus for exactly one status:

    src/components/records/entity-picker.tsx:387-390
    // No transition, so the only thing that moves focus is a control going away
    // under the operator's hands: the option they activated, going `disabled`.
    if (open && status.kind === "saving") return adrift ? "search" : "leave";
    return "leave";

So `pickerFocus({open: true, was: true, status: {kind: "failed", ...}, adrift: true})`
returns `"leave"` — and `{kind: "idle"}` (the superseded case) likewise. The panel
is still open on both of those paths, so `open !== was` is false and the transition
branch at :382 never runs.

**Repro (browser, and modelled offline by the two pins below)**

1. Open a record page with a reference field (`events`, `venue_id`) and press the
   Choose button. The panel opens focused on the search field.
2. Activate a row (Enter on the option, or click it). The write goes in flight,
   every option goes `disabled` (BUG-0097), and the focus effect correctly parks
   focus on the search field.
3. While the PATCH is still running, press on any non-control part of the panel —
   the hint line ("Choosing a row records the change and closes the picker.
   Escape cancels."), the window line, or the gap between two rows. The browser
   blurs the search field and leaves `document.activeElement === document.body`.
   The press is INSIDE the widget, so `retiresRefusal` correctly makes nothing of
   it, and neither `open` nor `status` changed — so the focus effect
   (`useEffect(..., [open, status])`, :761-775) does not run.
4. The write is refused. The panel stays open (correct — BUG-0119), `status`
   becomes `failed`, the focus effect runs, and returns `"leave"`.

   **Expected**: focus on the search field (the widget's one live control, and
   where the `saving` leg already parks it).
   **Actual**: `document.activeElement === document.body`. The operator's next
   Tab restarts at the top of the document — the precise defect DEBT-0013 was
   opened to kill — at the moment they most need to act on the sentence they are
   being shown.

5. Same branch, criterion 3's third moment: with focus adrift as above, let another
   widget on the page state a refusal. The page's one slot changes hands
   (`takeRefusalSlot`), this picker's statement goes `idle` with the panel still
   open, and the branch has no answer for `idle` either. Focus stays on the body.

**Why the builder's 12 new tests did not see it.** `pickerShell()`'s `settle()`
ran the focus effect after EVERY move, while the shipped effect is keyed
`[open, status]` and sleeps through a press that focuses nothing. The model
therefore re-decided focus at a moment the browser never asks the rule to, and
the `saving` leg re-parked focus on the search field before the answer arrived.
This QA pass made `runFocus()` honour the shipped deps; that change alone reddens
nothing else — all 67 of the pre-existing tests in the file still pass.

**Not a one-line fix, and please do not make it one.** Deleting
`&& status.kind === "saving"` from :389 would redden the existing pin "steals no
focus from a page that has merely drawn a picker", which requires
`pickerFocus({open: true, was: true, status: {kind: "idle"}, adrift: true})` to be
`"leave"` — an operator sitting in an open panel whose focus drifted for their own
reasons must not be yanked into the search box. The rule needs to distinguish "a
status change just arrived under the operator's hands" from "the widget is at
rest", which is a fourth input or a second transition edge, not a dropped clause.

**Pinned** (both `it.fails`, strict — they turn red the day the bug dies):
`tests/offline/records/entity-picker.test.ts`, in `describe("where the picker
leaves focus")`:
 - "puts focus back on a live control when an answer lands on a panel focus has
   slipped out of"
 - "puts focus back on a live control when another widget supersedes a refusal it
   is holding"
Un-`fails` both when the rule is fixed.
