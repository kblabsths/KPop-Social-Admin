# /browse pages further down its one curated view, and says so honestly

## Description
**Modules:** `src/app/browse/page.tsx` (wiring only), a NEW `src/components/browse/paged-browse-table.tsx` (`"use client"`).

The mirror of TASK-0067, on the surface whose window is the view's own. Read TASK-0067's landed diff first: where the two pages need the same thing, it is `src/components/ui/paging.tsx` or `src/lib/paging/**` — never a paste (LESSONS 5; common violation 9 is four byte-identical copies of one page helper). Both of those files are OUT of this ticket's scope and land before it (TASK-0076): this surface consumes the driver, it does not extend it.

**The first screen does not change.** Same window line, same figures, same row set, same column selector behaviour, byte-identical on the same fixture.

**Interface contract** (amended 2026-09-10 — `total` removed, `surface` and `reported` added; see the two rulings below):

```tsx
// src/components/browse/paged-browse-table.tsx
"use client";
export function PagedBrowseTable(props: {
  /** The name the events BODY answers to — `data-surface`, spelled by the page. */
  surface: string;
  view: BrowseView;
  /** The columns the URL says are shown, as the page resolved them. */
  shown: readonly BrowseColumnKey[];
  /** The rows the page RENDERED, in the order it rendered them. */
  initial: readonly BrowseRow[];
  /** The view + column state the page RENDERED, serialized — never the raw URL. */
  params: string;
  /** The surface's window, spelled by the page and by nothing here. */
  size: number;
  /**
   * The objects the PAGE has already reported above the table — its own legs'
   * `missing` / `reading`. A leg named once is not named again below.
   */
  reported: readonly string[];
}): ReactNode;
```

It renders the same `BrowseTable` with `[...initial, ...state.rows]`, the paged legs' notes beneath it, and `PageMore` beneath those.

**NO `total` PROP, AND THAT IS THE DRAWING RULE, NOT AN OMISSION** (amended 2026-09-10: the earlier contract carried `total: number | null`, which contradicted this ticket's own criteria and would have made the affordance unreachable). Browse's events read is a WINDOW read with **no count beside it at all** — `readRecentEvents` returns rows and nothing else — so a `total` prop on this surface is always `null`, and a `more` derived from it is always false. The honest signal that there is more is a FULL first window, asked of the one function that answers that question: `pageBound(String(held), view.window).kind === "ok"`, where `held` is the number of rows the page actually RENDERED. That is not a total and no sentence may present it as one — the surface says "the newest N by arrival", exactly as it does today, and the affordance says only that there is more to walk. A short first window means no affordance and the surface says the set is complete. `not_provisioned` or `error` on the events read means no affordance at all — zero occurrences of the control in the rendered HTML, graded in `tests/offline/absence/pages.test.ts` with every other surface.

**THE LEGS THE PAGE BROUGHT ARE RENDERED, AND THEY ARE RENDERED THE SAME WAY THE FIRST SCREEN RENDERS ITS OWN** (the gap QA measured on TASK-0068). Browse is read by FOUR queries: the events window decides the rows, and the venue and provenance legs FILL columns over that window's ids. The paging route already puts both on its `ok` arm (`NotedPageAnswer`, `notes: { venues, provenance }`) and TASK-0076 lands the driver half, so `state.notes` is a `PageNotes` record this wrapper can render. Render each non-null note through the SAME `StateOf` primitive the page uses — same component, same `data-not-provisioned` / `data-read-failed` hooks, same words — below the table and above the control. A page whose provenance leg refused must never reach the operator as events with a silently empty Sources column. This ticket writes no note of its own, imports no `lib/db` type into a component (§4), and spells **no leg key**: it renders the non-null notes the record holds, in the record's own order (the route composes venues then provenance and JSON preserves it).

**WHERE THE NOTES SIT IS DECIDED BY THE SURFACE HOOK, NOT BY TASTE.** `[data-surface="events"]` names the events BODY and nothing else: `tests/offline/browse/page.test.ts` pins "the leg notes stay outside it", and the live oracle grades the STATE of that element as the state of the events read. `StateOf` carries `data-state="error"` / `data-state="not_provisioned"`, so a paged leg note rendered INSIDE that element would grade an unreadable provenance leg as an unreadable events window — the precise defect that pin exists for. Therefore **the wrapper owns the surface div**: it renders `<div data-surface={surface}>` around the `BrowseTable` alone, and the paged notes and `PageMore` are its SIBLINGS after it. The page keeps rendering its own first-screen leg notes exactly where they stand today — above the table, outside the surface — and in the three non-paged arms the page renders the surface div itself, exactly as today. Exactly one element on the page carries that name, in every state.

**ONE OBJECT, REPORTED ONCE.** The page already names its own refused legs above the table; repeating the same object below the rows tells the operator nothing and doubles a red line. The wrapper renders a paged note only when the object it names — `missing` or `reading` — is not in `reported`, which the page fills from its own two legs. The identity is the OBJECT, not the leg key: it is the same string on both sides because it comes from the same read, so nothing here can drift from the route's key spelling.

**The column selector and paging do not fight.** Changing columns is URL state and re-renders the first screen from the server (paged-in rows are discarded — §5's amendment says so out loud); paging never rewrites the URL.

**Live (M3 EC4):** `tests/live/browse.live.test.ts` gains a paged walk reaching an event beyond the first window's last row, with its own independently written range query as the oracle, addressed by `data-surface` and deciding the state kind from `data-state` first.

## Acceptance criteria
On the same offline fixture the first server-rendered screen of /browse is byte-identical to the pre-ticket tree in its window line, its figures, its row set and its columns; the affordance is the only addition. It is drawn only when the first window came back full, absent on a short window (where the surface says the set is complete), and absent with zero occurrences of the control in the rendered HTML against a PGRST205 database where /browse renders data-state="not_provisioned" — graded in tests/offline/absence/pages.test.ts. One press is one request carrying an explicit bound; zero presses, zero requests. A refused page leaves the rendered row count unchanged and names the object, on one fixture that must refuse and one that must not. No sentence on the page presents the paged-in rows as a total. Changing a column re-renders the first screen from the server and no offset is ever written into the URL.

THE FIRST SCREEN'S STATE IS BUILT ON THE BOUND GRID. The held the page hands initialPage is the number of rows it actually RENDERED, and more is true only when that held is a bound this surface can page from — pageBound(String(held), view.window).kind === "ok" — which on this surface is the same question as "did the first window come back full", asked of the one function that answers it rather than re-derived beside it. A short first window is therefore never more: true, so no state is ever constructed off the grid. Pinned two ways: on a short-window fixture /browse draws no control and does not claim there is more, and across every fixture in the offline suite no FIRST server-rendered screen of /browse emits data-paging="limit" — that arm belongs to a state that has walked to the ceiling, and on a first screen it would be a limit sentence with no control and no way back (QA, BUG-0168 close).

THE WINDOW IS ONE NUMBER, END TO END. The wrapper hands usePageRows the size it was given and passes PageMore the size the hook handed BACK — literally `const { state, press, size } = usePageRows(...)` and `<PageMore size={size} …/>` — so the number the driver grades a page full-or-short against and the number the control renders in its label are the same value, and src/components/browse/paged-browse-table.tsx names neither BROWSE_VIEWS nor view.window (the window arrives as a prop from the page, whose view is its one spelling). Proved by rendering the wrapper at a window that is NOT 50: the control's label names that number, and a page of that many rows continues while a shorter one does not.

Against staging, a paged walk reaches an event beyond the first window's last row, graded by an independently written query. BROWSE_VIEWS still holds exactly one entry, the sidebar six links, src/app no new page route, and /browse's live parity suite is green.
THE LEGS THE PAGE BROUGHT ARE RENDERED, BESIDE THE ROWS THEY CAME WITH AND EXACTLY AS THE FIRST SCREEN RENDERS ITS OWN. On a fixture whose first-screen legs all answered and whose PAGED read finds field_provenance absent, one press appends that page's rows AND renders the leg's report below the table through StateOf — the same data-not-provisioned="field_provenance" hook and the same words the page's own card carries — and the same holds for a failed venues leg through data-read-failed. The note reaches the operator byte-identical to what the answer carried: the object is the database's own missing/reading and the account its own message, neither reworded nor truncated by this surface. A page whose legs answered renders no note at all, and no note is ever rendered from a state that has taken in no page.

THE NOTES SIT OUTSIDE THE SURFACE THE ORACLE GRADES. In every state of this page — paged and unpaged, legs fine and legs broken — [data-surface="events"] occurs exactly once, is not nested inside another element carrying that name, wraps the events table and nothing else, and contains no [data-state] element; the existing pin "holds the events body and nothing else — the leg notes stay outside it" is green unedited, and a paged leg note is a SIBLING after that element, above the control. The first screen's own leg notes stand exactly where they stand today, above the table.

ONE OBJECT IS REPORTED ONCE. On a fixture where field_provenance is absent for the first screen AND for the paged read, [data-not-provisioned="field_provenance"] occurs exactly once in the rendered markup after a press — the page named it, so the wrapper does not name it again. On a fixture where only the PAGED read's leg refused, it occurs exactly once too, below the rows. A leg that refused on one page stays reported after a later page whose legs answered, for as long as its rows are on screen.

THE WRAPPER SPELLS NO LEG KEY AND NO lib/db TYPE. It renders the non-null notes the record holds in the record's own order, so its output cannot drift from the route's key spelling; it imports nothing from lib/db (the StateOf seam, ARCHITECTURE.md §4), and the props it takes are exactly the contract's.
