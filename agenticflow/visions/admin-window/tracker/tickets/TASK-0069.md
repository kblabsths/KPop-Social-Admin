# /browse pages further down its one curated view, and says so honestly

## Description
**Modules:** `src/app/browse/page.tsx` (wiring only), a NEW `src/components/browse/paged-browse-table.tsx` (`"use client"`).

The mirror of TASK-0067, on the surface whose window is the view's own. Read TASK-0067's landed diff first: where the two pages need the same thing, it is `src/components/ui/paging.tsx` or `src/lib/paging/**` — never a paste (LESSONS 5; common violation 9 is four byte-identical copies of one page helper).

**The first screen does not change.** Same window line, same figures, same row set, same column selector behaviour, byte-identical on the same fixture.

**Interface contract:**

```tsx
// src/components/browse/paged-browse-table.tsx
"use client";
export function PagedBrowseTable(props: {
  initial: readonly BrowseRow[];
  /** The columns this view is showing — the selector's answer, unchanged. */
  columns: readonly BrowseColumn[];
  params: string;      // the view + column state the page RENDERED
  size: number;        // view.window
  /** Null when no read established that there is more. */
  total: number | null;
}): ReactNode;
```

It renders the same `BrowseTable` with `[...initial, ...state.rows]` and `PageMore` beneath it.

**When the affordance is drawn.** Browse's events read is a WINDOW read with no exact count beside it: the honest signal that there is more is a FULL first window (`rows.length === view.window`), and the answer's own `exhausted` after that. That is not a total and no sentence may present it as one — the surface says "the newest N by arrival", exactly as it does today, and the affordance says only that there is more to walk. A short first window means no affordance and the surface says the set is complete. `not_provisioned` or `error` on the events read means no affordance at all — zero occurrences of the control in the rendered HTML, graded in `tests/offline/absence/pages.test.ts` with every other surface.

**The column selector and paging do not fight.** Changing columns is URL state and re-renders the first screen from the server (paged-in rows are discarded — §5's amendment says so out loud); paging never rewrites the URL.

**Live (M3 EC4):** `tests/live/browse.live.test.ts` gains a paged walk reaching an event beyond the first window's last row, with its own independently written range query as the oracle, addressed by `data-surface` and deciding the state kind from `data-state` first.

## Acceptance criteria
On the same offline fixture the first server-rendered screen of /browse is byte-identical to the pre-ticket tree in its window line, its figures, its row set and its columns; the affordance is the only addition. It is drawn only when the first window came back full, absent on a short window (where the surface says the set is complete), and absent with zero occurrences of the control in the rendered HTML against a PGRST205 database where /browse renders data-state="not_provisioned" — graded in tests/offline/absence/pages.test.ts. One press is one request carrying an explicit bound; zero presses, zero requests. A refused page leaves the rendered row count unchanged and names the object, on one fixture that must refuse and one that must not. No sentence on the page presents the paged-in rows as a total. Changing a column re-renders the first screen from the server and no offset is ever written into the URL. Against staging, a paged walk reaches an event beyond the first window's last row, graded by an independently written query. BROWSE_VIEWS still holds exactly one entry, the sidebar six links, src/app no new page route, and /browse's live parity suite is green.
