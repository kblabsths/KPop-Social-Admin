# Seventeen cycles report errors and still say succeeded in healthy green — the palette bar TASK-0038 wrote and nothing built

## Description
Measured on the M2 endgame walk, 2026-09-09, walk instance on 127.0.0.1:8771 against staging, bundled Chromium, 1440x900, light and dark, computed styles at rest.

**Expected** — LOOK_AND_FEEL's palette, in the bullet TASK-0038 wrote: "**Healthy is green only when nothing needs a human.** An outcome whose own row or card carries a non-zero error count renders in **attention amber**, whatever word its producer wrote: the word stays verbatim in mono (copy bar 5) and only the colour is the app's reading of it. Green is for an outcome with nothing left to answer for. **Walkable on `/cycles`: no row that shows errors carries its outcome word in healthy green.**" The bullet names its own origin: an M1 user-sim found fifteen cycles reporting 108 errors each, labelled `succeeded` in green — "'succeeded' is doing work it hasn't earned."

**Found** — those same fifteen cycles are still green. Measured on `/cycles`, light theme, over the 69 rows of the Cycles table:

| rows | outcome | ERRORS column | rendered colour |
| --- | --- | --- | --- |
| 15 | `succeeded` | **108** | `rgb(1, 102, 48)` = `#016630` = `--color-healthy` |
| 2 | `succeeded` | **1** | `rgb(1, 102, 48)` = `--color-healthy` |
| 47 | `succeeded` | 0 | `rgb(1, 102, 48)` — correct |
| 4 | `died` | 0 | broken red — correct |
| 1 | `skipped` | 0 | neutral ink — correct |

Seventeen of the 69 rows on that page carry an error count and a green word. The fifteen 108-error rows all read `column "venue" of relation "events" does not exist` in the ERROR column of the same row — the page states the failure verbatim two cells to the right of a word coloured to say nothing failed. Rendered markup of an errored row's outcome cell:

    <span class="type-data inline-block rounded-control bg-chrome px-2 py-0.5 text-healthy">succeeded</span>

identical, class for class, to a clean row's.

TASK-0038 wrote the bar into the doc and changed no `src/` file ("No src/ or tests/ change" — its own History), and it named this walk location for the endgame to check: "on /cycles, every row with error count > 0 has its outcome word NOT in --color-healthy". Nothing built it. `src/components/cycles/outcome.tsx` maps the word alone — `OUTCOME_TONE = { succeeded: "healthy", failed: "broken" }` — and the row's error count never reaches the badge.

**Second copy, same defect.** `src/app/page.tsx:181` declares its own `OUTCOME_TONE` with identical content, for the Dashboard's cycles table. That table's six rows all carry `errors = 0` on staging today, so the Dashboard is not currently *showing* a green word it should not — but it is the same table drawn from the same producer, and it will show one the next morning a cycle errors. `outcome.tsx`'s own docstring says the map lives there so both halves of `/cycles` share it, "because two copies is how the same word comes to be green on one table and grey on the one below it"; the Dashboard's copy is exactly that.

Provenance checked before filing: `git log` on `src/components/cycles/outcome.tsx` (0543d42, DEBT-0004) and `src/app/page.tsx` (c8ee060 TASK-0039, 98e21be DEBT-0006, 7f12642 BUG-0074, …) returns ticket-bearing commits only. No human-lane divergence, so this is a violation and not a reconciliation.

Evidence: `agenticflow/tracker/evidence/M2/designer/cycles-dark-1440.png`, `cycles-light-1440.png`.

## Acceptance criteria
1. On `/cycles`, no row whose ERRORS cell is non-zero renders its outcome word in `--color-healthy`. The seventeen rows measured above (fifteen at 108 errors, two at 1) render `succeeded` in `--color-attention`. Asserted structurally in the offline suite over a fixture carrying an errored `succeeded` row and a clean one, and re-measured by computed style on the next walk.
2. **The word is untouched.** The badge still reads `succeeded` verbatim, in mono, at the `data` step (copy bar 5). Only the colour changes. A row with zero errors still renders healthy green; `failed` still renders broken red; `died` and `skipped` are unchanged.
3. The Dashboard's cycles table obeys the same rule from the **same** map: `src/app/page.tsx` stops declaring its own `OUTCOME_TONE` and takes the one in `src/components/cycles/outcome.tsx`, where that module's docstring already says it lives. Two copies of the tone decision do not survive this ticket.
4. The decision is made in one place: one function that takes the producer's word AND the row's error count and returns the tone, called by both tables — not a tone re-derived at each call site.
5. Adapter runs are unaffected: a run row carries no error-count column of its own (`failed` already renders broken and its `error` cell carries the text), and its rendering does not change.
6. No new colour enters the palette and no contrast regression: `--color-attention` on chrome measures >= 4.5:1 in light and dark (bar 12), the ratio the palette already records for the `high` severity badge.
7. Human-check: on `/cycles` at 1440x900, light theme, scrolling the Cycles table, no green word sits on a row whose ERRORS cell is not `0`. (human-checkable)
8. `npm run lint` and `tsc --noEmit` clean; the targeted offline files green; the two live page suites green.
