# Remove every deprecated surface; stand up the shell and the six routes

## Description
Module: `src/app/` (the shell and the route skeleton). Authority: spec section 3 and section 4; acceptance doc ground rule 'the build owns `src/` wholesale'; SPEC F1; M1 EC2, EC3, EC12; ARCHITECTURE section 2 (the exact survives/dies list) and section 5.

**Delete outright** — page, route, and any module whose only consumer was one of them:
`src/app/analytics/`, `src/app/database/`, `src/app/data-management/**` (including `completeness/`), `src/app/api/admin/events/[id]/route.ts`, `src/app/api/admin/groups/[id]/route.ts`, `src/app/api/admin/idols/[id]/route.ts`, `src/app/api/admin/catalog-search/route.ts`, `src/app/components/AdminNav.tsx`, and the whole `src/app/components/` directory once `EditableCell` has moved (TASK-0004). The events editor is **removed, not converted** — events stop being hand-editable until the verdict slice lands (spec section 3). Nothing is kept as dead code 'for reference': the contracts are the reference.

**Do not touch**: `src/middleware.ts`, `src/lib/auth.ts`, `src/lib/admin.ts`, `src/lib/supabase.ts`, `src/app/api/auth/[...nextauth]/route.ts`, `src/app/api/health/route.ts`, `src/app/login/page.tsx`, `railway.toml`, `supabase/migrations/`.

**Rewrite `src/app/layout.tsx`** as the shell: a 192px fixed left sidebar, chrome fill, hairline right edge, the six pages as **text labels with no icons** (the old unicode glyphs are dropped — one is a combining-mark hack), active item = chrome-inverse fill, sign-out at the bottom behind a hairline, content 16px-padded. **The layout performs no database read**: the 'Events: STALE/FRESH' strip and its `events` query are deleted (LOOK_AND_FEEL: no global status strip, the Dashboard owns health) — and a read in the root layout would take every page down when a table is absent, which acceptance test 9 forbids.

**Create the six routes** as real pages that render their `Page` shell, their title and their `Empty`/`NotProvisioned` state — no data yet, that is each page's own ticket:
`/` Dashboard, `/queues`, `/claims`, `/sources`, `/cycles`, `/browse`. Also create `/records/[table]/[id]` as a stub the edit tickets fill in. Each page function is `async` and is the only async component on its route (ARCHITECTURE section 5).

**Extend `tests/http/auth.http.test.ts`** to assert, for **every** route above plus `/queues/<id>` and `/records/groups/<id>`, that an unauthenticated request redirects to `/login`; and add the client-bundle scan: no service-role key material and no `SUPABASE_SERVICE_ROLE_KEY` value in any file `.next` emits for the client. Assert on the key NAME and on the shape of a key, never by printing a value.

Also assert the retired routes are **gone, not redirected**: a request to `/analytics`, `/database`, `/data-management` and `/data-management/completeness` returns 404.

## Acceptance criteria
[test 1, test 12; EC2, EC3, EC12] `npm run lint`, `./node_modules/.bin/tsc --noEmit` and `npm run build` exit 0. No retired page or route exists on disk and each retired path returns 404 rather than redirecting to a working page. No surviving module names `AdminNav`, and `src/app/components/` is gone. The six routes exist, each reachable from the sidebar, each rendering its title and a not-provisioned/empty state without touching the database from the layout. Every route and the two dynamic routes redirect an unauthenticated request to `/login`, and a scan of `.next`'s client output finds no service-role material. Sign-in, `src/lib/supabase.ts` and `railway.toml` are byte-unchanged. (human-checkable) The shell matches LOOK_AND_FEEL's frame — 192px sidebar, text labels, no icons, no status strip — at the close-review screenshots.
