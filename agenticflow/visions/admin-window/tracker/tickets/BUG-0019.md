# GaugeCard's absence reason is not asked isAbsent, so a blank reason renders a dash with no words

## Description
GaugeCard normalises the VALUE through the app's one definition of absence (isAbsent, src/lib/format.ts) but decides the REASON with `props.absent ?? UNSTATED_REASON` (src/components/gauges/gauge-card.tsx:149). `??` only catches null/undefined, so a blank reason is treated as a stated reason, and StatCard drops it (`sub ? <span…> : null`, src/components/ui/stat-card.tsx:68). The card then renders the dash with nothing beside it — the same wordless absence the UNSTATED_REASON fallback was introduced to prevent (its own docblock, gauge-card.tsx:38-47).

The union makes this the likely caller mistake rather than an exotic one: arm 3 REQUIRES `absent: string` on any nullable value (gauge-card.tsx:101-109), so a page whose reason is computed (a template over a source name that came back empty, or a "" written to satisfy the compiler) type-checks and silently loses the words.

Repro (exact, from tests/offline/gauges-ui/cards.test.ts's own `card` helper):
  render(h(GaugeCard, { label: 'median duration', value: null, absent: '' }))
Expected (LOOK_AND_FEEL 'a card that cannot measure says why'; gauge-card.tsx:38-47): the dash carries a reason line, as it does when `absent` is null/undefined and UNSTATED_REASON stands in.
Found: <div …><span class="type-micro …">median duration</span><span class="type-figure text-ink"><span class="text-ink-disabled" aria-label="no value">—</span></span></div> — no `type-data` sub-line at all, no words beside the dash.
Second spelling, same defect: `absent: '   '` renders <span class="type-data …">   </span>, a sub-line whose text is whitespace — a bare dash on screen.

Scope note: BUG-0018's own defect (floor qualifier + palette colour on an unmeasured dash) is FIXED and verified across 13 value spellings; this is only the reason path the same fix introduced. Latent, not shipped: no page consumes GaugeCard yet (grep GaugeCard src/app -> no match), which is why it is P3.

Suggested shape (not binding): ask the same definition about the reason — `isAbsent(props.absent) ? UNSTATED_REASON : props.absent` — so 'a blank string is nothing' means the same thing on both sides of the card.

Pin: tests/offline/gauges-ui/cards.test.ts, "says why it cannot measure even when the caller's reason is itself blank", marked `it.fails` (strict — it reddens on success and sends the reader here). Watched RED as a plain `it` first: 'AssertionError: "": expected 0 to be greater than 0' at cards.test.ts:291. The fix flips it back to `it`.
