# The verdict UI: every spec 7 action as one typed decision, one call, one transaction

## Description
**SPEC F10.** Fill the close slot F4 deliberately left empty. A review item's detail gains the §7 actions, one typed decision per action, and settles through exactly one call to `settle_review_item`.

**The actions, per shape (spec §7, verbatim):**
- `data_conflict` decision item: **choose a claimed value** — one control per evidence card, so the operator picks the observation they believe; **supply a different value** — the override form of FEAT-0011; **keep current & settle** — the disagreement is fine as it stands, canonical holds, the rejections still land.
- `entity_link` fact item: **link to an existing entity** — the picker of FEAT-0012; or **settle**, leaving it held so the claim keeps waiting in its bucket.
- Signal item (today's `entity_link` source-pattern): no verdict, a **disposition** — `fixed` (the breakage was addressed elsewhere, on its own surface) or `wont_fix`, **on which the note is required**. Either way the item settles and the `verdicts` row carries the disposition.

**One entry point.** Every action becomes ONE typed decision and ONE call to `settle_review_item`. There is no client-side multi-step settlement, no second write path, and no direct write to `review_items` or `verdicts` from Admin — the same one-place guard `tests/offline/db/one-place.test.ts` already applies to the edit route, extended to this call site and shipped with one input it MUST flag and one it must NOT (LESSONS 3).

**The absence case is the normal case and is graded first.** `settle_review_item` does not exist on staging and will not until Ben installs FEAT-0009's artifact. With it absent the close slot renders its `not_provisioned` card naming `settle_review_item`, offers NO control, and the rest of the detail page renders exactly as M1 shipped it. Build and grade that path before the happy path; it is what `main` deploys against.

**The note field** sits beside the action, optional everywhere except `wont_fix`, where the form refuses without one — and the form is not the only guard, because FEAT-0009's function raises too. Two guards, on purpose: the form is courtesy, the function is the contract.

**The recommendation slot still renders nothing.** Its producer is parked and stays parked.

**Data reality, not a defect:** staging holds exactly ONE review item and it is the `entity_link` source-pattern signal. The two fact-shaped items do not exist there. Their action sets are built and graded against fixtures in the offline suite; "built, not walkable on this data" is the honest grade, exactly as M1 graded the same gap. A criterion that demands a fact-shaped row on staging is mis-authored.

vision_trace: "Every spec §7 action settles a review item in one transaction, and every settlement and override lands as one row in the verdict log."

## Acceptance criteria
1. With `settle_review_item` ABSENT (staging today): the close slot on every review-item detail renders `data-state="not_provisioned"` naming `settle_review_item`, contains zero action controls, the page answers 200 and throws nothing; every other part of the detail renders as M1 shipped it. Graded by the offline absence suite and by the page's live suite.
2. With the function present (recording stub): a `data_conflict` item's close slot contains exactly the three controls "choose a claimed value" (one per evidence card), "supply a different value", "keep current & settle" and no others; an `entity_link` fact item contains exactly "link to an existing entity" and "settle"; a signal item contains exactly "fixed" and "wont_fix".
3. Each control's submission produces EXACTLY ONE call to `settle_review_item`, carrying one typed decision payload whose action name is one of spec §7's plus `override`. Asserted per control against the recording stub in the offline suite.
4. `wont_fix` with an empty note is refused by the form, and the refusal names the reason; the payload is never sent.
5. No code path in `src` writes `review_items` or `verdicts` other than through the single `settle_review_item` call site. Guarded by a structural test that ships one input it must flag and one it must not.
6. The recommendation slot renders nothing: the strings `recommend` and `recommendation` occur zero times in the rendered detail HTML.
7. `npm run lint`, `tsc --noEmit` and `npm test` green; the review-item detail page's live suite green.
