# ASK BEN: which of the adapter runs table's 22 columns does Cycles & runs show?

## Description
**Contract silence.** ARCHITECTURE marker `OPEN-RUNS`. SPEC named gap 1.

Spec section 4 puts *'`resolution_runs` and the adapter framework's `runs`, newest first, with the counts as columns and `error_summary` inline'* on the Cycles & runs page. For `resolution_runs`, `contracts/resolver.md` section 6 names every column, so that half is fully specified and is being built (TASK-0014). For `runs`, `adapters.md` is **not** among the contract snapshots, so 'the counts' is undefined — and the table has 22 columns.

What the table actually holds (scraper repo, migration `20260829000001`, read 2026-09-01): `run_id, source (text, no FK), started_at, ended_at, outcome (succeeded | partial | failed | skipped), failure_class (transient | structural | config), checkpoint_before, checkpoint_after, error_summary, payloads_fetched, payloads_archived, records_parsed, records_rejected, claims_emitted, claims_dropped_empty, claims_collapsed, claims_ai, records_linked, records_unlinked, records_escalated, batches_written, observations_returned`.

**Recommend** a nine-column row that reads like the GitHub-Actions-run-list taste reference — diagnosable before you click anything — and nothing else: `source`, `started_at`, duration (derived from `ended_at`), `outcome`, `failure_class`, `records_parsed`, `claims_emitted`, `records_unlinked`, `error_summary` inline. Rationale: source/when/how-it-ended answers 'did anything happen last night'; `failure_class` is the one column that says whose problem it is; parsed vs emitted is the yield; `records_unlinked` is the number that feeds the entity-link queue this app exists to render. The other thirteen are adapter-internal and belong on a run detail view that has no consumer yet.

TASK-0016 is blocked on this answer and holds the whole adapter-runs half; the resolver-cycles half ships without it.

(human-checkable) Ben names the column set (or approves the recommendation). The architect then removes the `OPEN-RUNS` marker from ARCHITECTURE and amends TASK-0016's criteria to that exact set, so 'no more, no fewer' is checkable.
