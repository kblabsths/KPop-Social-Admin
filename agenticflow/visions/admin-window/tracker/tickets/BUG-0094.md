# A server component importing a value from a "use client" module 500s the record page, and every automated tier stays green

## Description
Measured by QA on the BUG-0086 attack (2026-09-08), landed tree run/admin-window @ d2e4623, production build on 127.0.0.1:8805, staging.

**Expected** — a defect that makes the record page answer 500 is caught by a check the factory runs, not by a human loading the page. This class already happened once in this campaign: BUG-0086's first cut had `RecordFields` (a synchronous SERVER component) calling `hintSide` out of `EditableCell.tsx` (`"use client"`), the record page answered 500 ("Attempted to call hintSide() from the server"), and the builder found it only because it walked. `src/components/edit-cell-layout.ts` exists solely to dodge that boundary — the campaign now depends on a rule no test states.

**Found** — nothing catches it. QA restored the exact violation in a private worktree (a `hintSideFromClientModule` export added to `src/components/EditableCell.tsx`, imported by `src/components/records/record-fields.tsx`) and ran the tiers on that build:

- `vitest run --project=offline tests/offline/records/page.test.ts` — 93 passed. The offline tier is plain node with `renderToStaticMarkup` (STACK.md §4): there is no client boundary in it to violate.
- `npm run test:http` — 16 passed, 3 files. The http tier builds and starts the real app, and it DOES request `/records/...` — but with no database, so the page renders its named refusal and `RecordFields` never executes. The tier that could see this never reaches the code.
- `npm run lint` + `tsc --noEmit` — clean. TypeScript sees an ordinary function export.
- The same build, served with the staging env and driven with a minted cookie: `GET /records/walk_sandbox/00000000-0000-4000-8000-000000000001` answers **500** (server log: `digest: 3603077637`, thrown out of the ssr chunk). Restored, rebuilt, same URL answers **200**.

So a one-line import that ships a 500 on the app's primary edit surface passes lint, tsc, the offline suite, the http suite and CI. Only a walk sees it, and walks are not run per ticket.

**Where it bites**: every server component under `src/app/**` and `src/components/**` that imports from a `"use client"` module. `record-fields.tsx` is one import line away from it today, and the reason it is safe is a comment.

## Acceptance criteria
1. A check in an automated tier FAILS when a synchronous server component imports a value export from a `"use client"` module, and passes on the current tree. Graded by re-running the sabotage in the description (add an export to `src/components/EditableCell.tsx`, import it in `src/components/records/record-fields.tsx`): the check must go red, then green again when reverted.
2. The check names the offending file and the client module in its failure message — a `500 digest` in a server log is what this ticket exists to replace.
3. It covers `src/**` as a rule, not the two files of the repro: a new server component importing from any `"use client"` module is caught the same way.
4. `npm run lint`, `tsc --noEmit` and the full offline suite stay green.
