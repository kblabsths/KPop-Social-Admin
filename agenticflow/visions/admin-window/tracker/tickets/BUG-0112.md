# The record page's regime note sets its table name in sans — three table names on one screen, two in mono and the one in the prose not

## Description
Measured on the M2 endgame walk, 2026-09-09, on all three record surfaces at 1440x900.

**Expected** — LOOK_AND_FEEL's typographic split is the whole typographic idea: "**Mono carries every value the database produced** — counts, ids, timestamps, values, source names, buckets, tiers, error strings. Sans carries every word the app wrote — labels, headings, buttons, prose. That split *is* the typographic idea: the operator can always see which words are the machine's." Copy bar 5 names the same set from the other side: "Machine identifiers (`data_conflict`, `admin_locked`, `event_performers`, `wont_fix`) render verbatim in mono and are never prettified into Title Case prose."

**Found** — the record page's regime note renders the table's name in sans, on a page that renders the same kind of name in mono twice above and below it. Rendered markup, `/records/events/01a03f78-8bba-755c-8298-58f0549d9817`:

    <h1 class="text-ink"><span class="type-data normal-case tracking-normal">events</span> <span class="type-title">record</span></h1>
    ...
    <p class="type-body text-ink-secondary">events is resolver-owned: its values change through the resolution pipeline, …</p>
    ...
    <div data-state="not_provisioned" …><p class="type-body text-ink-secondary"><span class="type-data text-ink">verdicts</span> isn't in this database yet — …</p></div>

Three table names on one screen: `events` in the h1 is mono (`type-data`, and `normal-case tracking-normal` was added so the identifier keeps its case — BUG-0049 settled exactly this question for micro labels), `verdicts` in the card is mono, and `events` in the note between them is 12px sans body — indistinguishable from the app's own prose around it. The card immediately below the note is the proof the app already knows the rule: it wraps its identifier in `type-data`.

Same on all three regimes:

| page | the note's opening words, table name in sans |
| --- | --- |
| `/records/events/<id>` | "**events** is resolver-owned: its values change through the resolution pipeline, never by a direct edit." |
| `/records/venues/<id>` | "**venues** is resolver-owned: …" |
| `/records/walk_sandbox/<id>` | "**walk_sandbox** is a staging fixture table, edited directly: …" |

`walk_sandbox` is the loudest: an identifier with an underscore in it, set in a proportional face, mid-sentence.

This is the residual the M2 early walk's amendment to BUG-0099 named as its second leg for the `venue_id` reference ("the venue name renders in sans while the id beside it is mono — one line, two faces"). BUG-0099 fixed the reference line; the regime note above it was outside that ticket's scope and still carries the same defect.

Provenance checked before filing: `git log src/components/records/record-fields.tsx` returns ticket-bearing commits only (36209d7 BUG-0101, 7ce9f91 BUG-0099, aebcfcd TASK-0055, a76963e BUG-0086, 91a549f TASK-0040, …). No human-lane divergence; violation, not reconciliation.

Evidence: `agenticflow/tracker/evidence/M2/designer/event-light-1440.png`, `venue-light-1440.png`, `sandbox-rest-light-1440.png`.

**Sibling note (BUG-0107).** Both are record-page findings from this walk and both list `tests/offline/records/page.test.ts`. BUG-0107 is about the **edit cell's refusal** — how long it lives and whether it has an edge (`src/components/EditableCell.tsx`); this one is about the **typeface of a table name in the prose above the table** (`src/components/records/record-fields.tsx`). Different files, different rules (the Feel vs. the Look's type split), no shared line. Land in any order.

## Acceptance criteria
1. On all three regime notes (`events`, `venues`, `walk_sandbox`), the table's name renders in mono at the `data` step and keeps its case and its underscore verbatim — the same `type-data` span the not-provisioned card below it already uses for `verdicts`.
2. Every other machine identifier the record page prints in prose gets the same treatment: any column, table or function name inside a note renders mono, never sans body. The words the app wrote around them stay `type-body` sans in secondary ink.
3. The note's meaning and wording are otherwise unchanged: this ticket changes a face, not a sentence.
4. One spelling: the identifier-in-prose span is not re-typed per note. Whatever the app already uses (the not-provisioned card's spelling is the existing one) is what the notes use.
5. No change to the notes' spacing, order, or the paragraph's type step; no new colour.
6. Human-check: on `/records/walk_sandbox/00000000-0000-4000-8000-000000000001` at 1440x900, the word `walk_sandbox` in the note reads as the machine's word, in the same face as the `walk_sandbox` in the heading above it. (human-checkable)
7. `npm run lint` and `tsc --noEmit` clean; the targeted offline files green; the edit live suite green.
