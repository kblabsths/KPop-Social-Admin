# Phone (390px): the fixed 192px sidebar takes half the viewport and the content column collapses

## Description
Found on the M1 endgame designer walk (2026-09-03), responsiveness phase — Playwright device emulation, iPhone 13 (390x844), walk instance :8771 against staging.

**LOOK_AND_FEEL.md is silent on viewport.** Its frame rule says "a 192px fixed left sidebar" and nothing about small screens, and desktop is this milestone's stated target — so this is my taste filling a gap, licensed by VISION's "Ben, the ecosystem's operator, **at breakfast**". Filed at P3 deliberately: if the answer is "the window is a desktop tool, and the doc should say so", that is a good answer and I will write it into LOOK_AND_FEEL.md instead. What is not good is the current state being nobody's decision.

Measured at 390px:

- The sidebar keeps its full 192px — **49% of the viewport** — and the content column gets ~198px minus 16px padding on each side.
- On the Dashboard that leaves the attention cards one word per line: "nothing / open / — / no / question / is / waiting / on / a / verdict" reads down nine lines.
- The cycles table is clipped inside its own scroll region after two columns; `STARTED` and `OUTCOME` are all that fit.
- The page itself does not scroll horizontally (`documentElement.scrollWidth` = 390 = `innerWidth` on Dashboard, Queues and Browse), so the containment is correct — it is only the split that is wrong.

Evidence: `agenticflow/tracker/evidence/designer-walk-m1/dashboard-phone.png`, `queues-phone.png`, `browse-phone.png`.

The desktop rendering is unaffected by anything I would ask for here; at 1440 the frame is exactly right.

## Acceptance criteria
Either: below some stated width the sidebar stops consuming half the screen (collapsed, stacked above the content, or otherwise), and on that narrow viewport the Dashboard's attention cards read as sentences rather than one word per line —

Or: the answer is "desktop only", recorded as such, and this ticket closes as won't-fix with one line saying so. I will then write the minimum supported width into LOOK_AND_FEEL.md's frame rule; nobody else edits that file.

Whichever is chosen, the 1440x900 rendering is byte-identical to today's: same 192px sidebar, same 16px content padding, same table layout. Say so with a before/after check in the ticket History.

No horizontal page scroll is introduced at any width; `documentElement.scrollWidth === window.innerWidth` stays true at 390, 768 and 1440.

Human-check: at 390px wide, the Dashboard's two attention counts are readable without the text going one word per line. (human-checkable)
