# /claims draws the affordance only where it can be honoured, and pages past the window

## Description
**Modules:** `src/app/claims/page.tsx` (wiring only), a NEW `src/components/claims/paged-claim-list.tsx` (`"use client"`, the wrapper), `src/components/claims/index.ts`, and `src/lib/claims/filters.ts` (the query string one press carries).

**The first screen does not change.** M3 EC4 grades this: on the same fixture, the window line, every figure and the ROW SET of the first server-rendered screen are byte-identical to the pre-ticket tree. Paging is what the operator can do after that screen exists. What is added below the rows is the affordance and nothing else.

**Interface contract:**

```tsx
// src/components/claims/paged-claim-list.tsx
"use client";
export function PagedClaimList(props: {
  label: string;
  /** The first screen's rows — already shaped by the page (claimLines). */
  initial: readonly ClaimLine[];
  /** How many rows the whole narrowing holds, when a count established it. */
  total: number | null;
  /** The narrowing this page RENDERED, serialized — never the raw URL. */
  params: string;
  size: number;                       // CLAIM_WINDOW
  line?: ReactNode;
}): ReactNode;
```

It renders `<ClaimList rows={[...initial, ...state.rows]} …/>` — the same pure component, the same row markup — and `<PageMore …/>` beneath it, driven by `usePageRows` (TASK-0064). It fetches nothing itself.

```ts
// src/lib/claims/filters.ts
/** The facets a paging request carries: the narrowing this page APPLIED. */
export function claimsQuery(filter: ClaimsFilter, tab: ClaimsTab): string;
```

Built from the same filter object the reads were given, never from `searchParams` — a parameter the page DROPPED must not travel to the handler and come back as a different narrowing (`lib/url/dropped-params.ts`, BUG-0141, common violations row 20).

**When the affordance is drawn — the whole rule, and it is the page's decision, not the widget's:**

- Drawn only when a COUNT established that there is more: `listCount.kind === "ok" && listCount.data > rows.length`. This is the page's existing `truncated`, already computed for the window line.
- **A refused or absent count means NO affordance.** A control offered on a guess would be the page claiming a total no read established (§4.3, LESSONS 2). Say it in the receipt: this is the honest arm, not an oversight.
- `rows.kind !== "ok"` — `not_provisioned` or `error` — means no affordance, no wrapper, and the page renders exactly the state it renders today. M3 EC5 grades **zero** occurrences of the control in the rendered HTML against a `PGRST205` database.
- An empty `ok` window means no affordance: the Empty card and the window line stand as they do today (§4.3, BUG-0070).

**The refusal rule, inside the page** (M3 EC5, ARCHITECTURE §4.3 kind 3): a refused page leaves the rendered row count exactly as it was and names the object beside the rows. Prove it on two fixtures — one whose second page must refuse and one that must not (LESSONS 8).

**Absence is graded for every surface at once** (§4.3, BUG-0070): the paging affordance's absence on a not-provisioned `/claims` belongs in `tests/offline/absence/pages.test.ts`, the file that already generalises this rule across surfaces, not in a per-page comment.

**Live (M3 EC4).** `tests/live/claims.live.test.ts` gains a paged walk against staging: starting from the first screen it reaches a claim beyond the first window's last row, and the set of distinct `observation_id`s reachable by paging equals what an INDEPENDENTLY written range walk in the test's own query enumerates — no id twice, none skipped — and its size equals the head figure the page itself rendered. The oracle names its surface by `data-surface`, never by position, and decides the state kind from `data-state` before it compares a number (§10, common violations rows 6-8).

## Acceptance criteria
On the same offline fixtures, the first server-rendered screen of /claims is byte-identical to the pre-ticket tree in its window line, its figures and its row set; the only addition below the rows is the affordance. The affordance is present exactly when a count established there is more, and absent on all four honest arms — an exhausted fixture (where the surface says the set is complete), a refused or absent count, an empty ok window, and a PGRST205 database where /claims renders data-state="not_provisioned" with zero occurrences of the control in the rendered HTML, graded in tests/offline/absence/pages.test.ts alongside every other surface. One press issues exactly one request to the route handler carrying an explicit bound, and zero presses issue zero requests, asserted against a recording stub. A refused page leaves the rendered row count identical to what it was and names the object beside the rows, proved on one fixture that must refuse and one that must not. Against staging, a paged walk from the first screen reaches a claim beyond the first window's last row, and the distinct claim ids reachable by paging equal both an independently written range walk's enumeration and the count the page's own head figure states — no id twice, none skipped. The sidebar still holds exactly six links, src/app gains no page route, and /claims' six live parity assertions are green.
