# The entity_link fact lede still claims every claim the record holds is below

## Description
Found while attacking BUG-0124 (QA, 2026-09-09). BUG-0124 retired the source-pattern lede's completeness claim; the SAME claim stands one shape over, on the same block, and the fix's new header sentence now sits above it.

**Expected** (BUG-0124 criterion 2 and the designer's Expected: LOOK_AND_FEEL Voice bar 6 — 'A screen may not assert a completeness its own read cannot support'): a shape's lede says what the block below HOLDS and claims no total. Admin reads the ids in `review_items.evidence` and resolves each one; it never reads a record's claims, so 'every claim held by [the record]' is a population this page has not looked at.

**Found**, `src/components/review/shape-views.tsx:291` (`StuckFactEvidence`), rendered verbatim on the `entity_link` FACT shape:
'This record cannot link or be created. **Every claim held by it is below**, with what each one is waiting for.'

The page contradicts it out of its own mouth on a fixture where one evidence id resolves to nothing. Repro, offline, no database:

1. `cd '/Users/ben-m4/Desktop/Coding/KPOP/kspace Admin'`
2. In `tests/offline/review-item/page.test.ts`, render `stuckScript` with the item overridden to `reviewItemEntityLink({ evidence: [ID.observationB, '01920000-0000-7000-8000-000000000999'], folded_count: 700 })` — i.e. two evidence ids, one of which names no observation. That is exactly the pinned test 'no shape's lede claims a completeness its read cannot support > does not hold on the entity_link fact shape' now in that file.
3. The one page then carries, simultaneously:
   - lede: 'Every claim held by it is below, with what each one is waiting for.'
   - accounting: '1 of 2 evidence ids resolved to a claim, in the order they folded in.'
   - unresolved line: '1 of this item's evidence ids names no claim this database holds: 01920000-…-000000000999'
   - header (BUG-0124's new sentence): 'Each fold is a re-ask of this item, not a record: 700 folds over the 2 evidence ids it carries, listed below.'

Measured by running that test with `it.fails` removed:
`AssertionError: expected 'This record cannot link or be created…' not to match /\b(every|all|complete|entire)\b/i` — received 'This record cannot link or be created. Every claim held by it is below, with what each one is waiting for.' The conflict and source-pattern ledes pass the same guard.

This is the reading failure both M2 user-sims reported (a completeness claim beside a fold count that cannot be reconciled), on the shape BUG-0124's criteria did not name. It is pre-existing — `git show cab3efd` did not touch this lede — and is filed rather than folded into BUG-0124, whose own criteria are met.

The pin is landed strict: `it.fails("does not hold on the entity_link fact shape (BUG-0128)")` in `tests/offline/review-item/page.test.ts`. Fix the lede and it turns red — that is the signal to fold the shape into the passing per-shape test above it and delete the pin.
