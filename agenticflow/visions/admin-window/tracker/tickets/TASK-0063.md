# The paging leaf: the bound value class, the page answer, and the pure one-press driver

## Description
**Module:** a NEW pure domain leaf `src/lib/paging/` (ARCHITECTURE §4 rule 7 — it imports nothing that can reach a database, not a value and **not a type**, `lib/db/**` included), plus one small module `src/lib/db/paging.ts` on the db side where a `DbResult` may be named. No page, no component, no route handler in this ticket: this is the helper both surfaces and both route handlers need, seeded FIRST because builders in isolated worktrees cannot see each other's code (§13.7, common violation 9).

**Read before you start:** ARCHITECTURE §4.3 read kind 3 (the paged window read, amended 2026-09-10) is the contract. It rules the mechanism: an OFFSET into the first screen's own total order, a size the SERVER decides, a bound refused out loud when it is out of range, exhaustion as an answer rather than a refusal.

**Why a pure leaf and not a React hook.** This repo's offline tier has no DOM — `renderToStaticMarkup` only. A press cannot be simulated. So every decision paging makes (whether to issue a request, what bound it carries, what happens to the answer) lives in a directiveless module the offline suite drives DIRECTLY with a recording stub, and the client hook that lands in TASK-0064 is a two-line binding to it. That is also why §4 rule 1's amended exception is worded the way it is.

**Interface contract — spelled here, so two route handlers and two client wrappers cannot each invent one:**

```ts
// src/lib/paging/bounds.ts   (LEAF — imports NOTHING)
/** The two surfaces that page, and the ONE spelling of their route paths. */
export const PAGE_ROUTES = {
  claims: "/api/admin/claims/rows",
  browse: "/api/admin/browse/rows",
} as const;
export type PagedSurface = keyof typeof PAGE_ROUTES;

/** The URL parameter that carries the bound, spelled once. */
export const OFFSET_PARAM = "offset";
/** The largest offset any bound may name. */
export const MAX_PAGE_OFFSET = 100000;

export type PageBound =
  | { kind: "ok"; offset: number }
  | { kind: "refused"; reason: string; bound: string };

/**
 * The bound a request carried, or the reason it is refused. `size` is the
 * surface's own window, handed in by the server; it is never read from the URL.
 */
export function pageBound(raw: string | null | undefined, size: number): PageBound;

/** What a paging request answers — the JSON shape, on both sides of the wire. */
export type PageAnswer<Row> =
  | { kind: "ok"; rows: Row[]; offset: number; exhausted: boolean }
  | { kind: "not_provisioned"; missing: string }
  | { kind: "error"; reading: string; message: string }
  | { kind: "refused"; reason: string; bound: string };

/** Is this parsed body a PageAnswer at all? A foreign body is a refusal, never a crash. */
export function isPageAnswer(value: unknown): value is PageAnswer<unknown>;
```

`pageBound` refuses, naming the bound it was given, when the raw value is: absent or empty (the handler serves what comes AFTER the first screen, so an unstated bound is a refusal, not a defaulted 0); not a canonical decimal integer (a sign, whitespace, a leading zero, `1e3`, `50.0`, a non-digit — what is USED is what was SENT, common violations row 20); not a multiple of `size`; below `size`; or above `MAX_PAGE_OFFSET`. **It never clamps** (M3 EC6).

```ts
// src/lib/paging/machine.ts   (LEAF — imports bounds.ts and nothing else)
export interface PageRefusal { reason: string; object: string | null }

export interface PageState<Row> {
  /** The rows PAGED IN so far — never the first screen's. */
  readonly rows: readonly Row[];
  /** First screen + paged in. This is the next bound. */
  readonly held: number;
  readonly status: "idle" | "loading" | "exhausted";
  readonly refusal: PageRefusal | null;
}

export function initialPage<Row>(held: number, more: boolean): PageState<Row>;

export interface PageDeps {
  readonly route: string;      // PAGE_ROUTES[...]
  readonly params: string;     // the surface's own facets, already serialized
  readonly size: number;
  readonly fetchJson: (url: string) => Promise<unknown>;
}

/** The URL one press asks for — `route?params&offset=<held>`. */
export function pageUrl(deps: PageDeps, offset: number): string;

/** ONE press. Returns the next state; never throws. */
export async function requestPage<Row>(
  state: PageState<Row>,
  deps: PageDeps,
): Promise<PageState<Row>>;
```

**`requestPage`'s rules, each its own offline pin against a recording stub:**

1. **One press, one request; no press, no request.** Called on a state whose status is `loading` or `exhausted`, it calls `fetchJson` ZERO times and returns the state unchanged. Otherwise exactly ONE call, to `pageUrl(deps, state.held)`, whose query string carries `OFFSET_PARAM` explicitly.
2. **An `ok` answer appends in the order received**, `held` grows by the row count, `status` becomes `exhausted` when the answer says so and `idle` otherwise, and `refusal` is cleared.
3. **An `ok` answer with zero rows is exhaustion**, not a refusal, and the rows are unchanged.
4. **A refusal never extends the list** (M3 EC5, ARCHITECTURE §4.3): on `not_provisioned`, `error` or `refused`, `rows` comes back with the SAME length and the same members in the same order, `refusal` names the object (`missing` / `reading` / null for a bound refusal) and `status` returns to `idle` so the operator may try again.
5. **Foreign data is a refusal, never a throw**: a `fetchJson` that rejects, a non-JSON body, and a body `isPageAnswer` rejects all produce a refusal naming the route, with the rows unchanged.

**The layering guard is the one owner (§10).** `tests/offline/db/layering.test.ts` grades the leaf layer; this ticket adds `src/lib/paging/**` to it (a leaf that imports `lib/db/**`, `@supabase/supabase-js` or `process.env` must redden it) rather than hand-rolling a second predicate. import type { DbResult } from "./result";
```ts
import type { PageAnswer } from "../paging/bounds";

/**
 * One window read's result, as the wire answers it. `size` is the window the
 * server asked for: `exhausted` is `rows.length < size` — a short page is the
 * end of the set, and that is the ONLY thing that decides it. No count is read
 * to answer this, and no answer ever claims a total (ARCHITECTURE §4.3 kind 3).
 */
export function pageAnswerOf<Row>(
  result: DbResult<Row[]>,
  offset: number,
  size: number,
): PageAnswer<Row>;
```

`ok` maps to `{ kind: "ok", rows, offset, exhausted }`; `not_provisioned` and `error` map across UNCHANGED, carrying `missing` / `reading` + `message` so the client's refusal names the same object the page's own not-provisioned card would name (§4.1). This function is where the three-arm union meets the wire, and it is the only place that mapping is written.
