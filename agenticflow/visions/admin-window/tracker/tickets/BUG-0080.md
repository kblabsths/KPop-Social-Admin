# a non-operator 42883 from a TABLE read renders a provisioned table as not_provisioned

## Description
**Expected** (TASK-0047 criterion 2, and the classifier's own doc comment): a code the app must not read as an absence "still classifies as `error` carrying the database's own message" — and above all, `not_provisioned` must never be a confident claim about an object that is right there (`src/lib/db/result.ts`, MISSING_OPERATOR's comment: "a false absence is a confident claim about a table that is right there").

**Found**: `classify()` returns `{kind:"not_provisioned", missing:"groups"}` for a 42883 raised by a plain TABLE read whose message is NOT the operator sentence. `groups` is provisioned and holds rows; the card would tell the operator to install it.

**Repro, measured read-only on the declared staging target 2026-09-08** (a SELECT; nothing written), from a detached worktree via `npm run test:live`:

    db.from("groups").select("id").filter("created_at", "fts", "x").limit(1)
      -> code=42883  message="function to_tsvector(timestamp with time zone) does not exist"
      -> classify(error, "groups").kind == "not_provisioned"     <-- WRONG

    db.from("groups").select("id").filter("id", "plfts", "x").limit(1)
      -> code=42883  message="function to_tsvector(uuid) does not exist"
      -> classify(error, "groups").kind == "not_provisioned"     <-- WRONG

    control, same table, same code, the one shape that IS guarded:
    db.from("groups").select("id").ilike("created_at", "%x%").limit(1)
      -> code=42883  message="operator does not exist: timestamp with time zone ~~* unknown"
      -> classify(...).kind == "error"                            <-- right

**Offline repro** (no network): `classify(missingFunctionOnTableRead(), T.groups).kind` is `"not_provisioned"`, expected `"error"`.

**Regression introduced by admin-window/TASK-0047** (`src/lib/db/result.ts:322`, the new `FUNCTION_ABSENT_CODES` arm). Before a4900e6 every 42883 fell through to `kind:"error"`; the builder's own diff shows it, having had to move an existing case's fixture from `42883` to `42501` because 42883 stopped being an error (`tests/offline/db/result.test.ts`, "carries message, details, hint and code, in that order").

**Why the guard is short, not wrong.** `MISSING_OPERATOR` is a sentence match, and the operator sentence is only ONE of the 42883s a provisioned table can raise. Postgres also says `function <name>(<types>) does not exist` for a missing OVERLOAD of a function the caller never named — `to_tsvector(timestamptz)` above. The absent function is real; the object `missing` names is not absent, and `missing` is what reaches the card.

**Not reachable from product code today**: no `.filter(...,"fts"|"plfts",...)`, `.ilike`, `.textSearch` or `.rpc` exists anywhere under `src/` (`tests/offline/edit/config.test.ts` bans `.rpc(` outright), so no user hits it at this commit. It becomes live the moment a search/filter control or the FEAT-0010 call seam lands — which is why it is filed rather than left as a note.

**Direction is the architect's, not prescribed here.** The clean fix is probably not a longer regex: a TABLE read can never be a function absence, so the KIND of object the caller asked for is the discriminator (a `readFunction`/`callFunction` seam, or a kind argument to `classify`). A wider sentence match would still be one sentence behind the next shape.

**The pin is a strict xfail.** `tests/offline/db/result.test.ts`, "never calls a PROVISIONED table absent because a TABLE read raised 42883", is committed as `it.fails(...)` — green while the divergence stands, RED the day it is fixed. **The fix flips it back to a plain `it(...)`**, and the check below then proves it. Watched red as a plain `it()` before filing: `expected 'not_provisioned' to be 'error'`. The measured fixture is `missingFunctionOnTableRead()` in `tests/fixtures/stub-client.ts`.
