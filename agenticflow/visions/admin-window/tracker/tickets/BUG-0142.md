# The Dashboard's run links land on /cycles?run=<id>, which marks nothing and says nothing: the run the operator clicked is not identified

## Description
Walked 2026-09-09 on the walk instance (http://localhost:8771, STAGING, branch run/admin-window), cookie-authed, bundled chromium 151.

Steps from a clean start:
1. GET /. In the RUNS panel, the failing row "ticketmaster / 9d ago / failed / refusing to run: KSPACE_BOT_USER_AGENT is not set" carries two anchors, both to /cycles?run=01a057a7-61ab-7148-8bfe-cd6c5ad635cf.
2. Click either. URL becomes /cycles?run=01a057a7-61ab-7148-8bfe-cd6c5ad635cf, status 200.
3. Observed on that page: the run id 01a057a7 appears 0 times in the rendered text; `data-row-marked="true"` occurs **0** times in the HTML; the ADAPTER RUNS table renders all 5 runs unmarked; no sentence names a parameter that was not applied.
4. Contrast, same page and same minute: /cycles?cycle=01a06701-9f7b-7330-b136-8ab5786addec renders the line "Cycle 01a06701-9f7b-7330-b136-8ab5786addec is marked in the table below." and `data-row-marked="true"` occurs exactly **1** time. /cycles?cycle=not-a-uuid renders "Cycle not-a-uuid is not among the 200 newest cycles, so it is not in this window — it ran earlier, or no cycle carries that id."

Expected: the run the operator clicked is identified on arrival — marked in the ADAPTER RUNS table the way ?cycle= marks its row, or named in a sentence the way the same page already names an unapplied narrowing (/cycles?source=<name> does exactly that: "Narrowed to the runs whose source is <name>. This facet narrows the runs below and nothing else...").

Observed: the run parameter is consumed silently. With 5 runs in the window the operator can guess; the window caps at 200, where they cannot. Spec F3's "Everything on it links into the pages below — the dashboard is the entry to the investigation path, never a dead end" is the clause at stake.

Documented as intentional in src/app/cycles/page.tsx (~116): "One more parameter reaches this route today and narrows NOTHING here: run=<run_id> (the Dashboard's run lines). It is not guessed at — an unrecognised parameter narrows nothing rather than erroring, so the link lands on this page rather than dead-ending." The page's own SOURCE_FACET docstring records the opposite standard for the same situation: it says so in one sentence "rather than either ignoring the parameter silently — which is what it did until admin-window/TASK-0016". Marking the row or drawing the sentence is the architect's call; silence is what fails.

Evidence: agenticflow/tracker/evidence/M2/verifier/31-cycles-run-unmarked.png and 10-cycles-run-facet.png; run log agenticflow/tracker/notes/verify-M2-2026-09-09.md.

## Acceptance criteria
Standing on the Dashboard and clicking a run row's link, /cycles?run=<id> identifies that run — the matching ADAPTER RUNS row carries data-row-marked="true", or a sentence on the page names the run id and says what was and was not narrowed — and a run id outside the window says so, as ?cycle= already does. Pinned in tests/offline/cycles/page.test.ts.
