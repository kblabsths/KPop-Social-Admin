# choose_claimed_value adopts ANY observation in the ledger, not one of the item's evidence claims

## Description
**Expected** — `contracts/admin-observability.md` §7 spells the `data_conflict` answer as "**choose a claimed value** (one tap per evidence card)": the value adopted is one of the ITEM'S OWN evidence claims. The artifact says the same of itself, in the comment on this very arm (`M2-handoff-settle-review-item.md:526-528`): "the admin ADOPTS a claimed value, which means re-asserting it in their own voice. The value is read off the claim rather than re-sent by the dashboard, so the two cannot differ." The function's own stated posture (line 146) is "What it refuses is a decision that would write something other than what it says."

**Found** — the `choose_claimed_value` arm reads the observation by PRIMARY KEY ALONE, with no predicate binding it to the item or to the fact:

    agenticflow/tracker/for-human/M2-handoff-settle-review-item.md:537-540

        select claim.value
          into v_claim
          from public.observations as claim
         where claim.observation_id = (v_value ->> 'observation_id')::uuid;

Measured on the landed tree (commit c9b8133, run/admin-window), by extracting that statement's WHERE clause with the suite's own reader and asserting it names any binding:

    AssertionError: expected ' claim.observation_id = (v_value ->> …' to match
      /v_item\.evidence|claim\.domain|claim\.entity_id|claim\.field/
    + Received: " claim.observation_id = (v_value ->> 'observation_id')::uuid"

So ANY `observation_id` in the ledger is adopted. Its value is then re-ingested through the gate under the admin source for the DECISION's `domain`/`entity_id`/`field` (lines 581-589) and applied with `tier_at_apply = 'admin'` and `admin_locked = true` (lines 657-667) — `contracts/resolver.md` §8's admin stickiness, which no scraper claim can ever displace. The wrong value lands on the RIGHT row (the new observation carries the decision's own fact identity), so nothing downstream detects it.

The gate is not the backstop: it validates the adopted value against the TARGET field's declaration only, so any same-shaped foreign value passes. Concretely, on the installed events v3 / venues v2 schemas (`kspace Scraper/supabase/migrations/20260829000004`), adopting a `venues.name` claim (string, 1..200) into `events.title` (string, 1..300) validates and applies, admin-locked, forever.

**The asymmetry is the tell.** The artifact already refuses the analogous mismatch on the other side — lines 463-479 refuse a decision whose `domain`/`entity_id`/`field` differ from the item's, with its own message ("item % is about a different fact"). It guards item↔decision and leaves claim↔decision unguarded. And the binding datum the contract names is already in hand: `v_item.evidence` is read three statements later, at line 644, for the rejection set.

**Repro (offline, no database — the artifact is a text handoff nothing here executes):**

    ./node_modules/.bin/vitest run --project=offline tests/offline/handoff/settle-review-item.test.ts

The pin is landed as `it.fails(…)` (strict xfail, house convention — cf. BUG-0087): it goes RED the day the arm is bound, which is the signal to flip it back to `it`. Watched red as a plain `it` before pinning; the failure text above is that run.

**The fix is a predicate, not a redesign.** Either binding satisfies the pin and the contract: constrain the read to `claim.observation_id = any (v_item.evidence)` (the contract's own words, and it also refuses an override adopting a claim — `override` cannot fill `observation_id` today, so the arm is item-only in practice), or constrain the claim's own fact triple to the decision's `v_domain`/`v_entity_id`/`v_field`. Raise `KS027` on a miss, in the shape the neighbouring refusals already use, and add the citation to §4 of the note so Ben reads the choice rather than inherits it.

**Why it is filed and not waved through**: this artifact is pasted by hand into a repo this campaign may not enter, and the defect it would install is permanent by design (`admin_locked`). It is one predicate before the paste and an unpicked, unprovenanced canonical value after it.
