# ASK BEN: what does the edit surface show for provenance on groups and idols, which have none?

## Description
**Contract silence.** ARCHITECTURE marker `OPEN-PROVENANCE`. SPEC named gap 3.

Spec section 8 says *'per-field provenance shows at the edit surface'*, and LOOK_AND_FEEL quality bar 5 makes it a bar: *'provenance shows at the fact ... and every editable field'*. But `groups` and `idols` are **pre-cutover**: they edit directly, *'legal and unprovenanced as the ownership rules allow'* (spec section 8), so **no `field_provenance` row exists for them** and none will until catalog maintenance cuts them over (ROADMAP queue item 9).

So the two rules meet: the bar says show provenance at every editable field; the data says there is none to show.

**Recommend: render nothing in the provenance slot for a pre-cutover table** — no line, no placeholder, no 'unknown'. SPEC calls this 'the honest read' and asks for confirmation before shipping it. The alternative worth considering is one `micro` label per record (not per field) saying the table is not yet resolver-owned, so the operator knows the absence is structural rather than a lookup that failed — LOOK_AND_FEEL's Interaction principle that an empty state and an unprovisioned state must never share a rendering points that way. What must not happen is a per-field 'no provenance' line on every field of every record, which is noise the operator learns to ignore.

TASK-0018 builds everything else on the edit surface and leaves this slot empty until the answer lands.
