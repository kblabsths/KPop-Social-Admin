# A render that throws reaches the operator as Next's own 500: the app has no route-level error boundary

## Description
QA's boundary question from BUG-0228, ruled (architect, 2026-09-15): rows carrying every declared column with WRONG-TYPED values are admitted by the read layer on purpose — the row leg asks which columns are present, never what they hold — and the net for what a render then does with them is a route-level error boundary, not a fifth predicate in `lib/db` (LESSONS 13: `[{}]` defeats an element-type guard and the next shape defeats its successor).

Measured on this tree 2026-09-15: `src/app` contains NO `error.tsx` and no `global-error.tsx` at any depth. So every throw inside a rendered route — a render reading `row.name.trim()` on a number, a client-boundary violation (BUG-0222/BUG-0226 twin), a bug in a component — reaches the operator as Next's own unstyled 500 page carrying nothing this app wrote. Four surfaces were measured doing exactly that against an alien host (BUG-0228).

This is a NET, not a new voice. It must never become the place where a nameable refusal is handled: `lib/db` still never throws (§4.1), every classified answer still renders its own card, and nothing in `src/lib` may start throwing to reach this boundary. The boundary exists for the answer nobody classified and the bug nobody predicted.

EC10's "no new page route" is not touched: `error.tsx` is a boundary, not a route, and the sidebar is unchanged. This ticket is patch-lane, after M3.

## Acceptance criteria
1. `src/app/error.tsx` exists as the app-router error boundary (a client component, per the framework guide in `node_modules/next/dist/docs/` — read it before writing, AGENTS.md) and is reached by a throw from any of the six surfaces.
2. What it says, and the limit on it: the surface could not be drawn, named by route; the machine's own token (Next's `digest`, when there is one) verbatim in mono; and the app's fix sentence ("reload; if it repeats the answer this database gave is one this app cannot render"). It invents no cause, quotes no stack, and states no database fact — it does not know one.
3. It never replaces a refusal: `lib/db/**` still returns `DbResult` and never throws (§4.1), and no module gains a `throw` to reach this boundary. Pin it — the offline case asserts that a `not_provisioned` answer still renders the not-provisioned card and does NOT reach the boundary.
4. Look and feel: it uses the shared refusal primitives and the design tokens (the `text-broken` role and `type-*` scale, through `src/components/ui/**`), never a raw colour or a hand-spelled face; the machine's token wears the mono face and the app's sentence does not (LESSONS 6); the page frame and the sidebar stay drawn, so the operator is never stranded on a bare page (LOOK_AND_FEEL, the Frame).
5. `global-error.tsx` is a judgment call, not a requirement: add it only if the root layout itself can throw on a path you can name in the ticket history; otherwise say why not.
6. `npm run build` stays green and no surface's normal render changes — the six pages' offline suites are unchanged by this diff.
