# saidOnce misses every REAL transport failure: postgrest-js puts the cause's code between the Caused-by line and the stack head it must absorb

## Description
**Module:** `src/lib/db/result.ts` — `saidOnce()` (landed by admin-window/DEBT-0020, commit 465859b7), the ends-with line dedup inside `askedLineByLine`.

**Expected** (admin-window/DEBT-0020, criterion ONE SENTENCE, ONCE): on the transport-failure shape — the wrapper `message`, and a `details` carrying the wrapper line, the `Caused by: <name>: <cause.message>` line, that same sentence again as the head of `cause.stack`, and at least one V8 frame — the account states the cause sentence exactly once.

**Found**: it states it TWICE on every transport failure node actually produces, because node's causes carry a `code`. `node_modules/@supabase/postgrest-js/dist/index.mjs` builds `details` in this order (the `res.catch((fetchError) => …)` arm):

    errorDetails  = `${fetchError.name}: ${fetchError.message}`
    errorDetails += `\n\nCaused by: ${cause.name}: ${causeMessage}`
    if (causeCode) errorDetails += ` (${causeCode})`      <-- lands BETWEEN the two
    if (cause.stack) errorDetails += `\n${cause.stack}`

`getaddrinfo ENOTFOUND` carries `code: "ENOTFOUND"`, `connect ECONNREFUSED` carries `code: "ECONNREFUSED"` — so the attributing line ends `… db.invalid (ENOTFOUND)` and the stack head is `Error: getaddrinfo ENOTFOUND db.invalid`. `saidOnce`'s test is `kept.some((held) => held.endsWith(line))` (src/lib/db/result.ts:492-499): the kept line no longer ENDS WITH the repeat, the test misses, and both copies cross.

DEBT-0020 measured its before/after on a hand-built cause with NO `code` (the ticket's History, and `transportFailure()` in tests/fixtures/stub-client.ts, which has no `code` either), so the whole fix was derived and graded on the one transport shape a deployed instance never produces.

**Exact repro** — the real `@supabase/supabase-js` client over a transport that rejects the way node's `fetch` rejects (no network; host is `.invalid`), measured on run/admin-window at 5b553a2c:

    cause = Error("getaddrinfo ENOTFOUND db.invalid"); cause.code = "ENOTFOUND"
    cause.stack = "Error: getaddrinfo ENOTFOUND db.invalid\n    at GetAddrInfoReqWrap.onlookupall [as oncomplete] (node:dns:120:26)"
    wrapper = TypeError("fetch failed"); wrapper.cause = cause
    await readRows(T.pendingClaims, (db) => db.from(T.pendingClaims).select("id"), <client whose fetch throws wrapper>)

  cause WITHOUT a code (DEBT-0020's fixture)  -> 106 chars, sentence x1:
    "TypeError: fetch failed Caused by: Error: getaddrinfo ENOTFOUND db.invalid (1 runtime stack frame dropped)"
  cause WITH its code (what node hands back)  -> 158 chars, sentence x2:
    "TypeError: fetch failed Caused by: Error: getaddrinfo ENOTFOUND db.invalid (ENOTFOUND) Error: getaddrinfo ENOTFOUND db.invalid (1 runtime stack frame dropped)"
  ECONNREFUSED, same call                     -> 167 chars, sentence x2:
    "TypeError: fetch failed Caused by: Error: connect ECONNREFUSED 127.0.0.1:5432 (ECONNREFUSED) Error: connect ECONNREFUSED 127.0.0.1:5432 (1 runtime stack frame dropped)"

**The pin**: `it.fails("says the cause sentence once when the cause carries a code, as node's do")` in tests/offline/db/result.test.ts, in the "an account carries the parts the database authored" describe, beside DEBT-0020's own twin. It drives the REAL client, both codes. Watched RED as a plain `it` on the landed tree first: `AssertionError: Error: getaddrinfo ENOTFOUND db.invalid: expected 2 to be 1` at tests/offline/db/result.test.ts:2334. Flip `it.fails` back to `it` when it is fixed.

**What the fix must NOT cost** (the bars already standing, all green today and graded by the same file): a prefix-sharing pair keeps BOTH lines in both arrival orders (DEBT-0020's twin); a FRAMELESS part still crosses verbatim, repeated line and all (admin-window/BUG-0187's bar — measured: `details` of two identical `permission denied for table groups` lines with no frame still carries both, newline intact); the three questions stay three; no vocabulary and no length cap is introduced — `" (ENOTFOUND)"` must not be matched as text, and `Caused by:` must not become a spelling this file knows (LESSONS 4). The ten-fixture table and the whole account derivation stay as they are.
