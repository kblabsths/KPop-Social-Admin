# The override surface calls a claim an 'observation' — the one noun the glossary pins hardest

## Description
Found on the M2 early walk, 2026-09-08, in the rendered text of `/records/events/<id>` and `/records/venues/<id>` on the walk instance (127.0.0.1:8771, staging).

**Expected** — LOOK_AND_FEEL glossary, first row: use **claim**; never "observation, assertion, datapoint". Its stated reason is exactly this case: "`observation_id` stays a machine id; **the operator reads claims**."

**Found** — the regime note at the top of every `events` and `venues` record page, in prose (`type-body` sans, not mono, not an identifier):

> "`events` is resolver-owned: its values change through the resolution pipeline, never by a direct edit. An edit here is recorded as an admin override — **an observation** at the admin tier, applied through the pipeline and logged — and the pipeline then leaves that field alone."

`src/app/records/[table]/[id]/page.tsx:112-116`. This is the app's only explanation of what an override does, on the surface M2 exists to build, and it uses the banned synonym for the app's most-used noun. Everything else in the sentence is on-glossary — "override", "canonical" behaviour, "admin tier".

The sibling use is fine and must stay: `src/app/queues/[reviewItemId]/page.tsx:402` says "The resolver appends an **observation id** to `evidence` each time this item folds" — that names the machine id, which the glossary explicitly sanctions. A scan of the rendered text of all six walked surfaces found no other prose use of a banned synonym.

Provenance checked: the string landed in `admin-window/TASK-0054` ("events and venues edit as recorded admin overrides"), a ticket-bearing commit — a violation, not a human-lane divergence.

## Acceptance criteria
1. The regime note on the `events` and `venues` record pages says "claim" where it now says "observation"; the rest of the sentence is unchanged.
2. No prose string rendered by `src` uses a glossary-banned synonym for a pinned noun (observation / assertion / datapoint for **claim**; resolution, approval, judgement, vote for **verdict**), with the sanctioned exception of a machine identifier rendered verbatim in mono and of "observation id" naming the id itself. Asserted as a source-tree rule in `tests/offline/ui/copy.test.ts`, the way the inter-element-space rule is asserted there, and shipping with one string it must flag and one it must not.
3. The pages still answer 200 with `verdicts` absent and the not-provisioned card is unchanged.
4. `npm run lint` and `tsc --noEmit` clean; the targeted offline files and the record page's live suite green.
