# The evidence card's source is hand-faced with DATA_MUTED, so a source name reverses the app's own words beside it

## Description
**Expected** — `src/components/ui/identifier.tsx` names, in its own doc, exactly this value class as what the primitive is for: "an identifier span is precisely where foreign text lands: a status the database produced, **a source's own name**, a column name a URL asked for" (:35), and the `DATA_MUTED` doc is explicit that the const is not the way to draw one — "A machine identifier takes `<Identifier muted>` instead — never this" (:81). DEBT-0011 criterion 2 requires every call site rendering a machine identifier to import the primitive; criterion 4 requires that an identifier carrying a bidi control "cannot reorder the sentence around it".

**Found** — `src/components/evidence/evidence-pair.tsx:73-77` hands the WHOLE claim line the `DATA_MUTED` class and leaves the machine values as bare text nodes inside it:

    <span className={DATA_MUTED}>
      {claim.source} · {orDash(claim.tier)} ·{" "}
      <span title={age.title || undefined}>{orDash(age.text)}</span>
    </span>

`claim.source` is the source's own name straight out of the pipeline (`shape-views.tsx:270` ← `claim.source`, `app/queues/[reviewItemId]/page.tsx:279`) and `claim.tier` is `sources.tier` (the file's own comment: "`sources.tier` is the only place a claim's current tier comes from"). Neither goes through `Identifier`, so neither is isolated, and the app's own separators and relative age sit in the SAME bidi paragraph as the foreign value.

**Rendered markup** (offline, `renderToStaticMarkup`, source = `ticket<U+202E>master`, tier `official`):

    <span class="type-data text-ink-secondary">ticket‮master · official · <span title="2026-08-26 04:12 UTC">14d ago</span></span>

— one un-isolated inline box. `<Identifier muted>` renders `<span dir="ltr" class="type-data text-ink-secondary">`: the IDENTICAL class string, differing only by `dir="ltr"`. So wrapping the value changes nothing about the ink or the face — it only adds the isolation.

**Measured harm, Chromium (playwright, agenticflow/.venv-tools, 1440x900, headless), per-character Range rects sorted by x:**

| line | logical text | VISUAL order on screen |
| --- | --- | --- |
| as shipped (no `dir`) | `ticketmaster · official · 14d ago` | `ticketoga d41 · laiciffo · retsam` |
| same line, source wrapped in `<Identifier muted>` | `ticketmaster · official · 14d ago` | `ticketretsam · official · 14d ago` |

The app's own words — the `·` separators, `official`, and the age `14d ago` — are drawn backwards by data the app did not author. With the primitive the reversal is contained to the value's own box and every app word reads in order. This is precisely the row-15 / criterion-4 harm, at a call site the sweep edited (it already imports `Identifier` for `CardValue` one line above).

**Repro (offline, no server, no device):**
1. `cd "kspace Admin"`
2. `./node_modules/.bin/vitest run --project=offline tests/offline/ui/evidence-pair.test.ts`
3. The pinned test `gives the claim's source the isolation the identifier primitive gives an identifier` is `it.fails` today: no element's whole text is the source value, so the value carries no `dir` at all. Convert it to a plain `it` and it goes red (watched red before this ticket was filed: 1 failed | 10 passed).

**Browser repro:** `agenticflow/tracker/evidence/DEBT-0011/bidi.html` + `bidi.py` (run with `agenticflow/.venv-tools/bin/python`) render the shipped line and the isolated line side by side and print both orders.

**The fix** is `<Identifier muted>{claim.source}</Identifier>` (and the same for `orDash(claim.tier)`, which is `sources.tier`, the same class of value). The outer `DATA_MUTED` span stays — it is the line's app-authored prose face and it inks the separators. When it lands, flip the `it.fails` in `tests/offline/ui/evidence-pair.test.ts` back to `it`.

**Note for whoever takes it:** the primitive's `DATA_MUTED` doc says the const has "four places"; `grep -rn DATA_MUTED src` returns six sites (loading.tsx:14, stat-card.tsx:76, EditableCell.tsx:797, close/form.tsx:134, evidence-pair.tsx:74, :90). Two of those six are this file. `:90` (`{canonical.provenance}`) is a caller-composed sentence ("ticketmaster, applied 3d ago") with no separable value and is NOT part of this fix; the doc's count is a one-word correction while you are in the file.
