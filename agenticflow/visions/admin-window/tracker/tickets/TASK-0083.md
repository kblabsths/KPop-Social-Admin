# The README's tier table stops at four tiers, so the opt-in handoff suite is named nowhere a builder reads

## Description
TASK-0080 moved the guards that READ the sibling repo out of the every-builder suite into a fifth, opt-in vitest project (`tests/handoff/**`, `npm run test:handoff`, outside `npm test` and therefore outside `ci_command`) — the right cut, by input ownership (ARCHITECTURE §10). The cost of opting out is that nothing names the tier: QA measured (2026-09-15) that `test:handoff` appears only in ARCHITECTURE §10, in `tests/suite-globs.ts` and in `package.json`, and the README's script table and STACK §5's incantation table both list four tiers and stop. A tier nobody names is a tier nobody runs.

The README's front-door guard (`tests/offline/shell/shell.test.ts`) is ONE-DIRECTIONAL: every script the README names must exist in `package.json`, but a script the README omits is invisible to it. So this omission cannot be caught; it has to be written.

STACK.md §5 and the close checklist are the architect's files and were amended on 2026-09-15 (M3 close). This ticket is the README half only.

Measured for the ticket, 2026-09-15: `npm run test:handoff` is GREEN at HEAD — 1 file, 12 tests, 0.4 s — against a sibling that has raised KS033 since its 2026-09-13 migrations.

## Acceptance criteria
1. README's script table gains a `npm run test:handoff` row whose "What it runs" says three things: it runs `tests/handoff/**`, it is NOT part of `npm test`, and its subject is a repo this one does not own (`../kspace Scraper`) — so a red there is a fact about the sibling, not about your diff.
2. The paragraph under that table (the one that says the directory a test lives in IS its tier) names the handoff tier too, so the reader who counts tiers counts five.
3. Nothing else in README changes: no new heading, no re-ordering, no path or script the guard cannot resolve.
4. The front-door guard still passes, and the row's script exists in `package.json` — which is what makes the guard's one direction enough for this row.
