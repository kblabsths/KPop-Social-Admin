# STACK 5 retires the groups/idols walk-write exception before walk_sandbox exists, leaving the M1 endgame walks no write surface at all

## Description
Expected (Ben's standing ruling, quoted in agenticflow/tracker/for-human/TASK-0034.md section 1, landed and unchanged): 'walkers ... must confine itself to one field of one existing groups/idols row, note the original, restore it, and sweep. That is the walk-write rule UNTIL THE SANDBOX BELOW EXISTS; then the sandbox replaces it.' The exception is interim and ends when the TABLE exists.

Found: agenticflow/docs/vision/STACK.md line 298 (landed f2eb84b, TASK-0036) retires it on the TOOL's arrival instead: 'Until then there is no walk-write surface at all: do a read-and-render walk and say so in your finding. Do not fall back to editing a catalog row — that practice is retired.' and line 357 'This RETIRES the old exception ... which nobody should follow again.' walk_sandbox does not exist yet: measured on staging 2026-09-04 by two independent paths — (a) 'node tests/walk/reset-sandbox.mts' through the STACK 5 step 3 block exits 1: 'the table "walk_sandbox" is not on ubfjjqlvnpnoborczbdb.supabase.co'; (b) 'npx vitest run --project=live tests/live/residue.live.test.ts' reports 'walk_sandbox: not present on ubfjjqlvnpnoborczbdb.supabase.co ... 56 column(s) scanned across 4 of 5 mapped table(s)'.

So the two landed docs disagree about the state the repo is in RIGHT NOW, and the one walkers read is the one that removed the surface. Consequence, reachable today with no further change: the M1 endgame walks (designer, user-sims, verifier) have no writable surface, so the save path — the campaign's own core write behaviour, measured landing a 200 and a real column change under BUG-0038 — cannot be walked at all until Ben pastes the DDL, on a schedule the for-human note explicitly calls 'when convenient; nothing is blocked on it'.

Repro (exact):
  1. cd to the repo root on run/admin-window at f2eb84b or later.
  2. Run STACK 5 step 3 verbatim. It exits 1, naming walk_sandbox absent.
  3. Read STACK 5 step 3 bullet 3 (line 298) and the last caveat (line 357). A walker following them has no write surface and is told the interim practice is retired.
  4. Read agenticflow/tracker/for-human/TASK-0034.md section 1. It says the interim practice holds until the table exists.

Not filed as a failing test on purpose: the divergence is between two prose documents, and a test that graded their wording would be the copy-oracle this factory bans. The checks below are the same narrow-grep form TASK-0036's own checks already use (check 3 there is the identical negative shape); check 1 is RED as filed (measured: exit 1 today, the sentence stands at line 298).

Suggested shape, for the architect to rule on rather than a prescription: make the retirement conditional on the TABLE, not the tool — i.e. while the reset tool refuses 'walk_sandbox is not on <host>', the one-field-on-groups/idols exception (note the original, restore in a finally, residue sweep) remains the walk-write rule, and it retires the moment a reset succeeds. If instead Ben's ruling has genuinely moved to 'no catalog writes, ever, even in the interim', then for-human/TASK-0034.md section 1 is the stale half and should be corrected there, so the two docs agree either way.
