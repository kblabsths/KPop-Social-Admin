# Four byte-identical StateOf copies (and three WindowLines, one already drifted) stand in the pages instead of one ui primitive

## Description
M1 structure walk, 2026-09-03. Common violation 9.

`StateOf` — the component that turns a `not_provisioned`/`error` DbResult into the card the operator sees — is defined FOUR times, byte for byte including its comment, in `src/app/cycles/page.tsx`, `src/app/sources/page.tsx`, `src/app/claims/page.tsx` and `src/app/queues/[reviewItemId]/page.tsx`. It is not incidental duplication: it renders the `data-not-provisioned` and `data-read-failed` hooks that ARCHITECTURE §10's live-state rule requires every live oracle to read structurally. Four copies is four chances for that contract to drift, in the exact place a drift grades a broken page as a pass (common violation 6).

The drift has already happened one helper over. `WindowLine` stands three times: `cycles` and `sources` are identical but for the window's TYPE, and the `claims` copy has ALREADY diverged — it carries none of the `data-window` / `data-window-since` / `data-window-until` / `data-window-truncated` attributes the other two do, and says 'not the whole view' where they say 'not the whole table'. So the Claims window line cannot be read structurally at all, and the two sentences a reader would assume are one are two.

Also hand-copied, same cause: `RETRY` (4 pages) and `ARRIVES_WITH` (all 8 pages) — one sentence each, repeated verbatim, that a copy edit would have to find eight times.

Why it happened, so the next one does not: builders work in isolated worktrees and cannot see each other's code, so a helper nobody seeded as its own ticket becomes N hand-copies. That is now ARCHITECTURE §13.7.

Scope note: this ticket rewrites four PAGES. It is serial at its destination with every open bug on those pages, which is why it depends on all of them. If M1 closes before those clear, this is M2's — say so rather than co-dispatching it.

Not in scope: extracting the per-page sections into component modules (that is the sibling DEBT), and any change to what the four states RENDER — this is a fold, and the offline and live suites for all four pages must be untouched and green.

## Acceptance criteria
One `StateOf` and one `WindowLine` exist, exported from `src/components/ui` and imported by all four pages; no page file defines either. The shared `StateOf` renders exactly what the four copies rendered — the `data-not-provisioned={missing}` wrapper around `NotProvisioned` and the `data-read-failed={reading}` wrapper around `ErrorLine`, with the optional `eyebrow` — and the shared `WindowLine` carries the four `data-window*` attributes on every page that uses it, INCLUDING `/claims`, whose copy had dropped them; its sentence is one sentence, and the 'not the whole view' / 'not the whole table' split is resolved deliberately (a window over a view says view) rather than by whichever copy won. `RETRY` and `ARRIVES_WITH` are single exported constants, spelled once. The four pages' offline suites and their four live parity oracles are green, unchanged in what they assert: this fold changes no rendered output, and any diff a live oracle can see is a defect in the fold.
