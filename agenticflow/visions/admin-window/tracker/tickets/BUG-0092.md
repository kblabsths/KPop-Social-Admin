# The inline verdict block draws dashes it neither owns nor explains

## Description
`ItemVerdictBlock` (`src/components/review/close/slot.tsx`, campaign admin-window/TASK-0059) renders four lines that can be absent — actor, note, when, observation — but its dash contract covers only two of them. Its own docstring states the contract it breaks: "Rendered only when a dash is actually on screen", and LESSONS 1 states the other half: "Every nullable value goes through `lib/format.ts`'s dash".

Two legs, one block, one `if` each.

**Leg A — a dash the block draws and does not explain.**

Expected: the `data-absence-note` line renders whenever a dash is on screen (`slot.tsx`, `DASH_MEANS`' own docstring).
Found: the line is keyed to `note`/`observation` alone — `{note !== null && observation !== null ? null : (<p data-absence-note="dash">…)}` in `ItemVerdictBlock` — so a verdict whose `actor` is blank draws the app's dash on the "by" line with no line saying what a dash means. Measured on the landed tree (d2e4623), rendering `[data-surface="item_verdict"]` with `actor: "   "`, a note, and a resolvable observation: `[aria-label="no value"]` = 1, `[data-absence-note]` = 0.

**Leg B — a dash the app's own dash did not draw.**

Expected: an instant that will not parse is handed to `orDash` so the app's one dash element draws it — which is exactly what the sibling rendering of the SAME column does, `src/components/queues/verdict-log.tsx` (`created` column: `age.title === "" ? null : <span title={age.title}>{age.text}</span>`, "handed over as null so the table's dash draws it").
Found: the block renders `relativeAge(...).text` directly (`<span title={when.title} data-verdict-when={…}>{when.text}</span>`), and `relativeAge` answers `{ text: EM_DASH, title: "" }` for an unparseable instant (`src/lib/format.ts:86-91`). So the "when" line becomes a BARE em-dash text node: no `[aria-label="no value"]`, no title, no dash-meaning line — and the same `verdicts.created_at` renders two different ways on two screens. Measured on d2e4623 with `created_at: "settled last tuesday"`: stray em dashes inside the block = 1, `[aria-label="no value"]` = 0.

**Repro (exact), from the repo root:**
1. `./node_modules/.bin/vitest run --project=offline tests/offline/review-item/verdict-inline.test.ts`
2. The two tests under "the block's own dash contract" are `it.fails` pins carrying this ticket's id — they PASS today because the block is wrong. Remove the `.fails` (or fix the block) to see them red/green.

**Reachability, honestly (why P3 and not P2):** neither trigger is reachable from today's data path. `verdicts.actor` is `text not null` (`contracts/admin-observability.md` §7) and `verdicts.created_at` is a timestamptz PostgREST serialises as ISO, so no row `settle_review_item` can write lands here. It is priced P3 on user impact, not on class: the class is LESSONS 1, which this campaign has filed at P2 eight times (BUG-0085 is its twin, a blank note in the log's own table). Two things kept it a ticket rather than a residual: TASK-0059's own stored check already RENDERS the blank-actor state (its test "dashes an actor the row left blank"), so the ticket grades this state and grades it incompletely; and `newestFirst` in `src/lib/db/verdict.ts` explicitly contemplates an unparseable `created_at` ("sorts last rather than poisoning the comparison, so the row still renders") — the read hands the renderer a row the renderer then mis-draws.

**The fix is not prescribed**, and the pins are written so either shape passes: stop dashing the actor, or explain every dash; render the unparseable instant through `orDash`, or refuse the line. The pins assert only the invariant — every dash the block puts on screen is the app's dash element, and a dash on screen carries exactly one dash-meaning line.

## Acceptance criteria
1. Every em dash `[data-surface="item_verdict"]` puts on screen (outside its own dash-meaning sentence) is drawn by the app's one dash element — `orDash`, `[aria-label="no value"]` — including the "when" line on an instant that will not parse.
2. Whenever that block has a dash on screen it carries exactly one `[data-absence-note]`, and when it has none it carries none — on all four of its absent-able lines, actor and when included.
3. The two `it.fails` pins in `tests/offline/review-item/verdict-inline.test.ts` are turned back into ordinary `it(...)` by the fix and pass; the rest of that file and `tests/offline/review-item/page.test.ts` stay green.
4. `npm run lint` and `./node_modules/.bin/tsc --noEmit` are clean.
