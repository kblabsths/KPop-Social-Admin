# Browse: 'Starts (UTC)' states the zone in the header and again in all 50 cells, wrapping every row

## Description
Found on the M1 endgame designer walk (2026-09-03), walk instance :8771 against staging, 1440x900.

Voice copy bar 6: "scheduled times are absolute ... '2026-08-29 04:12 UTC' with **the zone stated once in the column header**".

`/browse` states it twice. The header reads `STARTS (UTC)`; every cell under it reads `2026-08-31 02:30 UTC`. The cell's own source comment already knows the rule — `src/components/browse/browse-table.tsx:18` says "scheduled times are absolute UTC with the zone stated once in the column header (`starts_at` — 'Starts (UTC)')" — but the shared formatter `formatInstant` (`src/lib/format.ts:39-40`) appends ` UTC` to the value, so the column gets it from both ends.

The cost is not only redundancy: the doubled token overflows the column, so **every one of the 50 rows wraps its date onto two lines**, which doubles the height of the whole table and is the reason a 50-row browse is 2,428px tall.

`formatInstant` is also used where the zone is NOT in a header — the app's window sentences ("read to 2026-09-03 21:44 UTC") and title attributes — where the ` UTC` suffix is correct and must stay. So this is a call-site question, not a one-line edit to the formatter.

Evidence: `agenticflow/tracker/evidence/designer-walk-m1/browse-light.png` (every row two lines tall), `browse-dark.png`.

**What this adds that BUG-0046 does not.** Both land in `src/lib/format.ts`, but on different functions and for different bars: 0046 is `count()` and noun agreement (copy bar 6's third clause), this is `formatInstant()`'s zone suffix (copy bar 6's second clause) and the row wrapping it causes on `/browse`, which 0046 never touches.

## Acceptance criteria
On `/browse` the zone is stated once. Whichever way it is resolved — header keeps `(UTC)` and cells drop the suffix, or the reverse — the rendered page states `UTC` for the starts column in exactly one place.

Rows in the recent-events table no longer wrap on the starts column at 1440x900; report the table's rendered height before and after in the ticket History.

`formatInstant`'s other callers are unchanged: the window sentences on `/queues`, `/claims`, `/sources` and `/cycles` still read "read to 2026-09-03 21:44 UTC", and the absolute instant still appears in the `title` attribute of relative ages.

`tests/offline/browse/page.test.ts` asserts the starts column's rendered cell text, and `tests/offline/format.test.ts` still covers the suffix behaviour its other callers depend on.

Human-check: on `/browse` at 1440x900, no row's date wraps and 'UTC' appears once per column, not once per cell. (human-checkable)
