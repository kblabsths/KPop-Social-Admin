# a failed read carries an INTERMEDIARY's HTML error page verbatim into the app's account, onto the claims card and through the paging route's error arm

## Description
**Expected** (ARCHITECTURE.md §4.1 — the account is the DATABASE's own words; common violations row 15 and LESSONS 4 — foreign text reaches an app sentence in its own box or not at all): a read the app could not complete is refused naming the object, in words a reader can read.

**Found**: when the failure is answered by the WAF in FRONT of PostgREST rather than by PostgREST, supabase-js hands the page BODY back as `error.message`, and `messageOf` (src/lib/db/result.ts:160) / `errorMessage` (:370) carry that whole HTML document into `DbResult.error.message`. Measured on the landed tree (run/admin-window @ df80591) against staging: a **4,547-character Cloudflare 'Attention Required!' document**, doctype and tags included, reaches the operator on TWO surfaces.

**Repro (exact), from the repo root on run/admin-window @ df80591:**

1. Launch a production build against staging on a scratch port (STACK.md §5's production-like block, `--port 8783`), and mint a cookie: `node tests/walk/session-cookie.mts`.
2. The paging route's error arm:
   `curl -s -H "cookie: $C" 'http://localhost:8783/api/admin/claims/rows?domain=events%27%29%20drop%20table%20groups%3B--&offset=50'`
   answers **HTTP 200** with `{"kind":"error","reading":"pending_claims","message":"<!DOCTYPE html>\n<!--[if lt IE 7]> …<title>Attention Required! | Cloudflare</title>… "}` — `message.length === 4547`, first 15 characters `<!DOCTYPE html>`.
3. The FIRST screen, same facet: `curl -s -H "cookie: $C" 'http://localhost:8783/claims?domain=<the same value>'` answers 200 and **renders that same document as escaped text inside its refusal card** — the response is 50,635 bytes and contains `&lt;!DOCTYPE html&gt;… Attention Required! | Cloudflare`.

Any facet value the WAF dislikes reaches this; the value above is one measured trigger, and the defect is the carrying, not the trigger.

**Not TASK-0066's code.** The route obeys its contract (`pageAnswerOf` crosses `message` unchanged, which its criteria require); the account is assembled below it, in the read path /claims has used since M2. It is filed here because the paging feature makes it worse: `requestPage` puts `answer.message` straight into the inline refusal slot (src/lib/paging/machine.ts, `case "error"`), so a 4.5 KB document lands in a one-line slot on TASK-0067's surface.

**Already pinned, watched red before filing**: `tests/offline/db/result.test.ts` — 'does not carry an intermediary's HTML page into the account'. Run as a plain `it` on the landed tree it fails on `expect(result.message).not.toMatch(/<!DOCTYPE/i)`; it is committed as a strict `it.fails` xfail so the branch stays green, and the fix flips it back to `it`. Do not add a second assertion of the same behaviour — extend that one.

## Acceptance criteria
ONE DERIVATION DECIDES WHAT AN ACCOUNT MAY CARRY, FOR EVERY READ IN THE APP. This is a class ticket, not a site fix: the rule is about the SHAPE of what the client handed back — never about which intermediary sent it, never about which surface renders it. `DbResult.error.message` carries the DATABASE'S OWN PROSE verbatim, or, where a part of the account is not prose but a DOCUMENT, an app-authored bounded description of what arrived instead. It is decided in exactly ONE place — inside `errorMessage`'s part assembly in `src/lib/db/result.ts`, the function every `kind: "error"` result already passes through — so `/claims`' refusal card, `GET /api/admin/claims/rows`' error arm, the browse paging route's error arm (admin-window/TASK-0068) and every other read in `lib/db/**` inherit it with no line of their own, and no second reduction is written beside any surface (`lib/paging/machine.ts` and `components/ui/error-line.tsx` are unchanged by this ticket).

THE TEST IS POSITIVE AND ANCHORED, NOT A SCRUB. ARCHITECTURE §7 / common violations row 15: text this app did not author never sits inside a sentence this app wrote — it reaches prose through an allowlist or inside its own box, and NEVER by removing the family that last broke it. `ErrorLine` inlines this string in one app-written sentence (`${reading} — ${failed}`, `src/components/ui/error-line.tsx`), so the message itself is where the rule has to hold. The derivation: a part whose FIRST non-blank character is `<` is a document — the doctype the WAF sent, an `<html …>` fragment with no doctype, an `<?xml …?>` prolog. Nothing else is inspected: no tag stripping, no entity decoding, no length cap on prose, no codepoint blocklist, and no second detector for a shape nobody has measured (LESSONS 4 — that is precisely the blocklist-chased-one-family-at-a-time class row 15 was promoted for). A database message that merely CONTAINS angle brackets is untouched.

COUNTED, NOT SPELLED. The replacement quotes NO part of the document — not its `<title>`, not its first line, not a tag. (`canSpellUrlValue` in `src/lib/url/spellable.ts` stays the URL-value question's predicate and is neither called here nor widened: a shared predicate answering a second question is how it gets widened by whichever question broke last, which that module's own doc already refuses.) The account becomes one app-authored clause naming WHAT arrived and HOW MUCH of it, with the document's real character count in it — for the measured 4,547-character Cloudflare page the account contains `4547` (or `4,547`), matches neither `/<!DOCTYPE/i` nor `/<\/?html[\s>]/i`, and is not one of this app's generic sentences ("something went wrong", "sorry" — the neighbouring case stays green). It is not blank and not a bare count: an operator reading it can tell that something other than the database answered. Which object failed is still named — `classify` answers `kind: "error"` with `reading` set to the object the query read, which `ErrorLine` prepends.

THE FIXTURE TABLE (LESSONS 8 — proved on more than the one shape that was measured). REDUCED: (1) the Cloudflare doctype document QA measured, already in the suite; (2) an nginx-style `<html><head><title>502 Bad Gateway</title></head><body>…</body></html>` with no doctype; (3) an `<?xml version="1.0"?><Error><Code>AccessDenied</Code></Error>` envelope, leading newline and indentation included. CROSSING VERBATIM, unchanged and in their existing order: (4) the real PostgREST refusal `{code:'42501', message:'permission denied for table pending_claims', details, hint}` — all four fields, code still appended in parentheses; (5) `operator does not exist: text <-> integer` with code `42883` on a TABLE read, which is `error` carrying that message verbatim, angle-bracket operator included — the fixture that stops this rule from becoming a bracket scrub; (6) a message quoting non-ASCII data the database itself echoed (a duplicate-key value in Hangul), which is the database's own words and is never reduced, truncated or transliterated.

CLASSIFICATION AND REDACTION ARE UNCHANGED. `messageOf` stays the RAW message `classify` mines the absent column out of (admin-window/BUG-0016), so every `not_provisioned` case in `tests/offline/db/result.test.ts` — quoted, unquoted-qualified, PGRST204, the function/table asked-object split — is green with no case rewritten. `withoutSecrets` remains the LAST step over whatever the account became, so a document-shaped part that embedded a JWT or a DSN cannot ship one by being reduced first; a fixture proves an HTML page carrying a `eyJ…` string yields an account with neither the document nor the token.

THE PIN IS FLIPPED, NOT DUPLICATED. `tests/offline/db/result.test.ts`' 'does not carry an intermediary's HTML page into the account' is a PLAIN `it` again — the strict `it.fails` marker is removed by the fix, not left behind — and it is that one case that grows the fixtures above; no second assertion of the same behaviour is added anywhere. `npm run lint`, `npm test` and `./node_modules/.bin/vitest run --project=offline tests/offline/db tests/offline/paging tests/offline/claims` are green on the landed tree.
