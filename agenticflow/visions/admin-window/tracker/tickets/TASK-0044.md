# ASK Ben: which columns of events and venues are editable at all

## Description
**SPEC named gap 7, filed blocked. Not a builder's pick** (spec §8 says the map is hand-written and says no more; AGENTS.md narrows it without fixing it). ARCHITECTURE §12 marker `EDIT_ALLOWLIST_EVENTS_VENUES`.

**What this decomposition added to the question, so Ben answers a closed list.** An admin edit is an observation through the gate, and the gate validates every claim against the registry schema for the domain (`domain_schema(p_domain, p_version)`). A column that is not a registry-declared field is refused by the database before it is refused by taste. Read 2026-09-08 from `kspace Scraper/supabase/migrations/20260829000004_events_take_up_the_third_schema.sql` (events v3) and `20260825000001_events_venues_reregister_with_real_facts.sql` (venues v2), the candidates are exactly:

- **events**: `title`, `event_type`, `status`, `starts_at`, `ends_at`, `time_precision`, `description`, `poster_url`, `ticket_url`
- **venues**: `name`, `address`, `city`, `country`, `latitude`, `longitude`, `timezone`, `website`, `image_url`

`venue` and `performers` are references, not cells: they are observed as `{"ref": …}` and resolved into `venue_id` / `event_performers` rows. `venue` is the picker's field (FEAT-0012); `performers` is out of scope for M2 and AGENTS.md forbids it as a field of `events` outright.

**The campaign's recommendation, so the answer can be one word.** Take the columns Ben already ruled visible on 2026-09-02 — events: `title`, `description`, `poster_url`, `starts_at`; venues: `name`, `city`, `country`, `address` — since those are the columns he said an operator comes to see, and every one of them is registry-declared. `event_type`, `status` and `time_precision` additionally carry CHECK constraints, so a free-text cell can produce a refusal the operator cannot predict; they are recommended OUT unless Ben wants them, in which case they want a fixed choice list rather than a cell (a widget this campaign has not costed).

**Deliverable**: the question written to `agenticflow/tracker/for-human/M2-edit-allowlist.md` — the two candidate lists, the recommendation, and the one-line consequence of each extra column — and this ticket blocked until Ben answers.

**What is NOT blocked**: everything in the override write path except the map's two entries. The write path, the route branch, the refusals and the absent-case rendering are all gradeable with an empty `editable` list, which is exactly what `events` and `venues` carry today.
