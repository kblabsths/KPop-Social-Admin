# /claims: a ?domain= that matches nothing is a dead end — every chip carries it forward and the empty card names an exit that does not exit

## Description
Found on the scoped re-look of `/claims` after BUG-0138 landed (designer, 2026-09-10; production build, own instance on 8783 against staging; evidence `agenticflow/tracker/evidence/M2/designer/claims-domain-zzz-deadend.png`).

**Measured on staging, `/claims?domain=zzz`:** all five bucket rows read `0`, the window line says the read found nothing, and the empty card says

    No claims matching these filters
    Widen a filter above; the 'all' chip on any row shows everything again.

Every anchor on that page carries `domain=zzz` forward, **including both `all` chips**:

    all (bucket)     -> /claims?domain=zzz
    all (source_id)  -> /claims?domain=zzz
    ticketmaster     -> /claims?source_id=01a05782-…&domain=zzz
    awaiting_row     -> /claims?bucket=awaiting_row&domain=zzz

So the one action the empty state names returns the operator to the same zeroed page, and there is no control on the screen that clears the narrowing that emptied it. The only exits are the sidebar's Claims link or editing the URL by hand — and the screen never says the word `domain`, so a person cannot know that is what to edit (that invisibility is BUG-0160; this ticket is the exit, which stays broken even once the narrowing is named).

This is new since BUG-0138: before it, `?domain=` was reported as a dropped parameter and the page rendered unnarrowed. The builder recorded the change of shape in the ticket's History ("`?domain=<anything nothing carries>` now NARROW and render NOTHING_MATCHED + window held 0"); what the ruling did not carry was the exit.

Violates LOOK_AND_FEEL copy bar 4 ("every empty and not-provisioned state names what the surface holds **and what fills it**") — the named filler does not fill it — and the Interaction principle for emptiness; the Voice register ("plain, specific") does not survive an instruction that cannot be followed.

Provenance checked: `git log` on `src/app/claims/page.tsx`, `src/components/claims/filter-bar.tsx`, `src/lib/claims/filters.ts` returns ticket-bearing commits only (5f08227 BUG-0138, 02dc0f5 DEBT-0008, cfe3e06 DEBT-0009). Not a human-lane divergence.

## Acceptance criteria
1. **The exit the empty card names works.** From `/claims?domain=<value nothing carries>`, the single control the card names clears **every** narrowing the page applied — including one with no chip row — and lands on a page that renders rows. Whatever that control is (an `all` chip that drops all facets, or a clear-narrowing control the card links to), the card's words and the control agree.

2. **A narrowing with no rendered control is not left un-clearable.** No reachable state of `/claims` renders zero rows with no on-screen control that undoes the narrowing responsible.

3. **The chip rows keep their present job for the facets they do render**: an inactive `bucket`/`source_id` chip still composes with the other facet, `all` still means "this facet, unset", and `in_window` still appears nowhere (LOOK_AND_FEEL bar 3).

4. The `NOTHING_MATCHED` / population distinction BUG-0138 preserved does not regress: `?tab=standing&domain=events` still renders "nothing here yet", not "nothing matched".

**Human-check (human-checkable):** open `/claims?domain=zzz`, click only what the empty card tells you to click, and arrive at a page showing claims.
