# A paged refusal whose reason is the app's own em dash is announced as the whole of a red alert — the one blank criterion 14 left uncovered

## Description
Found attacking BUG-0176 (landed 7eff4b8). Walked on a PRODUCTION build against staging on my own port 8796 (my PID, killed; reads only), driving the real page, the real `usePageRows`/`fetchJson` helper and the real driver, with the rows request fulfilled by a forced wire body.

REPRO (browser, 2026-09-11): build and start the app, open /claims (66 real staging rows, control drawn), intercept GET /api/admin/claims/rows* and fulfil it 200 `application/json` with `{"kind":"refused","reason":"—","bound":"75"}`, then press the control.

Expected (BUG-0176 criterion 14, and copy bar 3): 'a refusal whose reason holds no words carries ONE app-authored clause instead' — the same thing `{"reason":""}` now correctly draws, measured one press earlier on the same page: 'this press was refused and nothing came back to say why / Press it again to ask for the same rows.'
Found: the line reads `—` followed by 'Press it again to ask for the same rows.', class `flex flex-wrap items-baseline gap-2 text-broken`, computed colour rgb(193,0,7), `role="alert"`, visible, above the control. An alert in the broken red that names no failure and still instructs — copy bar 3 inverted, which is precisely the shape criterion 14 was written to remove.

OFFLINE REPRO (same fact, no browser): `requestPage` against a stub answering `{kind:"refused",reason:"—",bound:"75"}` publishes `{condition:"broken", reason:"—", reasonFrom:"this app", object:null}` — src/lib/paging/machine.ts:~320, `const wordless = !hasVisibleContent(reason)`.

WHY: criterion 14(c) names the app's ONE definition of blank BY FILE AND FUNCTION — `isAbsent` (src/lib/format.ts:247), for which a string is absent when `visibleContent(v) === "" || visibleContent(v) === EM_DASH`; the em dash is an absence in this app by construction, which is the whole reason `orDash`/`nullDash` exist (LESSONS 7). `refuse()` asks `hasVisibleContent` (src/lib/verdict/decision.ts:115) instead, which stops at the first clause. Seven inkless spellings ("", "   ", U+200B, U+00AD, U+3164, tab/newline, and the error arm's own blank message) ARE substituted correctly; the dash is the single input that is not.

THE BUILDER'S CALL WAS SOUND AND IS NOT WHAT NEEDS UNDOING (recorded at BUG-0176's close): `machine.ts` is a leaf and `src/lib/format.ts` imports React, so importing `isAbsent` there reddens tests/offline/db/layering.test.ts; `hasVisibleContent` is the leaf `isAbsent` itself delegates to, so no second predicate was invented (common violations row 15 is honoured). The uncovered input is the consequence, not the mistake.

THE OPEN QUESTION IS ARCHITECTURAL, so a builder should not improvise it: the leaf cannot see `EM_DASH` either (also src/lib/format.ts), and retyping the character is banned (LESSONS 4/5 — the fourth copy of a character class four M2 bugs are made of). Landing this needs a ruling on where the app's absence glyph lives — most plausibly beside `visibleContent` in the leaf (src/lib/verdict/decision.ts), with format.ts importing it — before `refuse()` can ask the whole question. Naming it here rather than guessing it.

REACHABILITY: identical to the class criterion 14 itself covers — this app's own routes never author a reason, so the input arrives only from a wire that misanswers (a proxy, a rewritten body, a future route). Low frequency, low impact: P3.

PIN: tests/offline/paging/machine.test.ts, 'words a reason the app itself calls an absence', written by QA and WATCHED RED against the landed code before this was filed (`AssertionError: "—": expected '—' to match /refus/i`), then held as `it.fails` so the run branch stays green. It carries its must-NOT-flag twin: a dash the answer wrote INSIDE words of its own stays the machine's, byte-identical. When the fix lands the case XPASSes — vitest reddens an `it.fails` that passes — and the builder flips `it.fails` back to `it` in the same diff.

## Acceptance criteria
1. **ONE spelling of the character, and it is in the leaf.** `export const EM_DASH = "—"` is declared in `src/lib/verdict/decision.ts` — the pure leaf that already owns `visibleContent`/`hasVisibleContent`, and that still imports NOTHING (ARCHITECTURE §4 rule 7; `tests/offline/db/layering.test.ts` stays green). `src/lib/format.ts` RE-EXPORTS that same binding instead of declaring its own, so every existing `import { EM_DASH } from "@/lib/format"` call site (15 of them, plus `tests/live/*`) is untouched and no lane in flight is disturbed. `src/components/edit-refusal.ts`'s `const DASH = "—"` (line 56, the second hand-spelling, measured 2026-09-11) is gone and asks for the one spelling instead. The constant's docstring states what it is — the app's ONE spelling of the CHARACTER, not a meaning: it is already the clause joiner in `error-line.tsx:48`, `paging.tsx:647/656` and the edit fix sentences, while "no value" is carried by `nullDash()` and by criterion 3's predicate (common violations row 18: one identifier, one meaning — so the identifier is named for the character it spells).

2. **A guard keeps it at one.** `tests/offline/verdict/decision.test.ts` grows a structural test beside the existing `factKey` one-spelling guard ("finds the join in src/ nowhere but factKey's own body") and reading through the same walker — `sourceFiles()` / `codeText()` in `tests/offline/source-tree.ts`, which strips comments, because the character appears in docstrings across the tree and prose is not a spelling. It asserts that a string literal whose WHOLE content is the em dash appears in exactly one file of the compiled source, `src/lib/verdict/decision.ts`, and exactly once in it. It carries both halves: a must-flag fixture in each quoting form this repo could write (`"—"`, `'—'`, backticked), and must-NOT-flag fixtures — a dash INSIDE an authored sentence is punctuation, not a spelling of the glyph (`title: "KPop Social Space — Admin"` in `src/app/layout.tsx:32` and the two composed sentences in `src/app/records/[table]/[id]/page.tsx:122-123` must stay unflagged, or the guard is unsatisfiable on the landed tree).

3. **The absence-of-text question lives in the leaf, and the two predicates agree BY CONSTRUCTION.** `src/lib/verdict/decision.ts` exports `isAbsentText(text: string): boolean` — true exactly when `visibleContent(text) === "" || visibleContent(text) === EM_DASH`. Its docstring states which question it owns (rule 7 ¶2's obligation on a leaf another leaf imports): "is this string one of the app's spellings of NO VALUE" — strictly wider than `hasVisibleContent`'s "is there any ink here", and the reason both exist. `isAbsent`'s string arm in `src/lib/format.ts` becomes that call and nothing else — one body, so the app cannot hold two answers — and neither file re-types the character or the `visibleContent(...) === EM_DASH` comparison.

4. **`hasVisibleContent` and its callers are left exactly as they are.** No caller anywhere is switched to `isAbsentText` except `refuse()` (criterion 5): not the two note guards in `decision.ts` (`present`/`decisionRefusals`), not `closeRefusal` (`components/review/close/actions.ts`), not `EditableCell.tsx`, not the PATCH route's blank check, not `lib/url/text.ts`, `lib/url/dropped-params.ts` or `lib/sources/names.ts`. The standing ruling in `lib/sources/names.ts:80` holds unchanged — a cell handed a LABEL asks `hasVisibleContent`, never the absence question, because a registry that NAMES a source `—` has a name. Widening the blank question to swallow the dash would change which verdicts the close form refuses and which labels render as nothing; that is a different ticket and is not this one.

5. **A refusal whose reason is the app's own absence glyph is worded by this app.** `refuse()` in `src/lib/paging/machine.ts` asks `isAbsentText(reason)` in place of `!hasVisibleContent(reason)`. Driven offline: `requestPage` against a stub answering `{kind:"refused", reason:"—", bound:"75"}` publishes `{condition:"broken", reason: WORDLESS_REFUSAL, reasonFrom:"this app", object:null}` — the same substitution `{"reason":""}` already gets, which is what BUG-0176 criterion 14 and copy bar 3 require. The file's import of the leaf stays ONE LINE (the closure guard in `tests/offline/db/layering.test.ts` reads imports line by line — a multi-line import reads as naming no module) and gains no second import; no `trim()`, no retyped character and no second predicate appears in `src/lib/paging/**`. `refuse()`'s docstring names the predicate it now asks and why the leaf can at last ask the WHOLE question rather than its first clause.

6. **The pin flips in the same diff, and its twin still holds.** `tests/offline/paging/machine.test.ts`'s `it.fails("words a reason the app itself calls an absence [admin-window/BUG-0184]", …)` becomes `it(…)`, with its four fixtures (`""`, `"   "`, `EM_DASH`, `` ` ${EM_DASH} ` ``) and its must-NOT-flag twin unchanged: an `error` arm whose message carries a dash INSIDE words of its own (`column events.badcol — does not exist`) still reaches the state byte-identical and `reasonFrom: "the machine"`. 7. **A fixture table proves the agreement, over both predicates.** `tests/offline/format.test.ts` drives ONE table of strings through `isAbsent` and `isAbsentText` and asserts the SAME verdict from each, in both directions: absent — `""`, `"   "`, `EM_DASH`, `" — "`, `"\u200b—\u200b"`, `"\u00ad"`, `"\u3164"`; present — `"—\u200b—"`, `"\u2800"`, `"0"`, `"no value"`, and `` `column events.badcol ${EM_DASH} does not exist` `` (the machine's own words, which must never be swallowed). The existing `isAbsent` cases stay: BUG-0089's and BUG-0085's fixtures are not thinned, renamed away or folded into this table.
