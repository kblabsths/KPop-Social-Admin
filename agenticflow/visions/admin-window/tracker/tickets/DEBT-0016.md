# newestFirst is exported twice over different key columns

## Description
`newestFirst` is declared in both `src/lib/db/verdict.ts` and `src/lib/db/cycles.ts`, over DIFFERENT key columns. The duplication is benign today — neither file imports the other's — and it is the same class DEBT-0010 opened and DEBT-0014 / DEBT-0015 closed one function at a time (`narrowedTo`, `isNarrowed`, `readPendingClaims`). ARCHITECTURE §11: contract vocabulary is the app's vocabulary, in code, and one name means one thing.

Two legal endings, and the ticket picks one on the evidence rather than assuming: either the two orderings are genuinely the same rule over a parameterised key column, in which case it is ONE exported thing with the column passed in; or they are two different rules, in which case each gets a name that says which order it is (LESSONS 4's principle — a predicate answering two questions gets one name per question).

Last known member of this class. Filed so the archive shows it was ruled on rather than missed.

## Acceptance criteria
The name `newestFirst` is exported at most once across src/, or each remaining declaration carries a name that states which ordering it is; grep proves the count. Every caller of both current declarations still orders identically, asserted by the existing tests of both modules. The layering test's twice-exported-name guard covers this name, on one input it must flag and one it must not.
