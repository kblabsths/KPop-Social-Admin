# Gauge cards: the figure card, the trend table and the distribution view

## Description
Module: `src/components/gauges/` — the presentation half of FEAT-0006. Authority: LOOK_AND_FEEL (Stat / gauge card, the data-table rule, the four mandatory states); spec section 5; ARCHITECTURE sections 4 and 7.

Three pure synchronous components, each taking the output shape of a `lib/gauges` aggregate function as plain props:

- `GaugeCard` — square, 1px border, surface fill, 12px padding: `micro` label, the `figure` number thousand-separated, at most one `data` line of sub-detail. Colour on the figure only when it carries a palette state.
- `TrendTable` — the data-table rule applied to a per-period or per-source series; no bespoke layout, no chart library.
- `Distribution` — an age/percentile distribution rendered as rows of label + `data` value; 'chart' here means the data-table rule and CSS bars built from tokens, **not a charting dependency** (none is allowed).

Each renders all four states from the `ui` primitives: loading, empty, **not provisioned** (gray, naming the missing table, never a zero that reads like data), error (one red `data` line naming what failed).

Out of scope: any data access (a component importing `lib/db` is a defect), any page, any new dependency.

## Acceptance criteria
Three components exist, are pure and synchronous, import nothing from `src/lib/db`, and render the four states through the `ui` primitives. Offline tests render each with a fixture aggregate output and with each of the four states and assert the emitted token classes and the presence of the named missing table in the not-provisioned case. No charting or UI dependency is added: no chart library name appears in `package.json`, and any dependency at all must first pass the supply-chain gate as a toolsmith DEP ticket against ALLOWED_DEPS.md — this ticket files none. (human-checkable) The cards match LOOK_AND_FEEL's gauge-card anatomy at the close-review screenshots.
