# Cycles & runs: BUG-0040's lead section broke the page's live parity oracle (4 live tests throw)

## Description
Landed on run/admin-window as 942768a (BUG-0040, commit 6cbf916). The page renders correctly in a browser; what is broken is the LIVE parity oracle that certifies it.

Expected: 'tests/live/cycles.live.test.ts:61' addresses the page's cycles surface positionally — const CYCLES = "section:nth-of-type(1)" — with the file's own comment at :58 stating 'The page's four surfaces, in the order src/app/cycles/page.tsx renders them'. 'stateOf' ('tests/live/parity.ts:213-231') requires that selector to match EXACTLY ONE surface and throws MarkupReadError otherwise.

Found: after 6cbf916 the selector matches TWO surfaces, so 4 of the 6 tests in cycles.live.test.ts throw
  MarkupReadError: 'section:nth-of-type(1)' matches 2 surfaces in this markup; a state is read of one surface, so the selector has to name one.
at cycles.live.test.ts:135 (via gradeSurface), :159, :189 and :217 (via stateOf). Measured 2026-09-03 on the landed tree.

Two changes in 6cbf916 each contribute one match:
 1. 'src/app/cycles/page.tsx:1192' inserts <LatestRun> — a new <Section> (:1117) that is now the page's FIRST top-level <section>, so it takes the address the cycles table used to hold.
 2. 'src/app/cycles/page.tsx:1245' wraps <AdapterRuns> in <div id={RUNS_ANCHOR}>. That div is a new parent, so the runs <section> becomes :nth-of-type(1) INSIDE it — a second element answering the same selector.

Also worth the builder's attention while repairing: 'cycles.live.test.ts:62-63' (HEALTH = section:nth-of-type(3), LATENCY = section:nth-of-type(4)) still grade the right two surfaces, but only by coincidence — the lead section added one top-level section (+1) while the div wrapper removed one (-1). Any further section change silently repoints them at the wrong surface. The runs half is unaffected: 'runs.live.test.ts' names its surface by the [data-surface="runs"] hook ('page.tsx:963') and passes 7/7; the LatestRun section carries no such hook.

Repro (from the repo root, staging names in .env; the live setup loads them):
  npm run test:live -- tests/live/cycles.live.test.ts
  => Test Files 1 failed (1); Tests 4 failed | 2 passed (6). Watched red 2026-09-03 15:29 on 942768a.

Why CI missed it: run.yaml ci_command runs 'npm test' (offline + isolated projects only), and BUG-0040's stored checks name only the two OFFLINE files — no path any of them drives reaches this oracle.

Fix direction is the builder's call: renumbering the positional constants is the one-liner, giving the lead section its own [data-surface] hook (and naming every surface by hook instead of position) is the repair that cannot break again. Do not weaken 'stateOf''s one-surface rule.

Not in scope: the separate, pre-existing failure in tests/live/residue.live.test.ts:112 ('operator does not exist: timestamp with time zone ~~* unknown' on groups.created_at) — that one is untouched by 6cbf916.
