# /queues ignores the source_id the Sources page links it with: another source's item renders as that source's review items

## Description
Walked 2026-09-09 on the walk instance (http://localhost:8771, STAGING, branch run/admin-window), cookie-authed, bundled chromium 151.

Steps from a clean start:
1. GET /sources. The registry row for **test_harness** carries a LINKS cell whose anchor `review items` points at `/queues?source_id=01a01808-8c6f-78aa-b7a7-b07ddb3b057a` (emitted by `queueItemsHref`, src/lib/sources/routes.ts:56).
2. Click it. URL becomes /queues?source_id=01a01808-8c6f-78aa-b7a7-b07ddb3b057a.
3. Observed: SIGNAL QUEUE renders `OPEN SIGNALS 1 / 1 high, 0 low / oldest 7d ago` and one row, "ticketmaster: records keep missing the creation bar at the stuck-record threshold", linking to /queues/01a06287-5b67-7d1f-b4a5-d90aa93cb01a. That item's review_items.source_id is 01a05782-8e7f-752c-ae60-3ce4c51962f6 (ticketmaster), not the test_harness id in the URL. Read directly on staging the same minute: review_items holds exactly 1 row (queue entity_link, status open, source_id 01a05782-...).
4. /queues?source_id=not-a-uuid renders the identical page: same single item, same counts.
5. Nothing says the parameter was dropped: zero elements carry data-empty, and the string "did not apply" occurs 0 times in the rendered text.

Expected: the queue narrows to the source the URL names (review_items.source_id exists and is populated), or the page states the parameter it did not apply, as /claims already does. Measured contrast on the same instance and minute: /claims?bucket=in_window renders "The URL carries bucket, which this page did not apply: nothing below is narrowed by it.", and /claims?source_id=01a05782-... narrows to "877 claims match these filters".

Observed effect: a source's own "review items" link presents another source's item as that source's. Spec F5 ("A source links to its review items and its runs") and spec section 4's entity-crossing navigation are the clauses at stake.

Deliberate at code level, not at operator level: queueItemsHref's docstring says "Queues does not offer this facet yet (its vocabulary is kind / queue / shape / status), and an unrecognised parameter there narrows nothing rather than erroring, so the link lands on the queues rather than anywhere broken until that facet is added (admin-window/TASK-0013's handoff)". The same class of problem on /cycles?source= was fixed by TASK-0016 with one sentence beside the table; the honest minimum here is the same sentence. Whether to add the facet or the line is the architect's call.

Evidence: agenticflow/tracker/evidence/M2/verifier/30-queues-source-not-narrowed.png and 27-queues-source-facet.png; run log agenticflow/tracker/notes/verify-M2-2026-09-09.md.

## Acceptance criteria
**Ruled 2026-09-09 (architect): option (a) — `/queues` gains the `source_id`
facet, AND the dropped-parameter line.** Spec F5 ("a source links to its review
items") is met by NARROWING, not by an apology: under (b) alone the anchor the
Sources page labels `review items` still lands on every source's items, and F5
is unmet at the verifier's own bar. `review_items.source_id` is a real,
populated column, this is the shape three surfaces already carry
(`/sources`, `/claims?source_id=`, `/cycles?source=`), and the line is required
either way — a `source_id` this page CANNOT use (`not-a-uuid`) must be named
rather than swallowed (BUG-0123's rule, TASK-0016's precedent).

1. **The facet is a filter field, not a page-local filter.**
   `ReviewItemFilter` (`src/lib/review/shapes.ts`) gains `source_id?: string`
   and `matchesFilter` compares it — the app's ONE predicate (spec §6,
   acceptance test 4). No `.filter(i => …)` anywhere else.

2. **Narrowed at the query and re-applied by the predicate**, exactly as
   `queue` and `status` are: `query()` in `src/lib/db/review-items.ts` adds
   `.eq("source_id", …)`, so a `review_items` table past `ROW_CAP` still
   answers a source URL COMPLETELY (ARCHITECTURE §4.3) instead of refusing,
   and the returned set is still decided by exactly one function.

3. **Chip vocabulary and narrowing vocabulary are two lists.** `FACETS` in
   `src/lib/review/queue-filters.ts` stays the CHIP vocabulary — the four with
   fixed `FACET_VALUES` — and a new exported `SOURCE_FACET = "source_id"`
   joins it in the set that drives `filterFrom`, `queuesHref` and `isNarrowed`.
   `/queues` reads no registry, so `source_id` offers NO chip row and
   `facetChips` / `filterBar` / `withFacet` / `FACET_VALUES` are untouched.
   `queuesHref` carries the source through every chip href and both tab hrefs:
   clicking `settled`, or the verdict-log tab, may not silently widen the page
   back to every source (LOOK_AND_FEEL bar 11 — the filter state survives).

4. **One uuid grammar, canonicalised once, at the edge.** A pure domain leaf
   may not import `lib/db/**` (§4 rule 7), so `filterFrom` takes the
   canonicaliser as an ARGUMENT — handed in, the way `claims/filters.ts` takes
   `FacetOptions` — and `src/app/queues/page.tsx` passes `canonicalRecordId`
   (`src/lib/db/records.ts`; BUG-0139/BUG-0140 own that one grammar). A second
   uuid pattern in the leaf is a defect. Called WITHOUT a canonicaliser,
   `filterFrom` reads no source facet at all — never an identity function — so
   an un-canonicalised id can reach the filter by no path, and the 32 existing
   `filterFrom(params)` call sites keep their present meaning.

5. **`narrowingOfKind` is unchanged and never carries a source.** No kind
   implies a source, so a `source_id` in the URL always counts as narrowing in
   `isNarrowed`, for both blocks.

6. **The population counts stay UNNARROWED by the source.** `readPopulation` /
   `countQuery` keep counting each shape's whole-table rows; the only
   requirement is that `narrows()` sees the new field so a source URL takes the
   population path. That is exactly what lets a source with no items render
   "nothing matched" rather than "this queue is empty" (BUG-0133), and the
   population leg still answers per kind beside the rows rather than refusing
   the whole read (BUG-0135, Common violations row 14).

7. **The scope is on screen and reversible.** With a source narrowing applied,
   `/queues` renders a scope element carrying `data-scope="source_id"` whose
   value is the id, spells that id VERBATIM in the mono/`type-data` treatment
   (a machine identifier), and links back to the same page and tab with the
   source narrowing removed and every other facet kept. The id it spells is the
   value `canonicalRecordId` RETURNED (`[0-9a-f-]{36}`) and never the raw
   parameter — which is how this new sentence satisfies Common violations
   row 15 (§7: text the app did not author reaches prose through an allowlist)
   without a second allowlist. The narrowing may NOT be visible only in the
   URL: `/queues` has no chip for it, so an unstated source scope is a page
   claiming a population its read did not cover. It renders from
   `src/components/queues/**`, not inline in the page (Common violations
   row 10). Its wording is the designer's, not this ticket's.

8. **The dropped-parameter line, with ONE owner — no copy.** `/queues` renders
   the same honest sentence `/claims` does, from the SAME code: the pure rule
   moves to a shared leaf `src/lib/url/dropped-params.ts` (`droppedParams`,
   `DroppedParams` — the blank test, the `^[A-Za-z0-9_.-]{1,64}$` renderable
   allowlist, the `named`/`withheld` split and the "APPLIED filter, not the
   vocabulary" rule all carried over intact, BUG-0123/0127/0136/0137), and the
   rendering moves to `src/components/ui/dropped-params.tsx` as
   `DroppedParamsLine`, exported from `src/components/ui/index.ts`.
   `src/lib/claims/filters.ts` re-exports the function so its callers and its
   two test files are untouched, and `/claims`' local component is deleted in
   favour of the shared one with its markup and hooks (`data-dropped-params`,
   `data-dropped-param`) unchanged — `tests/offline/claims/page.test.ts` pins
   that and must stay green without edits to its assertions. A second copy of
   this sentence is the defect Common violations row 9 promoted to a rule
   (§13.7): four blocklist patches landed on the one that exists, and a copy
   would be born with none of them. `/queues` passes an empty `neverNamed`
   (this route has no unrenderable word) and `tab` stays consumed, never
   dropped.

9. **The stale docstring goes.** `queueItemsHref` in `src/lib/sources/routes.ts`
   no longer says Queues "does not offer this facet yet"; it states the facet
   the link now uses. The link itself is unchanged.

**Pinned in `tests/offline/queues/page.test.ts`, four fixtures over
`reviewItemEdgePopulation()` (`tests/fixtures/rows.ts`), each asserting the
rendered ids and the `data-state` / `data-empty` of BOTH blocks:**

- **narrowed by a registered source** — `?source_id=<ID.sourceBandsintown>`
  renders exactly the four rows carrying it and no others, across both blocks
  (the source-pattern signals AND `EDGE_ID.dcOpenLowWithSource`, so neither
  block is hidden and neither leaks), each block's open sub-line naming its
  filtered scope;
- **an absent source renders the honest empty** —
  `?source_id=<ID.sourceTicketmaster>` (well-formed, registered, carried by no
  item) renders BOTH blocks empty in the `narrowing` / "nothing matched"
  rendering, never `NOTHING_IN_QUEUE`, and **renders no other source's row** —
  the defect this ticket was filed for;
- **a dropped unknown parameter is named** — e.g. `?record_id=<uuid>` renders
  the dropped-parameter line naming `record_id`, with the page otherwise
  unnarrowed;
- **`not-a-uuid` narrows nothing and is named** — `?source_id=not-a-uuid`
  renders the WHOLE population (no narrowing, no scope element) and names
  `source_id` in the dropped-parameter line; the page is never in an error
  state and no `22P02` reaches a read.

**Live (`tests/live/queues.live.test.ts`):** the oracle reads the state kind
from `data-state` BEFORE any number (Common violations row 6), and counts the
SAME narrowing the surface renders — its own `.eq("source_id", …)` on
`review_items` (row 7). A registered source with no items grades as `empty`
with 0, never as `error` and never as another source's row.

**Walk repro (the verifier's, unchanged):** from `/sources`, the
**test_harness** row's `review items` anchor
(`/queues?source_id=01a01808-8c6f-78aa-b7a7-b07ddb3b057a`) must render the
honest empty — staging's one `review_items` row belongs to `ticketmaster`
(`01a05782-8e7f-752c-ae60-3ce4c51962f6`), whose own link must render exactly
that one row. Evidence:
