# A source the registry NAMES "—" is rendered as an absence: the link is gone, the cell is labelled "no value", and the page explains a dash that stands for a name

## Description
Found attacking BUG-0154 on the landed tree (run/admin-window @ 94c4722, offline vitest + cheerio, no device, no network, 2026-09-09). BUG-0154 fixed the blank name; this is the same rule read by TWO predicates that disagree, and the disagreement is inside BUG-0154's own diff.

Expected (BUG-0154's own landed rules, and they contradict each other):
 1. `tests/offline/sources/names.test.ts` "leaves a name with any ink in it exactly as the registry wrote it" includes `"—"` with the reason spelled out: "An em dash is a character with INK, so it is a name and not an absence: `isAbsent`'s dash branch (`lib/format.ts`) recognises the string the app's OWN formatters return, and this value is a producer's. The app never invents a uuid for a label it can read." BUG-0154's own handoff states it as trap 1: "a name whose only ink is an em dash renders verbatim (content, not the app's dash)".
 2. Every claim leads to its SOURCE, one click (LOOK_AND_FEEL bar 10) — the harm BUG-0154 was filed on was an anchor with "nothing to read and nothing visible to click".
 3. `DASH_MEANS` is said "only while one is on screen" and says what a dash IS: "a value this row does not carry".

Found (measured on the review item page, `conflictScript` with `[T.sources]: {data:[sourceRow({source: "—"}), BANDSINTOWN]}`, item `data_conflict`): `sourceLabel` answers `"—"` verbatim (rule 1 holds at src/lib/sources/names.ts:88), and then the CELL swallows it. The row of CLAIM_A renders

  <span data-claim-source="">—</span>     (tag `span`, href undefined, `[aria-label="no value"]` count 1)

while the sibling row reads `bandsintown` in an anchor. So, on one page:
 - the operator's ONE route to that source is GONE — no `<a>` in the cell at all (`anchors in that td = 0`); before BUG-0154 this input rendered `<a href="/sources?source_id=…0101">—</a>`, a working link, so this is a REGRESSION of BUG-0154's diff on an input its own suite pins as content;
 - the cell's addressing hook is emptied: `data-claim-source=""` (evidence-cells.tsx:236 hardcodes `""`), though the comment beside it says the dash is drawn "inside the hook the suite addresses this cell by". `/claims` keeps `sourceId` there — the two cells do not even agree with each other;
 - the page then prints `[data-absence-note="dash"]` (count 1, measured 0 for every other name): "A — is a value this row does not carry: the claim states none, or the read that would name it did not answer." — a false sentence about a source whose name the app is holding;
 - the pair's two lines read `—` as well, so all three renderings converge on "this claim has no source".

Where it comes from — one question, two predicates (LESSONS 4: "a predicate answering two different questions gets widened by whichever one broke last, so give each question its own"):
 - `sourceLabel` (src/lib/sources/names.ts:88) asks `hasVisibleContent(name)` — "is there anything here a person could read" — and by that rule `"—"` is a NAME;
 - `sourceColumn` (src/components/review/evidence-cells.tsx:225 `value`, :233 `cell`) and `/claims`' source column (src/components/claims/claim-list.tsx:182) ask `isAbsent(row.source)`, whose dash branch (src/lib/format.ts:253, `visible === EM_DASH`) exists to recognise "the bare em dash a FORMATTING HELPER returns" (its own docstring: `count(null)`, `absoluteUtc(null)`, `relativeAge(null).text`) — a different question, asked here of a PRODUCER's value. By that rule the same string is an absence.
 One value, two verdicts (LESSONS 11). `sourceColumn.value` returning null is also what feeds `drawsDash`, which is why the false DASH_MEANS line appears.

Reach: one `sources` row named `—` (or `" — "`, or zero-widths + an em dash) — the same class of state BUG-0154 and BUG-0152 were filed and priced on, forbidden by the scraper's `CHECK (source ~ '^[a-z0-9_]+$')` and absent from staging (verified: no blank or dash-only name there). P3 for that reach; inside it the impact is BUG-0154's own, plus a page that now states an untruth.

Pins (landed on run/admin-window by qa-0154, `it.fails` while the divergence stands — THE FIX FLIPS BOTH TO PLAIN `it`), both watched RED first as plain `it` on this exact tree:
