# /cycles?cycle=<a real cycle id carrying the whitespace its paste brought> still denies a row the page is rendering, in an id that reads identically to it

## Description
Found attacking admin-window/BUG-0143 (which canonicalised `?cycle=` for case and hyphenation). Measured TWICE: offline against the fixture population, and over HTTP on a production build of run/admin-window at 621c4af against staging (`ubfjjqlvnpnoborczbdb`, port 8793, mine, killed after; 69 cycles in the window, `data-window-truncated="false"`).

Repro (over HTTP, exact) — cycle `01a066d7-6e69-7359-94e8-434dd3cb12fc` is row 3 of the window the page draws:

    GET /cycles?cycle=%2001a066d7-6e69-7359-94e8-434dd3cb12fc      (one leading space)

Expected: the answer the same page gives the same id with no padding — `data-cycle-found="true"`, one `tr[data-row-marked="true"]`, one `aria-current` (BUG-0143's criterion); or, failing that, the answer the page's OWN TWIN facet gives the identical input — `?run=%20<a real run id>%20` names `run` in the dropped-parameter line and passes no verdict (measured, same server, same minute).

Found: `data-cycle-found="false"`, 0 marked rows, 0 `aria-current`, 0 dropped params, and this sentence:

    Cycle 01a066d7-6e69-7359-94e8-434dd3cb12fc is not among the 200 newest cycles, so it is not in this window - it ran earlier, or no cycle carries that id.

while `[data-cycle="01a066d7-6e69-7359-94e8-434dd3cb12fc"]` is rendered three elements below and the window line on the same screen says the window did not fill (69 of at most 200). This is BUG-0143's own headline harm, still live - and WORSE than the uppercase case it fixed, because HTML collapses the padding: the denied id and the drawn row's id are character-for-character identical on screen, so the operator has nothing to see. `data-cycle-asked` carries the padding, the visible text does not.

Same result for a trailing space and for a trailing newline (`%0A`) - the shape a copy off a log line or a psql column actually has - and for a padded UPPERCASE spelling, which prints the paste's own casing back.

At src/app/cycles/page.tsx:219-221: `const askedRaw = firstValue(params[CYCLE_FACET]); const markedCycle = askedRaw === undefined ? null : canonicalRecordId(askedRaw); const askedFor = markedCycle ?? askedRaw;`. `canonicalRecordId` (src/lib/db/records.ts:167) is built on `RECORD_ID` (:109), which anchors `^...$` with no whitespace arm, so a padded id has no canonical form and falls to the raw branch - where `AskedCycle`'s absent arm passes a verdict on it.

TWO honest fixes; the builder should not guess:
(a) surrounding whitespace is part of the DERIVATION of a value from a request, so trim it where the value is derived - either at this page's edge or inside `canonicalRecordId` itself. Inside is the LESSONS-5 shape (one grammar, imported, not retyped per call site) but it moves `/sources`, `/queues` and the record routes too, which is an architect's call, not a builder's.
(b) leave the grammar alone and stop `?cycle=` passing a verdict on a value that has no canonical form - i.e. converge it with `?run=`, which reports the parameter as dropped. The BUG-0143 ticket explicitly declined that convergence as a design question; it is still one.

Whichever is chosen, the invariant below is the bar, and the three existing `?cycle=`-with-no-canonical-form cases in tests/offline/cycles/page.test.ts must be re-graded deliberately rather than deleted.

Related, NOT part of this ticket (residual for the designer/architect): `/cycles?cycle=` carrying an empty or whitespace-only value renders the same absent sentence with NO id in it at all - "Cycle  is not among the 200 newest cycles..." - while the sibling `?source=` facet two lines above deliberately earns no sentence for a blank value (src/app/cycles/page.tsx:224, `narrowedTo`).

## Acceptance criteria
The page never prints a not-in-this-window verdict naming an id whose row it is rendering. Concretely, on /cycles with a window that holds cycle C: for `?cycle=` carrying C with a leading space, a trailing space, a trailing newline, or padding plus uppercase, the page either (a) answers it as C - `data-cycle-found="true"`, exactly one `tr[data-row-marked="true"]`, that row's `aria-current`, and C printed in the database's own spelling - or (b) passes no verdict at all and names `cycle` in the dropped-parameter line, the way `?run=` answers the identical input today. What it may not do is render `data-cycle-found="false"` while `[data-cycle="C"]` is in the same document. Pinned by flipping the `it.fails` pin "never denies a row it is rendering, whatever the paste carried [admin-window/BUG-0145]" in tests/offline/cycles/page.test.ts back to a plain `it(...)`, with every other case in that file still green - including the three that grade a `?cycle=` with no canonical form, whose expectations may be UPDATED to the chosen answer but not removed.
