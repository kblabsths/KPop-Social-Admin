# STACK 5's interim walk-write branch names no runnable residue sweep, and points at groups/idols columns that sweep cannot see

## Description
Expected (agenticflow/docs/vision/STACK.md §5, step 3's interim branch, lines 303-307, landed cf728af): while the reset tool refuses, a save-path walk writes "one field of one existing `groups`/`idols` row: note the original value before you change it, restore it in a `finally` so a crashed walk still puts it back, and run the residue sweep afterwards." The restore-plus-sweep pair is what buys that catalog write its safety, so the sweep has to be (a) runnable by the walker and (b) able to see the value the walker was told to write.

Found, both halves false today:

(a) The sweep is named nowhere runnable. `grep -c residue agenticflow/docs/vision/STACK.md` = 1 — line 306, the words "the residue sweep", with no command, no file, no script. §5 is titled "The exact incantations" and its table carries rows for the walk instance, the production-like walk, the cookie mint and `node tests/walk/reset-sandbox.mts`, and no row for the sweep. The command exists only in a docblock a walker has no reason to open: tests/live/residue.live.test.ts:64, `npx vitest run --project=live tests/live/residue.live.test.ts`. Every other step of §5 is verbatim-runnable; this one is a noun.

(b) The sweep is blind to most of the columns the same sentence authorises. tests/live/residue.live.test.ts:73 `const CAMPAIGN_MARKER = "admin-window"`, and countMarked scans `ilike '%admin-window%'` over text columns only. Measured on staging 2026-09-04 by running the sweep (read-only, 5 tests passed, 7.0s):
  groups: "not scannable, ilike has no operator for their type: [... debut_date (date), member_count (integer) ...]"
  idols:  "not scannable ... [... birth_date (date), height_cm (smallint), weight_kg (smallint) ...]"
All five of those are in the `editable` list the doc's instruction points at (src/lib/edit/config.ts:140-150 for groups, :159-175 for idols), so "one field of one existing groups/idols row" permits them. And even on a text column the sweep only fires if the value the walker typed contains the literal "admin-window" — the doc never says to stamp the value, and the live suite's own writer does (tests/live/edit.live.test.ts:51, PROBE = "admin-window/TASK-0018 probe").

Consequence, reachable today: this IS the live branch — `node tests/walk/reset-sandbox.mts` through step 3's block exits 1 ("the table walk_sandbox is not on ubfjjqlvnpnoborczbdb.supabase.co"), and the sweep independently reports "walk_sandbox: not present". So the M1 endgame walkers (designer, user-sims, verifier) are under the catalog-row rule now. A walker that edits groups.member_count, or types "test" into groups.name, and dies before its `finally` leaves an unrestored value in a catalog table three repos share — and the doc's own safety net then reports "56 column(s) scanned ... clean". A false all-clear over real residue is worse than no sweep, because it is the thing the walker is told to trust.

Repro (exact):
  1. cd to the repo root on run/admin-window at 9e53936 or later.
  2. Read STACK.md §5 step 3, lines 303-307. Note it tells you to sweep, and look for the command in §5's incantation table and in the rest of the file: `grep -n residue agenticflow/docs/vision/STACK.md` returns exactly line 306.
  3. Run the sweep the only way it can be run: `npx vitest run --project=live tests/live/residue.live.test.ts`. Read its printed report: the "not scannable" list for groups and idols carries the editable columns above, and the scan string is "admin-window".
  4. Cross-read src/lib/edit/config.ts:140-150 — `member_count` and `debut_date` are editable, i.e. inside what step 3 authorises.

The bar for a close is both halves: §5 names the sweep's runnable command where the interim branch tells a walker to run it, AND the branch constrains the walk write so the sweep can actually see it (a sweepable text column, and a value carrying the campaign stamp) — or says plainly that the sweep cannot cover the other columns, so a walker knows the restore is the only net. The stored check below can only see the first half; the second is a judgment on re-attack.

Not filed as a failing test on purpose: the defect is in prose, and a test that graded wording would be the copy-oracle this factory bans. The check below is the same narrow-grep shape BUG-0071's and TASK-0036's own checks use; it is a POSITIVE grep, so it cannot pass vacuously on a broken path, and it is RED as filed (measured: `grep -qF "tests/live/residue.live.test.ts" agenticflow/docs/vision/STACK.md` exits 1 today).
