# build_judgments.md's M3 edition reports a closed lane as open: 'Not closed at this close' over three tickets done hours before it was written

## Description
The M3 edition of docs/build_judgments.md states, at the foot of entry 8 (docs/build_judgments.md:251-255):

  **Not closed at this close**: the last lane on this derivation —
  `DEBT-0020` → `BUG-0199` → `BUG-0196` (authorship is a fact the account
  carries, not a question a renderer asks) — is serial by the architect's ruling
  of 2026-09-11, truth before cosmetics, and an M3 P2 therefore waits on a
  `patch`-milestone ticket deliberately.

**Expected**: the file's own opening contract — 'Rewritten whole at each milestone close; this is the M3 edition, written 2026-09-11' and 'Nothing still open appears below as settled; the open questions … have their own section at the end' — makes every status claim in it a claim about the state AT the M3 close. Its inverse holds equally: nothing settled at the close may be presented as still open, because this file is the one a reviewer 'should read first' (line 13) while M3 EC12 is being graded.

**Found**: all three named tickets were `status: done` BEFORE the file was written, and so was the follow-on the lane produced:
  DEBT-0020  done 2026-09-11T16:28:12Z  (grep '→ done' agenticflow/tracker/tickets/DEBT-0020.md)
  BUG-0199   done 2026-09-11T16:28:24Z
  BUG-0196   done 2026-09-11T17:14:56Z  ← the 'M3 P2' the sentence says is waiting
  BUG-0200   done 2026-09-11T17:41:39Z  (filed off BUG-0196 by its QA, closed the same evening)
The file's commit is 0389ba2b, authored 2026-09-11T14:06:53-07:00 = 21:06:53Z (the builder claimed the ticket at 20:59:10Z) — between 3h52m and 4h39m AFTER the last of the three closed. Nothing in the lane was open when the sentence was written, and the whole lane including BUG-0200 is closed today.

**Where it came from** (not a carried-over error — it was authored fresh here): the sentence is M3.md:533's architect ruling of 2026-09-11 ~15:43, 'Consequence worth seeing: an M3 P2 now waits on a patch-milestone ticket', which was true when it was written. The M3 edition copied the consequence and added the heading 'Not closed at this close', which was false at that close. `git show 50dad3c7:docs/build_judgments.md | grep -n 'Not closed'` returns nothing: the M1 edition never carried it.

**Repro** (read-only, ~5 seconds, from the repo root):
  1. `sed -n '251,255p' docs/build_judgments.md` — reads the claim.
  2. `grep -h '→ done' agenticflow/tracker/tickets/DEBT-0020.md agenticflow/tracker/tickets/BUG-0199.md agenticflow/tracker/tickets/BUG-0196.md` — three closes, all 2026-09-11, all before 17:15Z.
  3. `git log -1 --format=%aI 0389ba2b` — 2026-09-11T14:06:53-07:00.

**Fix shape** (builder's call, one paragraph; the rest of the entry is accurate and verified): state the lane's real disposition at the close — DEBT-0020 / BUG-0199 / BUG-0196 / BUG-0200 all landed and closed on 2026-09-11, the serial ordering ('truth before cosmetics', architect, BUG-0196 history 2026-09-11T15:43:26Z) held and the wait was short exactly as M3.md predicted. Do NOT simply delete the paragraph and do not restate any OTHER lane as open unless its tickets really are: BUG-0210 (M3 P2, claimed) is open on src/lib/db/result.ts right now and a correct sentence may name it.

**Second, minor, same entry — no check, judge it on re-check**: entry 8's first sentence names the derivation '(`errorMessage`, `src/lib/db/result.ts`)'. That symbol no longer exists: BUG-0196 renamed it, and `grep -n 'function errorAccount' src/lib/db/result.ts` is line 732, whose first comment line reads 'Until admin-window/BUG-0196 this function was `errorMessage`'. No pin on this: the same staleness is pre-existing in the product's own comments and is out of this ticket's scope; correcting the doc's one citation to `errorAccount` is the whole of what is asked here.
