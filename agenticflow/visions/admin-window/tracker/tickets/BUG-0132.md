# Four evidence cells render a blank where the app's dash belongs, so one page shows an absent tier two ways

## Description
Found while attacking BUG-0130 (QA, 2026-09-09) on the landed tree (run/admin-window @ 11f2367), offline, `renderToStaticMarkup` of the review-item page. The lede BUG-0130 fixed now follows the block; the CELLS inside that block do not follow the app's absence rule.

**Expected** — three statements of one rule, all already written down:
- `Column.cell`, src/components/ui/data-table.tsx:47-52: "Anything absent — `null`, a falsy `flag && ...` body, an empty string, or the em dash a formatting helper returns — renders as the dash in disabled-gray; the cell never decides that itself (`isAbsent` in src/lib/format.ts, admin-window/BUG-0004)."
- ARCHITECTURE.md §6 trap 5, restated at src/components/review/shape-views.tsx:245-252: "A tier this app could not read is the app's own dash, not a blank and not a guessed tier."
- `recordColumn`'s own doc, src/components/review/evidence-cells.tsx:172-173: "`null`, so `DataTable`'s own `orDash` draws the app's one dash. An absence is rendered, never blanked."

**Found** — `valueColumn` (evidence-cells.tsx:94), `tierColumn` (:119), `payloadColumn` (:147) and `heldColumn` (:154) each return a `<span data-...>` ELEMENT wrapping the possibly-null value. `isAbsent` (src/lib/format.ts:247-257) has no branch for a React element and falls through to `return false`, so `orDash` (data-table.tsx:171) never fires and the cell renders EMPTY. `recordColumn` returns `null` instead and is the one column that gets this right — and it is the one column a test grades ("renders the table's dash for a folded record it can name no way at all", page.test.ts:1076).

Row cells transcribed verbatim from the render, `entity_link` fact item, the row of `01920000-0000-7000-8000-000000000201` (columns: value, source, tier now, observed, held by, payload):

1. `sources` registry unreadable — `stuckScript({ [T.sources]: { error: tableNotInSchemaCache(T.sources) } })`:
   `["TWICE World Tour", "01920000-0000-7000-8000-000000000102", "", "8d ago", "awaiting_row: at least one linked performer", "bandsintown/2026-08-31/forum.json"]`
   The "tier now" cell is `""`. The SAME absent tier renders as `—` in the evidence pair immediately above it (shape-views.tsx:250, `tier: row.tier ?? EM_DASH`), so one page shows one absence two ways: pair text `"... 01920000-0000-7000-8000-000000000102 · — · 8d ago"`, table cell blank.
2. a claim with `value` null and `payload_ref` null:
   `["", "bandsintown", "standard", "8d ago", "awaiting_row: at least one linked performer", ""]` — two blank cells. `EvidenceRow.value`'s own doc (evidence-cells.tsx:36-37) promises "`null` is a real absence and renders as the app's dash".
3. `pending_claims` refused — `stuckScript({ [T.pendingClaims]: { error: tableNotInSchemaCache(T.pendingClaims) } })`:
   `["TWICE World Tour", "bandsintown", "standard", "8d ago", "", "bandsintown/2026-08-31/forum.json"]` — the "held by" cell is `""`, under a lede that says the table holds the claims "with what each one is waiting for".

All three are states the page already handles deliberately elsewhere (BUG-0021 keeps the rows when the registry refuses; the page renders a separate `StateOf` for a refused bucket read), so none of this is a hypothetical.
