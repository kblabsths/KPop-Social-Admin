# The state contract, typed: ErrorLine names its read, a state card keeps its eyebrow, no headers-only table

## Description
Module: `src/components/ui` + `src/components/gauges` — the presentation contract four unwritten page tickets code against. **No page behaviour changes and no data layer is touched.** Authority: ARCHITECTURE §7 (amended 2026-09-02, three new rules), DECISIONS 2026-09-02 ("the four data-surface states are a TYPED contract"), LOOK_AND_FEEL "the four states, mandatory on every data surface" + Voice bar 4, and the residuals QA left on BUG-0016 and on TASK-0007/0008 that neither QA nor the builder would decide.

Three changes, all in the same direction: what the operator must be told becomes a REQUIRED prop instead of a caller remembering.

**1. `ErrorLine.reading` becomes required — and so does `GaugeState`'s error `reading`.**
Today it is `reading?: string` (`src/components/ui/error-line.tsx:22`, `src/components/gauges/state.tsx:25`), so a page rendering `result.message` without naming the read type-checks. That is BUG-0016's exact defect, left catchable only by review. `DbResult`'s error arm has carried `reading: string` since BUG-0016 (`src/lib/db/result.ts:14`), so every real caller already has the string to pass — the landed ones do (`src/app/browse/page.tsx:58,100`, `src/app/records/[table]/[id]/page.tsx:104`). Make both required; the rendering itself is unchanged for a caller that passed it. The three test call sites that omit it (`tests/offline/ui/primitives.test.ts:254,282`, `tests/offline/ui/tokens.test.ts:74`) get the read they are about; do not add an `?? ""` anywhere to keep them compiling.

**2. `Empty` and `NotProvisioned` take an optional `micro` eyebrow, and every gauge component passes its own label.**
`GaugeStateCard` replaces the WHOLE card for `empty` / `not_provisioned` (`stateReplacesSurface`, `state.tsx:47`), so today an operator facing a screen of unprovisioned gauges is told which tables are missing but not which knob each one tunes — the label is the only thing that says "cycle health" rather than "resolution latency". Add `eyebrow?: string` to both primitives, rendered as the `micro` label above the existing message (LOOK_AND_FEEL: `micro` is "the eyebrow label above a value"; same position it holds on `StatCard`). Then thread it: `GaugeStateCard` takes the label as a required prop, and `GaugeCard`, `TrendTable` and `Distribution` each pass the `label` they already require. It stays OPTIONAL on the primitive itself because a page renders `Empty`/`NotProvisioned` under a `Section` heading that already names the surface, and requiring it there would churn landed correct code for no operator gain — and there is no forgettable caller on the gauge path, where it comes from a prop the component already demands.

**3. `TrendTable` and `Distribution` take a REQUIRED `empty: { holds: string; filledBy: string }` and render it themselves.**
Today `rows: []` with no `state` reaches `DataTable` with no `placeholder` and renders a header row over an empty `<tbody>` — headers and nothing else, the one rendering that tells the operator nothing at all (`data-table.tsx:129`). The ruling on "who owns the empty state": **the component owns WHEN, the caller owns THE WORDS.** The component cannot invent "no cycles have run in this window" and Voice bar 4 forbids a bare "No data"; the caller cannot be trusted to remember a case it will not see in its fixtures. So: the prop is required, and when `state` is undefined and `rows.length === 0` the component renders `<Empty holds filledBy eyebrow={label} />` in place of the table — the same surface-card rule `stateReplacesSurface` already states. An explicit `state` still wins, so a page that knows the surface is empty for a REASON (a filter that matched nothing) may still pass its own empty state.

Boundaries.
- `GaugeCard` is unaffected by (3): a figure card has no rows. Its only change is passing `label` to `GaugeStateCard`.
- **Do not** change `DataTable`: its `placeholder` contract is correct and the two-borders rule that produced it stands.
- **Do not** touch `lib/db/**`, `lib/gauges/**` or any page's reads. No aggregate changes shape.
- If a landed page already mounts `TrendTable` or `Distribution` (none does today — grep), adding its `empty` words at that call site is in scope and nothing else under `src/app` is.
- BUG-0019 is a dependency because it edits `gauge-card.tsx` and `cards.test.ts` — the same destinations. It lands first; do not fold its fix in here, and do not undo it (`isAbsent` decides the reason, not `??`).

## Acceptance criteria
Offline tests prove all three, at the type level where the type can carry it. (1) `ErrorLine` and `GaugeState`'s error arm require `reading`: every existing call site names its read, and no `?? ""` or empty-string default was added to keep a caller compiling. (2) `Empty` and `NotProvisioned` render the eyebrow as a `micro` label when given one and are unchanged without it; a gauge in the `empty` and in the `not_provisioned` state renders its own label — asserted for all three gauge components, since that label is the only thing identifying which gauge is missing. (3) `TrendTable` and `Distribution` with `rows: []` and no `state` render the `Empty` card carrying the caller's words and the gauge's eyebrow, and emit NO `<thead>`-only table; a passed `state` still wins over the empty case; `rows: []` without `empty` does not type-check. Tokens and primitives only, no raw values, no new dependency (LOOK_AND_FEEL, ARCHITECTURE §7).
