# '0 ran longer than the 15m cadence' stands bare beside four cycles that never finished — the Zeroes bar, on the card the doc quotes

## Description
Measured on the M2 endgame walk, 2026-09-09, on `/cycles` at 1440x900.

**Expected** — LOOK_AND_FEEL, Interaction principles, Zeroes: "a zero states what it excludes whenever the excluded set is not empty — **'0 of 65 finished cycles ran longer than the cadence; 4 never finished'** — and never stands bare beside the rows it silently drops. The line names the excluded set and how many rows are in it; whether the figure is good news stays the operator's call, never the app's." The bar quotes the sim who earned it: "'0 ran long' sitting next to four corpses is the sort of reassuring sentence I've been burned by before."

**Found** — the Cycle health gauge's first card, verbatim on screen today:

    CYCLES IN THIS WINDOW
    69
    0 ran longer than the 15m cadence

and, in the same window, the outcome distribution below it reads `died  4`, and the note under the duration percentiles reads "4 of these cycles recorded no end, so they are counted as unmeasurable rather than as a duration of zero."

So the excluded set is four cycles, it is not empty, the page knows its size, and the zero does not name it. The doc's example sentence — "0 of 65 finished cycles ran longer than the cadence; 4 never finished" — is this exact card with this exact data: 69 in the window, 65 with a measurable duration, 4 without.

The qualification exists but is ~500px lower, under a different table, after three other cards. A reader who takes the card at face value reads "nothing ran long" from a figure computed over 65 of 69 rows.

`src/components/cycles/cycle-health.tsx:102` builds the line as a bare template — `` sub={`${count(health.overCadence)} ran longer than the ${cadence} cadence`} `` — with no reference to `health.unmeasurable`, which the same object already carries (the note below it renders from that count).

TASK-0038 wrote this bar into LOOK_AND_FEEL on 2026-09-09 and changed no `src/` file; nothing has built it since. It is the sibling of the palette bar filed as BUG-0106 — both were written for the endgame to enforce.

**Swept for others, and there is only this one.** Every other zero on the six pages already names its set or has an empty excluded set: `WRITES / 1,710 applied, 0 escalated, 49 created`; `RE-REJECTED CLAIMS 0 / Values a human already adjudicated out, pushed again`; `SOURCES RE-PUSHING ADJUDICATED VALUES 0 / of 0 with any claim adjudicated in this window`; `data_conflict FOLDED 0 / of 0 items read here, 0 folds in all`; `UNSET BY A HUMAN DECISION 0 / Decisions that name no claim, so they carry no wait to measure`; `/claims`'s zero buckets, whose table note says "A bucket with no claims is a real zero."

Provenance checked before filing: `git log src/components/cycles/cycle-health.tsx` returns one ticket-bearing commit (0543d42, DEBT-0004). No human-lane divergence; violation, not reconciliation.

Evidence: `agenticflow/tracker/evidence/M2/designer/cycles-light-1440.png`.

**Sibling note (BUG-0106, BUG-0109).** All three are `/cycles` findings from this walk and none shares a component. BUG-0106 is the **outcome badge's colour** in the Cycles table (`cycles/outcome.tsx`); BUG-0109 is the **window paragraph above** each table (`ui/window-line.tsx`); this one is the **sub-line of one gauge card** below them (`cycles/cycle-health.tsx`). The overlap is the test file `tests/offline/cycles/page.test.ts`, which all three extend in different places. Land in any order.

## Acceptance criteria
1. The Cycles-in-window card's sub-line names the excluded set and its size whenever that set is non-empty. On today's staging window it reads in the doc's own form — "0 of 65 finished cycles ran longer than the 15m cadence; 4 never finished" — rather than "0 ran longer than the 15m cadence".
2. When the excluded set **is** empty (every cycle in the window recorded an end), the line stays as it is now: no "0 never finished" clause is added to say nothing.
3. The line says what is excluded and how many; it does not say whether the figure is good news. No "healthy", no "all clear", no reassurance — the operator's call, per the bar.
4. The count of unfinished cycles in this line is the **same** number the outcome distribution's `died` row and the duration note already render, from the one read — the page cannot show three counts of one set.
5. The figure itself is unchanged (`69`), stays at the `figure` step in mono, and the sub-line stays one `data` line of sub-detail on the stat card (the card rule permits exactly one).
6. Human-check: on `/cycles` at 1440x900, reading only the Cycle health card row and nothing below it, it is clear that four cycles are outside the "ran longer than the cadence" figure. (human-checkable)
7. `npm run lint` and `tsc --noEmit` clean; the targeted offline files green; the cycles live suite green.
