# lib/db/verdict.ts: the one call site of settle_review_item, the readiness read, and the M2 guard inversion

## Description
**Module**: `src/lib/db/verdict.ts` — NEW, and the ONLY place in `src/` that ever calls `.rpc()`. Seeded before every surface that needs it because builders in isolated worktrees cannot see each other's code (§13.7); four pages hand-copying a readiness probe is common violation 9 happening again.

**Interface contract:**

    import type { VerdictDecision } from "@/lib/verdict/decision";

    /** The row the function returns, as this app reads it. */
    export interface VerdictReceipt {
      readonly verdict_id: string;
      readonly review_item_id: string | null;
      readonly action: string;
      readonly observation_id: string | null;
      readonly created_at: string;
    }

    /** THE one call. Returns DbResult and never throws (ARCHITECTURE §4.1). */
    export function settleReviewItem(
      client: DbClient, decision: VerdictDecision,
    ): Promise<DbResult<VerdictReceipt>>;

    /**
     * May a surface offer a settlement or an override at all?
     * `ok` -> yes; `not_provisioned` (missing: "verdicts") -> no, render the card.
     */
    export function readSettlementReadiness(
      client: DbClient,
    ): Promise<DbResult<"ready">>;

**How readiness is decided, and why it is not a probe call** (ARCHITECTURE §9.2, DECISIONS 2026-09-08). PostgREST cannot introspect a function without calling it, and calling `settle_review_item` to find out whether it exists is a write attempt dressed as a probe. So `readSettlementReadiness` reads the presence of the **`verdicts` TABLE** — a `head: true` count on `T.verdicts` — and nothing else. It is honest because the two migrations install together and the function's artifact writes the table it depends on, so "table present, function absent" is a state the handoff cannot produce; and if it arrives anyway, `settleReviewItem` returns `not_provisioned` naming `settle_review_item` and the same card is drawn after the click. **Both paths ship. Both are tested.**

**`decisionRefusals` is called before the RPC**, and a refused decision never reaches the database: the seam returns an `error` result carrying the refusal, so a malformed payload is a named refusal rather than a Postgres exception.

**The M2 guard inversion — this ticket owns it, and no other may touch these two files.** Two structural guards were authored in M1 to forbid exactly what M2 now builds, and they will redden every subsequent ticket if they are not turned here, once:
- `tests/offline/edit/config.test.ts` ("the write surface of the whole repo"): today it asserts no `.rpc(` anywhere and `settle_review_item` nowhere. It becomes: **`.rpc(` appears in `src/lib/db/verdict.ts` and nowhere else**, and `settle_review_item` is spelled in `src/lib/db/verdict.ts` and `src/lib/db/tables.ts` alone.
- `tests/offline/review/one-place.test.ts` ("nothing is scaffolded toward the M2 close"): the M2-close pin becomes the M2 pin — a `verdicts` read and a settle route are now expected, so the assertion becomes **one call site**, not none. Keep its self-proving probe tree (the `tests/.probes/` mirror) and its two fixtures: an input it must flag (a second `.rpc(` in a page) and one it must not (the sanctioned call in the seam).
- Ban the WRITE, never the word (§10, common violation 4): `verdict`, `settled` and `override` are the domain's own vocabulary and no guard may key on them.

**`lib/db/tables.ts`** already carries `verdicts`. Add the function name there too if and only if it needs one spelling — the not-provisioned card must name the same string the call used (§4 rule 4).

**The absence is the normal case and is graded FIRST.** `verdicts` and `settle_review_item` do not exist on staging and will not until Ben installs the handoffs — that is the database `main` deploys against for the whole of M2. Build and grade the not-provisioned path before the happy path.

**No Admin-side workaround for the absent function may be written** — spec §10's one forbidden move, this campaign's brightest line: no queued write, no "pending overrides" table, no retry buffer, no flag-guarded direct write, no second path "until Ben installs it". The surface degrades to what M1 already ships.
