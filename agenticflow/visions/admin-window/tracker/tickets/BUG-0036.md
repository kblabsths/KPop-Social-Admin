# stateOf's excluding filter drops a surface's OWN error card, grading an ERROR surface as ok

## Description
Module: tests/live/parity.ts, stateOf's card scan at :232 (`$(element).closest(excluding).length === 0`), reached from gradeSurface:701 via SurfaceGrade.excluding. Authority: ARCHITECTURE §10 rule 6 (an error is a FAIL) and stateOf's own docstring, parity.ts:199-207 — 'excluding names SUB-SURFACES INSIDE within' and 'A block can never say ok while rendering an error line'.

cheerio's closest() starts at the card itself and walks EVERY ancestor — the graded surface and the page wrapping it included — so the filter is not bounded to sub-surfaces inside `within`. An `excluding` selector that also matches the surface itself (or any ancestor of it) drops every card the surface holds, the ErrorLine among them, and dominantKind([]) answers 'ok'.

REPRO (offline, markup rendered from the real ErrorLine primitive):

    const broken = `<div data-surface="q">${errorLine()}</div>`;
    stateOf(broken, '[data-surface]')                    // 'error'  — correct
    stateOf(broken, '[data-surface]', '[data-surface]')  // 'ok'     — the defect
    assertState(broken, '[data-surface]', 'ok')          // returns; nothing thrown

Expected: 'error' — rule 6 is unconditional and the surface carries an ErrorLine; an exclusion may only silence a card belonging to a PROPER DESCENDANT sub-surface of `within`.
Found: 'ok', and assertState/gradeSurface grade the surface green. Measured 2026-09-02 on run/admin-window 3fdc924: 'AssertionError: expected \'ok\' to be \'error\''.

Reachability, stated honestly: no live test triggers it today — the one caller of `excluding` is tests/live/review-item.live.test.ts:102 (`within: [data-evidence-view]`, `excluding: [data-dial]`), which do not overlap. It is a defect in the SEAM, the same class and the same function as admin-window/BUG-0035, and the trigger is one selector: a test that grades `[data-surface="claims"]` while excluding the generic `[data-surface]` (or any wrapper selector matching an ancestor) makes its own oracle permanently vacuous with no red anywhere. USER-VISIBLE PATH: this classifier is the only staging-facing grade in the campaign; a surface it grades 'ok' while the page rendered an error line is exactly the four vacuous /claims passes admin-window/TASK-0032 was opened to remove — a broken page ships green.

Not to be fixed by dropping `excluding`: review-item needs it. Suggested shape (architect's call): confine the exclusion to elements strictly inside `within` — e.g. exclude a card only when an ancestor matching `excluding` is itself a proper descendant of the surface — and/or refuse (MarkupReadError) when `excluding` matches the surface itself.
