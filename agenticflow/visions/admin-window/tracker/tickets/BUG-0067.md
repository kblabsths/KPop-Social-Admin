# Cycles: the cycles window line renders in every state — data-window="cycles" over a table it could not read

## Description
Found while attacking admin-window/BUG-0063 (the same defect on /claims) on run/admin-window at fd09885. BUG-0063's builder reported it and left it out of scope (src/app/cycles/page.tsx is outside that ticket's touch_scope); this ticket carries it so the /runs form becomes the rule on all three surfaces.

Expected: the window line describes a window the page actually read. `/runs` states the rule in its own comment and honours it (src/app/cycles/page.tsx:1036-1050, `runs.kind === "ok" ? <p data-window="runs" .../> : null`), pinned by tests/offline/runs/page.test.ts "claims no window it never read"; `/claims` was moved onto the same form by BUG-0063 (src/app/claims/page.tsx:564). ARCHITECTURE.md: "a null count is a refusal, never a zero"; LOOK_AND_FEEL states 3-4 forbid a failed or absent read rendering as a confident figure.

Found: src/app/cycles/page.tsx:1283-1296 renders the cycles window line OUTSIDE every state branch, so it renders on a refused, absent and transport-failed read alike, publishing `data-window="cycles"`, `data-window-limit="200"` and a confidently-false `data-window-truncated="false"` about a read that returned nothing, above the prose "a window of at most 200, not a count of the cycles that exist" — over a table it could not read. `data-window-truncated` is computed `cycles.kind === "ok" && cycles.data.truncated`, so the non-ok read is folded into "false" rather than into absence.

REPRO A (offline, deterministic, no database):
  npx vitest run --project=offline tests/offline/cycles/page.test.ts -t "claims no cycles window it never read"
Landed as a strict `it.fails` xfail (this repo's idiom, cf. tests/offline/claims/page.test.ts "claims no count it never took"), so it is GREEN while the divergence lives and reddens the day it is fixed. It drives all three failures (refused / absent / transport) and asserts `[data-window="cycles"]` is absent while the refusal stays on screen. Seen red first as a plain `it(...)` against fd09885: "refused: expected LoadedCheerio{ ... } to have a length of +0 but got 1" at tests/offline/cycles/page.test.ts:981.

REPRO B (delivered HTML, production build, no database needed):
  1. git worktree add --detach <dir> fd09885; symlink node_modules and .env in
  2. npm run build in that worktree
  3. python3 agenticflow/tracker/evidence/BUG-0059/stub_postgrest.py (a stub PostgREST; write "error", "absent" or "column" into its mode.txt)
  4. SUPABASE_URL=http://127.0.0.1:<stub-port> SUPABASE_SERVICE_ROLE_KEY=stub AUTH_SECRET=qa-probe-placeholder-not-a-credential npm run start -- --port <free port>
  5. GET /cycles with a NextAuth cookie minted against that same AUTH_SECRET
Measured at fd09885, all three database moods, one request each:
  mode=error  (500)      GET /cycles = 200, 24301 bytes, data-window="cycles" x1, data-window-truncated="false", 5 refusal cards, resolution_runs named 8x
  mode=absent (PGRST205) GET /cycles = 200, 17398 bytes, data-window="cycles" x1, data-window-truncated="false", 5 refusal cards
  mode=column (PGRST204) GET /cycles = 200, 17573 bytes, data-window="cycles" x1, data-window-truncated="false", 5 refusal cards
The exact element delivered on mode=error:
  <p data-window="cycles" data-window-limit="200" data-window-truncated="false" class="type-body text-ink-secondary">The resolver's newest cycles, newest first - a window of at most 200, not a count of the cycles that exist.</p>
Positive control in the same three responses: data-window="runs" x0, data-window="cycle_health" x0, data-window="resolution_latency" x0 — every OTHER window on this page already drops correctly, so `cycles` is 1-of-4 diverging on its own route, not 2-to-1 across the app. On an ok read (mode=empty, and against staging) all four windows are present, which is the behaviour to keep.
Same server, same moods, /claims and /claims?tab=standing: 0 occurrences of any data-window* hook. That contrast is the fix this ticket asks for.

FIX: the /runs form, one clause — wrap the <p> in `cycles.kind === "ok" ? ... : null`, exactly as src/app/cycles/page.tsx:1036 already does for runs. An EMPTY window is still a window and must keep its line (the page looked, and nothing was there); tests/offline/cycles/page.test.ts "still states the cycles window on a read that happened, empty or not" is a plain passing `it` grading that direction, so the fix may not be "drop the line whenever rows are 0". Flip the `it.fails` back to a plain `it(...)` in the same commit.

Not a regression of BUG-0063: /claims is clean on every mood and both tabs (verified above). This is the pre-existing third surface.
