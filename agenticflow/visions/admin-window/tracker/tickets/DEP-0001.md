# Test runner: vitest + vite-tsconfig-paths

## Description
The repo ships no test framework (ALLOWED_DEPS.md, 'Product shape, for the record'), and acceptance test 1 requires a campaign test suite that is offline by default with staging tests behind an explicit live marker. STACK.md section 4 chooses **Vitest**.

Requested, dev-dependencies only:

- `vitest` (latest 3.x) — the runner. One of the four Next.js documents itself (`node_modules/next/dist/docs/01-app/02-guides/testing/vitest.md`, read 2026-09-01); runs TypeScript/ESM natively and needs one config file. Jest would additionally need `next/jest`, transform config and CJS/ESM mediation for the same result.
- `vite-tsconfig-paths` — so tests resolve this repo's `@/*` alias from `tsconfig.json` instead of hand-written relative paths (ARCHITECTURE section 1.2 bans `../` entirely).

**Deliberately NOT requested** — do not add them: jsdom, @testing-library/*, @vitejs/plugin-react, Playwright, Cypress, any UI kit, any ORM, any Postgres driver. Next's own guide says Vitest cannot render async Server Components; this campaign's answer is architectural (ARCHITECTURE section 5: the page function is the only async component, so a test renders it with `react-dom/server`, already a dependency). Browser screenshots are the walk agent's kit-owned Playwright, not a product dependency.

Install target: `devDependencies` in this repo only. Nothing is installed until this ticket lands the entries in `agenticflow/docs/ALLOWED_DEPS.md`.

## Acceptance criteria
`agenticflow/docs/ALLOWED_DEPS.md` carries a vetted (not grandfathered) entry for `vitest` and `vite-tsconfig-paths`, each with its version range, purpose, date and this DEP id. Identity, health and install-script posture are checked as normal — the intake note records that only two packages in the current 472-package tree carry install scripts, so a new install-script package arriving with these is a finding to state. No other package is added.
