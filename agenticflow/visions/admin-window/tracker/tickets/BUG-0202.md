# /browse discards a cols value that names no column, and every other parameter, in silence

## Description
Filed from the M3 user-sim walk of Tomas Berg (`agenticflow/tracker/for-human/M3-usersim-tomas.md`), 2026-09-11:

> "On **Browse**, the same games get nothing. `?cols=banana` renders all seven columns and says nothing. `?cols=` renders all seven columns and says nothing. `?table=venues` and `?q=BTS` are swallowed without a word. If I hand-edit a Browse URL and fat-finger a column name, I get the default view and no indication that what I asked for was discarded."

He shares a column view by URL — *"the column chips … survive in the URL so I can share the view"* — which is exactly the path on which a discarded `cols` matters: the recipient sees a different view from the sender's and nothing says so.

**Expected** — the same rule and the same module as the sibling ticket on `/sources`: `src/lib/url/dropped-params.ts`, authored for every route (BUG-0141) out of `/claims`' original (BUG-0123), rendered by `DroppedParamsLine`. LOOK_AND_FEEL bar 13 and the Look's *"no screen claims a mark it did not draw"*.

**Found** — `/browse` reads exactly one key and looks at no other: `const shown = shownColumns(view, params[COLUMNS_PARAM])` (`src/app/browse/page.tsx:124`, `COLUMNS_PARAM = "cols"`). `shownColumns` (`src/lib/browse/views.ts:154-170`) keeps only tokens that name a configured column and, when none does, silently returns the view's default set. `grep -rn "DroppedParamsLine\|droppedParams" src` returns three routes and `/browse` is not one of them.

**Deliberately NOT in this ticket: the partial case.** `?cols=title,banana` applied `title` and dropped one token. The shared rule's vocabulary is per KEY, not per token, and a token-level sentence would be a new kind of sentence on one page — the exact thing BUG-0141 moved the module to prevent. `cols` counts as applied when at least one of its tokens named a column; the fat-fingered token inside an otherwise-good list stays silent, on purpose, and that is recorded here rather than left for the next walker to re-find.

Provenance checked before filing: `git log src/app/browse/page.tsx` returns ticket-bearing commits only (BUG-0178, FEAT-0015, TASK-0068, BUG-0070 …). Not a human-lane divergence.

Sibling: BUG-0201 (`/sources`), same rule, disjoint files.

## Acceptance criteria
1. `/browse` names a parameter it did not apply, through the shared rule: the page calls `droppedParams` from `@/lib/url/dropped-params` and renders `DroppedParamsLine`. No second definition of the sentence.
2. `cols` is reported as APPLIED when at least one token it carried named a configured column, and as DROPPED when none did: `?cols=banana` and `?cols=nope,alsonope` are named; `?cols=title` and `?cols=title,banana` are not; `?cols=` (no value) is named by nobody, as the module already rules.
3. Every other key the URL carries — `?table=venues`, `?q=BTS`, anything — is named by the same line, verbatim in mono, under the module's existing allowlist and blank rules.
4. Nothing else moves: the column chips, their hrefs, the window line, the paged table, the row set and all four states render byte-identically to today for a bare `/browse` and for any URL whose `cols` applied.
5. The offline suite grades the new arm at the surface: a test named `names a cols value that chose no column as a parameter it did not apply` (that string, so the check below can find it) asserts the line is present for `?cols=banana`, absent for `?cols=title`, absent for `?cols=title,banana`, and absent for a bare `/browse`.
6. Human-check: at 1440x900, `/browse?cols=banana` says on screen that `cols` did not apply, and the seven default columns below it are then legible as the default rather than as the operator's choice. **(human-checkable)**
