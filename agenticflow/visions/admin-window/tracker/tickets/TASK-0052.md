# The live edit suite after the strike: prove the refusal, write only walk_sandbox, sweep

## Description
**Why this exists, and why it is early.** `tests/live/edit.live.test.ts` writes one field of a real `groups`/`idols` row and restores it — Ben's interim exception of 2026-09-02, which existed only because the direct path existed. The strike removes that path, so the suite's central act becomes a 403 and the suite goes red on the removal ticket's landing. M2 EC2 ("M1 is still green") fails until this is fixed, and every later ticket that carries `edit.live.test.ts` as its check inherits the red. **Land this immediately after the removal ticket.**

**This ticket lives in the post-strike world** (Ben's ruling, 2026-09-08; DECISIONS 2026-09-08; ARCHITECTURE §9's three-regime bullet and §13.8). VISION's "groups/idols edit directly within it" is struck, `pre_cutover` no longer exists as a regime or as an identifier, and the regimes are `resolver_owned` (override through the gate), `read_only` (`groups`, `idols` — no write path at all) and `sandbox` (`walk_sandbox` alone — a staging-only fixture table in nobody's domain, which is why the strike does not reach its direct PATCH). **The removal itself is the strategist's ticket, routed from the strike, and it lands before this one** — if `EDIT_CONFIG` still carries a `pre_cutover` entry when this ticket is claimed, say so and wait rather than doing the removal here.

**Never re-implement the struck path.** A ticket that gives a `read_only` table an `editable` column, adds a fourth `Regime` with a direct catalog write, or routes a catalog write around `settle_review_item` is wrong on its face.

**What the suite becomes:**
1. **The refusal is the assertion.** A PATCH naming a mapped `groups` column now answers 403 with the reason named, and the row is unchanged when re-read. That is the campaign's proof that the struck path is gone — a presence check on the new behaviour, not an absence check on the old (ARCHITECTURE §10; a negated grep would go green both when the path is removed and when the test drifts).
2. **The only live write is `walk_sandbox`** (M2 precondition 3; ARCHITECTURE §9.1). When the table is present: write one mapped column of one seeded fixture row, assert it landed, restore it, sweep. When it is ABSENT — Ben has not pasted the DDL yet — the write half is **skipped with the absence code read through the existing `codeOf`/`objectIsAbsent` idiom and a stated note**, exactly as `residue.live.test.ts` already treats the same table; an absent table is not an error and is not a silent pass either.
3. **The interim walk-write exception dies here.** It permitted one field of one `groups`/`idols` row precisely because the path existed. It does not, so it cannot be exercised, and STACK's walk recipe must not still tell a walker to try. Note that consequence on TASK-0037, which owned the retirement on a later schedule.
4. **The state kind before the number** (§10): every assertion names the kind it expects — `ok`, `empty`, `not_provisioned`, `error` — read structurally from `data-state`; `error` is always a FAIL.
5. **Sweep in a `finally`**, restoring the prior value, and the residue scan still runs after (acceptance test 13, M2 EC12).

## Acceptance criteria
1. `tests/live/edit.live.test.ts` no longer writes `groups` or `idols` on any path: a grep of the file finds no PATCH or update whose target is either table except inside the refusal assertion, and the suite passes against staging.
2. It asserts, live, that a PATCH naming a mapped `groups` column answers 403 with the reason named and the row is unchanged when re-read afterwards.
3. Its only write target is `walk_sandbox`, in a `finally`-restored round trip; with the table absent the write half skips on the absence code with a stated note and the suite still passes; with it present the write, the read-back and the restore all assert.
4. Every assertion names its expected state kind before comparing anything, read from `data-state`; `error` fails the suite.
5. `tests/live/residue.live.test.ts` passes afterwards and reports no campaign residue; its treatment of an absent `walk_sandbox` is unchanged.
6. The consequence for the interim walk-write exception is recorded on TASK-0037 as a comment (this ticket does not edit STACK; that is TASK-0037's scope).
