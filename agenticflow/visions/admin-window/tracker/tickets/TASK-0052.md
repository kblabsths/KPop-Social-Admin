# The live edit round trip moves to walk_sandbox: five coercions, the NOT NULL refusal, and the sweep

## Description
**Narrowed 2026-09-08 by the architect**, after Ben's strike and TASK-0040's landing: TASK-0040 owns inverting the groups/idols write case, re-aiming the http rewrite tripwire and re-expressing the residue floor. What is left for this ticket is the half TASK-0040 does not do — **the live edit suite needs a real write round trip, and after the strike there is exactly one table it may write.**

**`walk_sandbox` is present on staging with rows** — Ben pasted the DDL on 2026-09-08 and builder-118 measured it on 2026-09-09 (`residue.live.test.ts` swept it as 5 of 5 mapped tables; the row-count floor passed; columns `sandbox_id, label, note, tally, is_flagged, observed_on, created_at`). M2 precondition 3 is satisfied, so the write half is exercisable rather than skipped.

**What this ticket does:**
1. **One write round trip on `walk_sandbox`**, in `tests/live/edit.live.test.ts`: PATCH one mapped column of one seeded fixture row (`00000000-0000-4000-8000-000000000001`), assert it landed by re-reading, restore the prior value in a `finally`, and let the residue sweep run after (acceptance test 13, M2 EC12).
2. **The typed coercions the sandbox exists to walk**, one assertion each and each with its absent case: `label` (text), `note` (nullable text — clear it to the unqualified dash, then fill it), `tally` (integer), `is_flagged` (boolean), `observed_on` (nullable date).
3. **The refusal path is a pass, not a failure**: clearing a NOT NULL column (`label`, `tally`, `is_flagged`) is refused by the database (23502) and the surface must report the refusal without claiming the save landed — assert the refusal, assert the value is unchanged on re-read.
4. **The absence branch stays and stays honest**: if the table is ever absent again, the write half skips on the absence code read through the existing `codeOf`/`objectIsAbsent` idiom with a stated note — an absent table is not an error and is not a silent pass either.
5. **The state kind before the number** (ARCHITECTURE §10): every assertion names the kind it expects, read structurally from `data-state`; `error` is always a FAIL.

**Out of scope, because TASK-0040 owns it**: the groups/idols refusal assertions, the http tripwire, the residue floor's re-expression. Do not touch them here.

**The interim walk-write exception is dead** — it permitted one field of one `groups`/`idols` row precisely because the direct path existed. Note that consequence on TASK-0037, which owned the retirement on a later schedule; this ticket does not edit STACK.

## Acceptance criteria
1. `tests/live/edit.live.test.ts` performs one write round trip against `walk_sandbox` on staging — write, re-read, restore in a `finally` — and passes; it writes no other table on any path.
2. Each of the five mapped sandbox columns is exercised with its own assertion, including the nullable pair cleared to the unqualified dash and refilled.
3. Clearing a NOT NULL sandbox column asserts the database's refusal (23502) and asserts the value unchanged on re-read; the surface never claims the save landed.
4. If `walk_sandbox` is absent, the write half skips on the absence code with a stated note and the suite still passes; that branch is exercised at least once against a stubbed absence so it is not dead code.
5. Every assertion names its expected state kind before comparing anything; `error` fails the suite.
