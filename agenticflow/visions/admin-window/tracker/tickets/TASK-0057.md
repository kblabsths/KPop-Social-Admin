# A reference renders as a link: an idol reaches its group, a group reaches its idols

## Description
**SPEC F12, the display half — this is what ends the idol/group islands.** A reference renders as a **link to the record it names**, wherever it is shown. `events.venue_id` already ships that rendering (BUG-0034; `recordHref` in `lib/records/routes.ts` is the ONE record-URL spelling, DEBT-0001). Apply the same rendering to `idols.group_id`: an idol's record shows its group and reaches it in one click, and a group's record reaches its idols.

A user-sim spent a walk discovering that groups and idols are two islands — an idol page "lists stage_name, real_name, korean_name, position, nationality and so on, but not which group the idol belongs to, and it links nowhere".

**Two hard limits, because it is easy to over-reach here:**
1. **It adds no editable column.** `group_id` is a KEY. It is DISPLAYED (`display` + `reference`), never `editable` — SPEC F8's "user-facing fields only, never ids, keys, or timestamps" is unchanged, and the post-strike world makes it doubly so: `idols` is `read_only` and has no write path at all. A ticket that adds a key to an allowlist is wrong.
2. **It is not a door.** A first group is still reached only by pasting a uuid. Whether the app gets a groups/idols listing or a search is ROADMAP question 1, **Ben's alone**, and SPEC F7 forbids a second curated view until he answers. Do not build a listing, a search box, or a "browse groups" affordance under cover of this ticket.

**The group -> idols direction** needs one new read in `lib/db/records.ts`: the idols whose `group_id` is this group, as a **named window** with an explicit order and limit (§4.3), rendered as a list of links using `recordHref` — no second href helper, and no count presented as a total unless it is a complete read that refuses when truncated.

**Absence and nulls, both required** (LESSONS 1): an idol with a null `group_id` renders the dash with no qualifier and no broken link; a group with zero idols renders its labelled empty state and a real `0`, not a blank; a group id that resolves to no row renders the id with a stated "not found" rather than an empty link.

## Acceptance criteria
1. On an `idols` record the group renders as a LINK whose href is `recordHref("groups", <id>)` and resolves to that group's record page (200 authed); on a `groups` record its idols are reachable in one click, through the same one helper. No second href spelling is introduced.
2. `idols` carries `reference: { field: "group_id", domain: "groups" }` and `group_id` in `display`; `group_id` is NOT in `editable` for any table, the config guard still passes, and a forged PATCH naming `group_id` is refused server-side with 403.
3. A null `group_id` renders the dash with no qualifier; a group with zero idols renders a labelled empty state with a real `0`; an unresolvable id renders the id with a stated reason, never an empty link.
4. The group -> idols read is a named window with an explicit order and limit, and the surface states the window; no figure claims a total it did not measure (§4.3, LESSONS 2).
5. No listing page, no search control over `groups` or `idols`, no second Browse view: the sidebar still holds exactly six links, and `src` contains no search input over either table.
6. `npm run lint`, `tsc --noEmit`, the targeted offline files and the record page's live suite are green.
