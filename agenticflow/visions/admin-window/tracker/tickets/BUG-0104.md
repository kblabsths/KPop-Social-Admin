# A tall refusal on the SECOND-TO-LAST field is drawn past the fields table's clipping container - the ordinal growth rule rescues only the last line

## Description
Measured 2026-09-08 by QA attacking BUG-0101 on the LANDED run branch (`run/admin-window` at 88da50e): production build served on 127.0.0.1:8793 (bind-probed, not 8770/8771) against staging (`ubfjjqlvnpnoborczbdb`), bundled Chromium, 1440x900, BOTH themes, `walk_sandbox` row `...0001`, `reset-sandbox` before AND after (both "deleted 3, seeded 3, read back and verified").

BUG-0101 fixed the LAST line and its criterion 1 is green (see that ticket). Its rule is ORDINAL - `statusGrowth(row, rows)` returns `up` only for `lastOfSeveral` (`src/components/edit-cell-layout.ts:191`), everything else `down`. But the container clips a box that exceeds the room BELOW ITS OWN ROW, not just below the last row. The fields table has 6 rows in 220px; the 23502 refusal this surface already produces is 120px tall. On the second-to-last row there are 62px of room. So the same defect, undiminished, sits one row up.

**Expected** (BUG-0098 criterion 1, restated by BUG-0101 criterion 1): a refused write renders BOTH halves at the field - the database refusal verbatim in mono AND the app-voice sentence - inside the fields table container, at rest, nothing scrolled.

**Found**: clearing `is_flagged` (row 5 of 6, the second-to-last) draws the refusal box y 304 -> 424 against a container of y 143 -> 363. Byte-identical in light and dark.
- container `div.overflow-x-auto`: y 143, h 220, bottom 363; `scrollHeight` 281 vs `clientHeight` 220 (the box adds 61px of hidden overflow).
- refusal box `role="alert"`: 304 -> 424, h 120 - **61px below the container edge**.
- mono half `null value in column "is_flagged" of relation "walk_sandbox" violates not-null constraint / Failing row contains (...)`: 306 -> 402, cut 39px - the screenshot shows it ending mid-word at `A note a` on its third line.
- app-voice half `is_flagged cannot be cleared - type a value into it.`: 404 -> 422, `fullyOutside: true`. **Not painted at all**, exactly as BUG-0101 measured for the last row. Setting the inner container `scrollTop = 100` (it clamps to 61) brings the box to 243 -> 363 and the sentence back - the only way to read it, and the table shows no scroll affordance for that axis.

Exact repro:
1. `node tests/walk/reset-sandbox.mts` with the STACK.md section 5 staging mapping.
2. `npm run build` + `npm run start -- --port <free>`; mint the walk cookie; open `/records/walk_sandbox/00000000-0000-4000-8000-000000000001` at 1440x900.
3. Click the `is_flagged` value (row 5 of 6), select-all, Delete, Enter. Park the pointer at 0,0 and read the boxes.

This is a supported path, not a contrived one: STACK.md section 5 calls clearing one of `label` / `tally` / `is_flagged` "a walkable error path put there on purpose", and `tests/live/edit.live.test.ts` pins all three refusals. `label` (row 2) and `tally` (row 4) have room and stay inside (205 -> 325 and 271 -> 327, re-measured on this tree); `is_flagged` is the one whose own row has less room than its own box.

**Not a regression of BUG-0101 and not BUG-0086.** Row 5 was told `down` before that fix and is told `down` after it, so this box is drawn exactly where it was drawn all along; BUG-0101 changed only the last line. And nothing reflows: rows sit at 169.5 / 198.5 / 231.5 / 264.5 / 297.5 / 330.5 and cells at x 209 / 459.3 / 1175.7 (w 250.3 / 716.41 / 247.3) before, during and after a commit, in both themes.

**Expected: both halves of a refusal painted inside the fields table container. Found: on `is_flagged` the app-voice half is drawn 41-59px below that container and is not painted at all** - `src/components/edit-cell-layout.ts:191` (`statusGrowth`, ordinal: only the last of several grows up) with the box height set by the database sentence in `src/components/EditableCell.tsx:490` (`max-w-xs`), inside `src/components/ui/data-table.tsx:112` (`overflow-x-auto`, whose other axis computes to `auto` and clips).

**QA honesty, same as BUG-0101 carried**: there is NO offline pin for this and QA deliberately invented none. `tests/offline` is plain node with `renderToStaticMarkup` and no jsdom (STACK.md section 4), so a bounding box is unobservable there, and the only offline-observable fact - that `RecordFields` tells `is_flagged` `down` - is CORRECT for an ordinal rule. Asserting `up` there would pin an arbitrary "last two lines" hack rather than the invariant. The invariant is: no refusal this surface can produce is painted outside the container. Its fix is plausibly geometric (measure the box and flip or clamp), or structural (the container stops clipping the y axis / the box is not a child of it) - and criterion 4 below asks the fixer to pin whatever DECISION their fix introduces, exactly as BUG-0101 pinned `statusGrowth`.
