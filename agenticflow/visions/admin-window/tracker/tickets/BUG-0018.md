# GaugeCard puts a floor qualifier and a palette colour on an em dash it never measured

## Description
GaugeCard decides 'this figure is absent' with its own guard, `value === null` (src/components/gauges/gauge-card.tsx:93-105), instead of the app's single definition of absence, `isAbsent` in src/lib/format.ts (seeded by admin-window/BUG-0004 precisely because three hand-written guards disagreed). StatCard renders the em dash for anything `isAbsent` accepts — including the EM-DASH STRING every formatter returns for a null (`duration(null)`, `count(null)`, `relativeAge(null).text`) and any non-finite number — so the card can show the dash while GaugeCard still believes it has a figure, and keeps the two qualifiers that are only true of a figure.

Repro A (the intended call for a seconds figure; `duration` is the helper TASK-0008 itself added for exactly this):
  const p50 = aggregateCycleHealth({rows:[resolutionRunRow({ended_at:null,outcome:null})], window}).duration.p50;  // null
  render(h(GaugeCard, {label:'median duration', value: duration(p50), floor:true, tone:'broken'}))
Expected (the component's own docblock, gauge-card.tsx:100-104, and the invariant its sibling test 'never qualifies or colours a figure it does not have' already pins for the null arm): the dash carries no floor qualifier and no palette colour.
Found: <span class="type-body text-ink-secondary">at least</span> plus <span class="type-figure text-broken"><span class="text-ink-disabled">—</span></span> — an 'at least' and a broken-red on a figure that was never measured, and no reason line at all (the third arm's `absent` is unreachable here because the value is a non-null string).

Repro B (same defect, arithmetic path): value: Number.NaN or Number.POSITIVE_INFINITY with floor:true, tone:'broken' -> identical markup.

Impact: the reading is the one spec §5 forbids — a knob shown as unhealthy/attention when nothing was read. No page consumes GaugeCard yet (grep 'GaugeCard' src/app -> no match), so it is latent, not shipped; it becomes user-visible the moment the first gauge page renders a percentile that came back null.

Suggested shape (not binding): route the absence decision through `isAbsent` from lib/format, so 'unmeasured' means the same thing in GaugeCard, StatCard and DataTable.

Pins: tests/offline/gauges-ui/cards.test.ts, 'never qualifies or colours an absence that arrived as a formatted string' and 'never qualifies or colours a non-finite figure', currently marked `it.fails` (strict xfail, admin-window/BUG-<this>). Both were watched RED as plain `it` before the pin: 'expected [...] to not include type-body'. The fix flips them back to `it` — with the pin left in place they turn RED on success.
