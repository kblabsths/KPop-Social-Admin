# A foreign column-absent envelope makes the app name an intermediary's own text as the missing object — classify()'s mined column is admitted unvalidated

## Description
**Module:** `src/lib/db/result.ts` — `columnFromMessage` and the COLUMN-ABSENT arm of `classify()`.

**The contract this breaks, in its own docstring.** `classify`'s header says `missing` "is the name from `tables.ts` the query used, so the rendered not-provisioned card names the same string the query did" — i.e. `missing` is a name THIS APP chose. For a column-absent code that is false: the column half is mined out of the DATABASE'S MESSAGE by `columnFromMessage`, whose first spelling is `/'([^']+)'|"([^"]+)"/` — the first quoted run ANYWHERE in the message, unbounded in length and unconstrained in content, with no requirement that the word `column` appear at all (the `does not exist` anchor guards only the SECOND, unquoted spelling). `lastSegment` then splits that run on `.` and keeps the tail, so the value admitted is whatever followed the last dot inside the quotes.

**MEASURED** (architect, 2026-09-11, run/admin-window at 1e87f6a; `classify(error, "review_items")` driven through the real module with `vite-node`; probe kept at `agenticflow/tracker/evidence/M3/architect/missing-probe.ts`):

| error | `missing` returned |
| --- | --- |
| `{code:"42703", message:"column 'severity\" OR 1=1 --  <script>alert(1)</script> ' does not exist"}` | `review_items.severity" OR 1=1 --  <script>alert(1)</script> ` (60 chars) |
| `{code:"PGRST204", message:"Access denied by policy \"your request was blocked; contact support@evil.example for reference 8f3c1\""}` | `review_items.example for reference 8f3c1` (40 chars) |
| `{code:"42703", message:"blocked \"<!DOCTYPE html><html><head><title>Attention Required!</title></head></html>\""}` | `review_items.<!DOCTYPE html><html><head><title>Attention Required!</title></head></html>` (88 chars) |
| `{code:"42703", message:"column \"‮gnitset\" does not exist"}` | `review_items.‮gnitset` — an unterminated RTL override inside the value |
| `{code:"42703", message:"column \"severity\" does not exist"}` | `review_items.severity` — the honest case, which must not change |

Row 2 is the sharpest: no `column` word, no `does not exist`, nothing but a quoted run in an intermediary's refusal — and the app then tells its operator that an object called `example for reference 8f3c1` is not provisioned in this database.

**Reachability is admin-window/BUG-0179's own path, one field over.** postgrest-js hands the parsed body back AS the error object for any non-2xx (`error = JSON.parse(body)`, `node_modules/@supabase/postgrest-js/dist/index.mjs:143`), so an intermediary refusing with a JSON envelope authors `code` and `message` both. BUG-0173 closed the account (`message`), BUG-0179 closed the `code`; `missing` is the third field of the same record and the only one that is a CLASSIFICATION rather than prose, which is why neither ticket's derivation reaches it.

**Why this is fixed at the derivation and not at each renderer.** `missing` has seven consumers today and they do not agree on how they spell it. `src/components/ui/not-provisioned.tsx` and `src/components/cycles/latest-run.tsx` put it in `<Identifier>` — the bidi-isolated mono box §7 requires of foreign text, so those two are safe whatever it carries. But `src/app/api/admin/records/[table]/[id]/route.ts:325,408` and `src/app/api/admin/review-items/[reviewItemId]/settle/route.ts:149` inline it straight into an app-authored sentence — `` `${result.missing} is not present in this database` `` — in a JSON body, where there is no box to put it in; and `src/lib/paging/machine.ts:466` does the same into a refusal's sans prose (QA's residual (b) off BUG-0175's close; the RENDER half of that is folded into BUG-0176 criterion 13 and holds whatever `missing` carries, which is why this ticket is the other half and not a duplicate of it). Making every consumer isolate a value that is supposed to BE an object name is the shape ARCHITECTURE Common-violations row 20 was promoted against: one derivation per value class, in one home, not one property per surface.

**The ruling (architect, 2026-09-11) — an allowlist at the one derivation, and the fallback the code already has.**

`missing` is an OBJECT NAME. The app can say in advance what a legal one looks like — this file already spells the class, in `UNQUOTED_COLUMN_REFERENCE`'s own `[A-Za-z_][\w$]*` — so §7's first arm applies: foreign text reaches prose THROUGH AN ALLOWLIST when the app knows the shape. The mined column is admitted into `missing` only if it matches that grammar; otherwise `classify` returns the object the QUERY asked for, which is the arm the function already has and already tests (`column === null` -> `{kind:"not_provisioned", missing}`). No new arm, no new sentence, no count, no truncation, nothing removed from anything.

**This is not BUG-0179's forbidden fourth question.** That ban is on `partOfAccount`'s three questions, which govern the MESSAGE — free prose, where the app cannot say in advance what a legal one looks like, so a `<`-scan or a length cap there is a blocklist and is refused. A column name is the opposite kind of value: a bounded identifier class the app names itself. Row 15's two arms are exactly this distinction, and row 20's ruling is that each value class gets ONE derivation. Nothing in `errorMessage`, `partOfAccount`, `codeOfAccount` or `withoutSecrets` is touched here, and the database's message still crosses into the `error` arm byte-identical — a message this ticket refuses to mine a column out of is not scrubbed, it is simply not mined.

**NOT IN SCOPE:** the `error` arm's message (BUG-0173/BUG-0179, closed); which codes count as absence (`ABSENCE_CODES`, `COLUMN_ABSENT_CODES`) and the asked-object rule (TASK-0047, BUG-0080); the two API routes' sentences and `machine.ts`'s (they inherit an honest value from here — the paging render is BUG-0176 criterion 13); the transport account's twice-stated cause (DEBT-0020).

## Acceptance criteria
1. `missing` IS AN OBJECT NAME, ALWAYS. Every `{kind:"not_provisioned"}` `classify` returns names either the object the query asked for (the string `tables.ts` gave it) or that object qualified by a column that matches the app's own object grammar — a bounded identifier class spelled ONCE in src/lib/db/result.ts, of the shape this file already uses for an unquoted reference (`[A-Za-z_][\w$]*`, length-bounded). A mined column that does not match is not admitted: the verdict falls back to the arm that already exists, `{kind:"not_provisioned", missing}` naming the table alone, and the message it was mined from is neither scrubbed nor truncated nor counted — it is simply not mined. On the architect's five measured envelopes the four foreign ones all return `review_items` and the honest one still returns `review_items.severity`.

2. THE HONEST PATH IS BYTE-IDENTICAL. Both spellings a real Postgres/PostgREST column-absent message uses still resolve and still qualify: quoted (`column "severity" does not exist`, `column "severity" of relation "review_items" does not exist`, `Could not find the 'severity' column of 'review_items' in the schema cache`) and unquoted-qualified (`column events.badcol does not exist`), each still dropping its qualifier and naming `<table>.<column>` exactly as today (admin-window/TASK-0002, TASK-0047). The `column === missing` and `missing.endsWith(".<column>")` de-duplications are unchanged, a message naming no column still falls back to the table, and every existing not_provisioned verdict in tests/offline/db/result.test.ts is green with none rewritten.

3. ONE DERIVATION, IN ONE HOME, AND NO BLOCKLIST. The grammar is one named constant in src/lib/db/result.ts applied at the single point the column enters `missing`; it is not re-asked by any consumer, not copied into src/lib/paging/**, src/components/** or the API routes, and no call site is asked to isolate a value that is now an object name. Nothing is added to `partOfAccount`'s three questions, `errorMessage`, `codeOfAccount` or `withoutSecrets` — BUG-0179's "no fourth question" holds byte-for-byte and its named cases stay green. Nothing scans for `<`, `!DOCTYPE`, `html`, a codepoint class or a runtime vocabulary anywhere on this path (LESSONS 4, ARCHITECTURE Common violations row 15: this is row 15's ALLOWLIST arm, which is legal precisely because the app can say in advance what a column name looks like — a cap or a scan on the database's free-text MESSAGE would not be, and is not written).

4. TWO NEW NAMED CASES, EACH WITH ITS MUST-NOT-FLAG TWIN (LESSONS 8), in tests/offline/db/result.test.ts, each a local literal: it("spells a column only when the message named one this app could have named") — the architect's four foreign envelopes (the quoted-fragment injection, the quoted run carrying no `column` word at all, the whole document between quotes, the unterminated RTL override) each returning `not_provisioned` naming `review_items` and holding no character of the intermediary's text, alongside its twin, the four honest spellings of criterion 2 each still qualifying to `review_items.severity` / `events.badcol`. And it("still classifies a foreign column-absent envelope as an absence, not an error") — the verdict's KIND is unchanged by this ticket: an envelope that was `not_provisioned` before is `not_provisioned` after, so nothing is converted into a red error card on the way past.

5. THE CLASSIFICATION ITSELF IS UNTOUCHED. `errorCode` still decides every arm, `ABSENCE_CODES`/`COLUMN_ABSENT_CODES` are unchanged, the asked-object rule (a table read may not claim an absent function; `MISSING_OPERATOR` at 42883) is unchanged, and the `error` arm still carries the database's account exactly as BUG-0173/BUG-0179 left it. `classify`'s header no longer claims that `missing` is the name `tables.ts` gave the query without saying what the column arm admits — the docstring describes the landed code.

6. The diff is the two files of the touch scope and nothing else; `npm run lint` and `npm run typecheck` are clean and the targeted suites are green. (Targeted rather than the full suite: this ticket changes one verdict's STRING for foreign input only, criterion 4 pins that the KIND never moves, and tests/offline/absence/pages.test.ts is the consumer sweep that would see a changed not-provisioned surface — 404 tests, 3.1s measured on this tree today.)
