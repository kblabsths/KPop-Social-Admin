# Dashboard: both error columns render a component that returns null, so a row with no error_summary shows a BLANK cell

## Description
Filed by builder-50, dispatched to fix this defect under the id BUG-0024 — which the tracker had already given to a different, unrelated P1 (review-item observations.entity_type, opened by qa 2026-09-02T16:17:48Z). Rather than transition someone else's open bug to built with Dashboard work, the work is filed here under its own id. See the ID-collision comment on BUG-0024.

The defect, already pinned: tests/offline/absence/blank-cells.test.ts marks '/' with it.fails (KNOWN_BLANK), measured 10 of 10 rows blank (6 cycle rows + 4 run rows) on a fixture population whose nullable columns are all null.

Cause: src/app/page.tsx renders both 'error' columns (CYCLE_COLUMNS and RUN_COLUMNS) as <ErrorSummary summary={row.error_summary} href=... />. ErrorSummary returns null when error_summary is null or blank, but DataTable's orDash (src/lib/format.ts) receives the ELEMENT, never the null — isAbsent sees a React element, so the cell is emitted empty instead of the em dash the table promises ('never blank' — LOOK_AND_FEEL, Data table). Cycles (admin-window/TASK-0014, stateCell) avoided it by returning the null from the column function itself.

Same shape, same file: the 'outcome' columns of both tables render <Outcome outcome endedAt />, and Outcome returns null for a row that ENDED with no outcome recorded — a state the blank-cells fixture does not reach (it nulls ended_at too, so the row reads 'still running'), but a real one: resolution_runs.outcome is null until completion and the page's own docstring says the ended-with-no-outcome row is 'left to the table's own dash'. It is not; it is blank.

Fix: return the absence itself from the column (a plain function, not a component element), keeping the rendered markup for non-absent values byte-identical.

## Acceptance criteria
The Dashboard's two error columns and two outcome columns yield the null itself to DataTable, so a row with no error_summary (and a row that ended with no outcome) renders the shared em dash, not an empty cell. tests/offline/absence/blank-cells.test.ts's '/' entry leaves KNOWN_BLANK and passes as a plain it. Markup for a non-null error_summary and for every non-absent outcome is unchanged, byte for byte. No other page-level DataTable column in src/app/** or src/components/** (excluding src/components/ui) renders a child component that can return null; any found are fixed and named. Dashboard and absence offline suites stay green.
