# Two ledes send the operator to a table the page did not render when no evidence id resolves

## Description
Found while attacking BUG-0128 (QA, 2026-09-09), on the fixture the ticket's own attack brief named: an item whose evidence ids resolve to NO claim. BUG-0128 moved the fact lede from "Every claim held by it is below" to "The table below holds the claims behind this item's evidence ids" — the same construction BUG-0124 gave the source-pattern shape. Both new sentences assert, in the present tense, that a table below HOLDS claims. When nothing resolves there is no table at all: `ClaimRows` renders `<Empty>` instead (src/components/review/shape-views.tsx:204-210), and that card says the opposite in the app's own words.

**Expected** (the rule BUG-0124 and BUG-0128 both applied — a lede states what the block below it actually holds, and the page does not contradict itself out of its own mouth): when the evidence block renders its empty card, the lede does not point the operator at a table the page did not render.

**Found**, measured offline on the landed tree (run/admin-window @ da85544), rendered markup transcribed verbatim:

1. `entity_link` FACT shape, one evidence id that names no claim — `reviewItemEntityLink({ evidence: ['01920000-0000-7000-8000-000000000999'], folded_count: 12 })`, `observations` and `pending_claims` both scripted `{ data: [] }`. The one page carries simultaneously:
   - lede: "This record cannot link or be created. **The table below holds the claims** behind this item's evidence ids, with what each one is waiting for."
   - `<table>` elements inside `[data-evidence-view]`: **0**; `[data-state="empty"]` cards: 1
   - that empty card: "**No claims behind this item's evidence ids** — Every id it carries is listed below, and none of them names a row this database holds."
   - accounting: "0 of 1 evidence id resolved to a claim, in the order they folded in."
2. `entity_link` SOURCE-PATTERN shape, `reviewItemSourcePattern({ evidence: [], folded_count: 700 })`: lede "One source, many records stuck the same way. **The table holds the claims** behind this item's evidence ids; the source's own dial is beside it. …" over 0 `<table>` elements and the card "No claims on this item".
3. The `data_conflict` lede names no table and is unaffected — the defect is exactly the two ledes that name one.

Not a regression of BUG-0128: its criterion 1 prescribed this wording, the builder implemented it, and the shape BUG-0124 shipped carries the identical sentence. Both criteria sets are met; this is the state neither ticket's criteria drove.

Measured red before filing, with the pin's `it.fails` removed, on the landed tree:
`AssertionError: expected 'This record cannot link or be created…' not to match /\btable\b/i` and `AssertionError: expected 'One source, many records stuck the sa…' not to match /\btable\b/i` — 2 failed. In the healthy state the same read finds 1 `<table>` and the rule passes, so it is not a ban on the word: it fires only when the named table does not exist.

The pin is landed strict in tests/offline/review-item/page.test.ts, describe "no lede sends the operator to a table the page did not render". Fix the two ledes and it turns red with "Expect test to fail" — that is the signal to fold it into the passing test beside it and delete the pin.
