# Light palette fails bar 12: darken healthy/attention/broken/ink-secondary to the amended hexes

## Description
QA measured the landed token layer against LOOK_AND_FEEL quality bar 12 ('every string a person reads to act measures >=4.5:1 against the fill behind it') and four light-theme jobs fail: healthy green-600 #00a63e 3.22:1 on white, attention amber-600 #e17100 3.20:1 on white and 3.06:1 on chrome (and attention is the 'high' severity colour, the one that means needs a human), broken red-600 #e7000b 4.33:1 on the page fill, ink-secondary gray-500 #6a7282 4.39:1 on the page fill. Dark theme passes throughout (floor 5.25:1) and does not change. I ruled on the doc rather than narrowing the bar: three of the four are read-to-act text by their own palette job, so an exception would gut bar 12. LOOK_AND_FEEL.md's palette table now carries the darker light values, the ratios, and the reason amber stops at the 700 step; globals.css has to follow it hex-for-hex. Ratios below are measured against page #f3f4f6, the darkest of the three fills text sits on. No dark value moves, and --color-chrome-inverse needs no change: the doc was wrong (it said gray-800, which equals the dark chrome), the shipped gray-700 is right and the doc now says gray-700.

## Acceptance criteria
1. src/app/globals.css light @theme block reads: --color-ink-secondary: #4a5565 (gray-600, 6.87:1), --color-healthy: #016630 (green-800, 6.48:1), --color-attention: #bb4d00 (amber-700, 4.57:1), --color-broken: #c10007 (red-700, 5.83:1). Comments name the new ramp steps.
2. The retired mid steps #00a63e, #e17100, #e7000b and #6a7282 appear nowhere in globals.css.
3. The dark block is untouched, including --color-chrome-inverse: #364153 and --color-on-accent: #030712.
4. A new tests/offline/ui/contrast.test.ts parses the token values out of src/app/globals.css (both themes) and asserts, per theme, that ink, ink-secondary, accent, healthy, attention and broken each measure >=4.5:1 (WCAG 2.x relative-luminance formula) against page, surface and chrome; that on-accent measures >=4.5:1 against accent; and that ink measures >=4.5:1 against chrome-inverse. ink-disabled is asserted BELOW 4.5:1 and excluded by name, per the palette's stated exemption. The test must fail if any light state colour is put back to its mid step.
5. tests/offline/ui stays green and the app still builds; no component file changes (primitives name tokens, never hexes).
Human-check: on the Dashboard in light theme the healthy, attention and broken figures still read as green, amber and red at a glance, and secondary labels still sit visibly below primary text rather than level with it. (human-checkable)
