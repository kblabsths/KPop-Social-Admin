# Sources — lifecycle, tier, checkpoint, last run, and the per-source trends

## Description
Module: `src/app/sources/page.tsx` + `src/lib/db/sources.ts`. Authority: spec section 4 (Sources) and section 5 (the per-source gauge trends live here); `contracts/data-model.md` (source registry config + state); SPEC F5; acceptance tests 2, 9; LOOK_AND_FEEL (the data-table rule — this page carries no bespoke layout).

- The `sources` **state** rows: `lifecycle` (`candidate -> trial -> active <-> paused -> retired`), current `tier`, `checkpoint`, `note`, and **last run**.
- **`sources` has no last-run column.** Last run is the newest `runs` row whose `runs.source` **text** equals `sources.source`. There is no foreign key and none is possible (migration `20260829000001` says so deliberately) — match by name, in TypeScript, in one place.
- **Config is not state.** Everything the registry holds (description, domains fed, usage, dials, legal status) lives in scraper YAML, not in the database, and this campaign does not read scraper files at runtime (spec section 10). Render the state row; do not invent config columns.
- **A source links to its review items** (`/queues` filtered to that `source_id`) **and to its runs** (`/cycles` filtered to that source name).
- The **per-source gauge trends** render beside the rows (spec section 4): the per-source `awaiting_row` trend from the pending-claims gauge, and the **settled-values** gauge (per-source re-reject counts over time, from `observations.rejected_at` / `rejected_by`) — 'who keeps pushing adjudicated values'. The `awaiting_row` **threshold line** is not built: the per-source `resolver.stuck_pattern` dial lives only in scraper registry YAML and where Admin reads it is a blocked question. A hand-copied number is not an answer.
- Tier is a badge, not a colour: only severity and health carry colour, so a page of sources is not a rainbow.

Standing rules for every page ticket (ARCHITECTURE sections 4, 5, 7): the page function is the only async component on the route and every child is a pure sync component; read only through `src/lib/db/**`; table names live only in `tables.ts`; render all four states from the `ui` primitives (a missing table never throws and never renders as 0); tokens and primitives, never raw values; every filter, sort and tab is a `searchParams` value; ages relative with the absolute in the title attribute, scheduled times absolute UTC with the zone in the column header, machine identifiers verbatim in mono; **nothing settles anything in M1**.

## Acceptance criteria
[tests 2, 9; EC3, EC4] Offline tests render the page against fixtures and assert: each source's lifecycle, tier, checkpoint and last run render, with last run matched by source **name**; a source with no run renders the null dash, not a blank or a zero; the links to that source's review items and runs are real URLs. A live-marked parity test asserts the rendered source rows and their per-source counts against queries the test issues itself. Both per-source trends render, without a threshold line. The not-provisioned state names the missing table. No scraper file is read and no registry value is hand-copied into this repo.
