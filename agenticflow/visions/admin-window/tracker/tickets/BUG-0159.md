# The /sources narrowing chips label a source id with the registry string raw, so a blank-named row renders a chip with nothing to read or click beside a trend row that names it by its id

## Description
Found attacking BUG-0158 on the landed tree (run/admin-window @ 85e13cc, offline vitest, no device, no network, 2026-09-10). BUG-0158 fixed four `?? id` sites and added the one-owner guard; this is the SAME rule broken by a different spelling — no fallback at all — on the very page BUG-0158 edited.

Expected (`src/lib/sources/names.ts`, "The one owner of this rule: every surface that labels a source id calls here"): a narrowing chip IS a source labelled by its id — its whole href is `/sources?source_id=<uuid>` — so what it says is `sourceLabel(names, source.source_id)`, and a registry row that names nothing readable renders the id verbatim.

Found — `src/components/sources/source-chips.tsx:43`: `label={source.source}`, the registry string raw, with no fallback of any kind. MEASURED by rendering `/sources` offline with `sources` row `01920000-0000-7000-8000-000000000101` renamed to `""`, `"   "` and `"​"` (three cases, all fail):
  chip for that source -> label `""` (resp. `"   "`, `"​"`) — an empty control with nothing to read and nothing visible to click;
  the AWAITING-ROW TREND ROW for the SAME source in the SAME render -> `"01920000-0000-7000-8000-000000000101"` (asserted first in each case and green, so this is not a blanked page);
  the sibling chip for `...0100` -> `"bandsintown"` (unchanged).
So after BUG-0158 the page gives two different answers for one source in one render (LESSONS 11, one row one verdict), and the control is the one that says nothing.

Why BUG-0158`s guard did not catch it: `describe("what a source is called has one owner")` matches `/\?\?\s*...(sourceId|source_id)\b/` — the RETYPED fallback. `SourceChips` has no `??`, so an ABSENT fallback is invisible to it. Whatever fixes this should consider whether the guard can also see a source-labelling site that calls neither `sourceLabel` nor `??`.

Reach: `sources.source` is NOT NULL with `CHECK (source ~ ^[a-z0-9_]+$)` in the scraper repo, so a blank name needs a producer-side breach; staging has none. P3 for that reach — the same price BUG-0154/0156/0158 carried. Fix shape (not binding, one line): `/sources` already builds `const names = sourceNamesOf(held)` at `src/app/sources/page.tsx:190` and hands it to the trend two lines later; `SourceChips` renders from the same `held` at :215 and can take the same map, so the chip and the trend row below it answer from one rule.
