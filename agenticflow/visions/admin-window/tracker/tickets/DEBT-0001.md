# Two spellings of /records/<domain>/<id>: fold provenanceHref and eventRecordHref into one leaf helper

## Description
Module: `src/lib/records/` (the pure record leaf). Raised by builder-62 on BUG-0034 ("fields.ts reuses provenanceHref rather than adding a THIRD spelling of /records/<domain>/<id>; eventRecordHref is the second, and consolidating them is an architect call") — this is that call.

MEASURED 2026-09-02 on the landed tree. Exactly two files in `src/` construct the record URL:

    src/lib/browse/rows.ts:86     return `/records/events/${encodeURIComponent(eventId)}`;
    src/lib/claims/filters.ts:311 return `/records/${encodeURIComponent(domain)}/${encodeURIComponent(entityId)}`;

`grep -rlE "[`]/records/[^`]*[$][{]" src` = those two and nothing else (the third `${` hit, `src/components/records/submit.ts`, builds the `/api/admin/records/...` PATCH endpoint — a different URL, out of scope, do not touch it). The other `/records/` occurrences in `src/` are prose in docblocks.

Two spellings of one route is one route that can drift: `eventRecordHref` hard-codes the `events` domain and cannot return null; `provenanceHref` takes any domain and returns null for a missing entity_id. They agree today only because two people wrote `encodeURIComponent` the same way. `src/lib/edit/config.ts:73` already calls it "the one record URL this app builds", which is true of the design and false of the code — the same gap BUG-0034 found in that file's other comment.

THE RULING (destination and signature — do not re-derive them):

1. **One leaf, `src/lib/records/routes.ts`**, the sibling of the existing `src/lib/records/provenance.ts`. It imports NOTHING (ARCHITECTURE §4 rule 7). Neither current home may keep the function: `lib/browse/rows.ts` and `lib/claims/filters.ts` are both leaves, and the module map draws `lib/<leaf>/** -> (nothing)`, so a leaf importing a leaf is a new sideways arrow this contract does not have. Everything above the leaf (`app/**`, `components/**`, `lib/db/**`, `tests/**`) imports the new module directly.

2. **One export, one behaviour:**

```ts
/** The record surface for one canonical row: /records/<domain>/<id>. */
export function recordHref(domain: string, entityId: string | null): string | null;
```

   `null` for a null or empty `entityId` — `provenanceHref`'s existing contract (a claim in `awaiting_row` has no row to link to), kept verbatim including its docblock's reasoning. Both components carry both halves of `encodeURIComponent`. Browse's caller gains the null branch it does not need today (an event row always carries `event_id`); render the row unlinked in that case rather than re-adding a non-null variant — a second export is the drift this ticket exists to remove.

3. **Delete both old names.** `provenanceHref` and `eventRecordHref` disappear from `src/`; every consumer imports `recordHref`. The consumers, measured: `src/app/claims/page.tsx:33,235`, `src/app/queues/[reviewItemId]/page.tsx:14,168,259`, `src/components/records/fields.ts:1,171`, `src/components/browse/browse-table.tsx:4,35`, and in tests `tests/offline/claims/filters.test.ts`, `tests/offline/browse/views.test.ts`, `tests/offline/browse/page.test.ts`, `tests/live/browse.live.test.ts:4,187`. The `provenanceHref` string also appears as a PROP NAME on `src/components/claims/claim-list.tsx:46,87,93` and in `tests/offline/claims/page.test.ts` — that is a row field, not the helper; renaming it is optional and out of this ticket's bar.

4. **Behaviour does not change.** Every existing assertion about a rendered href stays true and stays in place; the URL bytes, the encoding and the null answer are all identical before and after. This is a fold, not a redesign, and it is the only work in the ticket.

TRAP: `tests/live/browse.live.test.ts` imports `eventRecordHref` and is not run by this ticket's checks (it needs staging). `tsc --noEmit` is what catches it — check 4 is not optional.

## Acceptance criteria
1. Exactly one file in src/ constructs a /records/<domain>/<id> URL: the new pure leaf src/lib/records/routes.ts, which imports nothing. 2. It exports one function, recordHref(domain, entityId: string | null): string | null — null for a null or empty entityId, encodeURIComponent on both halves — and no second, non-null or events-only variant exists anywhere. 3. provenanceHref and eventRecordHref are gone from src/ as function names, and every consumer (claims page, queue item page, records fields, browse table, and the offline and live tests that import them) calls recordHref instead. 4. No rendered URL changes: the offline records, browse, claims and queues suites pass unmodified in what they assert about hrefs, and tsc --noEmit and lint are clean, which is what proves tests/live/browse.live.test.ts was updated too. 5. Nothing else is refactored — src/components/records/submit.ts builds the /api/admin/records PATCH endpoint and is untouched, and the provenanceHref PROP on claim-list.tsx is a row field, not the helper.
