# A mirror tree under tests/.probes left by a KILLED run is never swept, and a later run that draws its pid walks the corpse as its own probe

## Description
Found attacking BUG-0188 on the landed tree (run/admin-window @ 3d5b99d, primary checkout, offline vitest, no device, no network, 2026-09-11). BUG-0188's own criteria are green here (all four stored checks exit 0; both of its literal repros are dead). This is the SAME defect class in the OTHER probe area — the one BUG-0188's builder named as out of scope with "no measured consequence" (BUG-0188 History, 2026-09-11T11:42:47Z). It has one, and it is measured below.

**Expected** (`tests/offline/review/one-place.test.ts:246-248`, the case's own comment): "The mirror is the whole world the scan saw, so nothing below is an accident of the real tree" — `expect([...walked].sort()).toEqual([ACTION_PROBE, ROUTE_PROBE].sort())`.

**Found — a false red, in a lane that planted nothing.** The mirror trees these self-guards walk are named from `process.pid` ALONE — `tests/.probes/m2-close-${process.pid}` (`tests/offline/review/one-place.test.ts:214`), `m2-one-call-${process.pid}` (:354), `inline-${process.pid}` (:269), `admin-locked-${process.pid}` (`tests/offline/edit/config.test.ts:1517`), `one-call-${process.pid}` (:2025), `strings-${process.pid}-…` (:1666), and the same idiom in `tests/offline/records/entity-picker.test.ts:2221`. Each is removed only in a case's `finally`, so a run KILLED mid-case leaves the whole tree on disk, and NOTHING sweeps it: `tests/.probes/` is gitignored (`.gitignore:74`) and ESLint-ignores the area (`eslint.config.mjs`, BUG-0030), so neither `git status` nor the suite ever names it. pids are recycled, so a later worker drawing the dead run's number walks the corpse's files as if it had planted them — and every case compares the walk with `toEqual`.
