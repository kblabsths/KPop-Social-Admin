# npm run test:live is red as invoked: one edit.live case exceeds its 60s timeout under the suite's own parallelism

## Description
M3 endgame verification, 2026-09-11, HEAD bed26500, staging ubfjjqlvnpnoborczbdb.

FROM A CLEAN START (repo root, nothing else touching staging):
  ( set -a && source .env && set +a && npm run test:live )
EXPECTED (M3 EC2, and the check block of every ticket that touches a page): exit 0.
OBSERVED: exit 1, twice out of two full-suite runs (12:10 and 12:16 local).
  FAIL |live| tests/live/edit.live.test.ts > a resolver-owned record page > shows the venue source on EVERY event the log holds a venue decision for, and moves no scalar's line
  Error: Test timed out in 60000ms.   (tests/live/edit.live.test.ts:598)
  Test Files 1 failed | 10 passed (11); Tests 1 failed | 120 passed (121)
Run 1 was under walk load; run 2 was clean, with only two idle local servers. Same failure both times.

THE SAME FILE ALONE IS GREEN:
  ( set -a && source .env && set +a && npm run test:live -- tests/live/edit.live.test.ts ) -> exit 0, 25 passed
  and that case takes 45,627 ms of its 60,000 ms budget with nothing else running - 76% of budget, solo.
So it is not a wrong assertion; the case walks every event the log holds a venue decision for (120 events on staging) as serial round trips, and under the eleven-file parallel run it crosses 60s.

WHY IT MATTERS: this is the command EC2 names and the command the campaign's tickets cite as their live gate. As invoked, the gate is red at the M3 close, and the next agent to run it will read a failure that says nothing about the tree. The six per-page parity suites themselves are all green (dashboard, cycles, browse, queues, sources, review-item, claims, runs, harness, residue - 10 files, 120 tests).

## Acceptance criteria
'( set -a && source .env && set +a && npm run test:live )' exits 0 on three consecutive runs on this machine with nothing else driving staging. The case that timed out either bounds its read (it proves a property over the venue-decision set, and a bounded sample or a single round trip carries the same property) or is given a stated timeout with the measured margin written beside it; its assertion is not weakened. Its solo wall time is recorded in the ticket in ms.
