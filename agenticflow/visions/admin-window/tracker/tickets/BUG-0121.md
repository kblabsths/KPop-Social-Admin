# The queues detail page's empty state cards set review_items in sans — the face BUG-0120 fixed one route over

## Description
Measured on the QA pass of admin-window/BUG-0120, 2026-09-09, on a production build (`next start`, port 8781) against staging, 1440x900, light and dark, console clean.

**Expected** — LOOK_AND_FEEL Voice bar 5: machine identifiers "render verbatim in mono and are never prettified into Title Case prose". `review_items` is a table name — the machine's word — and BUG-0112/BUG-0120 settled that a table name in this app's prose gets the identifier-in-prose spelling. The record page now does that in its heading, its regime note and BOTH empty cards.

**Found** — `/queues/<id>`'s two empty state cards print `review_items` in body sans, one line under the id they echo back in mono.

| path | line | face measured (light) |
| --- | --- | --- |
| `/queues/x` | `[data-review-item]` id echo | Geist Mono 11px, rgb(74,85,101) |
| `/queues/x` | "The address bar does not hold an id: **review_items** ids are uuids, 32 hexadecimal digits…" | Geist 12px, rgb(74,85,101) |
| `/queues/00000000-0000-4000-8000-000000000099` | `[data-review-item]` id echo | Geist Mono 11px, rgb(74,85,101) |
| `/queues/00000000-0000-4000-8000-000000000099` | "No row with that id in **review_items**" | Geist 12px, rgb(30,41,57) |

Dark theme identical but for ink (mono/sans both rgb(229,231,235) or rgb(153,161,175) per slot); the FACE disagreement is the same in both themes. Both states are ordinary operator paths: a half-pasted or stale id. Both answer 200.

Repro: start the built app against staging, open `/queues/x` at 1440x900 and read the id echo, then the card's second line — the same kind of word, two faces, one paragraph apart. Then open `/queues/00000000-0000-4000-8000-000000000099` and read the card's FIRST line.

Anchors: `src/app/queues/[reviewItemId]/page.tsx:180-183` (`NOT_AN_ID`, `${T.reviewItems}` interpolated into a plain string), `:602` (`holds={`row with that id in ${T.reviewItems}`}`). `Empty`'s `holds`/`filledBy` are already `ReactNode` since admin-window/BUG-0120 (`src/components/ui/empty.tsx:15-38`), so this route can wrap without touching the primitive — the fix is this file alone.

Scope note: `review_items` is not an English word on this screen, so there is no second-fixture trap of BUG-0120's kind here. `T.reviewItems` is the name the code already uses; wrap that one word, change nothing else. `review item` (two words, prose) is the app's own noun and stays sans.

Pinned red before filing: `tests/offline/review-item/page.test.ts`, describe "a table name in a queues empty state card" — two `it.fails` xfails, watched failing as plain `it`s with `expected [] to deeply equal [ [ 'type-data' ] ]` on both. They take their yardstick off the page's OWN machine word — the id it echoes above the card — so they pin no face literal; when the fix lands, `it.fails` turns red on the XPASS and the `.fails` comes off.

Evidence: `agenticflow/tracker/evidence/BUG-0120/walk.json` (computed styles, both themes, 8 states across both routes).

## Acceptance criteria
1. On both empty states of `/queues/[reviewItemId]` — the not-an-id card and the no-such-row card — `review_items` renders at the data step in mono, verbatim, in the same face the page gives the id it echoes above the card. The words the app wrote around it stay body sans.
2. One spelling, not a new one: the app's existing identifier-in-prose span (`type-data text-ink`, as `NotProvisioned`, the record page's `TableName` and the regime note emit).
3. No change to the cards' words, their order, their spacing, their type step, their eyebrow or their state hooks (`data-state="empty"`), and no change to which state answers which address.
4. The two `it.fails` pins in `tests/offline/review-item/page.test.ts` ("a table name in a queues empty state card") lose their `.fails` and pass as ordinary tests.
5. `npm run lint` and `tsc --noEmit` clean; the full offline suite green.
