# The app's one uuid grammar (isRecordId/canonicalRecordId) is pure but lives in lib/db/records.ts, so no leaf may import it and /claims never got it

## Description
M2 structure walk finding (architect, 2026-09-09), measured on run/admin-window.

`isRecordId` and `canonicalRecordId` (`src/lib/db/records.ts:167-178`) are PURE functions over a string — no client, no env, no table name. They are the app's ONE uuid grammar, and BUG-0140 exists because a URL spelling PostgREST matched was denied by a page that compared raw. Their docstring is explicit: 'canonicalise where the value is DERIVED from the request, once'.

They sit in a `lib/db/**` module, and §4 rule 7 forbids a pure domain leaf from importing `lib/db/**` — not a value and not a type. Two consequences already landed:

1. **A leaf cannot use the grammar.** The BUG-0141 ruling (ARCHITECTURE History, 2026-09-09) had to specify that `source_id` is 'canonicalised ONCE at the page with `canonicalRecordId` — handed INTO the leaf as an argument, because a pure domain leaf may not import `lib/db/**`'. That is a workaround for a misplaced file, written into a ruling as if it were a design choice.
2. **The grammar did not travel.** Five call sites import it (`app/sources/page.tsx`, `app/records/[table]/[id]/page.tsx`, `app/queues/[reviewItemId]/page.tsx`, the settle route, and BUG-0141's queues work). `/claims` is not among them: `src/lib/claims/filters.ts` takes `record_id` as a raw string facet, so BUG-0140's defect — a real id in an uppercased or hyphen-less spelling reading as 'nothing matched' — is still shipping on `/claims?record_id=`, one route over from where it was fixed. Common violations row 9 in its quietest form: not copied, just unreachable.

The move is small: the two functions and their tests go to a new pure leaf `src/lib/records/id.ts` (the `lib/records/**` leaf directory already exists, holding `provenance.ts` and `routes.ts`), `lib/db/records.ts` consumes the leaf, and the call sites change their import path. Nothing about the grammar itself changes.

Dependency: DEBT-0008 owns `src/app/claims/page.tsx` and lands first; this is the second write to that destination.

## Acceptance criteria
1. `isRecordId` and `canonicalRecordId` are declared in a pure leaf under `src/lib/records/` that imports nothing which can reach a database — no `lib/db/**`, no `@supabase/supabase-js`, no `process.env` (§4 rule 7). `lib/db/records.ts` consumes the leaf; the leaf does not import it back, not a value and not a type.
2. `/claims?record_id=<an id the view holds, uppercased>` and `/claims?record_id=<the same id with hyphens removed>` narrow to the same rows as the canonical spelling, and the chip and row links spell the narrowing back in the ONE canonical form — the property BUG-0140 established on `/sources`, now on `/claims`.
3. A `record_id` that is not a well-formed id still narrows nothing on `/claims` and is reported by the page's existing dropped-parameter path, unchanged.
4. Every case BUG-0140 pinned on `/sources` still holds, and the record page, the queues item page and the settle route behave identically — the import path moved, the grammar did not.
5. The leaf's purity is pinned by a test that fails if the leaf gains an import that can reach a database, on two fixtures (one import it must flag, one it must not) — or by extending `tests/offline/db/layering.test.ts`, which already owns that ratchet.
6. `npm run lint` and `tsc --noEmit` clean.
