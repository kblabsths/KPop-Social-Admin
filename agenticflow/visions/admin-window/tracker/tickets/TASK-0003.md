# The live harness: staging-only credentials, the parity helper, the sweep helper

## Description
Module: `tests/live/` — the harness every page's parity test plugs into. Authority: acceptance doc ground rules ('Staging only', 'an unset name is a refusal, never a fallback') and tests 1, 2, 13; SPEC F2; ARCHITECTURE section 10.

Ships:

1. `tests/live/setup.ts` — the ONE place `STAGING_SUPABASE_URL` and `STAGING_SUPABASE_SERVICE_ROLE_KEY` are read. It loads `.env` explicitly with `dotenv` (Vitest does not read it), and it **refuses loudly** — non-zero, no fallback, no default — when either name is unset. It then makes the app's data layer point at staging for the live run by setting the process env the app reads, in this file only; product code never mentions a `STAGING_` name.
2. **A staging-target guard.** The host in `STAGING_SUPABASE_URL` must match the staging target declared in `agenticflow/docs/SERVICES.md`; no declaration, or a mismatch, is a refusal. This is what makes 'production is never a target' structural rather than a promise. Add the `## supabase` section to `SERVICES.md` **only** if Ben has already declared the target there — if the section is absent, do not invent it: say so on the ticket and leave the guard refusing.
3. `tests/live/parity.ts` — the reusable per-page parity mechanism: render a page function to markup, extract a named number from it, and compare it with a count the **test itself** issues. The comparison query must be written independently of the `lib/db` function the page used — two paths to one number, or it proves nothing.
4. `tests/live/sweep.ts` — record-and-restore for any row a live test touches, run in a `finally` so a failing assertion still sweeps (acceptance test 13). In M1 the only writer is the edit-surface test (TASK-0017/0018); the helper exists now so nobody hand-rolls one later.
5. `tests/offline/live-guard.test.ts` — an offline test proving the refusal path: with the names unset, the setup module throws/exits rather than falling back.

Note for whoever runs this: as of 2026-09-01 `.env` carries neither STAGING name (Ben is adding them) and `SERVICES.md` declares no service. Until both exist, `npm run test:live` refusing IS the correct, passing behavior of this ticket — do not weaken the guard to make a live test run.

Out of scope: writing any actual page parity test (each page ticket writes its own), any fixture rows in resolver-owned tables (that is a blocked question), any `src/` change.

## Acceptance criteria
[test 1, test 13] `npm test` stays green with the STAGING names unset. `npm run test:live` exits non-zero with the names unset and says which name is missing — it never falls back to `SUPABASE_*`. The staging-target guard refuses a host that is not the one declared in `agenticflow/docs/SERVICES.md`. The parity helper and the sweep helper are exported and documented, and the sweep runs in a `finally`. No file under `src/` mentions `STAGING_`.
