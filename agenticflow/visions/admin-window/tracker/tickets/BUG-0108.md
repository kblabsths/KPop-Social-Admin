# The rest of BUG-0099's sweep: 132 links on Dashboard, Claims, Sources, Browse and the verdict log still announce themselves only under the pointer

## Description
BUG-0099 fixed three surfaces on the M2 early walk and said so in its own body: "Scope, honestly: `hover:text-accent` occurs in ten files under `src`, including the Dashboard, Claims, Browse and Sources tables which this early walk did not cover. **This ticket grades the three surfaces measured above; the rest is the endgame walk's sweep** unless the fix generalises, which it should." This is that sweep. The fix did not generalise: `src/components/cycles/links.ts` now publishes the one spelling (`IN_PAGE_LINK = "text-accent underline"`) and three files were converted to it, and eight files still carry the rejected one.

**Expected** — LOOK_AND_FEEL states twice, as fact about this app, that a link is drawn at rest: the asked-for-row rule ("carries that id as an in-page link **drawn as a link at rest** (accent ink, underlined)") and the resting-edit-affordance rule ("Hairline rather than accent is what keeps it apart from a link, **which this app draws as accent ink plus underline**").

**Found** — measured `color` and `text-decoration-line` at rest inside `main`, 1440x900, light theme, after the 120ms transition settles:

| surface | anchors | at rest | class |
| --- | --- | --- | --- |
| `/` Dashboard, the cycle and run "5d ago" / "8d ago" links | **11** | `rgb(30, 41, 57)`, `none` | `transition-colors hover:text-accent` |
| `/` Dashboard, the two run error strings | 2 | `rgb(193, 0, 7)`, `none` | `type-data whitespace-nowrap text-broken` |
| `/claims` (both tabs), bucket names and claim-row links | **61** | `rgb(30, 41, 57)`, `none` | `transition-colors hover:text-accent` |
| `/browse`, the 50 event titles | **50** | `rgb(30, 41, 57)`, `none` | `transition-colors hover:text-accent` |
| `/sources`, source names and the per-source "review items" / "runs" links | **10** | `rgb(30, 41, 57)`, `none` | `transition-colors hover:text-accent` |
| `/cycles` (fixed by BUG-0099's neighbour) | 2 | `rgb(152, 16, 250)`, `underline` — correct | `text-accent underline` |
| `/queues` row link, review-item header and evidence `source` (fixed by BUG-0099) | 3 kinds | accent + underline — correct | |

`/browse` is where it costs most: every one of the 50 titles goes somewhere, and not one of them says so — the page reads as a static list of event names. `/claims` is the same shape at 61.

Remaining files carrying `hover:text-accent`: `src/app/page.tsx`, `src/app/claims/page.tsx`, `src/components/browse/browse-table.tsx`, `src/components/claims/bucket-table.tsx`, `src/components/claims/claim-list.tsx` (x2), `src/components/sources/registry-table.tsx` (x3), `src/components/sources/trends.tsx`, and `src/components/queues/verdict-log.tsx` (x2). The last is not walkable today — `verdicts` is absent so the tab renders its not-provisioned card — but it is the verdict log's row links, and it ships the rejected spelling into the first screen the operator sees after Ben installs the migration.

The cost is bar 10's, not decoration's: "The investigation never leaves the app: from any review item you can reach its claims, from a claim its source and the fact's provenance, from an event its edit surface — each in one click". A route that announces itself only under the pointer is a route found by sweeping the mouse across a page.

Provenance checked before filing: `git log` on every file above returns ticket-bearing commits only (TASK-0039, DEBT-0006, DEBT-0003, BUG-0074, DEBT-0007, BUG-0049, BUG-0043, BUG-0048, BUG-0047, DEBT-0004, TASK-0058, …). No human-lane divergence; violation, not reconciliation.

Evidence: `agenticflow/tracker/evidence/M2/designer/browse-light-1440.png`, `claims-light-1440.png`, `dashboard-light-1440.png`, `sources-light-1440.png`.

**Sibling note (BUG-0106).** Both tickets touch `src/app/page.tsx` and both were found on this walk. BUG-0106 is about the **colour of a word the database wrote** — an outcome badge that must go amber when its row reports errors; this one is about **whether a thing that navigates says it navigates** — anchor ink and decoration at rest. They meet only in that one file and in no line of it: BUG-0106 deletes the Dashboard's duplicated `OUTCOME_TONE`, this one converts the Dashboard's eleven age anchors and two error anchors to `IN_PAGE_LINK`. Land either first; neither blocks the other.

## Acceptance criteria
1. Every anchor inside `main` on `/`, `/claims` (both tabs), `/sources`, `/browse` and the `/queues` verdict-log tab renders at rest as this app spells a link: accent ink plus an underline, no hover required. Measured by computed style; zero anchors under `main` remain at `rgb(30, 41, 57)` with `text-decoration-line: none`.
2. There is **one** spelling of a link in `src` and it is `IN_PAGE_LINK` in `src/components/cycles/links.ts` — the constant BUG-0099 established for exactly this. The eight files listed stop carrying their own; `hover:text-accent` occurs zero times under `src` outside that module's docstring.
3. The Dashboard's two run **error** anchors keep `text-broken` — an error line is red by palette job — and gain the underline, so a red string that navigates is distinguishable from a red string that does not.
4. Contrast holds in both themes (bar 12): accent measures >= 4.5:1 on `surface` and on `chrome`, including on a hovered row whose fill is chrome.
5. The resting **edit** affordance stays distinct from a link: an editable value keeps its 1px hairline underline in primary ink, a link is accent — the record page draws both and they are not confusable.
6. No change to ink weight, row height, cell padding or table density: this changes colour and decoration only.
7. Human-check: on `/browse` at 1440x900, without moving the mouse, it is visible that the event titles are links and the other columns are not. (human-checkable)
8. `npm run lint` and `tsc --noEmit` clean; the targeted offline files green; the four live page suites green.
