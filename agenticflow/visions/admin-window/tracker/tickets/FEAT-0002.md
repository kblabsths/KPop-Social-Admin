# Staging reads, the not-provisioned state, and the live/offline test harness

## Description
VISION: "Against a database that lacks the ecosystem tables, every page says so honestly and nothing crashes" and "Production is never a target. Only the staging project, by name; the deployed service is never repointed; no secret value ever appears anywhere." SPEC F2. Contracts read 2026-09-01: admin-observability.md §3 (server-side reads reach the internal tables) and §4; admin-build.md ground rules "Staging only" and "The deployed Railway service is never repointed", tests 9 and 13. Server-side, service-role reads of resolution_runs, review_items, the pending-claims classification view, the standing-disagreements view, observations, field_provenance, sources and the canonical tables, against the staging project named by STAGING_SUPABASE_URL and STAGING_SUPABASE_SERVICE_ROLE_KEY — an unset name is a refusal, never a fallback. When a backing table or view is absent, the page renders a not-provisioned state naming what is missing and nothing throws, which is what keeps every push to main deployable against whatever project the deployed service targets. Ships the test harness the other features plug into: offline by default, staging tests behind an explicit live marker, each live test sweeping every row it wrote, plus the reusable per-page parity mechanism (rendered numbers vs direct SQL on staging). Zero schema: no migration in this repo, no DDL from app code, no SQL-executing route.

## Acceptance criteria
M1 EC11, EC13, EC1, EC4. Acceptance test 9: against a database lacking the resolver tables, each of the six pages returns 200 with its not-provisioned marker and zero unhandled errors. Acceptance test 1: the suite is green with the STAGING_SUPABASE_* names unset (live tests skipped, never falling back) and green with them set. Acceptance test 13: the post-run sweep query returns zero campaign-written rows on staging. Zero schema — `bash -c "test $(ls supabase/migrations | wc -l) -eq 2"` passes (no migration added to this repo). Secret names only, never values — `bash -c "grep -q STAGING_SUPABASE_URL .env.example && grep -q STAGING_SUPABASE_SERVICE_ROLE_KEY .env.example"` passes and no value appears in any file, commit, ticket, receipt or evidence note. The production project is never contacted and railway.toml is untouched.
