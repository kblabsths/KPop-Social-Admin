# The verdict log's own observation id and action are the same missed call site BUG-0148 fixed one tab over — outside the identifier primitive

## Description
Found attacking admin-window/BUG-0148 on the landed run branch (03774e0), which put the review-item close block's unlinked observation id through the shared `Identifier` primitive.

**Expected** (DEBT-0011 criterion 2, the rule BUG-0148 was filed and fixed under): "Every call site that renders a machine identifier — a table or view name, a column name, a status/shape/bucket value, **an id** — imports the primitive." Criterion 4: the primitive is where the ARCHITECTURE §7 / Common-violations row 15 bidi isolation is applied ONCE, so every identifier gets it.

**Found**: `src/components/queues/verdict-log.tsx` renders the SAME column BUG-0148 just fixed, on the other tab, outside the primitive:

- `:143` — `<span data-verdict-observation={row.observationId}>{row.observationId}</span>`, the unlinked arm of the observation-id column (`verdicts.observation_id`, an id the database produced). Not an anchor; the linked arm at `:145-151` is the sanctioned anchor exception, this one is not.
- `:114` — `<span data-verdict-action={row.action}>{row.action}</span>`, the action column, whose own comment calls it a machine identifier "verbatim, in the table's own mono cell (§11)". Its twin in the review-item block (`review/close/slot.tsx:281`) already goes through `Identifier`.

Neither spells the face by hand, which is why DEBT-0011's one-owner sweep (`tests/offline/ui/primitives.test.ts`) is green on them: the mono face arrives from `DataTable`'s own cell, `src/components/ui/data-table.tsx:169` (`"type-data px-2 py-1.5 text-ink"`). The isolation arrives from nowhere.

**The table is not one of DEBT-0011's stated boundaries, and that is measured rather than argued**: `src/components/cycles/run-columns.tsx:73` (`source`) and `:185` (`failure_class`) are `Column.cell` bodies in the SAME `DataTable` that already render through `<Identifier>`. So the run table's cells are identifiers and the verdict log's are not, in one app.

**No user-visible harm today, and this ticket says so honestly.** A `<td>` is a block box, so a bidi override inside a cell can only reorder that cell's own content, and each of these cells holds exactly one value and no app-authored word. What is wrong is the same thing BUG-0148 was filed for: the face is coupled to an ancestor by inheritance rather than owned, the isolation is absent, and a future rule hung on the primitive (the next `unicode-bidi`, the long-identifier wrap BUG-0105 had to solve alone) will not reach these two cells. P3 for exactly that reason — completeness of the sweep, not a defect an operator can hit.

**Repro (offline, exact, on the landed tree)**: flip the strict pin `renders the log's machine values through the one identifier primitive, like the run table's cells` in `tests/offline/queues/verdict-log.test.ts` from `it.fails(` to a plain `it(`, then `./node_modules/.bin/vitest run --project=offline tests/offline/queues/verdict-log.test.ts`. Watched RED before filing: `1 failed | 23 passed`, failing at `expect(observation.attr("dir"))` with `an id the database produced is isolated here too: expected undefined to be 'ltr'` — AFTER `expect(primitive.attr("dir")).toBeDefined()` and the cell's own length/anchor assertions have passed, so the pin is not vacuous. As landed it is `it.fails` and the file is green at 24 passed; the day both cells go through the primitive the XPASS turns the file red and sends the reader here.

The pin types no class literal and no attribute value: the isolation marker is read off `Identifier`'s own render, so a restyle of the primitive moves the assertion with it.

**Fix shape**: wrap both cell bodies in `<Identifier data-verdict-observation=… >` / `<Identifier data-verdict-action=… >` (the hooks are already `data-*`, which the primitive's prop type carries), leave the two anchor cells (`item`, and the linked observation arm) exactly as they are, and flip the pin to a plain `it(`. Expect a markup delta of `dir="ltr"` plus the primitive's class pair on those two spans; the `td` already inks them identically, so nothing on screen moves.
