# A source is labelled by raw uuid on the review item and on Claims, while the rest of the app names it

## Description
Found on the M1 endgame designer walk (2026-09-03), walk instance :8771 against staging, 1440x900.

Three places render a source as its uuid where the app elsewhere renders its name:

1. **Review item header** (`/queues/01a06287-...`): two links read, verbatim on screen,
   `Its claims 01a05782-8e7f-752c-ae60-3ce4c51962f6` and `Its source 01a05782-8e7f-752c-ae60-3ce4c51962f6`.
2. **Claims, SOURCE column**: every one of the 877 rows renders `01a05782-8e7f-752c-ae60-3ce4c51962f6`.
3. **Claims, SOURCE_ID facet**: the single option is `01a05782-8e7f-752c-ae60-3ce4c51962f6`.

The app has the name and uses it everywhere else: `/sources`' identical `SOURCE_ID` facet offers `test_harness`, `test_harness_control`, `ticketmaster`; `/browse`'s SOURCES column reads `ticketmaster`; the record page's provenance reads `ticketmaster, applied 1d ago`; the Dashboard's runs table reads `ticketmaster`.

**The self-contradiction is on one screen.** On the review item, the header link `Its source 01a05782-...` and the 91 evidence-table cells directly below it that read `ticketmaster` point at the *same href* — `/sources?source_id=01a05782-8e7f-752c-ae60-3ce4c51962f6`. One page, one destination, two labels.

Rules: LOOK_AND_FEEL.md the Look, the evidence pair — "the **value**, then `source · tier · age`" and "The order and the anatomy never change between screens — that repetition is what lets the operator read a conflict in two seconds"; and the Voice register — "it talks like the pipeline's engineer reading you its own logbook — plain, specific". An engineer with the name in hand reads you the name.

This is not a broken link: the destinations are right and Feel bar 10 (the investigation never leaves the app) is met. It is what the link SAYS.

Evidence: `agenticflow/tracker/evidence/designer-walk-m1/reviewitem-light.png` (header links), `claims-light.png` (SOURCE column and the facet), `sources-light.png` (the same facet, named).

**What this adds that its siblings do not.** BUG-0041 is about how MANY claim rows `/claims` renders and where that leaves the gauge; BUG-0042 is about the review item's table overflowing its border. This one is about the WORDS in three cells and two links — it changes no layout, no row count and no scroll behaviour, and it would still stand if both siblings were fixed today.

## Acceptance criteria
On the review-item header, the two links read as a person would say them — the source named, not its uuid — and the label matches the label the same href carries in the evidence table below it.

On `/claims`, the SOURCE column and the SOURCE_ID facet render the source's name, exactly as `/sources`' facet already does for the same three sources.

Where a uuid is genuinely the only thing known (a source row not in the registry), the uuid still renders verbatim in mono rather than a blank or a guess — Voice bar 5.

Targeted offline tests pin the naming so a later refactor cannot fall back to the id: `tests/offline/review-item/page.test.ts` and `tests/offline/claims/page.test.ts` assert the rendered markup carries the source NAME for a source present in the registry, and that the header link's label equals the evidence table's label for the same href.

Human-check: on the review item and on Claims, no source appears as a bare uuid where `/sources` shows a name for it. (human-checkable)
