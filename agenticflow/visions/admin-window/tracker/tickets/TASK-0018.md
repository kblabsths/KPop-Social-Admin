# The edit surface — the record page, direct edits for groups and idols, read-only events and venues

## Description
Module: `src/app/records/[table]/[id]/page.tsx` + `src/components/records/`. Authority: spec section 8; SPEC F8; M1 EC10; acceptance test 7 (pre-cutover half); LOOK_AND_FEEL 'Key screens — Edit surface' ('the field, its value, its provenance, and whether it is admin-locked, on one line — editing must never hide where the value came from') and 'Inputs and inline edit'.

- One record page for every table in `EDIT_CONFIG`, reached from Browse (`/records/events/<id>`) and from a review item's affected record.
- **The widget follows the field's kind**: a scalar column edits as a cell — the `EditableCell` primitive (click to edit, Enter or blur saves, Escape reverts, a green confirmation for 1.5s, a red line naming the failure with the value reverting). Reference-field pickers arrive with the override path in M2 and are **not** built here.
- **A column absent from the map is read-only at the surface**, whatever the route could technically reach — and the route refuses it anyway (TASK-0017). Both halves, not either.
- **`events` and `venues` render read-only.** No editable widget, no disabled-looking input that could be re-enabled, no 'coming with the verdict slice' button.
- **Provenance at the field.** For a resolver-owned table, show the field's provenance line from `field_provenance` ('ticketmaster, applied 3d ago' / 'admin-set Jun 12') and whether it is `admin_locked`. For `groups` / `idols` — pre-cutover and unprovenanced by construction — **no `field_provenance` row exists**; what to render there is a blocked question (see the provenance ASK ticket). Until it is answered, render nothing in that slot rather than a guess, and do not invent a placeholder value.
- The live test for this ticket is the milestone's **only** writer: it edits one mapped field on one `groups` row and one `idols` row on staging, asserts the value persists across a reload, and **sweeps in a `finally`** by restoring the prior value (acceptance test 13). It also sends a forged edit naming an unmapped column and asserts the row is unchanged.

## Acceptance criteria
[test 7 pre-cutover half, test 13; EC10] A mapped column on a `groups` record and on an `idols` record edits, and the value persists after reload (proven by the live test, which restores the prior value in a `finally`). A column absent from the map renders read-only **and** is refused server-side. `events` and `venues` render with no editable field at all. Offline tests render the page for each table in the map and assert which fields are editable. The provenance slot renders per the rule above and never invents a value. (human-checkable) Screenshots of the groups and idols edit flows are captured for the close review.
