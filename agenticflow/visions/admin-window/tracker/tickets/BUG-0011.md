# PATCH with no `value` key silently NULLs a catalog column and answers 200

## Description
Expected (contract): the record PATCH route documents its body as `{ "field": …, "value": … }` (`src/app/api/admin/records/[table]/[id]/route.ts:26`, and `parseBody`'s own doc: "An empty string clears the field (`null`)"). A body that carries no `value` key at all states no intent — it is malformed, and the route already answers 400 for every other malformed shape (non-object body, non-string `field`, empty `field`, object/array `value`). The retired route this one carries over from (`git show 5cf4199^:"src/app/api/admin/groups/[id]/route.ts"`) nulled on `""` alone and never on an omitted key.

Found: the omitted key is coerced to an explicit NULL and WRITTEN, and the caller is told it succeeded.

`src/app/api/admin/records/[table]/[id]/route.ts:88` —
    if (value === null || value === undefined || value === "") {
      return { ok: true, field, value: null };
    }
`undefined` is what destructuring produces for an ABSENT key, so "the key is missing" and "the caller asked to clear this field" are the same branch.

Exact repro (measured 2026-09-02 on run/admin-window @ ac2738d, handler driven directly with the admin gate stubbed open — `agenticflow/tracker/evidence/TASK-0017/probe.test.ts`):

  PATCH /api/admin/records/groups/2f0bc11e-0000-4000-8000-000000000001
  content-type: application/json
  {"field":"bio"}

  STATUS: 200
  BODY:   {"ok":true,"record":{...,"bio":null}}
  WRITER CALLED: 1
  VALUE PASSED TO WRITER: null

Expected: a non-2xx naming the missing `value`, and `updateRecordField` never called. Found: 200 `{"ok":true}` and one UPDATE issued setting the column to NULL.

Impact. This is the app's only write path, it runs with the service-role key (RLS bypassed), and the columns it reaches are the vetted catalog. Of `groups`'s ten editable columns, nine are nullable in the scraper schema snapshot (`kspace Scraper/supabase/migrations/20260818000000_the_schema_arrives_as_one_snapshot.sql:3026` — only `name` is NOT NULL; `status` has a CHECK, which NULL passes), so a malformed request destroys a vetted value and is answered as a success. `idols` is the same shape. AGENTS.md's data-ownership rule makes Admin's job corrections — a silent null-out reported as `{"ok":true}` is the opposite.

Reachability is not theoretical: `JSON.stringify({ field, value })` OMITS the key when `value` is `undefined`, so a widget (TASK-0018) that lets an undefined reach the body produces exactly this request and gets a green "saved" back from `EditableCell`.

Not a security escalation — the caller must already be past `requireAdmin()`. It is silent, acknowledged data loss on the canonical catalog. P2.

Fix: distinguish an ABSENT `value` key from a present `null`/`""`. Suggested — refuse when `!("value" in body)` with 400 ("value is required; send null to clear the field"), leaving the explicit `null` and `""` clearing paths untouched (`tests/offline/edit/route.test.ts` > "still clears a column on an explicit null or an emptied input" pins those and must stay green).

The pin: `tests/offline/edit/route.test.ts` > "refuses a body that omits `value` instead of clearing the column" is marked `it.fails` — a strict pin, green only while the divergence is live. Fixing the route turns it RED; the fix therefore also flips `it.fails` back to `it` in that file. It was watched failing as a plain `it` against ac2738d before this ticket was filed (AssertionError: value omitted: expected 200 to be greater than or equal to 400).
