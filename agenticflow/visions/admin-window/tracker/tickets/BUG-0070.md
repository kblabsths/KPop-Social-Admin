# /claims drops its window line on a read that happened and found nothing, where every other windowed surface keeps it

## Description
Ruled by the architect 2026-09-04, from the M1 residual queue. Two suites
currently pin two different readings of the same rule and this ticket settles
which one is the contract.

**The rule, now written into ARCHITECTURE §4.3** (promoted this pass, third
instance of the class): *a window line states a read that HAPPENED, and an empty
window is still a window.* A surface publishes its `data-window` hook and its
sentence when, and only when, the read it describes returned — `ok` with rows or
`ok` with none. A refused, absent or unmade read publishes no line and no count.
That is what makes the ABSENCE of the line mean one thing everywhere ("this read
did not happen") and `data-window-held="0"` mean one thing ("it happened and
found nothing"), which is what lets a live oracle grade the empty case at all.

**Found**: `/claims` is the one surface that breaks it. On an `ok` read whose
matching set is empty, the list section renders the `Empty` card and returns
BEFORE the window line (`src/app/claims/page.tsx`, the `shown.length === 0`
branch, whose comment states the old reading: "an empty matching set renders the
Empty card above, with no line at all"). Measured on this tree 2026-09-04, every
surface that publishes a window against a populated database, then the same
surface against an empty one:

    /claims : healthy=[claims]                                 empty=[]
    /sources: healthy=[awaiting_row,rejections]                empty=[awaiting_row,rejections]
    /cycles : healthy=[cycle_health,cycles,resolution_latency,runs]
              empty=[cycle_health,cycles,resolution_latency,runs]

Six hooks keep their line on an empty read; one drops it. So on `/claims` an
operator who filters down to nothing is told nothing about where the app looked,
and the state is one hook away from the state where the read never happened.

**Which reading is the contract, and why this one.** Dropping the line on empty
would make an honest empty read and a failed read look identical on screen —
precisely the confusion BUG-0016, BUG-0063 and BUG-0067 each fixed one surface
at a time — and it would take the `0` away from the parity oracles that grade
by `data-window-held`. Keeping it costs a sentence beside a card. The card and
the line say different things and both are true: the card says what would fill
the surface, the line says where the app looked.

**Scope note — the `Empty` card stays.** This is not "render the table instead".
The list still renders the Empty card (all three of this page's emptinesses keep
their own rendering: the view that holds nothing, the filter that matched
nothing, the view that is not in this database); the window line stands with it.
And the not-provisioned and error states keep dropping the whole line, which is
the half that is already right and already pinned.

**The second half of this ticket is what stops the fourth surface repeating
it.** `tests/offline/absence/pages.test.ts` already grades the rule, but its
"keeps the line on a read that happened and found nothing" leg asks `/cycles`
alone — which is why `/claims` diverged under a test whose docstring claims to
grade the rule itself. Generalise that leg to every surface that publishes a
window on a healthy read (measured: three routes, seven hooks today), so a new
surface inherits the rule instead of a comment about it.

## Acceptance criteria
On /claims, an ok read whose matching set is empty renders the Empty card AND the window line: the [data-window=claims] hook stands with data-window-held=0 and data-window-truncated=false, and the sentence beside it describes the window the page read. A read that did NOT happen — refused, transport failure, or the view absent — still publishes no window line and no count hook at all, exactly as it does today (the it.fails-adjacent pins in tests/offline/claims/page.test.ts stay green, and the docstring at the 'claims no count it never took' block is corrected, since it states the retired reading as fact). tests/offline/absence/pages.test.ts's second leg is generalised from /cycles to EVERY surface that publishes a window on a healthy read, asserting each keeps the same hook set on an ok-but-empty read; measured on this tree 2026-09-04 the leg then grades three routes and seven hooks (/claims claims; /sources awaiting_row rejections; /cycles cycle_health cycles resolution_latency runs) instead of two, and it fails rather than thinning out if a surface stops publishing a window entirely. The Empty card is unchanged and still renders — the line stands with it, never instead of it — and the three emptinesses this page distinguishes (the view holds nothing, the filter matched nothing, the view is not in this database) keep their three distinct renderings. tests/live/claims.live.test.ts still grades a populated staging read unchanged, and its empty branch, if it has one, reads the state kind structurally before it compares a number.
