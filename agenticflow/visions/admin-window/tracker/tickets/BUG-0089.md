# A wont_fix note of invisible characters passes all three note guards and settles the item

## Description
**Expected** (spec §7 / SPEC F10 / TASK-0051 criterion 2): `wont_fix` is the one action whose note is the contract — "the note is required: why the condition stands" — and a blank one is refused by the form, by `decisionRefusals`, and by `settle_review_item`. Three guards, deliberately.

**Found:** all three test blankness the same way, and none of them tests it by *visible content*. `closeRefusal` (`src/components/review/close/actions.ts:184`) and `present()` (`src/lib/verdict/decision.ts`, invariant 3) both use `String.prototype.trim()`, which strips the Unicode WhiteSpace set and U+FEFF but NOT the Cf format characters; the SQL artifact uses `v_note ~ '^[[:space:]]*$'` (`agenticflow/tracker/for-human/M2-handoff-settle-review-item.md:295`), whose POSIX class does not match them either. So a note of U+200B (zero-width space), U+2060 (word joiner) or U+00AD (soft hyphen) — the characters an operator gets by PASTING out of a web page or a PDF — is graded as a written note by every guard.

Measured on the landed tree (65e91ef, re-checked on 51c0c3a), `tests/offline/review-item/zz-qa-probe.test.ts` (a scratch probe, deleted; the pins below are its permanent form):

    closeRefusal(wont_fix, note):
      " " NBSP        -> note_required   (refused)
      "　"             -> note_required   (refused)
      "﻿" BOM         -> note_required   (refused)
      "​" ZWSP        -> null            (ACCEPTED)
      "⁠" word joiner -> null            (ACCEPTED)
      "­" soft hyphen -> null            (ACCEPTED)
      "  ​  "         -> null            (ACCEPTED)

    POST /api/admin/review-items/{id}/settle {action:"wont_fix", note:"​", value:null}
      -> 200, and the scripted database recorded 1 call to settle_review_item
         carrying p_decision.note = "​"
      (the four trim()-blank spellings above: 400 note_required, 0 database calls)

**Repro (exact):**
1. Open a signal review item's detail with `verdicts` installed (offline: `tests/offline/review-item/signal-actions.test.ts`'s `closeMarkup({kind:"ok"})`).
2. Paste a single zero-width space into the note field — nothing appears.
3. Press "Close as won't fix".
4. Expected: the form refuses and names the reason, sending nothing. Actual: the request is sent, the route answers 200, and `settle_review_item` is called once with a note of `"​"`.

**Why it is not cosmetic:** the item settles and `verdicts.note` — the permanent record of why the condition stands — holds a string nobody can read. The verdict log then renders it as content, because `isAbsent()` (`src/lib/format.ts:242`) also uses `trim()`: `verdict-log.tsx:171` takes the `isAbsent` branch only for a trim()-blank note, so an invisible one draws a blank `td` with **no em dash** — exactly the rendering admin-window/BUG-0085 was filed to remove.

**Pinned RED before filing**, then flipped to strict `it.fails` in commit 51c0c3a:
- `tests/offline/verdict/decision.test.ts` — "flags a note whose every character is invisible on wont_fix"; observed red: `"​": expected [] to include 'note_required'`.
- `tests/offline/review-item/signal-actions.test.ts` — "refuses a note whose every character is invisible" and "puts no invisible-only note on the wire"; observed red: `expected [ { …(2) } ] to deeply equal []`.

**The fix is one shared blankness test, not three** — the same identifier (`note_required`) already spans the two TS guards, so the predicate belongs beside them once and the SQL's regex widened to match. Flip the three `it.fails` pins back to `it(...)` when it lands. Whether the SQL half is a scraper-repo handoff or an edit to the artifact note in this repo is the architect's call.
