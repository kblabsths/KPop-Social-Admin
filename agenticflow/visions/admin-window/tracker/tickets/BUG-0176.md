# A paged not-provisioned answer renders red, stutters its object and tells the operator to press again for a table that does not exist — /claims and /browse

## Description
Walked on a production build against staging (own port 8795, my PID, killed; reads only). Forcing the paging route to answer {kind:'not_provisioned',missing:'pending_claims'} — the arm ARCHITECTURE §4.3 kind 3 builds on purpose ("A refusal is a refusal: not_provisioned naming its object") — draws this, in red #c10007, mono:

  pending_claims — pending_claims is not provisioned    Press it again to ask for the same rows.

Four rules, one line.

1. RED FOR AN UNAVAILABLE TABLE. LOOK_AND_FEEL, Palette: "RED MEANS BROKEN, NEVER UNAVAILABLE. A MISSING BACKING TABLE IS GRAY." And the four states, state 3: "Not provisioned — hairline border and SECONDARY TEXT naming the missing table and what creates it. GRAY, NEVER RED, never a zero that reads like data." The Refusal component carries text-broken on every arm, so the one arm that is about absence is painted as breakage.

2. THE OBJECT IS SAID TWICE. machine.ts builds the reason as "<missing> is not provisioned" AND passes the same missing name as the object, so Refusal's "object — reason" form renders "pending_claims — pending_claims is not provisioned". Register: "plain, specific" (LOOK_AND_FEEL, The Voice).

3. IT NEVER SAYS WHAT FILLS IT. Copy bar 4: "Every empty and NOT-PROVISIONED state names what the surface holds AND WHAT FILLS IT." The app's own canonical form is one component away — src/components/ui/not-provisioned.tsx renders "<missing> isn't in this database yet — it arrives with the scraper repo's migration." MEASURED on the same page one press apart: forcing /browse's provenance LEG to answer not_provisioned on page 2 drew exactly that sentence, in gray, beside the rows — "event_field_provenance isn't in this database yet — it arrives with the scraper repo's migrations." The LEG note is right and the PAGE refusal, ten pixels away, is wrong.

4. THE FIX IS WISHFUL. "Press it again to ask for the same rows." — pressing a button will not provision a table, so the operator is sent around a loop that cannot terminate. paging.tsx's own docstring states the rule it breaks: "the fix is only ever one the operator can take … the fix is never wishful (LESSONS 1, CONTENT)." The retryable branch is decided by whether a control is DRAWN, which is the right question for a transport failure and the wrong one for a missing object.

Reachability: the arm fires when the backing object disappears between the first screen and a press (the first screen would otherwise have rendered NotProvisioned and drawn no control). Rare, deliberate, and built — so its words and its colour are graded.

RULES VIOLATED: LOOK_AND_FEEL Palette ("red means broken, never unavailable"), the four states → state 3, copy bar 4, copy bar 3 ("names what failed, THEN WHAT TO DO"). Traces to VISION: "every page says so honestly and nothing crashes".

NOT IN SCOPE: the other refusal arms' red (a page that could not be read IS broken); the error arm's words; the hooks; NotProvisioned's own call sites.

Evidence: agenticflow/tracker/evidence/M3/designer/claims-refusal-db-error.png, browse-paged-leg-note.png (gitignored; the strings above are the durable record).


## The ruling (architect, 2026-09-11) — the arm carries FACTS, the app's one spelling carries the words

**Chain.** Behind BUG-0175, which lands the refusal's authorship fact
(`reasonFrom`) in the same interface and the same component; BUG-0175 is behind
BUG-0174. Serial at the destination: one component (`Refusal`), one construction
point (`refuse()`), three tickets, one file. The designer's sibling note stands —
the two criterion sets do not overlap, and BUG-0175 still grades the mono/sans
split on the four arms this ticket deliberately leaves red.

**The rules, by row:**

- `LOOK_AND_FEEL.md:88` (The Look → Palette, last row): *"Red means broken,
  never unavailable. A missing backing table is gray."* and the four data-surface
  states, state 3: *"hairline border and SECONDARY TEXT naming the missing table
  and what creates it. Gray, never red, never a zero that reads like data."*
- `LOOK_AND_FEEL.md:405` (copy bar 4): *"Every empty and not-provisioned state
  names what the surface holds and what fills it"*, whose own example is this
  app's exact clause; and copy bar 3 (`:401`): what failed, then what to do.
- `ARCHITECTURE.md` §7: the four data-surface states are four named primitives
  and `NotProvisioned` is the one for absence — *"a page that hand-rolls an
  empty state is a defect"*. A refusal line that says a table is missing is
  saying state 3 in a place a card cannot stand; it says it in the app's words
  or it is a hand-rolled fifth spelling.
- LESSONS 5 and Common violation 9 (`ARRIVES_WITH` ×8, DEBT-0003): a shared
  spelling gets imported, never retyped.

**1. The arm carries facts; the component owns the sentence.** `machine.ts` is a
lib module: it may not import a component (§4, one-way dependency), so it must
not author this arm's prose — which is also what kills the stutter structurally,
because a reason that does not name the object cannot say it twice. The contract
BUG-0175 leaves becomes:

```ts
// src/lib/paging/machine.ts
export type PageRefusal =
  | {
      /** A press this app could not complete — the four red arms. */
      condition: "broken";
      reason: string;
      reasonFrom: "this app" | "the machine";   // BUG-0175
      object: string | null;
    }
  | {
      /** The backing object is not in this database — absence, not breakage. */
      condition: "not provisioned";
      missing: string;
    };
```

`refuse()` keeps building the broken arm exactly as it does; the
`not_provisioned` case stops composing `${answer.missing} is not provisioned`
and carries `missing` alone.

**2. One spelling of the sentence, in the one place the app spells it.** The
clause `src/components/ui/not-provisioned.tsx` renders — *"…isn't in this
database yet — it arrives with \<what creates it\>."* — is now needed in a second
place, so it becomes ONE exported spelling in that file which both the card and
the paging refusal render. `ARRIVES_WITH` (`src/components/ui/state-of.tsx:15`,
"the scraper repo's migrations") stays the single spelling of what creates it and
is IMPORTED, never retyped. **The card must render byte-identically after the
extraction** — its existing cases in `tests/offline/ui/primitives.test.ts` pass
unmodified.

**Client boundary**: `paging.tsx` is `"use client"` and already imports
`./button` and `./window-line` by relative path. Import the spelling the same
way — never through the `src/components/ui` barrel (BUG-0094: a server module
importing a value out of a `"use client"` module builds green offline and answers
500 in production; `tests/offline/shell/client-boundary.test.ts` owns the rule
and is in the check line).

**3. Gray, from the same token the card uses** (`text-ink-secondary`), applied to
THIS arm only: the wrapper's blanket `text-broken` is what paints absence as
breakage, and the four broken arms keep their red.

**4. No wishful fix.** For an absent object there is no press and no reload that
provisions a table, so this arm draws neither instruction: the clause naming what
creates it IS copy bar 3's "what to do" half. The retryable / reload branch stays
exactly as it is for the arms a retry can clear — it keeps being decided by
whether a control is drawn, which remains the right question for a transport
failure. Every other invariant of the line is untouched: a refusal appends no
row, moves no bound, and does not remove the control.

The not-provisioned arm is OUTSIDE this rule — after criteria 1-5 it carries a fact and no reason at all, and it has its own words.
