# Claims' dropped-parameter line spells a hole again when the URL's key is invisible but not whitespace (?%E2%80%8B=1, ?%00=1)

## Description
Found while attacking admin-window/BUG-0127's blank-key fix on the LANDED tree (run/admin-window @ 8520fb6), over HTTP against a production build (own port 8796, staging, 2026-09-09) and in Chromium (both colour schemes).

**Expected** — BUG-0123 criterion 3: the dropped-parameter line names the parameter "verbatim in mono", and BUG-0127's own pin, `tests/offline/claims/page.test.ts` "spells a name, or none, but never a hole where a name goes".

**Found** — a key whose codepoints are invisible but NOT whitespace is spelled into the mono span, where it lays out at 0px and the sentence reads with the same hole BUG-0127 closed:

    $ curl -s -b <session> 'http://localhost:8796/claims?%E2%80%8B=1'
    200
    <p data-dropped-params="1" ...>The URL carries <span data-dropped-param="&#x200b;" class="type-data text-ink">&#x200b;</span>, which this page did not apply: nothing below is narrowed by it.</p>

Visible text: `The URL carries , which this page did not apply: nothing below is narrowed by it.`

Measured in a real browser (playwright, bundled Chromium, `agenticflow/tracker/evidence/BUG-0127/walk.py`), IDENTICAL in light and dark:

    ZWSP key U+200B     name span width_px=0     visible=False
    soft hyphen U+00AD  name span width_px=0     visible=False
    NUL key U+0000      name span width_px=0     visible=False  (Chromium drops the codepoint; the span is empty)
    record_id (control) name span width_px=59.41 visible=True

Six keys reach `named` and are spelled, all measured over HTTP on the production build:
`?%00=1` (NUL), `?%E2%80%8B=1` (ZERO WIDTH SPACE), `?%C2%AD=1` (SOFT HYPHEN), `?%E2%81%A0=1` (WORD JOINER), `?%E2%80%8E=1` (LEFT-TO-RIGHT MARK), `?%7F=1` (DELETE). `/claims?%E2%80%8B=1`'s body markup is 60630 chars against the bare page's 60409 — the difference is this sentence.

**Where** — `droppedParams()` at `src/lib/claims/filters.ts:184`: `if (key.trim() === "") continue;`. `String.prototype.trim` strips only the spec's WhiteSpace/LineTerminator set, so U+0000, U+007F, U+00AD, U+200B, U+200C, U+200E, U+2060, U+3164 and U+2800 all survive it (probe: `agenticflow/tracker/evidence/BUG-0127/trim-probe.js`), and the surviving key is rendered verbatim by `DroppedParamsLine` at `src/app/claims/page.tsx:382-410`. The rule the docstring states — "a key that is empty or whitespace-only names nothing, so it asked for nothing" — is right; `trim()` expresses only its whitespace half.

**Not caused by BUG-0127**: the same URLs produced the same hole before that fix. BUG-0127 closed the whitespace half; this is the half its `trim()` cannot see.

**Not a bug (checked, for the next reader):** everything BUG-0123 and BUG-0127 pinned still holds on this tree — `?=x`, `?%20=1`, `?%20%20=1`, `?%09=1`, a 500-space key and `?tab=standing&=x` all render body markup BYTE-IDENTICAL to the bare page (60409/60409, scripts and gauge excluded); `record_id` and `BUCKET` are named verbatim; `?record_id=abc&foo=1` names both on one line; `?in_window=1` is counted and not named; the parked bucket appears nowhere in the body markup on any of these URLs, including `?=in_window` and `?bucket=in_window`. Next's RSC flight payload (`self.__next_f.push`) echoes the raw query on every route and is not visible text.

**Scale** — P3: the rows, counts, chips, window line and bucket caption are all correct and unmoved in this state; only the sentence is holed, and reaching it takes a deliberately percent-encoded invisible codepoint. It is filed rather than fixed in place because it is the same contract BUG-0123 exists to keep: a line that names a parameter names something the operator can read back.

## Acceptance criteria
1. `/claims?%00=1`, `/claims?%E2%80%8B=1`, `/claims?%C2%AD=1`, `/claims?%E2%81%A0=1`, `/claims?%E2%80%8E=1` and `/claims?%7F=1` no longer render a name with no renderable glyph. Either arm is a fix, the builder picks — the same two BUG-0127 offered: treat a key with no renderable glyph as naming nothing (ignore it, as the whitespace half already is), or spell something an operator can read back. The rule chosen must be stated in `droppedParams`' docstring, as BUG-0127's is.
2. Whatever arm is chosen, the rows, counts, chip hrefs, window line and bucket caption for those URLs are unchanged from the bare page's (877 in all, no filter asserted), and no value from the URL reaches the markup.
3. Every case BUG-0123 and BUG-0127 pinned still holds: `record_id` and `BUCKET` named verbatim, `bucket` named without echoing its value, `tab` never named, an empty VALUE saying nothing, a blank/whitespace key saying nothing, `in_window` counted and never spelled, two dropped names on one line.
4. The strict pin in `tests/offline/claims/page.test.ts` ("names a parameter an operator can read back, whatever the key's codepoints") flips from `it.fails` to `it`.
5. `npm run lint` and `tsc --noEmit` clean; the offline suite green.
