# A long unbroken token in a refusal is painted past the fields table container on the X axis - the mono half has no word-break rule

## Description
**Expected** (the invariant BUG-0098 / BUG-0101 / BUG-0104 established, restated by BUG-0104 criterion 1): both halves of a refusal are painted inside the fields table container (`div.overflow-x-auto`), at rest, nothing scrolled.

**Found**: the refusal's mono half has no word-breaking rule, so a long UNBROKEN token inside the database's own words is painted outside its own opaque box and — past roughly 180 characters — outside the container itself, over the Provenance column and with no background behind it.

Measured 2026-09-09 by QA attacking BUG-0104 on the LANDED run branch (`run/admin-window` at 726e73b): production build on 127.0.0.1:8795 (bind-probed, never 8770/8771/8772), staging `ubfjjqlvnpnoborczbdb`, bundled Chromium, 1440x900, light theme, `walk_sandbox` row `...0001`, `reset-sandbox` before AND after (both "deleted 3, seeded 3, read back and verified").

**Exact repro**
1. `node tests/walk/reset-sandbox.mts` with the STACK.md section 5 staging mapping.
2. `npm run build` + `npm run start -- --port <free>`; mint the walk cookie; open `/records/walk_sandbox/00000000-0000-4000-8000-000000000001` at 1440x900.
3. Click the `observed_on` value (last row), select-all, type `nope-` followed by 300 `x` characters, Enter. Park the pointer at 0,0 and read the boxes.

**Numbers.** The alert BOX is inside the container on both axes; what leaves it is the TEXT.
- container `div.overflow-x-auto`: x 209 -> 1423, `clientWidth` 1214. Before the refusal `scrollWidth` 1214; with it, `scrollWidth` **2331** — the refusal alone adds 1117px of horizontal scroll to the fields table (the axis BUG-0042 is about).
- alert box `role="alert"`: y 285 -> 357, x 549.3 -> 869.3, `transform: none`. `statusShift` correctly answers 0 here — **this is not a BUG-0104 regression**: `STATUS_BOX` is untouched by that fix (`git show e1f75bf -- src/components/EditableCell.tsx | grep -c STATUS_BOX` = 0), and the defect is on the axis that fix never touches.
- mono half: box x 553.3 -> 865.3 (width 312) but `scrollWidth` **1987** — the database's words are painted to x ~2540, i.e. **1117px past the container's right edge at 1423**, crossing the Provenance column (x 1175.7 -> 1423) unbacked, because `bg-surface` paints the box and not the overflow.
- app-voice half unaffected: y 337 -> 355, x 553.3 -> 865.3, fully inside.
- rows do not move (169.5 / 198.5 / 231.5 / 264.5 / 297.5 / 330.5 before, during and after), so BUG-0086 is not touched.

**Threshold, measured on the same instance** (`observed_on`, same viewport):
- 40-char unbroken token: mono `scrollWidth` 312 == box width — nothing outside.
- 60-char unbroken token: painted to x 962.3, **97px outside its own box**, still inside the container.
- a pasted 60-char URL (`https://calendar.example.com/events/2026/01/15/kpop-showcase`, which has break opportunities): painted to 903.3, 38px outside its box.
- ~180 chars and up: the words leave the container.

**Not reproducible with wrappable words**, which is why it is a break rule and not a height rule: `note` rewritten to 349 characters of short words and then `is_flagged` cleared gives a 136px box inside a container that grew to 252 with it (Postgres caps the `Failing row contains` detail itself, so a refusal taller than the whole container is not constructible on this surface today — the top-alignment branch of `statusShift` stays browser-unreached and offline-pinned only).

**QA honesty, the same BUG-0101 and BUG-0104 carried**: there is NO offline pin for this and QA deliberately invented none. `tests/offline` is plain node with `renderToStaticMarkup` and no jsdom (STACK.md section 4), so painted overflow is unobservable there, and the only offline-observable fact — which class the mono span carries — is a presentation-literal pin QA is banned from writing. Pin whatever DECISION the fix introduces, exactly as `statusShift` and `statusGrowth` were pinned; if the fix carries no expressible decision (one wrapping rule on the mono half), the ticket says so in one line and pins what IS observable: both halves still inside the one `role="alert"`, the database's words still verbatim.

**P3 on impact**: the actionable half (`Type a date, like 2026-01-15.`) is fully readable throughout, the operator recovers by reopening the cell, and it takes a ~180-character unbroken paste to leave the container at all.
