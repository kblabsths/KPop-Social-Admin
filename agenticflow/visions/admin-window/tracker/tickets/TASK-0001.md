# Toolchain: Vitest, the offline/live/http suites, and a lint that exits 0

## Description
Module: repo toolchain (no product behavior). Stands up the test harness every later ticket plugs into. Authority: `contracts/admin-build.md` test 1 and its ground rules; SPEC F2; `agenticflow/docs/vision/STACK.md` section 4 (the runner choice and the three suites); ARCHITECTURE section 10.

Do exactly this:

1. Install `vitest` and `vite-tsconfig-paths` as devDependencies **only after DEP-0001 has landed them in `agenticflow/docs/ALLOWED_DEPS.md`** (the supply-chain hook blocks anything else).
2. `vitest.config.mts` with `tsconfigPaths()` so `@/*` resolves, and three projects/globs:
   - offline: `tests/offline/**/*.test.ts` — the default
   - live: `tests/live/**/*.live.test.ts`
   - http: `tests/http/**/*.http.test.ts`
   The offline glob must be structurally unable to reach `tests/live` or `tests/http`.
3. `package.json` scripts: `test` = the offline project, `test:live` = the live project, `test:http` = **`next build` followed by** the http project (self-contained: any ticket can run `npm run test:http` as a check without a build step of its own), `typecheck` = `tsc --noEmit`. Do not change `dev`, `build`, `start`, or `engines`.
4. **`eslint.config.mjs`: add `agenticflow/**` to `globalIgnores`.** Measured 2026-09-01: `npm run lint` reports 2064 errors, every one of them inside `agenticflow/.venv-tools/.../playwright/driver/**` (the kit's Python venv ships bundled JS). With the ignore, lint exits 0 in 2.8s. Acceptance test 1 is unreachable without it. Do not touch any rule, and do not add ignores for product paths.
5. `.env.example`: add the NAMES `STAGING_SUPABASE_URL` and `STAGING_SUPABASE_SERVICE_ROLE_KEY` with empty values, next to the existing `SUPABASE_*` names. **Names only — never a value, in any file, commit, ticket or note.** Do not edit `.env`.
6. `tests/offline/toolchain.test.ts`: one real test asserting the offline project's include globs exclude `tests/live` and `tests/http` — the structural proof behind 'offline by default'.
7. `tests/http/auth.http.test.ts`: starts the built app on port **8772**, asserts `/api/health` returns 200 and `/` redirects to `/login` for an unauthenticated request, and stops the server in a `finally`. It must need no database. TASK-0005 extends it to every route.

Interface contract for every later ticket:

- offline tests: `tests/offline/**/*.test.ts`, no network, run by `npm test`
- live tests: `tests/live/**/*.live.test.ts`, run by `npm run test:live`
- http tests: `tests/http/**/*.http.test.ts`, run by `npm run test:http` (builds first), port **8772**
- shared fixtures: `tests/fixtures/` (TASK-0002 seeds the builders)

Out of scope: any `src/` change, any product behavior, any other dependency, `.env`, `railway.toml`, `next.config.ts`.

## Acceptance criteria
[test 1] `npm run lint` exits 0 with zero errors and zero warnings from product paths, and `npm test` passes with **no** `STAGING_SUPABASE_*` names in the environment. `npm run test:live` and `npm run test:http` both exist as scripts. `.env.example` carries both STAGING names and no value. The offline suite cannot see `tests/live` or `tests/http` by construction, and that is asserted by a test rather than by inspection. No file under `src/` changed.
