# The error arm's `authored` field is optional, so the only guard on it is a regex inside a closed ticket's checks

## Description
M3 endgame ruling (architect, 2026-09-11), from QA's residual on BUG-0200. Recorded in ARCHITECTURE section 10 and LESSONS 12.

WHAT IS TRUE TODAY. Every `kind: "error"` arm this repo builds under `src/lib/db/**` carries an `authored` array (the segments that say which words the DATABASE wrote and which the app did), and BUG-0200 proved it with a perl sweep over `find src/lib/db -name "*.ts"` that walks each `kind: "error"` object and fails any without `authored`.

WHY THAT IS NOT DURABLE, QA's finding, not a guess: the sweep lives ONLY in BUG-0200's stored `## Checks` — a closed ticket — so nothing runs it again, ever. And it is a regex over one spelling: an arm built by spreading a base object, by a helper that returns the union member, or with the key written on another line is invisible to it. The next error arm anyone adds is unguarded and the class comes back.

THE DURABLE FORM. `authored` is declared OPTIONAL on the error member of the result union (`src/lib/db/result.ts:43`, `authored?: readonly AccountSegment[]`). Make it REQUIRED and the type checker becomes the standing runner: every construction site, in every spelling, is checked by `tsc --noEmit`, which already runs on every ticket and in ci. No regex, no sweep, no ticket-local guard.

MEASURED BEFORE FILING (2026-09-11, HEAD aa4051aa): `./node_modules/.bin/tsc --noEmit` exits 0 today, and BUG-0200's own sweep passes over at least 9 sites, so every existing arm already supplies the field — this is a type tightening over code that already complies, not a migration.

TRAPS FOR WHOEVER TAKES IT. (1) The field may be optional because a caller outside `lib/db` constructs the union too; if `tsc` names such a site, the answer is that arm supplying its own segments, never widening the type back. (2) `accountText(authored)` and `message` must stay in step - `message` is derived from the segments, and the two must not become two spellings of one fact (LESSONS 11). (3) Do not delete or weaken any assertion in `tests/offline/db/result.test.ts`; the type change must leave the account's rendered text byte-identical.

## Acceptance criteria
`authored` is REQUIRED on the error member of the `DbResult` union in `src/lib/db/result.ts` - no `?` - so every construction site in every spelling is checked by the compiler rather than by a regex living in a closed ticket's checks. `./node_modules/.bin/tsc --noEmit` exits 0 with the field required, which is the proof that every existing arm already supplies it. The account's rendered text does not change: the offline suites that read it are green unchanged, and no assertion in them is deleted or loosened to make the type fit. `npm run lint` exits 0.

(human-checkable) The point of the change is that the guard now runs on every ticket forever without anyone remembering it; if the required field forces any call site to invent segments it does not have, that is a finding to report rather than a cast to write - `as` and `!` are not the fix here.
