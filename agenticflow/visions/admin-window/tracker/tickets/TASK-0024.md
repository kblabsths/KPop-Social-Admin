# ASK BEN: where does Admin read the per-source stuck_pattern dial, which lives only in scraper YAML?

## Description
**Contract silence.** ARCHITECTURE marker `OPEN-DIAL`. SPEC named gap 4.

Spec section 5 says the pending-claims gauge judges each source's `awaiting_row` trend *'against its pattern threshold'*. `contracts/resolver.md` section 12 puts that threshold in the source registry: a global default of 20 records per source in 7 days, with a per-source override keyed `resolver: {stuck_pattern: {count, window}}` in `registry/sources/<source>.yaml` — **a file in the scraper repo**. Spec section 10 says reuse that would need scraper files at runtime is *'a flagged gap, not a silent copy'*, and this campaign does not read scraper files at runtime.

So the gauge can render the trend but cannot honestly draw the line. Options, worst to best in my reading:

- Hand-copy the values into Admin: **no.** The contract forbids it by name, and the copy drifts silently the first time a dial changes.
- Read the YAML from a sibling path at runtime: **no.** ARCHITECTURE section 1.2 — a relative parent path resolves inside the worktree during builds, and the deployed Railway service has no sibling repo at all.
- Show only the global default (20 in 7d) and label the line 'global default; per-source overrides not visible here': honest, cheap, and wrong for exactly the sources that have an override.
- **Recommend: ship the trend with no threshold line in M1**, and file the real fix as a handoff for later — the registry becomes readable to Admin the way the ecosystem already intends (spec section 10's 'the common home for cross-repo artifacts is infrastructure.md's — registry hosting, codegen'), i.e. the dial lands in a row Admin already reads, not in a file it has to reach for.

TASK-0007 and TASK-0013 ship the trend without the line; only the threshold overlay waits.

## Acceptance criteria
(human-checkable) Ben says where the dial comes from, or confirms shipping the trend without a threshold line in M1. The architect then removes the `OPEN-DIAL` marker from ARCHITECTURE and, if the answer needs new work, files it — including any scraper-side change as a **handoff** ticket, since a campaign is running in that repo.
