# Queues — two queues of equal standing, with exact filters

## Description
Module: `src/app/queues/page.tsx` (+ its presentational components). Authority: spec section 4 (Queues) and section 6; `contracts/resolver.md` section 11; SPEC F4; M1 EC6; acceptance tests 4 and 2; LOOK_AND_FEEL quality bar 2 and 'Key screens — Queues'.

- `review_items` renders as **two queues of equal standing**: the decision queue and the signal queue, **at the same width, the same type scale and the same level of the page**. Neither is nested inside, beside or beneath the other, and neither is styled as the primary inbox (spec section 4 rationale: 'a signal is the machine breaking, a decision is a question about one datum; tuned signals outrank the inbox they'd be filed under').
- **Open items first, ordered severity then age**, settled items browsable. The sort is stated on screen ('open first, severity then age') — LOOK_AND_FEEL quality bar 6.
- **Filters for queue and for shape**, as `searchParams`. Each filter returns **exactly** the matching items — no extras, none missing. Ordering, classification and filtering all come from `lib/review/shapes.ts` and `lib/db/review-items.ts` (TASK-0006); do not re-implement any of it here.
- A row reads as one sentence: what happened (`summary`), how old, how many times folded (`folded_count` as 'asked again xN').
- Each row opens `/queues/<review_item_id>`.
- The **queue-health gauge** (TASK-0007) renders on this page: per queue open count, age distribution, opens vs settles per week, fold rates.

Every page ticket in this milestone carries the same standing rules (ARCHITECTURE sections 4, 5, 7):
- The page function is the **only** async component on the route; every child is a pure synchronous component taking plain props. That is what lets the tests render `await Page(props)` with `react-dom/server`.
- Read only through `src/lib/db/**`; never build a Supabase client in a page; never spell a table name outside `src/lib/db/tables.ts`.
- Render all four states from the `ui` primitives: loading, empty, **not provisioned** (naming the missing table, gray, never a zero), error (the database's own message). A missing backing table must not throw and must not take the rest of the app down.
- Use tokens and primitives, never raw hex, arbitrary type sizes or ad-hoc radii.
- **State lives in the URL**: every filter, sort and tab is a `searchParams` value and survives the back button.
- Voice: buttons are a verb plus their object; ages are relative with the absolute in the title attribute; scheduled times are absolute UTC with the zone stated once in the column header; machine identifiers render verbatim in mono; empty and not-provisioned states name what the surface holds and what fills it.
- **Nothing settles anything in M1.** No verdict action, no settle control, no fixed/won't-fix, no scaffolding toward them.

## Acceptance criteria
[tests 4, 2, 9; EC6] The two queues render at the same width and type scale, neither nested in the other. Offline tests over a fixture population containing all three shapes in both statuses prove that for **every** queue-filter and shape-filter value the rendered id set equals the expected id set, and that the order is open-first, then severity, then age. The sort is stated on screen. A live-marked parity test asserts the rendered queue counts against counts the test issues itself. The not-provisioned and empty states render without throwing. The queue-health gauge renders on the page. No settle control exists anywhere in the markup.
