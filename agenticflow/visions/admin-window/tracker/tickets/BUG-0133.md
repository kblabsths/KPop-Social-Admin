# A queue block blames a filter for a zero its own empty queue produced

## Description
Found attacking BUG-0131 (QA, 2026-09-09), on the surface that fix owns, and it is the state STAGING IS IN RIGHT NOW. BUG-0131 is correctly fixed; this is the same rule at the trigger its structural derivation cannot reach.

**Expected** — LOOK_AND_FEEL, the four states ("a table with no rows and a filter that matched nothing are different states and never share a rendering"), as BUG-0129/BUG-0131 restated it: a block whose rendered set is identical with and without a URL facet may not tell the reader that facet is why it is empty, nor scope its open figure by it.

**Found** — `src/app/queues/page.tsx:305`, `narrowed = isNarrowed(filter, narrowingOfKind(kind))`. `narrowingOfKind` is derived from the SHAPE REGISTRY (`src/lib/review/queue-filters.ts:243-290`), so it answers "can a row of this kind ever carry another value?" — never "does this table hold any row of this kind at all?". When a block's own queue is EMPTY, no facet can have removed a row from it, yet every facet outside the kind's implied set still flips the block to the filtered rendering.
