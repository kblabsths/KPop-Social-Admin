# /claims: the gauge's own window line names no narrowing, so ?domain= moves every figure on that card under a sentence that says it read the whole table

## Description
Found attacking the landed BUG-0160 fix (qa, 2026-09-10; production build on :8785 against staging, minted cookie, server killed after; commit 3383965 on run/admin-window).

BUG-0160 gave the LIST's window line and the bucket caption the words for a `?domain=` narrowing. The gauge section on the same page — whose read `gaugeFilter` (`src/app/claims/page.tsx:1110`) narrows with the SAME facet — was not touched, and it renders a `ReadWindow` through `WindowLine`'s scan arm (`src/components/ui/window-line.tsx:455-470`), which has no `scope` at all. So every figure on that card is narrowed and its sentence says it read the whole table.

**Measured on staging, the gauge section's own window line (`[data-surface="gauge"] [data-window="pending"]`), byte-identical in all three states:**

    Claims observed since 2026-06-12 20:12 UTC, read to 2026-09-10 20:12 UTC
    — a window of at most 1,000 rows, not the whole table.

| URL | data-window-held | "Claims in this window" | sub |
| --- | --- | --- | --- |
| `/claims` | 877 | 877 | 1 source, 2 domains |
| `/claims?domain=events` | 849 | 849 | 1 source, 1 domain |
| `/claims?domain=groups` | 0 | 0 | 0 sources, 0 domains |

Expected: the sentence stating the window a figure came from names the narrowing that read carried — the rule the list's line one section up now follows ("849 claims in the events domain in all…") and the rule `DrawnWindow.scope` exists for (`window-line.tsx:96-131`, BUG-0114).
Found: `src/app/claims/page.tsx:619-623` renders `<WindowLine gauge={PENDING_WINDOW} window={gauge.window} measured="Claims observed" />` — the scan arm takes `measured` and no scope — so the same 122-character sentence stands over three different reads, and the facet has NO chip row to read it off (`CHIP_FACETS`, BUG-0138). `?source_id=` is narrowed there too and equally unnamed, but its chip shows on screen; `?domain=` shows nowhere on that card.

Worst instance: `/claims?domain=groups` renders "Claims in this window 0", "Buckets holding claims 0 of 5" and, in the age distribution, the NOT-NARROWED emptiness — "No claims in this window / A claim the resolver cannot apply yet appears here, and its wait is measured." — blaming the database for a zero a URL facet produced (LESSONS 3, the two-fact rule `claimsNarrowed` already applies to the list and the bucket table on this page).

Repro:
1. `( set -a && source .env && set +a && SUPABASE_URL="$STAGING_SUPABASE_URL" SUPABASE_SERVICE_ROLE_KEY="$STAGING_SUPABASE_SERVICE_ROLE_KEY" AUTH_URL="http://localhost:8785" npm run build && SUPABASE_URL=... npm run start -- --port 8785 )`
2. `node tests/walk/session-cookie.mts`, add the cookie, GET `/claims` then `/claims?domain=events` then `/claims?domain=groups`.
3. Read `[data-surface="gauge"] [data-window]` on each: identical text, `data-window-held` 877 / 849 / 0.

Pinned RED by `tests/offline/claims/page.test.ts` > "the gauge's window line" > "says what narrowed its own read, where no chip row can say it" (a strict `it.fails` on the run branch — flip it to a plain `it(...)` when you fix it). Its non-vacuity leg reads the query the page actually built: the observations read carried `.eq("domain","venues")`, and the sentence over the figures names nothing.

Not BUG-0161 (the dead-end chips) and not BUG-0162 (the "reach the rest" clause): this is the gauge surface's own sentence.

## Acceptance criteria
1. The gauge section's window line states the narrowing its own read carried: with `?domain=<value>` set, the rendered text of `[data-surface="gauge"] [data-window]` names the domain facet and its value, in the app's own words and in the one spelling `unchippedNarrowings` already owns (`src/lib/claims/filters.ts`) — never a second spelling.

2. It is said exactly where the read carried it: an unnarrowed page renders the sentence it renders today, to the byte, on both tabs; a `?source_id=` narrowing is named on the same rule (its read carries it too).

3. An emptiness the URL produced is not explained as an emptiness the database produced: where the gauge's figures are zero UNDER a narrowing, the card's words say a narrowing emptied it (the two-fact rule of `lib/url/narrowing.ts`, as the list and the bucket table already apply it).

4. Nothing else on the page moves: the list's window line, the bucket caption, the chip rows, every `data-*` hook and every other page's window line stay as BUG-0160 left them.

5. `tests/offline/claims/page.test.ts` > "the gauge's window line" > "says what narrowed its own read, where no chip row can say it" is a plain `it(...)` and green.
