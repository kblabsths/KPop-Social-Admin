## Description
EC11 is the criterion this defaces: it requires every ecosystem page to render a not-provisioned state NAMING what is missing. It does name it — and then runs the name into the next word, so a human reads 'eventsisn't'.

REPRO from a clean start (no staging needed; measured 2026-09-03, verifier M1 walk).
1. Start a stub PostgREST of your own that answers every read 404 with a PostgREST absence body:
     {"code":"PGRST205","message":"Could not find the table 'public.<t>' in the schema cache"}
   (I ran a 20-line python http.server on 127.0.0.1:8785, my own pid, killed after.)
2. Launch a second app instance pointed at it, on a free port:
     ( set -a && source .env && set +a && SUPABASE_URL="http://127.0.0.1:8785" SUPABASE_SERVICE_ROLE_KEY="stub-not-a-real-key" AUTH_URL="http://localhost:8782" npm run start -- --port 8782 )
3. Mint a cookie (node tests/walk/session-cookie.mts) and open /browse, /, /queues, /claims, /sources, /cycles, /records/groups/<id>.

EXPECTED: 'events isn't in this database yet - it arrives with the scraper repo's migrations.'
OBSERVED: 'eventsisn't in this database yet - it arrives with the scraper repo's migrations.'
