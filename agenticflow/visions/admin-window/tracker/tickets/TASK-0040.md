# Strike the direct-edit path: groups/idols leave EDIT_CONFIG, and every surface that assumed it is reconciled

## Description
**Ben struck the direct-edit scope from the frozen VISION (2026-09-08, routed 2026-09-09).** The struck sentence is "groups/idols edit directly within it", with his note: *"admin edits catalog tables only through the observation pipeline; do not re-implement direct edits. groups/idols stay as test tables until they are removed."* He ruled two adjacent things the same day: groups/idols get **no door** (no listing, no search, no Browse entry — ROADMAP question 1 answered "nothing"), and the group row's own `source_*` provenance columns **stay hidden** as he ruled on 2026-09-02.

**A strike licenses nothing. This ticket only removes and reconciles.** No new surface, no compensating feature, no new regime invented here, and above all no second write path built anywhere to keep the old behaviour reachable. If a step seems to need one, stop and report it.

**Sequencing — read this before you claim it.** What `Regime` means in a world with no catalog `pre_cutover` table (the walk sandbox is the only `pre_cutover` entry left) is the **architect's ruling of 2026-09-08**, being written today into `agenticflow/docs/DECISIONS.md` and as an ARCHITECTURE rule. Do not start until that ruling is in the repo; take the regime mechanics and the "do not re-implement direct edits" rule **from it, by reference**. Do not restate the rule in a third place and do not decide the sandbox's regime yourself.

**The change itself is two entries.** Delete the `groups` and `idols` objects from `ENTRIES` in `src/lib/edit/config.ts`. That is the whole mechanism: the map is the one allowlist, so the consequences follow by construction — `editConfigFor("groups")` returns null, the record page `notFound()`s, and `PATCH /api/admin/records/groups/<id>` refuses `unknown_table` with 404. After it, **no catalog table is writable from Admin**: `events`/`venues` stay resolver-owned with an empty `editable` list until FEAT-0011 lands their override path (that path is FEAT-0011's, not this ticket's), and nothing here touches their rendering.

**What must be reconciled, not deleted silently:**

- **`tests/live/edit.live.test.ts`** — its `describe.each(["groups","idols"])` write case is the direct path's proof. **Invert it**, do not drop it: the record URL 404s, a forged PATCH naming a column the old allowlist carried is refused, and the staging row re-reads identical. The suite must still prove the negative on both tables.
- **`tests/http/auth.http.test.ts`** hardcodes `/records/gro%75ps/2f0bc11e` expecting **200** (the percent-encoding / case-variant rewrite tripwire, BUG-0017). That expectation inverts — but the tripwire it guards must survive, re-aimed at a table that IS on the map, or a future unmapped table starts rendering silently.
- **`tests/live/residue.live.test.ts`** — its editable-table floor asserts that a `pre_cutover` table has a scanned text column and a non-zero row count, so a sweep over nothing cannot pass as clean. **Before the map narrows, run the sweep once against staging with `groups`/`idols` still on it and paste the result into this ticket's History.** That is the last chance anyone has to see a leftover from the interim walk-write exception; after this the sweep cannot look there at all. Then re-express the floor over the surfaces Admin can still write, keeping the property that an empty sweep fails loudly.
- The offline suites that assert the two entries (`tests/offline/edit/config.test.ts` and the record-page/route suites) assert their **absence** instead.

**Leave alone:** `src/lib/db/tables.ts`'s `groups`/`idols` names (the sweep and the schema description still spell those tables — the table registry is not the edit map); `events`/`venues` behaviour; `.env.example`; port 8771; `walk_sandbox`'s entry (the architect's call); VISION.md, which is byte-identical before and after. No migration and no DDL from this repo, ever.

**No door means no door.** Do not add a read-only groups/idols listing, a search box, a Browse entry, or a nav link "to make up for" the removal. If the architect's ruling keeps a read-only *record* rendering for either table, follow that ruling and the four-state contract; do not invent one from your own judgment.

## Acceptance criteria
1. `EDIT_CONFIG` carries no `groups` and no `idols` entry and `EDITABLE_TABLES` names neither; a grep over `src` finds no second allowlist, no per-table route, and no helper that reintroduces either table's write path.
2. `PATCH /api/admin/records/groups/<id>` and `/api/admin/records/idols/<id>`, naming any field including one the retired allowlist carried, are refused server-side (404, `unknown_table`, the refusal naming the table); the staging row re-reads identical, every column compared.
3. `/records/groups/<uuid>` and `/records/idols/<uuid>` answer the app's framed 404 (or exactly the rendering the architect's 2026-09-08 ruling names — no third option invented here), and the rewrite tripwire for a case-variant and percent-encoded table name still holds, re-aimed at a table that IS on the map.
4. Nothing was added: no new write path, no new `Regime` value chosen by this ticket, no listing, no search box, no Browse entry and no nav link over `groups`/`idols` anywhere in `src`; the sidebar still holds exactly six links.
5. Every test that exercised the direct write is converted rather than deleted — `tests/live/edit.live.test.ts` proves the refusal on both tables, `tests/http/auth.http.test.ts` keeps its rewrite tripwire, and the offline config suite asserts the two entries are absent.
6. The residue sweep ran once against staging with the old map still in place and its result is pasted in this ticket's History; afterwards its editable-table floor is expressed over what Admin can still write, and a sweep with nothing to scan still fails loudly instead of passing clean.
7. `events` and `venues` behaviour is unchanged (still read-only, still refusing), `src/lib/db/tables.ts` still spells both catalog table names, `.env.example` is untouched, port 8771 is untouched, and `agenticflow/docs/vision/VISION.md` is byte-identical before and after.
8. `npm run lint`, `./node_modules/.bin/tsc --noEmit` and `npm test` green; `npm run test:live -- tests/live/edit.live.test.ts` and `npm run test:live -- tests/live/residue.live.test.ts` green.
