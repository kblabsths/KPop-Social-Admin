# a case variant of a configured table serves the client-rendered error shell, not the app's framed 404

## Description
**Expected** (admin-window/BUG-0017's whole reason, and the invariant admin-window/BUG-0081 just restored for encoded spellings): a record URL whose table the edit map does not carry answers with the app's OWN framed 404 — the routed miss, server-rendered through the root layout — never a `notFound()` thrown from the dynamic segment.

**Found**: a CASE variant of a configured table gets the client-rendered error shell instead. `next.config.ts`'s `beforeFiles` source is compiled case-insensitively while `editConfigFor` is exact (`Object.prototype.hasOwnProperty` on the map, `src/lib/edit/config.ts`), so the matcher reads `EVENTS` as a configured table, does NOT claim the URL, and it reaches `src/app/records/[table]/[id]/page.tsx` — where `editConfigFor("EVENTS")` is null and `notFound()` throws inside the render shell. That is exactly the divergence BUG-0081 removed for `gro%75ps`, on the one spelling class left over.

**Repro, measured 2026-09-08 on a production build of run/admin-window @ 269bad0** (own `next build` + `next start --hostname 127.0.0.1 --port 8792` from a detached worktree, `SUPABASE_URL` pointed at a dead port so no database is involved, minted `authjs.session-token`, id `2f0bc11e-0000-4000-8000-000000000001`):

    GET /records/events%20/<id>     -> 404, len 9728, framed: <h1> present, href="/", token-layer class, no id="__next_error__"
    GET /records/groups/<id>        -> 404, len 9728, framed   (the routed-miss control)
    GET /records/EVENTS/<id>        -> 404, len 8004, id="__next_error__" present, NO <h1>, no navigation
    GET /records/Events/<id>        -> 404, len 8004, id="__next_error__"
    GET /records/WALK_SANDBOX/<id>  -> 404, len 8016, id="__next_error__"
    GET /records/EV%65NTS/<id>      -> 404, len 8006, id="__next_error__"   (case + encoding, same class)
    GET /records/EVENTS/<id>?x=1    -> 404, len 8034, id="__next_error__"

Every OTHER spelling in the same sweep is framed: plain and encoded struck tables, doubly-encoded (`gro%2575ps`), `%2F`-bearing, trailing `%20`, `..`, a 4000-character segment, a mapped name with one wrong byte (`ev%66nts`), a mapped name plus a suffix (`eventsx`), a bad escape (`gro%zzps`) — 32 of 32 unmapped spellings framed, 4 of 4 case variants shelled.

**Not a security finding, measured**: the gate is untouched on every one of these spellings — anonymous `GET /records/EVENTS/<id>` answers 307 to `/login?callbackUrl=...`, as do all 44 URLs in the sweep, so nothing discloses which record surfaces exist. `PATCH /api/admin/records/EVENTS/<id>` is refused by `requireAdmin()` exactly like every other spelling; no write path is involved.

**Case is NOT an encoding equivalence, and this ticket does not ask for one.** A URI path is case-sensitive (RFC 3986 §6.2.2.1), so `EVENTS` correctly has no record surface — the defect is only the DOCUMENT it is refused with. `EDIT_CONFIG`'s keys are the database's own spelling and must stay exact; the fix belongs in the routing layer, not in `editConfigFor`.

**Direction is the architect's, not prescribed here.** `next.config.ts` already records the constraint: the rewrite is what decides the miss, and its source is matched case-insensitively by Next's own compiler. Whether the answer is a case-sensitive matcher for this one rule, an exclusion written to match only the exact spelling, or deciding the miss somewhere else, is a design call — the last of the BUG-0017 class either way.

**P3 for the same reason BUG-0081 was**: no browser uppercases a path segment on its own, so the reach is a hand-typed or hand-edited URL and the impact is a degraded 404 document, not a wrong answer. Raise it if the architect judges the BUG-0017 class worth closing whole.

**The pin is `it.fails`.** `tests/http/auth.http.test.ts`, in the `a record URL for a table the edit map does not carry` describe: `it.fails("BUG-XXXX: serves the framed 404 for a case variant of a configured table")` — green while the divergence stands, RED the day it is closed. **The fix flips it to a plain `it(...)`**, and the check below then proves it. Watched red as a plain `it()` on this exact tree before filing: `AssertionError: /records/EVENTS/2f0bc11e: expected '<!DOCTYPE html><html id="__next_error…' to match /<h1[\s>]/`. Block 1b of the same file continues to pin the STATUS of that URL and pins no document shape, so the two do not collide.
