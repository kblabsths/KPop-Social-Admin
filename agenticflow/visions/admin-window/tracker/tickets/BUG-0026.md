# Dashboard renders 10 blank table cells when error_summary is null (component body defeats orDash)

## Description
Expected (contracts/admin-build.md, LOOK_AND_FEEL state 4 / the four-state contract; src/components/ui/data-table.tsx: "a null renders as an em dash ... never blank"): every DataTable cell whose value is absent renders the em dash.
Found: the Dashboard renders 10 EMPTY <td> elements (6 cycle rows + 4 run rows) when error_summary is null. Measured 2026-09-02 on run/admin-window at 14a3e71: `/ rendered a cell with nothing in it: expected 10 to be +0`. Every other surface renders 0 blank cells in the same state.

Mechanism (file:line):
- src/app/page.tsx:199 `function ErrorSummary({summary, href})` returns `null` when `summary === null || summary.trim() === ""`.
- src/app/page.tsx:237 (CYCLE_COLUMNS "error") and src/app/page.tsx:269 (run columns "error") both set `cell: (row) => <ErrorSummary .../>`.
- src/components/ui/data-table.tsx:135 passes the cell body through `orDash(body)`. The body is a React ELEMENT (<ErrorSummary/>), never `null`, so `isAbsent` (src/lib/format.ts, campaign admin-window/BUG-0004) can never see the absence and the cell is emitted empty.

Repro (offline, no database):
1. cd to the repo root on run/admin-window.
2. Open tests/offline/absence/blank-cells.test.ts and empty the KNOWN_BLANK map (`const KNOWN_BLANK: Readonly<Record<string, string>> = {};`).
3. `./node_modules/.bin/vitest run --project=offline tests/offline/absence/blank-cells.test.ts`
4. Observe: `a page whose rows carry nothing but nulls > / renders no blank table cell` fails with `expected 10 to be +0`; the other 7 surfaces pass.
The state driven is `sparseScript()` (tests/offline/absence/surfaces.ts) — the populated fixture database with every column the fixture row types declare nullable set to null, which is exactly a real row whose producer reported no error.

Currently pinned, not hidden: tests/offline/absence/blank-cells.test.ts marks `/` with `it.fails` via KNOWN_BLANK, so the suite is green today and reddens the moment the defect goes away without the pin coming off. The pin names this BUG id.

Known-good fix shape (already applied on Cycles for the same defect, campaign admin-window/TASK-0014): the column returns the null ITSELF rather than a component that renders null — see src/app/cycles/page.tsx:351-355, `cell: (row) => row.error_summary === null || row.error_summary.trim() === "" ? null : (<span .../>)`. Fixing the primitive instead (teaching orDash to look inside an element) is the page ticket's call, but the operator-visible bar is the same: no cell may be blank.

Closing this ticket requires removing `/` from KNOWN_BLANK in tests/offline/absence/blank-cells.test.ts (which removes the BUG id from that file) — that is what makes the checks below discriminate a real fix from a removed pin.

## Acceptance criteria
The Dashboard yields the ABSENCE ITSELF to DataTable rather than a component element, on both "error" columns (error_summary) and both "outcome" columns, so a row with no error_summary — and a row that ended with no outcome recorded — renders the shared em dash and never an empty cell. tests/offline/absence/blank-cells.test.ts has an EMPTY KNOWN_BLANK map and its "/" case passes as a plain `it` (0 blank cells). Markup for a non-null error_summary and for every non-absent outcome is unchanged. No other page-level DataTable column under src/app/** or src/components/** (excluding src/components/ui) renders a child component that can return null; any found are fixed and named in the handoff. The other seven surfaces still render 0 blank cells, and tests/offline/dashboard, tsc and lint stay green.
