What the gate can and cannot enforce (.claude/hooks/remote_gate.py, read 2026-09-02):
- `declared_services()` collects the first word of every line starting with "## ". `railway` is in REMOTE_CLIS. Undeclared -> every railway invocation is refused. Declared -> every railway invocation PASSES SILENTLY. There is no per-command, per-environment or read-only granularity. Declaration is a binary switch, and it opens on `up`, `down`, `redeploy`, `link`, `variables`, `run` and `add` all at once.
- The production fence is TEXTUAL ONLY: PROD_RE searches the command's own tokens for prod/production. Railway creates every project with an environment named `production` by default [web-sourced: https://docs.railway.com/environments - "All projects in Railway are created with a production environment by default"], and the CLI acts on the LINKED environment when none is named. So `railway up`, `railway redeploy`, `railway logs` and `railway variables` carry no prod/production token, sail past PROD_RE, and hit the production environment anyway. The fence catches the honest command (`railway up -e production`) and misses the dangerous default (`railway up`). This is not a bug I am asking anyone to fix - PROD_RE is a name fence and it does what it says - it is the reason declaration cannot be made safe by prose.
- Two concrete losses if `## railway` is declared while nothing needs it: (i) `railway variables` prints secret VALUES into a transcript, burning the production service-role key and forcing a rotation - SERVICES.md's own secrets rule; (ii) `railway link` / `railway up` can repoint or redeploy the live service, which is precisely what M1 EC13 grades as never having happened. Today both are impossible by construction. After declaration both are one plausible agent command away, and the only remaining defense is that the agent read the prose.
