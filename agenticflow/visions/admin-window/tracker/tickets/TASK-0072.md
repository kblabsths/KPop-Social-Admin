# One home for the narrowing vocabulary, and a window's scope stops being a string somebody splits

## Description
**Modules:** `src/components/ui/window-line.tsx` (the shared primitive — a SHARED SURFACE, §13.2's exception applies and the offline checks below are wide), `src/lib/url/narrowing.ts` (the leaf that gains the vocabulary), `src/lib/claims/filters.ts` (which keeps its facet table and loses the shape), and the eleven call sites that pass a `scope`.

**No rendered byte changes in this ticket.** Every window line on every surface renders exactly what it renders today, on every fixture. This is a contract change with a behaviour of zero.

**Two jobs, one destination, which is why they are one ticket** (§13.9: consolidation-shaped work is serial at its destination — both of these write `window-line.tsx` and the claims page):

**1. `DrawnWindow.scope` stops being a comma-joined string.** It is composed by `narrowedTo`, joined with `NARROWING_JOIN`, then SPLIT BACK APART by `besides` and `narrows` inside the same file. A facet value containing `", "` could forge a segment. It is unreachable today — which is exactly why the M2 close ruled it gets no ticket of its own and is fixed STRUCTURALLY the moment something touches the window line's scope contract (DECISIONS 2026-09-10 ruling 4, SPEC F15's constraint). This ticket touches it, so it is fixed here and nowhere else.

```ts
// src/components/ui/window-line.tsx
export interface DrawnWindow {
  …
  /** The narrowings this read carried, as PHRASES. Joined once, at render. */
  scope: readonly string[] | null;     // was: string | null
}

/** Compose a scope from phrases, dropping the ones this read did not carry. */
export function narrowedTo(phrases: readonly (string | null)[]): readonly string[] | null;
```

`besides(scope, stated)` filters the array and `narrows(scope, stated)` asks `includes` — neither splits anything. `NARROWING_JOIN` survives as the render-time join and as the ONE spelling of it. The scan arm's optional `scope` takes the same type.

**2. The unchipped-narrowing vocabulary moves to the leaf that owns URL meaning.** `UnchippedNarrowing`, `unchippedNarrowings` and `unchippedPhrase` live in `src/lib/claims/filters.ts`, so `/sources` cannot say the same sentence without retyping it — and retyping it is the class that took five bugs on this exact family (LESSONS 5; the M2 structure walk's common violation 9). They move to `src/lib/url/narrowing.ts`, generalised over the facets a surface declares:

```ts
// src/lib/url/narrowing.ts   (LEAF)
export interface UnchippedNarrowing { facet: string; value: string; before: string; after: string }
/** One facet a surface renders no control for: how to read it off a filter. */
export interface UnchippedFacet<Filter> { facet: string; before: string; after: string;
  value: (filter: Filter) => string | undefined }
export function unchippedNarrowings<Filter>(
  filter: Filter, facets: readonly UnchippedFacet<Filter>[]): UnchippedNarrowing[];
export function unchippedPhrase(narrowing: UnchippedNarrowing): string;
```

`/claims` keeps its own facet table (today's `?domain=`) beside its filters, exported as `CLAIMS_UNCHIPPED_FACETS`, and imports the shape. `src/lib/claims/filters.ts` re-exports nothing it no longer owns: one declaration, one home (common violations row 18 — no identifier exported twice from `src/` with two meanings). `tests/offline/url/narrowing.test.ts` is the OWNER map for this vocabulary (DEBT-0014) and it is where the new home is pinned.

**The `<NarrowedBy>` markup face stays where it is** (`src/app/claims/page.tsx`): it renders the identifier through `ui/Identifier` and is presentation, not vocabulary. Its words still come from `unchippedPhrase`'s inputs, which is the point — one narrowing, one wording, two faces.

**Grade it on the tree, not on one page:** the offline suites of every surface that draws a window line are checks on this ticket, and the criterion is byte-identity of rendered markup.

## Acceptance criteria
DrawnWindow.scope is a readonly string[] | null; narrowedTo returns the phrase list; besides filters that list and narrows asks includes; nothing in src splits a scope on the join string — grep shows zero non-comment split( calls in window-line.tsx and NARROWING_JOIN is used only where the line renders. A facet value containing ", " cannot forge a segment, proved on a fixture carrying one: the phrase renders whole and besides subtracts it whole, and the same fixture on the pre-ticket shape splits into two. UnchippedNarrowing, unchippedNarrowings and unchippedPhrase are declared exactly once in src, in src/lib/url/narrowing.ts, and lib/claims/filters.ts declares none of them while keeping its own facet table; tests/offline/url/narrowing.test.ts names the new owner. Every window line on every surface renders byte-identically to the pre-ticket tree on the same fixtures — claims, cycles, queues, browse, dashboard, sources, review — and the live parity suites for /claims and /cycles are green. No copy changes, no figure moves, no surface is added.
