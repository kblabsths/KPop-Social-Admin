# The entity_link fact item's two actions: link to an existing entity, or settle

## Description
**SPEC F10 / spec §7, the `entity_link` FACT item** (`source_id` null — the source-pattern item with `source_id` set is the SIGNAL and takes dispositions instead; `lib/review/shapes.ts` is the one place that distinction is made, §11). Its close slot offers exactly two controls:

1. **Link to an existing entity** — the picker of FEAT-0012, rendered inside the close slot. Produces `action: "link_entity"` carrying the chosen entity's id as `value.ref`; `settle_review_item` writes the confirmed match, which the resolver's next cycle reads to unlock the waiting claims.
2. **Settle** — leave it held. The item settles; the claim keeps waiting in its bucket. Produces `action: "settle"` with `value` null.

Each is exactly one call. There is no "create the entity" control here or anywhere: entity creation is the resolver's, and the picker offers only rows that exist.

**Fixtures, not staging**: no `entity_link` FACT item exists on staging (the one row there is the source-pattern signal). This is graded offline against the fixture; "built, not walkable on this data" is the honest grade, exactly as M1 graded the same gap.

**The absence is the normal case and is graded FIRST.** `verdicts` and `settle_review_item` do not exist on staging and will not until Ben installs the handoffs — that is what `main` deploys against. The surface renders its not-provisioned state naming the missing object, offers no control it cannot perform, and nothing throws. **No Admin-side workaround** for the absent schema may be written (spec §10's one forbidden move).

## Acceptance criteria
1. With `verdicts` present (stub) and an `entity_link` fact fixture: the close slot contains exactly two controls — the picker's link action and "settle" — and no others; no create affordance exists on any path.
2. The link action's submission is exactly one call carrying `action: "link_entity"`, the item's id, and the chosen entity as `value.ref`; "settle" is exactly one call carrying `action: "settle"` and a null `value`. Both asserted against the recording stub, and `decisionRefusals` returns `[]` for each.
3. The shape distinction is read from `lib/review/shapes.ts`: a fixture with `source_id` set renders the SIGNAL's dispositions and not these two, and a fixture with `source_id` null renders these two and not the dispositions — both asserted, so a mis-shaped item cannot silently take the wrong action set.
4. With `verdicts` absent: neither control renders and the not-provisioned card names the missing object.
5. `npm run lint`, `tsc --noEmit`, the targeted offline file and the review-item live suite are green.
