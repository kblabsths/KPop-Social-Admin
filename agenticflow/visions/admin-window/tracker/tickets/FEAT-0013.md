# The verdict log made visible: a tab on Queues, and each settled item's verdict inline

## Description
**SPEC F13.** The verdict log is rendered, because spec §7 makes it "the one record of every admin data action" and VISION makes it a success criterion. Ben named "the verdicts table UI" as part of what makes this campaign satisfied.

**It is a TAB, not a seventh page.** VISION names six pages — Dashboard, Queues, Claims, Sources, Cycles & runs, Browse — and this campaign does not add one. The verdict log lives as a tab on **Queues** (the surface whose items it settles), reached by a URL facet, exactly the way the standing-disagreements subset lives as its own tab on Claims. That precedent shipped in M1 and is the rendering to copy. The sidebar still holds exactly six links at the M2 close; a ticket that adds a seventh is wrong.

**What it renders**, newest first, one row per `verdicts` row: `actor`, `action`, the item settled as a link (nothing on an override — `review_item_id` is null there), the observation written as a link (nothing on a settle-only verdict — `observation_id` is null there), the `note`, and `created_at`. Both nulls are structural, not missing data: they are how the log distinguishes an override from a settlement and a settle-only verdict from a value-carrying one. Render them as the mandated dash and say once, on the surface, what a dash means there — LESSONS class 1, and BUG-0053 is the M1 bug that cost a walk exactly this.

**A settled review item's detail carries its own verdict inline**, so the investigation path ends where the decision was made rather than sending the operator to a different tab to find out what they themselves decided.

**Absence is the normal case.** `verdicts` does not exist on staging and will not until Ben installs FEAT-0009's artifact. The tab renders its `not_provisioned` card naming `verdicts`, the page answers 200, nothing throws, and the surface's live parity oracle asserts the not-provisioned STATE rather than a number — an oracle that asserts a count against a table that does not exist is the M1 bug class that cost six chained tickets (DECISIONS 2026-09-02, "a live oracle names the page's state kind before it compares a number").

**The window rule applies** (DECISIONS 2026-09-04): the tab publishes its window line when the read RETURNED — with rows or with none — and drops the line whole when the read was refused, absent, or never made.

**No dial, no threshold, nothing dial-shaped** on this surface: it is a log, not a gauge.

vision_trace: "The verdict slice. Every spec §7 action settles a review item in one transaction, and every settlement and override lands as one row in the verdict log."

## Acceptance criteria
1. The sidebar holds exactly six links at the M2 close, unchanged from M1; the verdict log is reachable only as a URL facet of an existing page, and no new top-level route serves it.
2. With `verdicts` ABSENT (staging today): the tab renders `data-state="not_provisioned"` naming `verdicts`, the page answers 200, zero page errors, and its live oracle asserts the not-provisioned state rather than comparing a count.
3. With `verdicts` present (stub/fixture): rows render newest first carrying actor, action, item link, observation link, note and time; a null `review_item_id` and a null `observation_id` each render the mandated dash, and one line on the surface says what a dash means there.
4. A settled review item's detail renders its own verdict inline; an unsettled item's detail does not.
5. The window line follows the read, not the rows: present when the read returned (rows or none), absent when the read was refused or never made. Graded by the shared absence suite, not by a per-surface docstring.
6. Zero dial, gauge, or threshold rendering on this surface; the string set the gauges use appears nowhere on it.
7. `npm run lint`, `tsc --noEmit` and `npm test` green; the Queues live suite green.
