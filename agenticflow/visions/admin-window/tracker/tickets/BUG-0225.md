# The sibling-code reader answers from three grammars it cannot actually read — state its bar once instead of a fifth instance

## Description
Filed by the architect 2026-09-12 from QA's unfiled residuals on BUG-0220 (that ticket is under QA grade and is not touched by this one). This is the FOURTH ticket on one reader in one week — BUG-0207, BUG-0212, BUG-0213, BUG-0220 — and Common violations row 25 already counts the class at 3. LESSONS 13 says what to do with a chain like this: stop fixing the instance, state the property that makes the next instance impossible, and put THAT in the criteria.

THE THREE RESIDUALS QA MEASURED AND DID NOT FILE:
- CRLF input blinds the reader (the pattern carries no m flag; the sibling's .gitattributes pins LF today, so a CRLF input is an input from somewhere the guard did not expect — which is exactly when a guard is load-bearing).
- A one-line compound body is not read.
- Bracket depth reset on a blank line can INVENT A DECLARATION the sibling never made.

The third is the serious one and it is the class's signature: not a miss, a false positive ABOUT ANOTHER REPO'S CODE. Every previous round of this chain was the same shape — our guard asserting something about a tree we do not own on the strength of a grammar we guessed.

THE BAR, stated positively (this is the design; it is what the criteria grade): THE READER ANSWERS TWO QUESTIONS ABOUT THE SIBLING — which codes it DECLARES, and where it RAISES them — over the grammars its tree actually contains, and WHEN ITS INPUT IS IN A SHAPE IT CANNOT PARSE IT SAYS SO, loudly, by name. A silent partial answer that is then compared as if complete is the defect; a reported failure to read is a correct answer. Compare declaration to declaration (LESSONS 4), never similarity to similarity.

ORDERING: depends on TASK-0080, which moves the sibling-reading cases to tests/handoff/. Both tickets write the same destination; landing them in parallel is a merge collision in a file whose whole content is the thing being moved. Move first, then state the bar.

## Acceptance criteria
1. THE READER'S PROPERTY IS STATED IN ONE PLACE AND GRADED: for each of the two questions it answers, either it produces the sibling's own declarations, or it reports — by name, failing the case — that it could not read its input. No path returns a partial answer that a comparison then treats as complete (the shape that made an empty map 'agree with everything' in earlier rounds).

2. THE THREE MEASURED BLIND SPOTS ARE FIXTURES, EACH WITH BOTH POLARITIES (LESSONS 8): a CRLF input; a one-line compound body; a bracketed list containing a blank line. For each, one input the reader MUST read correctly and one it must refuse to guess at. The blank-line case specifically asserts that NO declaration is invented.

3. NOTHING THE SIBLING REALLY DECLARES IS LOST: every case that passes today over the real sibling checkout still passes, unweakened, and the codes this campaign allocated are still found where they are found now.

4. The cases run in the opt-in handoff project TASK-0080 installs, not in the every-builder suite, and a machine without the sibling checkout still skips loudly.

5. No new attribution heuristic is introduced. If a case cannot be decided by a declaration both repos spell, it is reported as undecidable and routed to Ben — never decided by text similarity (Common violations row 25, LESSONS 4).
