# claims.live.test.ts: the parked-bucket test grades the standing tab against the whole-view count

## Description
Found by the architect on the TASK-0031 confirmation run (2026-09-03) — the first run in which `/claims` could render at all, so this assertion was previously masked by the page's error state.

`tests/live/claims.live.test.ts`, "the parked bucket against staging > is a string the database still spells, and the page never does", loops four param sets and grades each with:

    within: listOf(params.tab),
    counted: () => countRows(() => claimCount()),

`claimCount()` is the WHOLE view (`neq bucket in_window`) — 859 on staging. But `listOf("standing")` selects the standing tab's list, whose set is `bucket = 'standing_disagreement'`, which staging holds **0** of (measured: `agenticflow/tracker/evidence/architect/claims-probe3.tsv`, `view head count eq bucket=standing_disagreement -> count=0`). So `gradeSurface` computes expected `ok` from 859 while the page renders its honest EMPTY, and throws:

    StateMismatchError: 'section:nth-of-type(1)' rendered its EMPTY state, but
    this test counted 859 row(s) of 'pending_claims', which is OK.

**The page is correct and no product code is implicated.** Three facts pin that down: (1) the sibling test four lines above — 'renders the standing tab as exactly that bucket's subset' — grades the same surface with the RIGHT count (`exactCount(...).eq("bucket","standing_disagreement")`), gets `empty`, and passes; (2) iteration 1 of the failing loop (`{}`, the buckets tab, `section:nth-of-type(2)`) grades `ok` against 859 and passes its `not.toContain("in_window")` assertion; (3) 11 of the 12 claims+sources live assertions are green, and all six Sources ones are.

Near miss of ARCHITECTURE Common violations row 6's class: that rewrite made the oracle name the state kind before comparing numbers, and this test names the kind correctly but counts a different set than the surface renders. Recorded as **row 7** (count 1).

**Cost of leaving it:** the property this test exists for — that no rendering of the page spells `in_window`, in any tab, under any filter, including a URL naming it — currently runs for exactly ONE of its four param sets; the other three throw before reaching `expect(markup).not.toContain(PARKED_BUCKET)`. The parked-bucket property is 25% verified. That is the real defect; the red is just what made it visible.

## The fix, as small as it is

Per-tab counting, mirroring the sibling test: when `params.tab === "standing"`, `counted` reads `exactCount(T.pendingClaims).eq("bucket", "standing_disagreement")`; otherwise `claimCount()`. Extracting a `standingCount()` helper and using it in both places is welcome.

Three things NOT to do. Do not reach for `emptyAtZero: false` — that switches off the empty/ok grading this file was hardened to do (row 6) and is the vacuous pass, not a fix. Do not touch `src/**`: `src/lib/db/claims.ts`, `src/lib/claims/filters.ts` and `src/app/claims/page.tsx` are correct as written. Do not 'fix' the `?bucket=in_window` iterations by expecting an empty page — `chosen()` in `filters.ts` deliberately makes a value outside the offered vocabulary narrow NOTHING (so a hand-typed URL shows the unfiltered page, not an empty one that reads as an empty database), so those two param sets grade against the same count as the bare one, differing only by tab.
