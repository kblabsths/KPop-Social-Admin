# LOOK_AND_FEEL bar 14's own record grades /browse by the superseded proposal's metric, so a surface that fails Ben's rule reads as passing

## Description
Bar 14 (landed cbeda10d, TASK-0079) states the rule by POSITION: "every element that is not a row — the control that extends or moves the list, a total, a legend, an action — renders **above** the list or on **its own surface** ... never after the last row." Its own trace then grades the two paged surfaces by the SUPERSEDED proposal's metric — whether the control stays on screen after a press — and names only one failing surface.

Expected (bar 14's own sentence, LOOK_AND_FEEL.md:335-341): every list surface whose rows can run past the fold at 1440x900 is graded on where its non-row elements sit relative to the last row; a control after the last row fails, whether or not it stays visible.

Found (LOOK_AND_FEEL.md:349-358): "Known failing surface at the time of writing ... `/claims`' 'show the next 50' control goes viewport y=434 -> 2,066 ... the same control on `/browse` stays at y=852 because the browser's scroll anchoring holds it." Singular "Known failing surface", plus /browse offered as the contrast, reads as /browse passing. But /browse's control is the SAME `PageMore`, rendered AFTER the rows:
  - `src/components/browse/paged-browse-table.tsx:156-158` renders `<BrowseTable>`; `:177` renders `<PageMore>` after it, last child of the column.
  - `src/components/claims/paged-claim-list.tsx:107` renders `<ClaimList>`; `:115` renders `<PageMore>` after it.
Both controls sit after the last row. /browse's list is long in bar 14's own sense: its window is at most 50 event rows and the M3 endgame measurement only makes sense on a scrolled document (scroll anchoring adjusts scrollY when content above the viewport grows — M3-endgame-walk.md:237). So under bar 14 /browse fails exactly as /claims does; y=852 measures visibility after a press, which is precisely the metric Ben's ruling replaced ("it is not about the control staying on screen after it acts, it is about the control never being at the bottom in the first place", TASK-0079 description).
