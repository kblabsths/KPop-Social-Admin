# /cycles shows a ?source= name the browser collapsed, not the name it queried: ?source=%20ticketmaster says "No runs from ticketmaster" while ?source=ticketmaster draws five

## Description
Found attacking admin-window/BUG-0153 on the landed run branch (e82044d). BUG-0153 closed the BIDI half of `?source=` with the allowlist arm and it holds (measured below). This is the OTHER half of the same question — a value the allowlist ADMITS whose rendered spelling is not the name the read used.

Expected — this page's OWN ruling on a padded paste, applied to `?cycle=` and `?run=` by admin-window/BUG-0145 and BUG-0146 ("answers a padded paste of a run id the way its twin answers one": `canonicalRecordId` strips padding by INK, so a stray space around an id changes no page): whatever `?source=` carries, the name the page SHOWS is the name the page QUERIED. ARCHITECTURE.md §7 row 15's purpose is the same — text this app did not author must not change what a sentence this app wrote MEANS.

Found — `sourceNarrowing` (src/lib/db/runs.ts:237-241) trims only to detect a blank-only value and otherwise returns the value verbatim, so `.eq("source", " ticketmaster")` reaches PostgREST while a browser collapses the space out of every sentence that names it. The page then states, in its own words, a false fact about a registered source, with nothing on the dropped-parameter line and no visible cue that the URL carried anything unusual.

MEASURED IN CHROMIUM (playwright, agenticflow/.venv-tools), production build of the landed tree against staging (ref ubfjjqlvnpnoborczbdb.supabase.co), this lane's own bind-probed port 8836 (child pid 71563, killed, port re-probed free), viewport 1440x900, BOTH colour schemes — byte-identical in light and dark, read-only, nothing written:

  GET /cycles?source=ticketmaster            -> 200, 5 run rows drawn
    window line (innerText): "... The window did not fill - 5 of at most 200 - so it holds all the runs from ticketmaster the read found: runs from ticketmaster recorded since 2026-08-31 10:35 UTC; ..."
  GET /cycles?source=%20ticketmaster         -> 200, 0 run rows drawn
    window line (innerText): "... The window did not fill: the read happened and found no runs from ticketmaster at all."
    empty card (innerText):  "No runs from ticketmaster"
    facet paragraph (innerText): "Narrowed to the runs whose source is ticketmaster, matched by name. ..."   <- identical to the registered page's, character for character
    data-source-facet=" ticketmaster"; [data-dropped-params] ABSENT (the page claims it applied the facet)
  GET /cycles?source=ticketmaster%20          -> same: 0 rows, "found no runs from ticketmaster at all", nothing dropped
  GET /cycles?source=tic%20%20ketmaster       -> 0 rows, visible "no runs from tic ketmaster", data-source-facet="tic  ketmaster"

So the three sentences an operator READS are the registered source's name in every case, while the read was of a different string: one invisible character apart, the page renders 5 runs or claims there are none. The DOM text still holds the space (line_dom "... no runs from  ticketmaster at all."); only the layout collapses it, which is what the operator sees.

BUG-0153 itself is NOT undone by anything here and closed green: same walk, `/cycles?source=%E2%80%AEbandsintown` -> 200, 0 bidi controls outside <script>, 0 in body innerText, no [data-source-facet], `source` on the dropped line, window line = the unnarrowed sentence with all 5 rows; `?cycle=%E2%80%AEnot-a-uuid` -> 0 controls, `cycle` dropped (BUG-0147 intact); `/claims?source_id=<uuid>&domain=%E2%80%AEevents` and `/queues?source_id=<uuid>&bucket=%E2%80%AEjunk` -> 200, 0 controls anywhere in the text, junk keys reported dropped.

Repro (offline, exact, on the landed tree): in tests/offline/cycles/page.test.ts, the strict pin "shows the ?source= name it queried, not one the browser collapsed [admin-window/BUG-0155]" (in `describe("a ?source= link arriving from the Sources page")`), flipped from `it.fails(` to a plain `it(`. Watched RED before filing, once per case: `queried " bandsintown": expected 'bandsintown' to be ' bandsintown'`, and the same for a trailing space, blanks at both ends, and a double space inside (4 failed | 139 passed). As landed the pin is `it.fails` and the file is green; the day the hole closes the XPASS turns it red and sends the reader here.

Two honest arms, and the ticket should not guess silently:
(a) CANONICALISE the value where it is derived (`sourceNarrowing`), the way `canonicalRecordId` already canonicalises a padded id for `?cycle=`/`?run=` (BUG-0145/0146) — collapse the padding, query and spell the same string. Cheap, keeps every URL answering a page. Note a name with an internal double space still cannot be spelled faithfully in prose, so this arm must decide that case too (collapse it or refuse it).
(b) REFUSE a value whose rendered spelling differs from itself, and report `source` on the shared dropped-parameter line — BUG-0153's own arm, extended from "cannot be spelled safely" to "cannot be spelled faithfully".
The pin passes under either.

P3, the same price as the four tickets before it in this family and for the same reasons: URL-supplied only, on an admin surface behind `admin_allowed_emails`, no privilege boundary crossed, nothing written. It is a truthfulness defect on three sentences of one page. The CLASS for the architect: five tickets (BUG-0123, 0127, 0136, 0137, 0147, 0153) have now landed on "a URL value inside a sentence this app wrote", each closing one property of the value (no markup, no bidi, some ink, bounded length) — this one is the property none of them stated: WHAT IS SHOWN IS WHAT WAS USED. A predicate that answers "may I spell it" cannot answer it; the answer belongs where the value is derived, beside `canonicalRecordId`.

## Acceptance criteria
No ?source= value may leave /cycles showing a source name that differs from the name the runs read was narrowed by. Either arm satisfies it: canonicalise the value where it is derived, so what is spelled and what is sent are one string (as canonicalRecordId already does for ?cycle= and ?run=, admin-window/BUG-0145/0146); or refuse a value whose rendered spelling differs from itself and report source on the shared dropped-parameter line. An ordinary source name (?source=ticketmaster) must still be spelled in full in both sentences and must still narrow the runs read, and no bidi control may re-enter either sentence (admin-window/BUG-0153 must stay closed). Pinned by flipping the strict pin 'shows the ?source= name it queried, not one the browser collapsed [admin-window/BUG-0155]' in tests/offline/cycles/page.test.ts from it.fails( to a plain it(, with every other case in that file, in tests/offline/runs/page.test.ts and in tests/offline/runs/read.test.ts still green.
