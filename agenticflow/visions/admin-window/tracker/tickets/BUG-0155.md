# /cycles shows a ?source= name the browser collapsed, not the name it queried: ?source=%20ticketmaster says "No runs from ticketmaster" while ?source=ticketmaster draws five

## Description
Found attacking admin-window/BUG-0153 on the landed run branch (e82044d). BUG-0153 closed the BIDI half of `?source=` with the allowlist arm and it holds (measured below). This is the OTHER half of the same question — a value the allowlist ADMITS whose rendered spelling is not the name the read used.

Expected — this page's OWN ruling on a padded paste, applied to `?cycle=` and `?run=` by admin-window/BUG-0145 and BUG-0146 ("answers a padded paste of a run id the way its twin answers one": `canonicalRecordId` strips padding by INK, so a stray space around an id changes no page): whatever `?source=` carries, the name the page SHOWS is the name the page QUERIED. ARCHITECTURE.md §7 row 15's purpose is the same — text this app did not author must not change what a sentence this app wrote MEANS.

Found — `sourceNarrowing` (src/lib/db/runs.ts:237-241) trims only to detect a blank-only value and otherwise returns the value verbatim, so `.eq("source", " ticketmaster")` reaches PostgREST while a browser collapses the space out of every sentence that names it. The page then states, in its own words, a false fact about a registered source, with nothing on the dropped-parameter line and no visible cue that the URL carried anything unusual.

MEASURED IN CHROMIUM (playwright, agenticflow/.venv-tools), production build of the landed tree against staging (ref ubfjjqlvnpnoborczbdb.supabase.co), this lane's own bind-probed port 8836 (child pid 71563, killed, port re-probed free), viewport 1440x900, BOTH colour schemes — byte-identical in light and dark, read-only, nothing written:

  GET /cycles?source=ticketmaster            -> 200, 5 run rows drawn
    window line (innerText): "... The window did not fill - 5 of at most 200 - so it holds all the runs from ticketmaster the read found: runs from ticketmaster recorded since 2026-08-31 10:35 UTC; ..."
  GET /cycles?source=%20ticketmaster         -> 200, 0 run rows drawn
    window line (innerText): "... The window did not fill: the read happened and found no runs from ticketmaster at all."
    empty card (innerText):  "No runs from ticketmaster"
    facet paragraph (innerText): "Narrowed to the runs whose source is ticketmaster, matched by name. ..."   <- identical to the registered page's, character for character
    data-source-facet=" ticketmaster"; [data-dropped-params] ABSENT (the page claims it applied the facet)
  GET /cycles?source=ticketmaster%20          -> same: 0 rows, "found no runs from ticketmaster at all", nothing dropped
  GET /cycles?source=tic%20%20ketmaster       -> 0 rows, visible "no runs from tic ketmaster", data-source-facet="tic  ketmaster"

So the three sentences an operator READS are the registered source's name in every case, while the read was of a different string: one invisible character apart, the page renders 5 runs or claims there are none. The DOM text still holds the space (line_dom "... no runs from  ticketmaster at all."); only the layout collapses it, which is what the operator sees.

BUG-0153 itself is NOT undone by anything here and closed green: same walk, `/cycles?source=%E2%80%AEbandsintown` -> 200, 0 bidi controls outside <script>, 0 in body innerText, no [data-source-facet], `source` on the dropped line, window line = the unnarrowed sentence with all 5 rows; `?cycle=%E2%80%AEnot-a-uuid` -> 0 controls, `cycle` dropped (BUG-0147 intact); `/claims?source_id=<uuid>&domain=%E2%80%AEevents` and `/queues?source_id=<uuid>&bucket=%E2%80%AEjunk` -> 200, 0 controls anywhere in the text, junk keys reported dropped.

Repro (offline, exact, on the landed tree): in tests/offline/cycles/page.test.ts, the strict pin "shows the ?source= name it queried, not one the browser collapsed [admin-window/BUG-0155]" (in `describe("a ?source= link arriving from the Sources page")`), flipped from `it.fails(` to a plain `it(`. Watched RED before filing, once per case: `queried " bandsintown": expected 'bandsintown' to be ' bandsintown'`, and the same for a trailing space, blanks at both ends, and a double space inside (4 failed | 139 passed). As landed the pin is `it.fails` and the file is green; the day the hole closes the XPASS turns it red and sends the reader here.

Two honest arms, and the ticket should not guess silently:
(a) CANONICALISE the value where it is derived (`sourceNarrowing`), the way `canonicalRecordId` already canonicalises a padded id for `?cycle=`/`?run=` (BUG-0145/0146) — collapse the padding, query and spell the same string. Cheap, keeps every URL answering a page. Note a name with an internal double space still cannot be spelled faithfully in prose, so this arm must decide that case too (collapse it or refuse it).
(b) REFUSE a value whose rendered spelling differs from itself, and report `source` on the shared dropped-parameter line — BUG-0153's own arm, extended from "cannot be spelled safely" to "cannot be spelled faithfully".
The pin passes under either.

P3, the same price as the four tickets before it in this family and for the same reasons: URL-supplied only, on an admin surface behind `admin_allowed_emails`, no privilege boundary crossed, nothing written. It is a truthfulness defect on three sentences of one page. The CLASS for the architect: five tickets (BUG-0123, 0127, 0136, 0137, 0147, 0153) have now landed on "a URL value inside a sentence this app wrote", each closing one property of the value (no markup, no bidi, some ink, bounded length) — this one is the property none of them stated: WHAT IS SHOWN IS WHAT WAS USED. A predicate that answers "may I spell it" cannot answer it; the answer belongs where the value is derived, beside `canonicalRecordId`.

## Acceptance criteria
The class is ruled: ARCHITECTURE.md §7, "What is SHOWN is what was USED: one derivation per URL value class" (common violations row 20, promoted at seven bugs: BUG-0137, 0143, 0145, 0146, 0147, 0153, 0155). The arm is NOT the builder's to pick — this ticket lands the derivation, and the interior case is refused. Eight criteria.

1. ONE derivation, one home. `canonicalUrlText(value: string | undefined): string | null` is declared in `src/lib/url/text.ts` and is the only place a free-text URL facet value is derived. It is a pure leaf — it reaches no client, no `process.env`, no table name and nothing under `lib/db/**`, and `tests/offline/db/layering.test.ts`'s leaf set names it. Its steps, in order: `undefined` narrows nothing (`null`); strip the padding a paste carries, BY INK and at the ENDS only; nothing with ink left narrows nothing; a value `canSpellUrlValue` refuses (`src/lib/url/spellable.ts`, unchanged) narrows nothing; a value a browser would RE-SPELL narrows nothing, which inside printable ASCII is exactly a run of two or more U+0020; otherwise the stripped value is returned. What it returns is the ONE string that is both SENT to PostgREST and SPELLED in every sentence that names the facet.

2. `sourceNarrowing` is retired in the same move. `readRuns` (`src/lib/db/runs.ts`) and `/cycles` (`src/app/cycles/page.tsx`) both call `canonicalUrlText` directly; no code line and no comment in `src/` names `sourceNarrowing`; the OWNER map in `tests/offline/url/narrowing.test.ts` carries `canonicalUrlText: "src/lib/url/text.ts"` in its place, and `tests/offline/db/layering.test.ts`'s comment about the edge is updated to the new home. Rationale, so nobody re-adds it: once its body is one call to the derivation it is a second name for one question (common violations row 18), and it is row 17's named second instance — a pure function parked in `lib/db/**` where no leaf may reach it.

3. ONE ends-only ink-padding strip. `trimInkPadding` in `src/lib/url/text.ts` is the only declaration of that strip in `src/`, and `canonicalRecordId` calls it: the private `trimPad` in `src/lib/records/id.ts` is gone, its behaviour is carried over unchanged (read by code point via `Array.from`, asking `hasVisibleContent` one end character at a time), and the uuid grammar's answers do not move — `tests/offline/records/page.test.ts` (including QA's astral-pair attack at ~:1094), `tests/offline/queues/filters.test.ts` and the `?cycle=`/`?run=` cases in `tests/offline/cycles/page.test.ts` stay green. A hand-copied second strip is the defect this criterion exists to prevent (LESSONS 5; common violations row 9).

4. A padded name narrows and spells as its twin. `/cycles?source=%20ticketmaster`, `/cycles?source=ticketmaster%20` and `/cycles?source=%20%20ticketmaster%20%20` each render what `/cycles?source=ticketmaster` renders: the same run rows, `data-source-facet="ticketmaster"`, and `ticketmaster` spelled in full in the facet paragraph, in the runs window line's scope clauses and in the empty card — with `source` NOT on the dropped-parameter line. That is BUG-0145/0146's answer for `?cycle=`, now this facet's too.

5. Interior padding is REFUSED, not collapsed and not boxed. `/cycles?source=tic%20%20ketmaster` narrows nothing: no `[data-source-facet]` element anywhere on the page, no sentence names the value, every run in the window is drawn under the unnarrowed window line, and `source` appears as a `[data-dropped-param]` on the shared dropped-parameter line — the same arm the bidi value takes today (BUG-0153), so no new rendering is built. The alternative arm the ticket offered — an `Identifier` box carrying `white-space: pre` — is REJECTED by this ruling (§7 records why): do not build it, and do not weaken the pin to admit it.

6. The queried value equals the spelled value on every arm. For every `?source=` the page renders, either `[data-source-facet]`'s attribute equals the string `readRuns` narrowed the query by AND equals the text of the `dir="ltr"` box inside that paragraph as a browser lays it out (whitespace collapsed), or there is no facet element at all and `source` is reported dropped. Pinned by flipping the strict pin "shows the ?source= name it queried, not one the browser collapsed [admin-window/BUG-0155]" in `tests/offline/cycles/page.test.ts` from `it.fails(` to a plain `it(`, with its four cases and its assertions unchanged.

7. Nothing this family already closed reopens. `?source=ticketmaster` still narrows the runs read and is spelled in full in all three places; `?source=a-source-the-registry-never-heard-of` is still spelled in full over a 0-row window (BUG-0147/0153's "answer a half-typed URL" bar, which is why a SINGLE interior space is admitted and only a run of two or more is refused); `?source=%E2%80%AEbandsintown` still puts zero bidi controls in the body text and reports `source` dropped (BUG-0153); `?source=` and `?source=%20%20` still narrow nothing and earn no sentence. `readRuns` sends exactly `canonicalUrlText`'s output to `.eq("source", …)` and nothing else. The unit assertions in `tests/offline/runs/read.test.ts` move onto `canonicalUrlText`, and the two that INVERT under this ruling — `" spaced "` was returned verbatim and now derives to `spaced` — are rewritten to the new answer, never deleted.

8. The seam asks the DERIVATION, not the allowlist. `AskedSource` and the runs half's `source` gate (`src/components/cycles/adapter-runs.tsx`) render the facet only when the value handed in is already its own canonical form (`canonicalUrlText(v) === v`), replacing the `canSpellUrlValue` re-ask, so a second caller handing that component a raw parameter cannot reintroduce the defect. `?cycle=`'s seam (`src/components/cycles/asked-cycle.tsx`) keeps `canSpellUrlValue` and is not touched: its value queries nothing, so "not among the 200 newest cycles" is true of every spelling of it (§7).
