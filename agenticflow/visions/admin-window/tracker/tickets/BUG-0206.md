# RESOLUTION LATENCY renders three zeros and a dash over a window that holds nothing, directly under the panel BUG-0203 just fixed

## Description
The sibling half of BUG-0203, on the panel directly below it, on the same page,
in the same viewport, over the same table — still reachable on staging today.

**Expected** — LOOK_AND_FEEL -> The Feel -> Interaction principles -> Zeroes:
"a zero states what it excludes whenever the excluded set is not empty ... and
never stands bare beside the rows it silently drops." BUG-0203 settled what a
gauge panel does about that: at a counted zero the four figures give way to the
panel's own Empty state, built from the `EmptyWords` it already composes.

**Found** — `src/components/cycles/latency.tsx:30-37` composes exactly those
words (`nothing = latency.applies === 0 && latency.verdictUnsets === 0`,
holds: "decisions in this window", filledBy: "The resolver applies a claim to
canonical, ...") and hands them ONLY to its `Distribution` and its
`TrendTable` (lines 78-119). The four `GaugeCard`s above them
(`src/components/cycles/latency.tsx:45-77`) render regardless.

Measured on staging at 2026-09-11 18:03 UTC by server-rendering
`src/app/cycles/page.tsx` through the live harness (`renderPage`, read-only,
no writes):

    latency window [2026-09-04T18:03:40.727Z, 2026-09-11T18:03:40.727Z)
    field_provenance total=1712  in-window=0  excluded=1712
    resolution_runs  total=69    (the table rendered above the panel)
    cycle_health surface state: empty   (BUG-0203's fix, correct)
    resolution_latency surface state: ok

and the RESOLUTION LATENCY panel rendered, verbatim:

    Applies in this window      0   Claims that became the canonical value
    Median wait, claim to apply —   no apply in this window had a claim to measure from
    Unset by a human decision   0   Decisions that name no claim, so they carry no wait to measure
    Applies with no claim found 0   The claim behind the apply was not in this read - a join gap, not a wait

Three zeros and a dash, each with a sub-line, over a window that holds nothing,
excluding 1,712 `field_provenance` rows and naming none of them, two inches
under the 69-row cycles table — and now directly under a CYCLE HEALTH panel
that (correctly, since BUG-0203) says the window holds nothing. One page, two
adjacent panels, two different answers to the same emptiness.

This is the reading both M3 user-sims filed BUG-0203 for, still available on the
same screen: "a wall of 0s under a heading ... reads as good news at a glance".

**Repro (exact)**
1. `cd "kspace Admin"` on `run/admin-window`.
2. `npm run test:live -- tests/live/cycles.live.test.ts` passes — the live
   oracle grades this surface `ok` with `emptyAtZero: false`, so it never
   asks the question.
3. `./node_modules/.bin/vitest run --project=offline tests/offline/cycles/page.test.ts -t "renders no latency figure"`
   passes ONLY because the pin is a strict `it.fails`. Flip it to a plain
   `it(...)` and it fails at `figureLabels(markup)` still containing
   "Applies in this window" over `emptyWindows()` (watched red, this tree,
   2026-09-11).
4. Or drive it: the staging page at `/cycles` renders the four figures above.

**What the fix has to touch, beyond the component** (the same three consequences
BUG-0203 had, so the builder is not surprised):
- `tests/offline/cycles/page.test.ts`: flip the `it.fails` pin named in check 2
  to a plain `it(...)`; narrow `LATENCY_COUNTS` out of "states every labelled
  count as a real 0, and the wait it cannot measure as an absence" the way
  BUG-0203 narrowed `HEALTH_COUNTS` out of it, keeping LESSONS 7 intact over a
  window that HOLDS a decision; and update "grades each gauge on the read
  behind its own figures, block cards excluded", which currently asserts
  latency grades `ok` at an empty window.
- `tests/live/cycles.live.test.ts`: the latency case's `emptyAtZero: false` and
  `figure: "Applies in this window"` become the BUG-0203 shape.
- `Median wait, claim to apply` is an absence, not a count; it goes with the
  other three, since at `nothing` there is no wait to measure either.

**Out of scope, same as BUG-0203**: no new read, no sentence relating this
window to the table above it (M3 EC7), no colour, no tone, no staleness word,
and the `WindowLine` above is untouched.

## Acceptance criteria
On /cycles, where the resolution-latency read found no decision in its window (`latency.applies === 0 && latency.verdictUnsets === 0` — the condition the panel already computes as `nothing`), the panel renders none of its four GaugeCard figures or their sub-lines ("Applies in this window", "Median wait, claim to apply", "Unset by a human decision", "Applies with no claim found"), and in their place stands ONE state card of the surface's own — no `data-gauge-block` marker, so `ownCards(markup, '[data-surface="resolution_latency"]')` is exactly `["empty"]` — built from the `EmptyWords` the panel already composes. The `WindowLine` above is untouched and still the first thing under the heading. Where the window holds one or more decisions the panel renders exactly what it renders today: four cards, all four sub-lines, the distribution, the domain table and the closing note. No new read, no figure from another read, no sentence relating this window to any other surface (M3 EC7), and no colour, tone, severity or staleness word. Pinned by flipping the strict `it.fails` case 'renders no latency figure where the window holds no decisions (admin-window/BUG-0206)' in tests/offline/cycles/page.test.ts back to a plain `it(...)`, with every other case in that file green — which requires narrowing LATENCY_COUNTS out of 'states every labelled count as a real 0, and the wait it cannot measure as an absence' over an EMPTY window while keeping LESSONS 7 pinned over a window that HOLDS a decision, and updating 'grades each gauge on the read behind its own figures, block cards excluded'. tests/live/cycles.live.test.ts's latency case takes the BUG-0203 shape (no `emptyAtZero: false`, no `figure:`, an empty arm asserting no figure stands beside the words) and passes against staging.
