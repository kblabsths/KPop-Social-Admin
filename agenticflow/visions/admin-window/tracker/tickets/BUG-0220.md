# The registry reader takes a narrower declaration grammar than the sibling's own parser, so a typing pass next door reddens npm test and a single-quoted claim passes

## Description
QA attack on admin-window/BUG-0213, 2026-09-11, run/admin-window at 3920c720 (landed).

BUG-0213's fix answers attribution from a declaration on each side, per the architect's ruling — correct, and its own repro is dead (measured below). But the sibling's registry is the SIBLING's file, and what counts as a declaration in it is defined next door as code: `_declared_by` / `code_declarations` in `kspace Scraper/tests/live_safety/test_codes_named_once.py:72-105` parse the file with `ast` after blanking comments, and accept an `Assign` OR an `AnnAssign` whose single target is a Name and whose value is a string constant. Expected: the guard reads a registry entry in every form the sibling's own parser reads as a declaration — those three forms declare the same meaning, so our four stay green, and a stranger's claim stays red whichever of them it is written in.

Three forms the neighbour calls declarations are invisible to it, and the gap runs in BOTH directions.
