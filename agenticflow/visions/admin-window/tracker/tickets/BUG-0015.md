# Frame: a hovered nav item is pixel-identical to the active one, so two items read as current

## Description
Early walk of M1 (real app on 8771, 1280x900, light and dark). LOOK_AND_FEEL's Frame rule gives the active nav item one rendering of its own: 'Active item = chrome-inverse fill (gray-200 / gray-700) with primary text' — and the token layer says so in its own comment (--color-chrome-inverse, 'active nav item'). The shipped sidebar hands that exact rendering to hover as well. Measured on / with the pointer over 'Queues': the hovered item computes background rgb(229,231,235) and colour rgb(30,41,57); the active 'Dashboard' computes background rgb(229,231,235) and colour rgb(30,41,57). Identical, to the byte. Dark theme is the same story on the gray-700 pair. So while the pointer is anywhere in the sidebar the Frame shows TWO items dressed as current, and the operator's only cue to where they are is the one they are not touching — see agenticflow/tracker/evidence/designer/frame-nav-hover.png, where Dashboard (active) and Queues (hovered) are indistinguishable. The 'Sign out' button carries the same hover pair, so hovering it dresses a sign-out control as a seventh, active nav item. This matters more than a cosmetic nit because the sidebar is on all six pages and it is the only persistent statement of location the window has; the Feel's repeat-use principle ('nothing moves between visits, counts sit in fixed positions') rests on that statement being unambiguous, and bar 10's one-click investigation is navigated from here. Provenance checked: shell.tsx is 5cf4199, admin-window/TASK-0005 — ticket-bearing, so this is a violation, not a human-lane divergence. Hover is a state, not a claim of place; the Look reserves chrome-inverse for the claim.

## Acceptance criteria
1. On every page, an item under the pointer is visibly distinct from the active item: their computed background and colour pair are not equal, in light and in dark.
2. The active item keeps exactly the rendering LOOK_AND_FEEL names — chrome-inverse fill with primary text — and no non-active item, including the sign-out control, is given that fill in any state.
3. Hovering the sign-out control does not render it as a nav item.
4. The 120ms colour transition and the accent focus ring are unchanged; keyboard focus stays visible on every item (bar 9), and the focus ring is not the thing carrying the hover distinction.
5. tests/offline/shell asserts the active item's classes and a non-active item's hover classes are not the same set, so the two states cannot silently converge again.
Human-check: with the pointer resting on 'Queues' while on the Dashboard, exactly one sidebar item reads as 'you are here'. (human-checkable)
