# The reference field: a picker that links rows, and a reference that renders as a link

## Description
**SPEC F12.** A reference field is a picker, never a text box — and a reference RENDERS as a link to the record it names.

**Amended 2026-09-09 for Ben's vision amendment of 2026-09-08.** He struck "groups/idols edit directly within it" and ruled that groups/idols get **no door** (no listing, no search, no entry point) and stay as test tables until they are removed. **The display half of this ticket died with it**: linking `idols.group_id` to a group's record page was the "ends the idol-group islands" half, and after TASK-0040 neither table has a record surface to link to or from. That work is cut — not deferred, not rebuilt behind a flag. What survives is the edit half below, which VISION still carries word for word.

**The edit half (spec §8, acceptance test 8).** A field whose kind is `reference` edits through an **entity picker**. The picker's choice lands as the admin-tier observation **plus its confirmed match**, so the apply produces `venue_id` / `event_performers` ROWS instead of writing text into a column. The picker searches within the referenced entity's own table, offers only rows that exist, and **never creates an entity** — entity creation is the resolver's, not Admin's. Absent `settle_review_item`, the picker does not render at all: the field is read-only with the reason named, like every other override-regime field (FEAT-0011).

**The display half, as it now stands.** A reference still renders as a **link to the record it names** wherever both ends have a record surface — which today means `events.venue_id`, already shipped (BUG-0034 replaced a bare uuid with a link; `recordHref` is the one spelling, DEBT-0001). Nothing new is built for it here. **Do not** add a link, a picker, a listing, a search box or a Browse affordance over `groups` or `idols`: they have no door by Ben's ruling, and reaching for one under cover of this ticket is exactly the over-reach the strike forbids.

**It adds no editable column.** SPEC F8: the map holds "user-facing fields only, never ids, keys, or timestamps". A key is DISPLAYED, never mapped. A ticket that adds a key to the allowlist is wrong.

**Same absence rule as every M2 surface:** with the function absent, the reference field is read-only and says why; nothing throws; the link rendering still works, because it is a read.

vision_trace: "The edit surface driven by one hand-written map of what is editable: ... a reference field links rows, never text; provenance is visible at the field."

## Acceptance criteria
1. A `kind: reference` field renders an entity picker, never a text input; a structural test asserts no code path submits a reference field's value as a string.
2. The picker's submission payload carries the chosen entity's id AND its confirmed match, asserted against the recording stub; the payload contains no free text for that field.
3. The picker offers only rows that exist in the referenced table and has no create affordance: zero controls in the picker create, insert, or accept an unmatched value.
4. With `settle_review_item` absent, a reference field renders read-only with the reason named; no picker control appears; the page answers 200 and throws nothing.
5. The shipped reference rendering (`events.venue_id` -> the venue's record) still resolves to a 200 authed page through the single `recordHref` spelling; no second href helper is introduced.
6. No key column is in `EDIT_CONFIG`'s editable list for any table: the existing config guard still passes, and a forged PATCH naming a key is refused server-side with 403.
7. Nothing gives `groups` or `idols` a door: no listing page, no search input, no Browse entry, no nav link and no cross-link to either table anywhere in `src`; the sidebar still holds exactly six links and Browse still renders exactly one curated view.
8. `npm run lint`, `tsc --noEmit` and `npm test` green; the record page's live suite green.
