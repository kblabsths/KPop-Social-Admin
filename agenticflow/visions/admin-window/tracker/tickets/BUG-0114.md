# A ?source=-narrowed runs window states the facet's oldest run as the whole table's floor: '/cycles?source=X' says 'nothing earlier is retained' about runs it never read

## Description
Found while attacking BUG-0109 (the not-filled clause), 2026-09-09, on the landed run branch.

**Expected** — LOOK_AND_FEEL bar 13 and BUG-0109 criterion 1: on a window that did not fill, "the bottom of the list is the object's own floor and not the window's cap". `didNotFill` (`src/components/ui/window-line.tsx:230-244`) renders that as `"<rows> recorded since <oldest>; nothing earlier is retained"` — a claim about the OBJECT.

**Found** — the only drawn window in the app whose read is NARROWED makes the claim anyway. `/cycles` reads its runs through `readRuns({ source: askedSource })` (`src/app/cycles/page.tsx:192`), which adds `.eq("source", <name>)` (`src/lib/db/runs.ts:224`). Under that facet the window still comes back below its cap, so `truncated` is false and the line names the facet's oldest row as the point before which nothing is retained. Runs older than it are retained — they are just from another source, and the same page renders them without the facet.

`DrawnWindow` carries no fact about the narrowing, so `didNotFill` cannot know: `limit`, `held`, `truncated`, `over`, `oldest`. The `?source=` value reaches `AdapterRuns` only as the separate `AskedSource` paragraph, which sits directly BELOW the window line — so one screen says both "Narrowed to the runs whose source is bandsintown" and "runs recorded since <bandsintown's first run>; nothing earlier is retained".

**Repro (offline, deterministic — the pin committed with this ticket)**
1. `cd "kspace Admin"`
2. `./node_modules/.bin/vitest run --project=offline tests/offline/runs/page.test.ts -t "does not offer its bottom row"`
3. The test is `it.fails` and passes, i.e. its assertion is red today. Flip it to `it(` to read the failure:

```
AssertionError: expected 'The adapters’ newest runs, newest fir…' not to contain '2026-09-02 02:00 UTC'
Received: "The adapters’ newest runs, newest first — a window of at most 200, not a count
of the runs that exist. The window did not fill — 3 of at most 200 — so it holds all the
runs the read found: runs recorded since 2026-09-02 02:00 UTC; nothing earlier is retained."
```
at `tests/offline/runs/page.test.ts:500`. The same `runs` population holds a run started `2026-09-02T01:00:00Z` (`UNREGISTERED`, source `a-source-the-registry-never-heard-of`) — an hour EARLIER than the instant the faceted line offers as the floor, and rendered on the same page with no facet.

**Repro (in the app)**
1. Sign in to the dashboard; open `/sources`.
2. Click any source's runs link — `sourceRunsHref` (`src/lib/sources/routes.ts:65`) builds `/cycles?source=<name>`. It is a first-class in-app link, not a hand-typed URL.
3. Read the Adapter runs window line: with runs from more than one source in the table, it names that source's oldest run as the table's floor.

**Reachability today** — measured on staging 2026-09-09 through `renderPage(CyclesPage, { source })` with an independent `runs` read: the table holds 5 runs, ALL from `ticketmaster` (floor `2026-08-31T10:35:50Z`), so today the faceted sentence is accidentally true and the plain and faceted lines are byte-identical. It becomes false the first time a second adapter files a run — bandsintown and eventbrite are named sources of this ecosystem (root CLAUDE.md), and `/sources` already links each of them here.

**Second manifestation, same root cause.** With `?source=` matching nothing, the same helper's zero-row arm renders "The window did not fill: the read happened and found no runs at all." (`window-line.tsx:236`) directly above the page's own empty card, which says the window holds "runs from <name>". "no runs at all" is a claim about the table; the read only looked at one source's.

**Not a bug in the sibling surfaces** — checked: `/cycles` cycles, `/queues` verdicts, `/browse` events and the Dashboard's two panels all read unfiltered (`src/lib/db/cycles.ts:193`, `verdict.ts:436`, `browse.ts:119-124`, `dashboard.ts:180-208`), and `/claims` and the entity picker pass `oldest: null`. `runs` is the only narrowed drawn window.

**Expected fix shape (not prescriptive):** either the window carries the fact that its read was narrowed, and `didNotFill` states the floor of what it read rather than of the object ("…of the runs from bandsintown"), or a narrowed window states no floor at all — the same honest `oldest: null` `/claims` uses. What it may not do is state a floor of the object over a read that did not cover it.
