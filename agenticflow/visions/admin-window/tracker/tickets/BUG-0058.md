# The staging residue sweep never runs: it ilikes a timestamp column and throws, so no walk's write was ever verified clean

## Description
The residue sweep is the check every walk relies on before it claims its staging writes were cleaned up (STACK.md section 5: 'restores it before the walk ends, and sweeps for residue afterwards'; acceptance test 13). It has never produced a clean result — it throws before it grades a single column.

Repro (repo root, staging names in .env, 1 second):

  npx vitest run --project=live tests/live/residue.live.test.ts
  x staging, after the campaign > carries no value this campaign wrote, in any column it could write 815ms
    -> Error: the residue sweep's count of groups.created_at failed: operator does not exist: timestamp with time zone ~~* unknown
    at countMarked tests/live/residue.live.test.ts:112:11
    at residueIn tests/live/residue.live.test.ts:133:16
    at tests/live/residue.live.test.ts:167:24
  Test Files 1 failed (1); Tests 1 failed | 1 passed (2)

Expected: the sweep counts marker-bearing values in every TEXT column of every editable table and reports 0, or names the rows it found. Its own comment at tests/live/residue.live.test.ts:63-64 states the rule it means to follow: 'ilike against a non-text column is an error rather than an answer'.

Found: 'textColumns' decides what is text by sampling rows and asking 'typeof value === "string"' (tests/live/residue.live.test.ts:92). PostgREST serialises timestamptz as a JSON STRING, so 'groups.created_at' (and every other timestamp/date/uuid-shaped column) is classified as a text column, and 'countMarked' then issues '.ilike("created_at", "%admin-window%")' (:107-110), which Postgres refuses: 42883 'operator does not exist: timestamp with time zone ~~* unknown'.

Impact — this is why it matters beyond a red test: the throw happens on the FIRST such column, inside the loop at :165-170, so the sweep aborts and NO column of NO table is ever counted. Every walk that reported 'swept for residue, clean' got an exception, not a zero: a real leftover value in groups.name would be invisible behind this failure. The failure is deterministic and independent of any ticket — it reproduces on the landed tree with no BUG-0041 file involved (BUG-0041 touched only src/app/claims, src/components/claims and tests/offline/claims).

Note the type-sniffing cannot be fixed by ignoring 'created_at' by name: the same misclassification hits any timestamp, date, uuid or enum column on any table added to EDIT_CONFIG, and the file deliberately refuses to carry a copy of the schema. A sweep that skips a column silently would also re-introduce the vacuous pass this file exists to prevent — an unsweepable column has to be named, not dropped.

## Acceptance criteria
npx vitest run --project=live tests/live/residue.live.test.ts is green against staging and reports a real per-column result: it counts the marker in every editable text column of every table in EDIT_CONFIG and asserts 0.

A column the sweep cannot ilike (timestamp, date, uuid, numeric, enum) is excluded by a rule that does not depend on the JSON type of a sampled value, and the exclusion is visible — the test still asserts that every editable text column named in EDIT_CONFIG was among the scanned ones (the existing check at :156-163 must keep passing).

A refusal from the database is still a failure, never a zero: an error from a scan of a column the sweep DID decide to grade still throws with the column name and the code.

The offline suite, tsc and lint stay green.
