# Two offline tests crash (ENOENT) when they walk src/ while the layering suite's probe is in flight

## Description
Found attacking BUG-0029 on the landed tree (run/admin-window, 7fda465). BUG-0029 hid the layering suite's probe from every COMPILER (moved it into the dot-directory src/.probes/, verified: an ill-typed file there leaves tsc --noEmit at 0, npm run lint at 0, npm run build at 0, and is absent from tsc --listFilesOnly). It did not hide it from the offline suite's OWN src/ walkers, and it turned a transient FILE into a transient DIRECTORY, which adds a second crash site.

Four offline test files walk src/ recursively in parallel workers while tests/offline/db/layering.test.ts creates and rm -rf's src/.probes/__credential_guard_probe__.ts around each of its ~20 scanWithProbe() calls (layering.test.ts:258-267):

- tests/offline/claims/read.test.ts:348 codeText() -> bare fs.readFileSync, no ENOENT guard, no "__" name filter.
- tests/offline/browse/views.test.ts:672 and :684 -> bare fs.readFileSync(file, "utf8") inline in both it() bodies, same gaps.
- tests/offline/edit/config.test.ts:264 and tests/offline/review/one-place.test.ts:65 already handle it (skip "__"-prefixed names AND swallow ENOENT on read) — their comments name this exact hazard. The two above were never given the same treatment.
- readdirSync is unguarded in ALL FOUR walkers: src/.probes/ is now a directory the walk descends into, so it can also die with "ENOENT ... scandir". Before BUG-0029 the probe was a plain file (src/__credential_guard_probe__.ts) and no directory could vanish mid-walk.

Expected: npm test is deterministic — the offline suite is green or red on the code, never on the interleaving of two workers (BUG-0029's own stated bar: "a green suite is green in the primary tree and in a receipt worktree alike").
Found: it crashes with ENOENT and reddens the offline project.

## Repro A (proves the walkers see into src/.probes/, deterministic, 100%)

  mkdir -p src/.probes
  printf 'import { T } from "@/lib/db/tables";\nexport const x = supabase.from(T.pendingClaims);\n' > src/.probes/__qa_visible_probe__.ts
  printf 'export const y = ".rpc(";\n' > src/.probes/__qa_rpc_probe__.ts

Observed: 2 failed | 110 passed. "what Browse must NOT contain > has no SQL-executing route and no whole-table browser" -> expected [ Array(1) ] to deeply equal []; "the view has exactly one reader > queries pending_claims from src/lib/db/claims.ts alone" -> expected [ ...(2) ] to deeply equal [ 'src/lib/db/claims.ts' ]. edit/config.test.ts and review/one-place.test.ts stayed green (their "__" filter). So the dot-directory is invisible to compilers and fully visible to these two walkers.

## Repro B (the real timing race, 26 of 40 runs red)

Background loop doing exactly what scanWithProbe does, at higher frequency:

  while true; do mkdir -p src/.probes; printf 'export const key = process.env.SUPABASE_SERVICE_ROLE_KEY;\n' > src/.probes/__qa_race_probe__.ts; rm -rf src/.probes; done

against 40 sequential runs of:

  ./node_modules/.bin/vitest run tests/offline/claims/read.test.ts tests/offline/browse/views.test.ts

Observed: 26/40 runs exit non-zero. Two error shapes, both from the walk:
- 24 runs: "ENOENT: no such file or directory, open '<repo>/src/.probes/__qa_race_probe__.ts'" (readFileSync)
- 2 runs (loop iterations 19 and 21): "ENOENT: no such file or directory, scandir '<repo>/src/.probes'" (readdirSync on the vanished probe directory — the variant that BUG-0029 introduced and that the two hardened walkers do NOT survive either).
Control: 22 consecutive full `npm test` runs WITHOUT the churn loop were green (5 idle, 5 under 8 CPU spinners, 12 under 20 spinners on a 10-core box), so the natural rate is low — this is a receipt-flipper, not a permanent red.

tests/offline/toolchain.test.ts, describe "walking src/ while the layering probe comes and goes". It plants a DANGLING SYMLINK at src/.probes/__credential_guard_probe__.ts (readdir lists it, open fails ENOENT — the race with the timing removed) and runs the four walkers as a child vitest, asserting no ENOENT and exit 0. ## The bar (the fix is the builder's call)

No offline test may redden because another worker created or removed a path under src/. The two obvious shapes: give claims/read.test.ts and browse/views.test.ts the ENOENT-tolerant reader and "__"-name filter their two siblings already have, and make every one of the four walkers tolerate readdirSync throwing ENOENT on a directory that vanished; or stop putting the probe under src/ at all. Do NOT fix it by deleting a walker or by weakening what it asserts — these four rules are the campaign's structural guards. When the walkers are fixed, remove the .fails marker on the pin so it protects the invariant going forward.
