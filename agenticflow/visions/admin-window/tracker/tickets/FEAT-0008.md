# The edit surface — the config map and pre-cutover direct edits

## Description
VISION: "The edit surface driven by one hand-written map of what is editable: groups/idols edit directly within it." SPEC F8. Contracts read 2026-09-01: admin-observability.md §8 (the edit surface) and §3 (events stop being hand-editable until the verdict slice lands); admin-build.md ground rule "One hand-written config drives the edit surface"; the AGENTS.md data-ownership rule. One hand-written map from table name to its editable columns — user-facing fields only, never ids, keys or timestamps; everything absent from the map is read-only at the surface, whatever a route could technically reach. Everything else derives from the regime of the table; in M1 only the pre-cutover regime is built: groups and idols edit directly within their allowlist, legal and unprovenanced as the ownership rules allow, and a scalar column edits as a cell. events and venues render read-only and no write path to them exists from Admin — the override path, the admin_locked provenance stamp, the verdicts override row and the reference-entity picker all belong to the verdict slice and must not be built or scaffolded here. No catalog row is inserted or deleted from Admin; scraped_events is never written; no allowlist is widened to a link or a non-scalar (performers and venues are links, not fields of events).

## Acceptance criteria
M1 EC10. Acceptance test 7, pre-cutover half: a column present in the map edits and the value persists after reload; a column absent from the map refuses even a forged request — refused server-side rather than merely hidden, leaving the row unchanged; a groups/idols edit updates directly within its allowlist. No write path from Admin to events, venues or event_performers, no insert or delete of catalog rows, and `bash -c "! grep -rq scraped_events src"` passes. No migration, no DDL from app code, no SQL-executing route. Screenshots of the groups and idols edit flows are captured for the milestone-close review (human-checkable). `npm run lint` and `npm run build` exit 0.
