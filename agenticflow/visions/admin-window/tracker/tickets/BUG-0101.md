# A refusal on a record's LAST field draws its app-voice half outside the table's clipping container - the half BUG-0098 shipped is the half that disappears

## Description
Measured 2026-09-08 by QA attacking the BUG-0098 + BUG-0099 batch: production build of `run/admin-window` at e73fa20, served on 127.0.0.1:8792 against staging (`ubfjjqlvnpnoborczbdb`), bundled Chromium, 1440x900, BOTH themes, `walk_sandbox` row `...0001` (`reset-sandbox` before AND after; "deleted 3, seeded 3, read back and verified" both times).

**Expected** — BUG-0098 criterion 1: "A refused write renders BOTH halves at the field: the database's own refusal verbatim in mono, and one sentence in the app's voice naming what to do." And the rule this repo already wrote down for this exact box, `hintSide` (`src/components/edit-cell-layout.ts:135-151`): "Below the last row there is no neighbour, only the table's own container: `DataTable` wraps its table in `overflow-x-auto`, and a box whose other axis is `visible` computes to `auto` - it clips. So the last line's hint hangs above."

**Found** — `EditStatus`'s failed box is `STATUS_BOX` (`src/components/EditableCell.tsx:451-452`), anchored `absolute top-0 left-full`. It grows DOWNWARD from the row's top and obeys no side, so on a record's LAST field it grows past the fields table's bottom edge - and the half it loses is the second one, the app-voice sentence BUG-0098 shipped.

Exact repro:
1. `node tests/walk/reset-sandbox.mts` with the STACK.md §5 staging mapping.
2. `npm run build` + `npm run start -- --port <free>`; mint the walk cookie; open `/records/walk_sandbox/00000000-0000-4000-8000-000000000001` at 1440x900.
3. Click the `observed_on` value - the LAST row of the fields table - type `nope`, press Enter. (Any refusal on the last row does it; `observed_on` is simply the last editable field of this record.)

Measured at rest (pointer parked at 0,0), identical in light and dark:
- fields table scroll container (`div.overflow-x-auto`): top 143, height 220 -> bottom edge y=363; `scrollHeight` 250 vs `clientHeight` 220.
- the refusal box (`role="alert"`): y 337 -> 393.
- mono half `invalid input syntax for type date: "nope" (22007)`: 339 -> 371, so its second line is cut 8px mid-word.
- app-voice half `Type a date, like 2026-01-15.`: 373 -> 391, **entirely below the container's bottom edge - 28px outside, `fullyOutside: true`**. None of it is painted. Scrolling that inner container to `scrollTop: 30` brings it back (`insideNow: true`), which is the only way to read it.
Walk screenshot (gitignored, local): `agenticflow/tracker/evidence/BUG-0098/lastrow-light.png` - the refusal ends mid-word and no sentence follows it.

**This is not BUG-0086's class and does not reopen it.** Nothing reflows: in the same walk, row geometry before and after the refusal is identical (rows at y=169.5 / 198.5 / 231.5 / 264.5 / 297.5 / 330.5; cells x=209 / 459.3 / 1175.7, w=250.3 / 716.41 / 247.3 in both snapshots), so the status is out of the flow exactly as BUG-0086 requires. This is the OTHER consequence of being out of the flow - the one `hintSide` already handles for the hint and nobody handles for the status.

Rows other than the last are correct and stay correct: `tally` / 22P02 box 271->327 and `label` / 23502 box 205->325 both sit inside y=363, both halves painted, both fix sentences right ("Type a whole number, like 7." / "label cannot be cleared - type a value into it.").

It gets worse with message length, not better: the box is `max-w-xs`, so its height is a function of the refusal's own words. `label`'s 23502 DETAIL already measures 120px tall; that same refusal on a last row would put ~94px outside the container. FEAT-0011's gate refusals arrive in this same box.

**Expected: both halves render at the field (BUG-0098 criterion 1). Found: on a record's last field the app-voice half is drawn 28px below the fields table's clipping container and is not painted at all** - `src/components/EditableCell.tsx:451` (`STATUS_BOX`, anchored `top-0`, no side), while `src/components/edit-cell-layout.ts:149` already computes that side for the hint.

Note for the fixer, and QA's own honesty: there is NO offline pin for this today and QA did not invent one. `tests/offline` is plain node with `renderToStaticMarkup` and no jsdom (STACK.md §4), so a bounding box is unobservable there - `edit-cell-layout.ts`'s own docstring says it: "The decision is pinned offline; the boxes themselves are measured in a walk." The decision this needs does not exist yet, which is why criterion 4 asks for it.

## Acceptance criteria
1. On the LAST field of a record, a refused write renders BOTH halves inside the fields table's own container: with the cell resting and nothing scrolled, the app-voice sentence is painted in full and the mono refusal is not cut mid-line. Measured on a production build at 1440x900 in both themes, `/records/walk_sandbox/00000000-0000-4000-8000-000000000001`, `observed_on` typed `nope`.
2. Every other row keeps exactly what it has today: `tally` / 22P02 and `label` / 23502 still render both halves at the field, unchanged.
3. The status stays OUT of the row's flow (BUG-0086, unchanged): committing a cell moves no row's y and no cell's x or width. Nothing here re-introduces the reflow, and the box stays inert to the pointer.
4. The placement decision is a PURE rule in `src/components/edit-cell-layout.ts`, beside `hintSide`, and is pinned in the offline suite the way `hintSide` is (`tests/offline/ui/editable-cell.test.ts`) - geometry stays a walk fact, the decision does not.
5. The refusal is still the database's words verbatim, both halves are still inside the one `role="alert"`, and the success path is untouched: `saving...` in secondary, `saved` in healthy for ~1.5s.
6. `npm run lint` and `tsc --noEmit` clean; the targeted offline files and the record page's live suite green.
