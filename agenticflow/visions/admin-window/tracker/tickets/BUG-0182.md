# One pretty-printed document is counted once per line, so the account grows larger than the page it summarised

## Description
**Module:** `src/lib/db/result.ts` — `askedLineByLine`, the per-line arm of question 2 (admin-window/BUG-0179 criterion 5).

**Expected** (the property "COUNTED, NEVER QUOTED" exists to deliver, admin-window/BUG-0170 and BUG-0173): an account that COUNTS a document rather than quoting it is shorter than the document it counted, and it states the length of what arrived.

**Found:** one document is counted once per LINE, so a pretty-printed page becomes one clause per markup line and the account is 2-3x LONGER than the part it replaced, with no number in it equal to the length of anything that arrived. Nothing foreign is quoted — the leak admin-window/BUG-0179 closed stays closed — but the operator reads a wall of the APP's own repeated sentence and a list of lengths (15, 19, 6, 47, 24 …) describing a document that arrived once.

Measured on run/admin-window at 6ac0060 (the landed BUG-0179), through `classify` and rendered through `StateOf` -> `ErrorLine`:

1. A realistic Cloudflare interstitial (17 lines, 426 chars) one line below the client's own prose — `details = "reference 8f3c1\\n<page>"`, the exact shape criterion 5 exists for: part 442 chars -> **account 1,380 chars**, 17 clauses.
2. A fuller interstitial (21 lines, 713 chars) in the same field: part 729 chars -> **account 1,692 chars, 21 clauses**, rendering **2,045 characters of markup** into one `data-state="error"` card.
3. Scale: a 400-line document one line below prose, part 11,505 chars -> **account 32,020 chars** (ratio 2.78), 400 clauses.
4. Through the `code` field beside a real message (the field BUG-0179 newly routed through the derivation), with a code whose first line is not markup: code 2,105 chars -> **account 15,935 chars**, 200 clauses.

The same page as the WHOLE part is one clause of 85 characters (`documentInstead(raw)` at the part granularity) — so the two granularities of one question give answers that differ by 20x on the same bytes.

**Reachability:** the operator-visible error card on any page whose read meets an intermediary (`/claims` has six HEAD count reads and three cards; measured by QA on BUG-0179), and the PATCH route's JSON body (`Response.json({error: result.message})`, src/app/api/admin/records/[table]/[id]/route.ts:334). A WAF interstitial is served pretty-printed; the whole-part arm catches it when the part BEGINS with it, and this arm is what is left when it does not.

**Not culpable to admin-window/BUG-0179**, which implemented its criteria faithfully: criterion 5 REQUIRES question 2 be asked line by line of every part, and its named case uses a one-line page (`<html><body>504 Gateway Time-out</body></html>`) where one line is one clause. The class pre-dates that ticket in the FRAMED path (pre-fix `withoutRuntimeFrames` already mapped `isDocument(line) ? documentInstead(line) : line` per line, 6ac0060^1); BUG-0179 extended the path to frameless parts and to the code, which is where it now shows. All seven of its criteria verified green by QA on the landed tree.

**Not admin-window/DEBT-0020**, and a line-level dedup does not fix this: DEBT-0020 is a repetition of words the DATABASE authored, deduplicated by dropping an identical line. Here the repeated clauses are the APP's own and are all DIFFERENT strings — each carries its own line's length (15, 19, 6, 47 …) — so an identical-line rule collapses none of them. The question for the architect is whether a RUN of document lines is one document (counted once, at the length of the run), and it is a ruling, not a builder's choice.

**Repro (offline, exact):**
```
./node_modules/.bin/vitest run --project=offline tests/offline/db/result.test.ts -t "counts ONE document once"
```
The pin is `it.fails("counts ONE document once, however many lines it was printed on (admin-window/BUG-XXXX)")` in tests/offline/db/result.test.ts, watched RED as a plain `it` on 6ac0060 (`AssertionError: expected 1380 to be less than 442`) before it was flipped. **Flip it back to a plain `it` when this is fixed** — strict, so it reddens the day the divergence disappears. Its must-not-touch twin, `it("counts a pretty-printed document that IS the whole part exactly once")`, is green today and forbids the lazy fix of counting less: the whole-part arm must still count, and still state the length of what arrived.

## Acceptance criteria
THE RULING THE TICKET ASKS FOR (architect, 2026-09-11): A RUN OF CONSECUTIVE DOCUMENT LINES IN ONE PART IS ONE DOCUMENT. `askedLineByLine` emits ONE `documentInstead` clause per run of consecutive lines that answer question 2, and the number in that clause is the length of the document AS IT ARRIVED — the run's own characters, the newlines between its lines included — never a per-line length and never the length of the whole part. §4.1's one derivation is kept, not widened: the same `isDocument` predicate decides each line exactly as today, nothing new is inspected, no fourth question is added, no length cap and no vocabulary match appears anywhere on this path (Common violations row 15, LESSONS 4). The clause is emitted once per document instead of once per line; that is the entire change to the derivation.

1. THE ACCOUNT IS SHORTER THAN WHAT IT COUNTED. On each of the four shapes QA measured — the 17-line Cloudflare interstitial one line below the client's own prose, the fuller 21-line one, the 400-line document, and the 200-line `code` beside a real message — the rendered account is SHORTER than the part it replaced, and carries exactly ONE document clause rather than one per line. Asserted as a property of the account against the part (`account.length < part.length`, and one occurrence of the clause), never against a recorded constant: the clause's wording is `documentInstead`'s and this ticket does not touch it.

2. THE TWO GRANULARITIES OF ONE QUESTION NO LONGER ANSWER 20x APART. The same document counted as the WHOLE part and counted as a run one line below the database's prose produce the same single clause, differing only in the number of characters each one actually carried. The whole-part arm is unchanged: `partOfAccount`'s `isDocument(trimmed)` -> `documentInstead(raw)` still counts and still states the length of what arrived, and QA's must-not-touch twin `it("counts a pretty-printed document that IS the whole part exactly once")` is green with no line rewritten.

3. THE OVER-GROUPING TWIN, WHICH FORBIDS THE LAZY FIX (LESSONS 8). A named case carries both directions: one document printed over N lines counted ONCE at the length of the run — and a part carrying TWO documents separated by a line of the database's own prose counted as TWO, each at its own length, with the prose line still crossing verbatim between them. A rule that folds a whole part into one clause, or that counts everything after the first `<` as one document, fails the twin. `it("counts two documents in one part as two, not as one")` exists in tests/offline/db/result.test.ts as a plain `it`, with its fixtures local literals.

4. EVERYTHING ELSE THE DERIVATION DOES IS UNCHANGED, BYTE FOR BYTE. A part where NO line answers either question is still returned UNTOUCHED — not re-joined, not re-trimmed, not re-spaced; prose lines are still kept verbatim and joined as they are today; runtime frames are still dropped, still counted, and `framesInstead`'s wording and placement are unchanged; the part is still never truncated at the first frame (admin-window/BUG-0016); the provenance question is still asked first; `withoutSecrets` still runs LAST; the `code` arm (admin-window/BUG-0179) and the serialised arm are untouched, and no question is added to `partOfAccount`'s three. The ten-fixture table of tests/offline/db/result.test.ts keeps its five-and-five shape with every carries/never assertion unchanged and no case rewritten, and BUG-0170's, BUG-0173's and BUG-0179's pins are green.

5. STILL COUNTED, NEVER QUOTED. No byte of any document reaches the account: the four measured shapes render no `<`, no tag name, no `DOCTYPE` and no character of the intermediary's own text, on the `DbResult` and through `StateOf` -> `ErrorLine` in rendered markup.

6. THE PIN FLIPS. `it.fails("counts ONE document once, however many lines it was printed on (admin-window/BUG-0182)")` lands as a plain `it(...)` with its own assertion unchanged (the account is shorter than the part it replaced), so it reddens the day the divergence comes back.

7. The diff is the two files of the touch scope and nothing else; `npm run lint` and `npm run typecheck` are clean and the targeted suites are green.
