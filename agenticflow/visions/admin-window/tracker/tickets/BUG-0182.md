# One pretty-printed document is counted once per line, so the account grows larger than the page it summarised

## Description
**Module:** `src/lib/db/result.ts` — `askedLineByLine`, the per-line arm of question 2 (admin-window/BUG-0179 criterion 5).

**Expected** (the property "COUNTED, NEVER QUOTED" exists to deliver, admin-window/BUG-0170 and BUG-0173): an account that COUNTS a document rather than quoting it is shorter than the document it counted, and it states the length of what arrived.

**Found:** one document is counted once per LINE, so a pretty-printed page becomes one clause per markup line and the account is 2-3x LONGER than the part it replaced, with no number in it equal to the length of anything that arrived. Nothing foreign is quoted — the leak admin-window/BUG-0179 closed stays closed — but the operator reads a wall of the APP's own repeated sentence and a list of lengths (15, 19, 6, 47, 24 …) describing a document that arrived once.

Measured on run/admin-window at 6ac0060 (the landed BUG-0179), through `classify` and rendered through `StateOf` -> `ErrorLine`:

1. A realistic Cloudflare interstitial (17 lines, 426 chars) one line below the client's own prose — `details = "reference 8f3c1\\n<page>"`, the exact shape criterion 5 exists for: part 442 chars -> **account 1,380 chars**, 17 clauses.
2. A fuller interstitial (21 lines, 713 chars) in the same field: part 729 chars -> **account 1,692 chars, 21 clauses**, rendering **2,045 characters of markup** into one `data-state="error"` card.
3. Scale: a 400-line document one line below prose, part 11,505 chars -> **account 32,020 chars** (ratio 2.78), 400 clauses.
4. Through the `code` field beside a real message (the field BUG-0179 newly routed through the derivation), with a code whose first line is not markup: code 2,105 chars -> **account 15,935 chars**, 200 clauses.

The same page as the WHOLE part is one clause of 85 characters (`documentInstead(raw)` at the part granularity) — so the two granularities of one question give answers that differ by 20x on the same bytes.

**Reachability:** the operator-visible error card on any page whose read meets an intermediary (`/claims` has six HEAD count reads and three cards; measured by QA on BUG-0179), and the PATCH route's JSON body (`Response.json({error: result.message})`, src/app/api/admin/records/[table]/[id]/route.ts:334). A WAF interstitial is served pretty-printed; the whole-part arm catches it when the part BEGINS with it, and this arm is what is left when it does not.

**Not culpable to admin-window/BUG-0179**, which implemented its criteria faithfully: criterion 5 REQUIRES question 2 be asked line by line of every part, and its named case uses a one-line page (`<html><body>504 Gateway Time-out</body></html>`) where one line is one clause. The class pre-dates that ticket in the FRAMED path (pre-fix `withoutRuntimeFrames` already mapped `isDocument(line) ? documentInstead(line) : line` per line, 6ac0060^1); BUG-0179 extended the path to frameless parts and to the code, which is where it now shows. All seven of its criteria verified green by QA on the landed tree.

**Not admin-window/DEBT-0020**, and a line-level dedup does not fix this: DEBT-0020 is a repetition of words the DATABASE authored, deduplicated by dropping an identical line. Here the repeated clauses are the APP's own and are all DIFFERENT strings — each carries its own line's length (15, 19, 6, 47 …) — so an identical-line rule collapses none of them. The question for the architect is whether a RUN of document lines is one document (counted once, at the length of the run), and it is a ruling, not a builder's choice.

**Repro (offline, exact):**
```

```
The pin is `it.fails("counts ONE document once, however many lines it was printed on (admin-window/BUG-XXXX)")` in tests/offline/db/result.test.ts, watched RED as a plain `it` on 6ac0060 (`AssertionError: expected 1380 to be less than 442`) before it was flipped. **Flip it back to a plain `it` when this is fixed** — strict, so it reddens the day the divergence disappears. Its must-not-touch twin, `it("counts a pretty-printed document that IS the whole part exactly once")`, is green today and forbids the lazy fix of counting less: the whole-part arm must still count, and still state the length of what arrived.
