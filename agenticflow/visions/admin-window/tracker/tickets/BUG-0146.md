# /cycles?cycle= still denies a row it is rendering when the paste's padding is ink-less rather than whitespace (ZWSP, SOFT HYPHEN, NUL, the bidi controls)

## Description
Found attacking admin-window/BUG-0145 on the landed run branch (eebb071). BUG-0145 answered the paste that brought a SPACE along by trimming in `canonicalRecordId`; its four enumerated spellings are green. Its BAR, though, is its first criterion sentence — "The page never prints a not-in-this-window verdict naming an id whose row it is rendering" — and that sentence is still false for a whole family of padding.

Expected: for `?cycle=` carrying a real cycle C the window is drawing, the page either answers it as C (BUG-0143's criterion) or passes no verdict and names `cycle` in the dropped-parameter line. It may not render `data-cycle-found="false"` while `[data-cycle="C"]` is in the same document.

Found: it does exactly that for every ink-less character outside the Unicode `White_Space` set. Measured on the landed tree, offline against the fixture population (`tests/offline/cycles/`, cycle `0192f0c1-0000-7000-8000-00000000000b`, drawn in the window: `rowDrawn=1`):

    pad                       canonicalRecordId   found     marked  denial names the drawn id
    U+0020 SPACE              <canonical>         "true"    1       false     <- BUG-0145's fix
    U+00A0 NBSP               <canonical>         "true"    1       false
    U+3000 IDEOGRAPHIC SPACE  <canonical>         "true"    1       false
    U+0009/0A/0D/0B/0C        <canonical>         "true"    1       false
    U+200B ZERO WIDTH SPACE   null                "false"   0       TRUE
    U+00AD SOFT HYPHEN        null                "false"   0       TRUE
    U+2060 WORD JOINER        null                "false"   0       TRUE
    U+0000 NUL                null                "false"   0       TRUE
    U+007F DEL                null                "false"   0       TRUE
    U+202E RIGHT-TO-LEFT OVR  null                "false"   0       TRUE
    U+200E LEFT-TO-RIGHT MARK null                "false"   0       TRUE
    U+3164 HANGUL FILLER      null                "false"   0       TRUE

All eight lay out at 0px — this campaign measured these very codepoints in Chromium, both colour schemes, for admin-window/BUG-0136 — so the denied id reads character-for-character like the row drawn below it and the operator has nothing to see. That is BUG-0145's own headline harm, unchanged, from a family its fix does not reach. `data-dropped-params` is absent on all eight, so the page passes a verdict rather than reporting the facet dropped: neither of the two honest arms.

They really arrive. Measured over real HTTP on this tree (`next dev` on the QA lane's own bind-probed port 8796, the http suite's database sentinel, killed after; script kept at agenticflow/tracker/evidence/BUG-0145/http-probe.sh):

    GET /cycles?cycle=%E2%80%8B0192f0c1-0000-7000-8000-00000000000b
      -> data-cycle-asked first codepoint U+200B  (raw, undecoded padding reaches the page)
    GET /cycles?cycle=%C2%AD<id>   -> U+00AD
    GET /cycles?cycle=%E2%80%AE<id>-> U+202E
    GET /cycles?cycle=%20<id>      -> U+0030 (trimmed; BUG-0145 working)
    GET /cycles?cycle=%C2%A0<id>   -> U+0030 (trimmed)

Repro (exact, offline, on the landed tree): `./node_modules/.bin/vitest run --project=offline tests/offline/cycles/page.test.ts`, with the eight `it.fails` cases named `[admin-window/<this ticket>]` flipped to a plain `it.each(`. Each fails with `expected 'Cycle <U+200B><id> is not among...' not to contain '<id>'` while `renderedCycles(markup)` contains that same id. All eight were watched red before this was filed.

ROOT, and why it is one line of judgment and not a typo: `canonicalRecordId` (src/lib/db/records.ts:167) tests padding with `String.prototype.trim()`, which strips the Unicode `White_Space` set (plus U+FEFF) and nothing else. This app already HAS a definition for the rest — `visibleContent` / `hasVisibleContent` in src/lib/verdict/decision.ts, the app's ONE definition of blank, whose own note reads: "Three guards all tested blankness with `trim()`, so all three agreed, and all three were wrong the same way" (admin-window/BUG-0089), and admin-window/BUG-0136 then ruled for the URL layer specifically that "names nothing is decided by INK, not by whitespace". BUG-0145 landed a fourth `trim()` guard on the other side of that ruling.

TWO honest answers, and the builder should not guess between them silently:
(a) decide the padding with the app's own ink test rather than `trim()` — the LESSONS-5 shape, and the one that makes `?cycle=` consistent with what `/claims` already does to a URL. Note the seam it opens: `visibleContent` removes ink-less characters ANYWHERE, not only at the ends, so `<half-an-id><U+200B><rest>` would acquire a canonical form Postgres itself would refuse from a verbatim segment. Bounding the strip to the ENDS keeps `canonicalRecordId`'s stated invariant (what it returns is always something `isRecordId` accepts) with no such question.
(b) leave the grammar and stop `?cycle=` passing a verdict on a value with no canonical form — BUG-0143's declined convergence with `?run=`, still a design question, and it answers this whole family at once.

`isRecordId` must NOT move either way: it is asked of values carried to the query verbatim (a dynamic segment, a PATCH body's `ref`) and Postgres refuses padded uuids. Verified unchanged and still refusing on this tree.

NOT part of this ticket:
- U+202E is the sharpest member above, because `AskedCycle` spells the raw value into the app's own sentence (src/components/cycles/asked-cycle.tsx:76) and a bidi override's scope is the paragraph — admin-window/BUG-0137 measured exactly that harm on the dropped-parameter line and answered it with a renderable allowlist. Whether this sentence needs the same allowlist is a separate question from the denial; fixing the denial removes the padded route to it but not `?cycle=<U+202E>not-a-uuid`.
- `/sources?source=` and `/queues?source_id=` share the root but not the harm: an ink-less-padded id narrows nothing there and the page renders unnarrowed, the same answer `?source=nobody` gets. No false verdict.
- admin-window/DEBT-0009 is concurrently moving this grammar to a leaf module. The defect is behavioural; whichever file the two functions live in when this is built is the file to fix.

## Acceptance criteria
On /cycles with a window that holds cycle C, a `?cycle=` carrying C padded with any ink-less character that is not Unicode White_Space — U+200B, U+00AD, U+2060, U+0000, U+007F, U+202E, U+200E, U+3164 — must not render `data-cycle-found="false"` while `[data-cycle="C"]` is in the same document. Either arm satisfies it: the page answers it as C (found="true", exactly one `tr[data-row-marked="true"]`, one `aria-current`, C printed in the database's own spelling), or it passes no verdict at all and names `cycle` in the dropped-parameter line. Pinned by flipping the eight `it.fails` cases 'never denies a row it is rendering, padded with %s [admin-window/BUG-0146]' in tests/offline/cycles/page.test.ts back to a plain `it.each(`, with every other case in that file still green — including BUG-0145's own four whitespace spellings, which must keep answering as the row, and the three that grade a `?cycle=` with no canonical form at all, whose expectations may be UPDATED to the chosen answer but not removed. `isRecordId` must still refuse every one of these paddings as it stands (tests/offline/records/page.test.ts).
