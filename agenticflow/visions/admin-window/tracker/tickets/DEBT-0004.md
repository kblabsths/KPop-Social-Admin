# /cycles and /sources carry their own presentation: 1,291- and 793-line pages, no components module, while every other page has one

## Description
M1 structure walk, 2026-09-03. Common violation 10, now ARCHITECTURE §13.6.

Measured on the tree today (total lines / non-comment code lines / locally-defined React components):

| page | total | code | local components |
| --- | --- | --- | --- |
| src/app/cycles/page.tsx | 1291 | 844 | 8 |
| src/app/sources/page.tsx | 793 | 557 | 6 |
| src/app/claims/page.tsx | 562 | 404 | 4 |
| src/app/queues/[reviewItemId]/page.tsx | 485 | 300 | 3 |
| src/app/page.tsx | 394 | 243 | — |
| src/app/browse/page.tsx | 136 | 85 | — |
| src/app/records/[table]/[id]/page.tsx | 196 | 90 | — |

`src/components/` holds `browse/`, `claims/`, `queues/`, `records/`, `review/`, `shell/`, `gauges/`, `evidence/`, `ui/` — one per page that has one. `/cycles` and `/sources` have none, so their sections were written where the page function is. §5's division of labour (the page reads and shapes; components render) was never wrong, and nothing in the contract said WHERE the components go — so two pages grew them inline and the third and fourth started to.

What moves, and only this: the PascalCase components each page defines — `CycleHealthSection`, `LatencySection`, `AdapterRuns`, `LatestRun`, `AskedCycle`, `AskedSource` to `src/components/cycles/`; `SourceChips`, `AwaitingRowTrendSection`, `RejectionSection`, `sourceLabel` to `src/components/sources/`. `StateOf` and `WindowLine` are DEBT-0003's, which is why this depends on it — landing both at once means two rewrites of the same two files.

Judgment for the builder: the column builders (`cycleColumns`, `runColumns`, `runCells`, `stateCell`, `sourceColumns`) are presentation too and may move with their section. The `firstValue`/`filterFrom`/`*Href` helpers are URL and param work — they belong to the page, or to a leaf under `lib/`, never to a component.

Not a behaviour change. Every rendered attribute — `data-surface`, `data-window*`, `data-cycle`, `data-run`, `data-latest-run*` — is contract that live oracles read; a move that changes one is a defect. This is why the live suites for both pages are checks here.

Scope note: this rewrites both page files wholesale and is serial at its destination with every open bug on them. It depends on DEBT-0003 and, through it, on those bugs. If M1 closes first, this is M2's.

## Acceptance criteria
`src/components/cycles/` and `src/components/sources/` exist and hold those pages' section components, each a pure synchronous component taking plain props (§5), importing nothing from `lib/db/**` (§4 rule 1). Neither page file defines a PascalCase component any more; both pages read, shape and hand props down. Every data- attribute the two pages render today is rendered unchanged after the move — the four live oracles (`cycles`, `runs`, `sources`, plus the dashboard's read of the same gauges) and both offline page suites pass with no edit to what they assert. The two page files come in under 300 non-comment code lines each, which is where the dashboard (243) and /queues (276) already sit.
