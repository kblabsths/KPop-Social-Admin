# F15 — every windowed figure is true about the read that produced it

## Description
Three landed instances of the rule LESSONS 2 already states, on the two pages that carry the most of them. This adds NO surface; it corrects sentences and bounds that are wrong today. Behavior: SPEC F15.

1. **Two figures on one page silently disagree.** The Claims tab gauge transports a 1,000-row window; past 1,000 claims its bucket figures diverge from the head counts printed above them on the same page, with nothing saying so. Staging is at 877 — this is live within months, not theoretical. Either they are read the same way, or the page says which is a window and which is a total; never both presented as the same kind of fact.
2. **/sources' two scan-window lines name no narrowing while their read carries one.** This is the same defect BUG-0163 fixed on /claims one page over; /claims is the model to copy, by IMPORT and not by retyping (LESSONS 5).
3. **`readClaimCountSince` has no upper bound** while the scan it is printed beside is [since, until] and capped at 1,000. A count over a different interval than the rows beside it is a false relationship, whichever way it is resolved.

CONSTRAINT carried from the M2 close (retro ruling 4): if this work touches the window line's scope contract, `DrawnWindow.scope`'s comma-joined string — split back apart by the line that renders it, so a facet value containing ', ' could forge a segment — is fixed STRUCTURALLY at that point. It is unreachable today and it is not a separate ticket; do not file one.

vision_trace: VISION, 'What success looks like' — "Six pages ... each showing real staging rows whose numbers match what the database says." A bucket figure that diverges from the head count above it, and a window line that names a narrowing its read did not carry, are both that sentence failing.

## Acceptance criteria
On a fixture holding more than 1,000 claims, the Claims tab gauge's bucket figures and the head counts above them are either equal, or each is labelled in RENDERED TEXT as the kind of fact it is (window vs. total) — asserted on rendered HTML, not on the read; and that fixture produces no rendered sentence asserting a relationship between two figures no single read established. /sources' two scan-window lines name the narrowing their read carried, for a narrowed URL and an unnarrowed one, and /sources vs /sources?<facet>=<value> do not render byte-identical window lines when the facet narrows the read. readClaimCountSince and the scan it is printed beside carry the same bounds, asserted at the read and on the rendered page for a fixture where an unbounded upper edge would change the number. The narrowing sentence is IMPORTED from the one place /claims already owns it, not retyped: grep shows no second hand-written copy. No new surface, no new figure, and the sidebar still holds exactly six links.
