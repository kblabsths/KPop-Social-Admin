# The verdict block's observation id is still hand-faced — the one call site DEBT-0011's sweep left outside the identifier primitive

## Description
Found attacking admin-window/DEBT-0011 on the landed run branch (99b8b1b), which swept 48 hand-spellings of the identifier face behind `src/components/ui/identifier.tsx`.

**Expected** (DEBT-0011 criterion 2): "Every call site that renders a machine identifier — a table or view name, a column name, a status/shape/bucket value, **an id** — imports the primitive." And criterion 4: the primitive is where the ARCHITECTURE §7 / Common-violations row 15 bidi isolation is applied ONCE, so every identifier gets it.

**Found**: `src/components/review/close/slot.tsx:309-313` — the settled item's verdict block renders `verdict.observationId` (an id the database produced, labelled "observation id") as a hand-faced `<span data-verdict-observation={observation} className="type-data">`, not through `Identifier`. It is the unlinked arm; the linked arm one branch below (`:314-321`) is the sanctioned anchor exception, this one is not an anchor.

The site is in a file the sweep edited: `ItemVerdictBlock` in the SAME function converted `verdict.action` from `<span className="type-data text-ink">` to `<Identifier data-verdict-action=…>` at `:281-283` (commit 2cf6be1), and left the observation id 30 lines below it.

**The rendered face is already the primitive's, so the swap is a no-op on screen** — which removes the one reason DEBT-0011 gives for its stated exceptions (Eyebrow, the page h1: "inking them from the primitive would change what they draw"). `VerdictLine` (`slot.tsx:226-236`) wraps the value in `<span className="type-body text-ink">`, so the child's `type-data` sets the face and `text-ink` is inherited. MEASURED in Chromium (production build of the landed tree, QA lane's own bind-probed port 8813, viewport 1440x900, colour-scheme light), by injecting the shipped markup and the primitive's markup side by side into a live page so the app's own CSS applies:

  shipped   `<span class="type-data">`               font "Geist Mono", 11px, rgb(30,41,57), width 52.81px, unicode-bidi: normal
  primitive `<span dir="ltr" class="type-data text-ink">`  font "Geist Mono", 11px, rgb(30,41,57), width 52.81px, unicode-bidi: isolate

Same font, same size, same colour, same 52.81px box. The ONE difference is the isolation criterion 4 exists to deliver.

**No user-visible harm today, and the ticket says so honestly.** Same probe with an unterminated U+202E in the value: the app's label "observation id" reads in order in both arms (`observation id` + the value's own 8 characters reversed), because `VerdictLine`'s `<p className="flex …">` blockifies its two children into separate bidi paragraphs AND the id is the last content of its own box, so an override has nothing of the app's own words to reach. The same holds for the out-link in `src/components/review/item-header.tsx:174` (measured: "Its source" unreordered), which is why that one is NOT filed here. This is a completeness defect in the sweep, not a rendering defect: the id's face is coupled to an ancestor's ink by inheritance rather than owned, and a future rule hung on the primitive — the next `unicode-bidi`, the long-identifier wrap BUG-0105 had to solve alone — will not reach this site. That is exactly the accumulation ARCHITECTURE Common violations row 16 was promoted at 3 to stop.

**Repro (offline, exact, on the landed tree)**: `./node_modules/.bin/vitest run --project=offline tests/offline/review-item/verdict-inline.test.ts` with the strict pin `renders the observation id through the one identifier primitive, like the action beside it` flipped from `it.fails(` to a plain `it(`. It fails at `expect(shown.attr("dir"))` with `an id the database produced is isolated too: expected undefined to be 'ltr'` — after the assertion above it, on `[data-verdict-action]`, has already PASSED, so the pin is not vacuous (watched red before filing: 1 failed | 32 passed). As landed the pin is `it.fails` and the file is green at 33 passed; the day the site goes through the primitive the XPASS turns the file red and sends the reader here.

The pin types no class literal and no attribute value: both are read off `Identifier`'s own render, so a restyle of the primitive moves the assertion with it.
