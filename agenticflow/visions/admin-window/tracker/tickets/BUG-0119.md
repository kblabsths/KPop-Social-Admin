# A refused choice in the entity picker outlives every operator move but Escape-inside-the-panel, and never yields the page's one refusal slot

## Description
BUG-0111 gave the picker the cell's confirmation clock and wired Escape through `retiresRefusal`. The other half of BUG-0107's rule did not come with it, and the builder named the gap in BUG-0111's handoff. Filed as a chained ticket rather than a bounce: BUG-0111's own defect (a confirmation that never retires) is fixed and pinned, and this is a different mechanism — the page-wide listeners and the page's refusal slot, not the clock.

**Expected** — BUG-0111 criterion 3: "a failed choice's red line stands until the operator acts on it, and BUG-0107's rule for when that is (Escape, blur, opening another control) applies to the picker too if it lands first". BUG-0107 landed (done, 2026-09-09) and its own criterion 2 is "at most ONE refusal on screen at any moment", enforced by `takeRefusalSlot` (`src/components/EditableCell.tsx:419`).

**Found** — `src/components/records/entity-picker.tsx` contains zero references to `armRetire` and zero to `takeRefusalSlot` (grepped over the landed tree at baa33b7; the only two callers are `EditableCell.tsx:1245`/`1270` and the cell's own tests). The picker's single retire path is a React `onKeyDown` on the OPEN panel's wrapper div (`entity-picker.tsx:588-604`), so:

1. A refusal leaves the panel open (`choose()` calls `setOpen(false)` only when `outcome.ok`, `entity-picker.tsx:545-548`). If the operator then presses anywhere outside the panel or Tabs away, focus leaves the wrapper and the panel-scoped `onKeyDown` never fires again — the red line stands until the operator toggles that same picker's "Choose" button (`cleared`). That is exactly the state BUG-0107 was filed for, on the widget BUG-0107 did not cover.
2. Because the picker never calls `takeRefusalSlot`, a picker refusal and a cell refusal can be on screen simultaneously — the stacking BUG-0107 measured on the cells ("`label` at 596,205 320x122 under `observed_on` at 549,299 320x58, overlapping 273x28px").

The reducer half is already complete and proved: `reducePick`'s `abandoned` arm delegates whole to `reduceEdit`, so `{kind:"press",inside:false}`, `{kind:"focus",inside:false}` and `{kind:"superseded"}` all retire a picker refusal correctly today and `{kind:"press",inside:true}` correctly does not (pinned green in "hands every BUG-0107 move to the one decision", `tests/offline/records/entity-picker.test.ts`). **Only the component's arming is missing** — which needs `EditableCell`'s inline `RetireHost` adapter (`EditableCell.tsx:1256-1268`) extracted and shared, the way `armConfirmationClock` was extracted for the clock.

## Acceptance criteria
1. A picker refusal ends on the same moves the cell's does — a pointer press outside the widget, focus landing elsewhere, and Escape from wherever focus is (not only from inside the open panel) — every one of them dispatched as a `RetireMove` and decided by the one exported `retiresRefusal`, never by a condition re-written per listener (BUG-0107's own bounce).
2. A picker refusal takes the page's single refusal slot (`takeRefusalSlot`), so a picker's refusal and a cell's can never be on screen at the same moment, in either arrival order.
3. The `RetireHost` DOM adapter is EXTRACTED from `EditableCell`'s effect and shared, not copied into the picker — one adapter, the way BUG-0111 made one clock. A second copy of the listener wiring is the defect this ticket is about, one level up.
4. The pin in `tests/offline/records/entity-picker.test.ts` ("arms the page-wide retire rule for a refusal the open panel cannot end") flips from `it.fails` to `it` and passes, and the cell's own retire tests (`tests/offline/ui/editable-cell.test.ts`) are unchanged and green.
5. `npm run lint` and `tsc --noEmit` clean; the targeted offline files green.
