# Cycles & runs: 'Cycle <id> is marked in the table below' — the row carries only aria-current and is visually identical to all 68 others

## Description
Found by the document-blind user-sim walk (Tomas, 2026-09-03), `agenticflow/tracker/evidence/user-sim-m1/tomas.md`, "Two small things that cost the tool nothing to fix". Confirmed live on :8771 and at source, 2026-09-03.

**Feel bar 10:** "The investigation never leaves the app: from any review item you can reach its claims ... each in **one click**, each a real URL."

Clicking a cycle on the Dashboard lands on `/cycles?cycle=<id>` and the page prints:

    Cycle 01a065c6-965b-7062-b13e-0930d2a5c3e8 is marked in the table below.

**It is not marked.** Measured in the delivered HTML of `/cycles?cycle=01a065c6-965b-7062-b13e-0930d2a5c3e8`, the asked-for row is byte-identical to its neighbours except for one attribute:

    <tr class="border-t border-hairline transition-colors hover:bg-chrome">
      <td class="type-data px-2 py-1.5 text-ink">
        <span id="cycle-01a065c6-..." data-cycle="01a065c6-..."
              data-cycle-state="died" aria-current="true">01a065c6-...</span>

`aria-current="true"` (`src/app/cycles/page.tsx:310`) has no style bound to it anywhere. Same row background, same text colour, same weight, no glyph. Nothing on screen distinguishes it from the other 68 rows.

The page also does not move to it. The id in the sentence IS an anchor (`href="#cycle-<id>"`, line 432) but it is styled `type-data text-ink hover:text-accent` — at rest it is indistinguishable from the mono ids printed as plain text everywhere else on the page, so it does not read as the thing to click. Tomas did not find it: "I ended up scanning 36-character UUIDs by eye to find it."

**Why this one matters more than its size.** Tomas's whole walk was an attempt to falsify the tool's numbers, and this is the one claim he could falsify: "This is the tool making a claim about *itself* that I could disprove in thirty seconds — a bad look on a page whose selling point is that its claims check out." Everything else on Cycles & runs held under hand-summation (he re-added all 69 rows against the health panel and found not one cell off). This sentence spends that credit.

Note for the builder: LOOK_AND_FEEL.md's data-table rule defines hover (chrome fill) but no *marked-row* rendering, so the visual is a design gap as well as a build one — see `agenticflow/tracker/evidence/user-sim-m1/DESIGNER-JUDGEMENT.md`, which proposes the rule. Until it lands, the marked row uses the palette's accent for selection ("Accent — selection, active nav/tab/chip, focus"): a chrome-inverse row fill, or an accent left rule, and NOT a new colour, a shadow, or motion (the motion budget is closed).

Evidence: `agenticflow/tracker/evidence/user-sim-m1/tomas-12-cycle-deeplink-not-marked.png`.

Sibling note: BUG-0040 (newest adapter run below the fold) and this one both land in `src/app/cycles/page.tsx`; 0040 moves a section's position on the page, this changes one row's rendering and one sentence, and neither touches the other's hunk.

## Acceptance criteria
On `/cycles?cycle=<id>` where the id is in the window, the asked-for row is visibly distinguishable from every other row without hovering, using only the existing palette (accent for selection) and existing type steps — no new colour, no shadow, no animation, no change to the row's height or the table's density.

The page's sentence and the page's behaviour agree. Either the row is marked (and the sentence may keep saying so), or the sentence is rewritten to describe what actually happens; the screen must not claim a mark it does not draw.

`aria-current="true"` stays on the row — the accessible marking is correct today and is not the defect.

The anchor in the sentence reads as a link at rest, not only on hover (the app's other in-page anchor at `src/app/cycles/page.tsx:578` gets the same treatment, so the page does not spell "link" two ways).

`/cycles` with no `?cycle=` parameter is unchanged: no row is marked, and the 69-row table renders exactly as it does today.

`tests/offline/cycles/page.test.ts` asserts the asked-for row's rendered markup carries a distinguishing class or attribute that the other rows do not, and that the unfiltered table carries none.

Human-check: click a cycle from the Dashboard and find that cycle in the table below without reading a single UUID. (human-checkable)
