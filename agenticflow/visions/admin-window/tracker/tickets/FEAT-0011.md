# The edit surface's override half: events and venues write only as recorded overrides

## Description
**SPEC F11.** `events` and `venues` become editable — but ONLY as recorded overrides the pipeline can see and protect. This is the half of the edit surface M1 deliberately shipped read-only.

**Amended 2026-09-09 for Ben's vision amendment of 2026-09-08.** He struck "groups/idols edit directly within it" from VISION: *"admin edits catalog tables only through the observation pipeline; do not re-implement direct edits."* This ticket is the surviving half and it is now the ONLY half — after TASK-0040 there is no direct catalog write path anywhere in this app, and **this ticket may not restore one, not for `groups`, not for `idols`, not as a fixture, not as a test seam.** A strike licenses nothing new either: the override path is exactly the events/venues scope VISION still carries, and nothing more.

**The regime decides the write path; configuration never does.** The one hand-written `{table -> editable columns}` map gains `events` and `venues` entries, but adding a table to the map does not choose how it writes: `EDIT_CONFIG`'s `Regime` does. A resolver-owned table's edit lands as an **admin-tier observation through the gate**, applied synchronously through `apply_resolution`, provenance stamped **`admin_locked`**, and logged in `verdicts` as `action = 'override'` with a **null `review_item_id`** — spec §7's "an override is the same row without the item". What remains of the pre-cutover regime after the amendment — whether the walk sandbox keeps it, and under what name — is the **architect's ruling of 2026-09-08**; read it and follow it, do not re-open it here.

**No direct write path to `events` or `venues` may exist.** The entry point is `settle_review_item`, item-less. M1 proved the negative for these two tables by measurement (the only mutating call in `src` was one `.update()` reachable only through `decideEdit`, and `events.title` / `venues.name` PATCHes answered 403); M2 must keep the negative true while making the tables editable. That is the whole difficulty of this ticket.

**Absence degrades to M1, not to a broken control.** With `settle_review_item` absent — staging today, and `main`'s deploy target until Ben installs FEAT-0009 — `events` and `venues` render READ-ONLY with the reason named. No control appears that would call a missing function. This is graded before the happy path.

**Per-field provenance shows at the field** for a resolver-owned record, read from `field_provenance`: "ticketmaster, applied 3d ago" / "admin-set Jun 12", so admin stickiness is visible. Releasing an `admin_locked` fact is itself a verdict action on that fact, never a direct write. (The pre-cutover provenance sentence Ben confirmed on 2026-09-02 stays exactly as it is wherever a pre-cutover record still renders — do not change its wording, and do not surface a catalog row's own `source_*` columns: Ben ruled on 2026-09-08 that they stay hidden.)

**Two affordances the M1 user-sim walks earned, on the shared edit cell:**
1. An editable value is **distinguishable from a read-only one before it is touched** — a 1px hairline underline on the value, not colour and not weight. A stranger found the edit affordance by tabbing, not by looking, and said a mouse-first colleague would read the page as read-only.
2. A click-to-edit cell **opens with its existing value selected**, so a straight retype replaces and an arrow key still appends. A stranger wrote a wrong value into the shared catalog because the caret sat at the end and nothing was selected.

**Contract gap, blocked not guessed (SPEC named gap 7):** WHICH columns of `events` and `venues` are editable at all is not enumerated anywhere. Spec §8 says the map is hand-written and says nothing more; AGENTS.md narrows it ("performers and venues are LINKS — `event_performers` / `venues` — not fields of `events`") without fixing it. The first `events`/`venues` map entry is an ASK BEN, not a builder's pick. Widening the allowlist to a non-scalar is forbidden by AGENTS.md outright.

vision_trace: "The edit surface driven by one hand-written map of what is editable: ... events/venues edit only as recorded overrides that the pipeline can see and protect; a reference field links rows, never text; provenance is visible at the field."

## Acceptance criteria
1. With `settle_review_item` ABSENT: an `events` record and a `venues` record render read-only with the reason named; zero inputs, selects, textareas or forms on either page; a forged PATCH naming a mapped `events` column is refused server-side with the reason, and the row is unchanged when re-read.
2. With the function present (recording stub): editing a mapped `events` or `venues` column produces EXACTLY ONE call to `settle_review_item` carrying `action = 'override'`, a null `review_item_id`, the admin-tier observation, and nothing else. No `.update()`, `.insert()`, `.upsert()` or `.delete()` in `src` targets `events` or `venues` on any path.
3. A column ABSENT from the map on `events` or `venues` refuses a forged request server-side with 403 naming the field — never a hidden widget.
4. The write path is chosen by `Regime` and by nothing else: a structural test asserts the override branch is selected by the regime enum and that no configuration key can move a table between regimes. It grades whatever pre-cutover entry the map still carries after TASK-0040 and the architect's 2026-09-08 ruling — and if none survives, it asserts the branch on a fixture, never by putting a catalog table back on the map.
5. No direct catalog write path is restored by this ticket: `groups` and `idols` remain absent from `EDIT_CONFIG`, their record URLs and PATCHes still refuse exactly as TASK-0040 left them, and no fixture, seam or test helper writes either table.
6. Per-field provenance renders at the field on an `events`/`venues` record from `field_provenance`; wherever a pre-cutover record still renders, its 2026-09-02 sentence is unchanged and no `source_*` column of a catalog row is surfaced.
7. On the shared edit cell, wherever it renders: an editable value carries a resting affordance distinguishing it from a read-only value without hover, focus or click; opening a cell selects its existing value so a straight retype replaces it. Asserted in the offline render suite.
8. The `events`/`venues` allowlist was answered by Ben on a blocked ticket, not chosen by a builder; every column in it is a vetted scalar of that table, and no link column (`venue_id`, performers) appears in it.
9. `npm run lint`, `tsc --noEmit` and `npm test` green; the record page's live suite green; M1's forged-request refusals still 403/404/405 exactly as the M1 verdict recorded them, except where TASK-0040 deliberately inverted one.
