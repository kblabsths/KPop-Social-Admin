# The shared edit cell's two affordances: visible before it is touched, and open with the value selected

## Description
**Two affordances the M1 user-sim walks earned** (SPEC F11), on the shared edit cell, and they apply to **every** regime that has a write path — the sandbox today, `events`/`venues` when their allowlist lands.

1. **An editable value is distinguishable from a read-only one BEFORE it is touched.** A stranger found the edit affordance by tabbing, not by looking, and said a mouse-first colleague would read the whole page as read-only. The affordance is a **1px hairline underline on the value** — not colour, not weight (LOOK_AND_FEEL; colour is reserved and weight is the type scale's). It is a resting state: no hover, no focus, no click required to see it.
2. **A click-to-edit cell opens with its existing value selected**, so a straight retype replaces and an arrow key still appends. A stranger wrote a wrong value into the shared catalog because the caret sat at the end and nothing was selected.

**Scope discipline.** This ticket changes the cell's resting rendering and its open behaviour. It does not change what is editable, the write path, the refusals, the provenance line, or any page's layout. `src/components/EditableCell.tsx` keeps its name and its place at the components root (§11: the one PascalCase file, the one old component that re-earned its place).

**Use the tokens, never raw values** (LOOK_AND_FEEL, `app/globals.css`'s `@theme`): the hairline is a token'd border colour at the token'd width, and it passes the existing contrast test in both themes.

## Acceptance criteria
1. A cell whose column is editable renders a 1px hairline underline in its RESTING state — asserted in the offline render suite on markup with no hover, focus or click applied — and a read-only cell renders none. Both fixtures, in both themes.
2. The affordance is drawn from the design tokens: no raw hex, no raw px colour, in the changed lines; the contrast test still passes for both themes.
3. Opening a cell selects its existing value: the rendered input carries the select-on-open behaviour, asserted structurally rather than by a comment, and an empty cell opens with an empty input and no selection error.
4. Neither change alters what is editable: `decideEdit`'s answers are byte-identical before and after (the edit-config guard still passes), and no page's column set moves.
5. `npm run lint`, `tsc --noEmit`, the targeted offline file, and the record page's live suite are green.
