# Adopt the five residual designer bars into LOOK_AND_FEEL and clarify copy bar 6

## Description
**Adopt five proposed bars into `LOOK_AND_FEEL.md`, and clarify a sixth.** The designer's judge pass on the two M1 user-sim walks proposed seven bars and deliberately did NOT write them in — "LOOK_AND_FEEL.md does not change during a judge pass". The milestone boundary IS the revision pass. Source: `agenticflow/tracker/evidence/user-sim-m1/DESIGNER-JUDGEMENT.md` §4.

**Strategist's adoption call: all seven, but split by home.** Two of them (4.1 an editable value looks editable at rest; 4.2 an inline editor opens with its value selected) are behaviour on a control M2 is rewriting anyway and ride on **FEAT-0011** — write them into the file here, but do not build them here. The remaining five are this ticket's:

- **4.3 — a zero states what it excludes when the excluded set is non-empty.** "0 of 65 finished cycles ran longer than the 15m cadence; 4 never finished" — never a bare zero standing beside the rows it silently drops. Earned by: "'0 ran long' sitting next to four corpses is the sort of reassuring sentence I've been burned by before."
- **4.4 — healthy is green only when nothing needs a human.** A run whose own row carries a non-zero error count renders its outcome in attention amber, whatever word the database wrote — the word stays verbatim (Voice bar 5), the colour tells the truth about it. Earned by: fifteen cycles reporting 108 errors each and still labelled `succeeded` in green.
- **4.5 — every windowed list states its window on screen**, including where the window is bounded by the data's own floor rather than by a row cap: "runs recorded since 2026-08-31; nothing earlier is retained". This is the app's single most-praised behaviour and nothing in the file protects it. Pairs with DECISIONS 2026-09-04 (the line follows the read, not the rows); do not contradict that ruling.
- **4.6 — a row the URL asked for is marked with a chrome-inverse fill** — the same device as the active nav item, no new colour — and the page moves to it. A `?<facet>=<id>` deep link lands on its row. BUG-0054 already had to invent this rendering; the file should carry what shipped.
- **4.7 — clarify Voice copy bar 6** on the record page's raw stored value. `/records/events/<id>` renders `starts_at` as `2027-05-01T19:00:00+00:00` while `/browse` renders the same instant as `2027-05-01 19:00 UTC`. Bar 6 says "never a raw ISO string in a scannable column"; the Look's mono/sans split says "mono carries every value the database produced". Both readings are defensible from the file as written, which is the fork test failing. **Say which, in one clause on bar 6.** The designer declined to legislate mid-judge-pass; deciding it is this ticket's job.

**Write the bars; do not sweep for violations in this ticket.** Each must be walkable as written (that is the file's own standard). The M2 endgame designer walk grades the app against the amended file and files what it finds — that is cheaper and better targeted than a speculative conformance sweep now, and it is how M1's bars were enforced.

**Do not** touch VISION.md. **Do not** add a bar that is dial-shaped or that names a threshold value: 4.3 and 4.4 describe how a figure is QUALIFIED and COLOURED, never what number is good. **Do not** drop or weaken the three behaviours both sims named as the reason they trusted the tool: hedged window labels, verbatim error text inline in a run row, and the app declaring what it cannot know.

## Acceptance criteria
1. `LOOK_AND_FEEL.md` carries bars 4.3, 4.4, 4.5 and 4.6 in their correct sections (Feel interaction principles, Look palette/state colours, Feel quality bars, Look component rules/data table), each written so it is checkable against the running app.
2. Voice copy bar 6 carries one added clause saying whether the edit surface's value column is scannable prose or the stored value verbatim, so the two readings can no longer both be defended.
3. Bars 4.1 and 4.2 are written into the Look's inline-edit component rules, with a note that FEAT-0011 builds them — the file states the bar; this ticket builds no UI.
4. No bar added names a threshold number or is dial-shaped: each governs qualification, colour, or placement, never what value is good.
5. The three behaviours both sims praised are still required by the file after the edit: hedged window labels, verbatim error text inline, and the app declaring what it cannot compute.
6. `VISION.md` is byte-identical before and after.
7. `npm test` green (the file is not code, but the copy guards over it must not redden).
