# Review-item detail miscounts resolved evidence when an id repeats

## Description
Expected (contracts/admin-observability.md §6 and this page's own contract — 'every observation id in review_items.evidence resolved to its row', and src/lib/db/review-item.ts:334 'the page names them rather than dropping them, because a silently shorter list would read as an item with less evidence than it has'): the accounting sentence under the evidence block accounts for every id the item carries — resolved plus unresolved equals the ids looked at.

Found: with a repeated evidence id the sentence understates and contradicts itself. src/app/queues/[reviewItemId]/page.tsx:441-445 divides the DEDUPLICATED claim count by the RAW array length:
    {count(evidence.data.claims.length)} of {count(row.evidence.length)} evidence ids resolved to a claim
while readItemEvidence (src/lib/db/review-item.ts:364) correctly does distinct(item.evidence) first, so claims and unresolved are both over DISTINCT ids. An item whose evidence is [A, A, B], with A and B both resolving, renders two claim rows, NO unresolved id, and the sentence 'json2 of 3 evidence ids resolved to a claim' — telling the operator one evidence id went unaccounted for while naming none.

Reachable from real data, no malformed row needed: review_items.evidence is 'uuid[] default {} not null' with no uniqueness (kspace Scraper migration 20260901000002), and contracts/resolver.md §11 (line 487) folds by APPENDING to it — 'new evidence folds in: folded_count increments, evidence appends' — with no dedup rule. The builder's own distinct() call is the acknowledgement that duplicates occur.

Repro (offline, no database):
1. cd '/Users/ben-m4/Desktop/Coding/KPOP/kspace Admin'
2. ./node_modules/.bin/vitest run tests/offline/review-item/page.test.ts -t 'accounts for every evidence id when one is repeated'
3. The test is PINNED it.fails (strict) for this ticket, so it is GREEN only while the defect is live. Watched failing as a plain it() against run/admin-window @ 552a243:
   AssertionError: 2 of 3 reported resolved, but no id is listed as unresolved: expected 1 to be +0

Fix: make the two figures come from one accounting. Either report over the distinct ids the read actually looked at, or have readItemEvidence carry the id count it deduplicated to; do not fix it by dropping distinct(), which would render the same claim twice and double-count the evidence. Then flip the pinned it.fails back to a plain it() — the assertion is behavioural (resolved + unresolved must cover the ids the page says it looked at) and pins no wording.
