# toolchain.test.ts's own tree walk reddens on the layering probe — the BUG-0032 race, one file over

## Description
Found attacking BUG-0032 on the landed tree (run/admin-window, dfd9bcc). BUG-0032 fixed the four walkers; the fix's OWN new test re-creates the same hazard, at the same probe path, in the same offline project.

tests/offline/toolchain.test.ts:372, describe "the source-tree walk" > it "hides nothing that exists in the real tree":

    const real = sourceFiles();
    expect(real).toEqual(allSourceFiles());

That equality is FALSE by design for exactly as long as src/.probes/__credential_guard_probe__.ts is on disk: hiding a dot-dir from sourceFiles() while allSourceFiles() reaches it IS the fix (tests/offline/source-tree.ts:108-118). tests/offline/db/layering.test.ts:223-228 writes and removes that exact path ~20 times per run, in a PARALLEL WORKER of the same offline project (no singleFork there). So the assertion is decided by the interleaving of two workers, not by the code — the precise defect class BUG-0032 was filed to eliminate.

Expected (BUG-0032's own bar, and its acceptance criterion's spirit): no offline test reddens because another worker created or removed a path under src/.
Found: tests/offline/toolchain.test.ts > the source-tree walk > hides nothing that exists in the real tree — AssertionError: expected [ ...(88) ] to deeply equal [ ...(89) ], at tests/offline/toolchain.test.ts:372.

## Repro A (deterministic, 100%)

    mkdir -p src/.probes
    touch src/.probes/__credential_guard_probe__.ts
    ./node_modules/.bin/vitest run --project=offline tests/offline/toolchain.test.ts
    rm -rf src/.probes

Observed: exit 1, "Tests 1 failed | 15 passed (16)", the failure named above. The same probe planted for the same command over the four BUG-0032 walkers exits 0 (4 files, 118 passed) — so this is the one file left holding the hazard.

## Repro B (the real timing, amplified faithfully)

A churn child reproducing layering's scanWithProbe cycle — mkdir+write, hold 17ms, rm, gap 17ms — run against 12 sequential runs of tests/offline/toolchain.test.ts: 6 of 12 exit non-zero, every one of them on "hides nothing that exists in the real tree", never on a walker.

The 17ms hold is measured, not invented: polling fs.existsSync(src/.probes) 11,806,630 times across a 12s window containing one real 826ms layering run saw the directory present 338,071 times — ~343ms on disk, ~69% of layering's 499ms test phase, over ~20 scans.

## Why it is green today, and why that is not safety

Natural rate on this box: 0/10 runs of (toolchain + layering) together, 0/5 npm test. toolchain.test.ts spends ~3.6s in a beforeAll that shells out to tsc and two 'vitest list' startups, so in a small file set layering has finished before toolchain's test bodies run. That ordering is an accident of scheduling, not a guarantee: with 51 files and a bounded worker pool, layering's start time is uncorrelated with toolchain's. This is a receipt-flipper of exactly the profile BUG-0032 itself carried (0/37 natural, 26/40 amplified) and was rightly filed as P2 for.

## The pin (on the branch, commit ffc3d0f)

tests/isolated/probe-race.isolated.test.ts, describe "walking src/ while the layering probe comes and goes", it.fails("reddens no OTHER offline file that walks the tree either") — plants the probe and runs toolchain.test.ts as a child vitest pinned to --project=offline. Watched RED as a plain it() (expected 0, got 1, tests/isolated/probe-race.isolated.test.ts:184), then marked it.fails so the branch stays green; npm test with the pin: 51 files/1520 passed + isolated 1 file/6 passed, lint clean, tsc --noEmit 0. It lives in the isolated project on purpose — BUG-0032's own history records that an in-tree pin for this hazard turns a sub-1-in-37 flake into a 1-in-5 one.

## The bar (the fix is the builder's call)

The assertion is worth keeping — it is what stops the dot/__ filter from silently hiding a real source file — but it must not be decided by another worker's timing. Two obvious shapes: assert the relationship that is actually invariant (allSourceFiles() is a superset of sourceFiles(), and every path in the difference is dot- or __-prefixed), or take the two listings so that a probe present in one is present in both. Do NOT weaken it to a length check, delete it, or move layering's probe out of src/ (BUG-0029 put it there so no compiler sees it). When it is fixed, remove the .fails marker on the pin.
