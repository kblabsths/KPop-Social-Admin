# The record page's empty state cards set their table name in sans — the face BUG-0112 fixed one paragraph above

## Description
Measured on the QA pass of admin-window/BUG-0112, 2026-09-09, on the production build (`next start`) against staging, 1440x900, light and dark.

**Expected** — LOOK_AND_FEEL Voice bar 5: machine identifiers "render verbatim in mono and are never prettified into Title Case prose"; the type split is "mono carries every value the database produced … so the operator can always see which words are the machine's". BUG-0112 settled that a table name in this page's prose is the machine's word and gave the regime note the app's identifier-in-prose spelling.

**Found** — the two empty-state cards on the same route still print the table name in body sans. `/records/walk_sandbox/x` (any non-uuid segment) shows the SAME name four times on one screen:

| where | face measured (light) |
| --- | --- |
| `h1` identifier | Geist Mono 11px, rgb(30,41,57) |
| regime note (BUG-0112's fix) | Geist Mono 11px, rgb(30,41,57) |
| empty card line 1 — "No **walk_sandbox** record at this address" | Geist 12px, rgb(30,41,57) |
| empty card line 2 — "…: **walk_sandbox** ids are uuids, 32 hexadecimal digits… Admin has no **walk_sandbox** listing: …" | Geist 12px, rgb(74,85,101) |

Dark theme identical but for ink (mono rgb(229,231,235) vs sans rgb(153,161,175)). The same holds for the unknown-id card ("No walk_sandbox record with that id" + "Admin has no walk_sandbox listing…"), reached by any well-formed uuid no row carries. Both states are ordinary operator paths: a half-pasted or stale id.

Repro: start the built app against staging, open `/records/walk_sandbox/x` at 1440x900, read the note and the card under it — the name reads as the machine's word in the note and as the app's own prose in the card, one paragraph apart.

**Why it was not BUG-0112's** — the builder named it as an out-of-scope residual and was right to: BUG-0112's criterion 2 scopes itself to "any … name inside a note", and this page's three `data-note` paragraphs all comply. `Empty` takes `holds`/`filledBy` as `string` (`src/components/ui/empty.tsx:15-19`), so no call site can wrap anything; the fix is `ReactNode` on a shared primitive with 17 call sites, which is a ticket of its own and not a face change.

Anchors: `src/app/records/[table]/[id]/page.tsx:366-369` (`holds={\`\${config.table} record at this address\`}`, `filledBy={notAnId(config)}`), `:428-431` (the unknown-id pair), `:225-232` (`foundBy`), `:274-279` (`notAnId`), `src/components/ui/empty.tsx:36-38` (both lines rendered as plain `type-body` text).

Scope note for whoever takes it: only the TABLE NAME is the machine's word here. "Browse lists recent events, and an event's record links to its venue" says `events` as English, and it must stay sans — which is why the pinning tests use `walk_sandbox`, the one name of the three that cannot be read as a noun.

Pinned red before filing: `tests/offline/records/page.test.ts`, describe "a table name in an empty state card" — two `it.fails` xfails, watched failing as plain `it`s with `"No walk_sandbox record at this address…": expected +0 to be 1` and `"No walk_sandbox record with that id…": expected +0 to be 1`. They take their yardstick off the page's own heading, so they pin no face literal; when the fix lands, `it.fails` turns red on the XPASS and the `.fails` (and this reason) come off.

Evidence: `agenticflow/tracker/evidence/BUG-0112/walk-light.json`, `walk-dark.json` (computed styles, both themes, all six states).

## Acceptance criteria
1. On both empty states of `/records/[table]/[id]` — the mistyped-id card and the unknown-id card — every occurrence of the TABLE's name renders at the data step in mono, verbatim, in the same face the page's own heading gives that name. The words the app wrote around it stay body sans.
2. English words that happen to match a table name are untouched: "Browse lists recent events, and an event's record links to its venue" keeps `events` in sans prose. Only the identifier is wrapped.
3. One spelling, not a new one: the identifier-in-prose span is the app's existing `type-data text-ink` spelling (`NotProvisioned`, the regime note, the heading) — and if `Empty` is widened to `ReactNode`, the other 16 call sites keep rendering exactly what they render today.
4. No change to the cards' words, their order, their spacing, their type step or their state hooks (`data-state="empty"`).
5. The two `it.fails` pins in `tests/offline/records/page.test.ts` ("a table name in an empty state card") lose their `.fails` and pass as ordinary tests.
6. `npm run lint` and `tsc --noEmit` clean; the full offline suite green.
