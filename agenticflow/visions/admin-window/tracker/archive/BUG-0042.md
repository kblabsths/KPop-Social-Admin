# Review item detail: the evidence table overflows the page instead of scrolling inside its own border

## Description
Found on the M1 endgame designer walk (2026-09-03), walk instance :8771 against staging, 1440x900, on the one review item staging holds: `/queues/01a06287-5b67-7d1f-b4a5-d90aa93cb01a` (shape `entity_link_source_pattern`).

LOOK_AND_FEEL.md, the Look / Component rules / Data table: **"Tables that exceed their width scroll horizontally *inside their own border*; the page does not."**

Measured on the running app:

- `main.flex-1.overflow-auto`: `scrollWidth` 1525 vs `clientWidth` 1248 — the CONTENT PANE is what scrolls, not the table.
- The table's own `payload` header cell has `getBoundingClientRect().right` = **1582**, i.e. 142px past the 1440 viewport, and the same is true of all 91 `sha256/...` payload cells (right = 1574).
- Collateral: the section's intro paragraph ("One source, many records stuck the same way...") is stretched to right = **1583** by the same overflow, so the prose is clipped too — not just the table.
- The table's right border is not visible anywhere on the screen.

The other four table pages (`/cycles` with 13 columns, `/browse`, `/sources`, `/claims`) all report zero overflow at 1440 — this is the only surface where the rule fires, so the fix is local, not a token change.

Cost: review-item detail is one of LOOK_AND_FEEL's five key screens — "The operator must be able to decide without opening another tab: contenders, canonical, tiers, ages" — and today a column of the evidence is off-screen with a page-level scrollbar as the only way to it, which also drags the page furniture sideways.

Evidence: `agenticflow/tracker/evidence/designer-walk-m1/reviewitem-light.png` (payload column running off the right edge), `reviewitem-dark.png`.

Not prescribing the fix. Confining the horizontal scroll to the table's own bordered box is what the rule asks; whether `payload` is worth 71 characters of width is a separate question I am not raising here.

## Acceptance criteria
At 1440x900 on a review-item detail page, `document.querySelector("main").scrollWidth === clientWidth` — the content pane does not scroll horizontally — and no element's bounding rect extends past the viewport's right edge.

Where the evidence table is wider than its column, the horizontal scroll happens inside the table's own 1px border, and that border is visible on both sides at rest. (Look: data table.)

The section's prose paragraphs wrap at the content width and are not stretched by the table.

A targeted offline test in `tests/offline/review-item/page.test.ts` pins the wrapper that owns the scroll, so a later markup change cannot hand it back to the page.

Human-check: open the review item at 1440x900 — the page has no horizontal scrollbar, and the evidence table's own right border is on screen. (human-checkable)
