# A refused inline save outlives its edit — Escape, blur and a later successful save all leave the red line standing, and two of them stack over the values beneath

## Description
Measured on the M2 endgame walk, 2026-09-09, on `/records/walk_sandbox/00000000-0000-4000-8000-000000000001` — the one surface a walk may write — 1440x900, light theme. Two legs, one control, one screenshot proving both.

## Leg 1 — the refusal outlives the edit it refused

**Expected** — LOOK_AND_FEEL, Inputs and inline edit: "click a value, it becomes an input with a 1px accent border; Enter or blur saves, **Escape reverts**. Confirmation is a green `data` word beside the field **for 1.5s**; failure is a red `data` line that names the failure, **and the field reverts to its old value**." A status belongs to the edit that produced it; when that edit ends, so does the status. `EditableCell.tsx`'s own comment states the intent: "A refusal is not [on a clock]: it stands until the operator does something about it — reopening the cell is what clears it."

**Found** — reopening the cell is the *only* thing that clears it. Measured sequence on the `tally` cell (`role="alert"` node polled after each step):

| step | refusal on screen? |
| --- | --- |
| type `seven`, Enter, wait for the answer | yes — `invalid input syntax for type integer: "seven" (22P02)` / `Type a whole number, like 7.` |
| press **Escape** | **yes**, unchanged, same box at x=490 y=271 |
| wait a further 4s | **yes** |
| click elsewhere on the page | **yes** |
| open `note`, retype it, Enter, save **successfully** | **yes** |

So the screen ends up showing `tally` at rest, reverted to `7`, correct, un-open, carrying its hairline resting underline — and a red line beside it claiming a failure that no longer pends. The operator abandoned the edit; the app did not.

`Escape` is handled at `src/components/EditableCell.tsx:990-995`: it sets `ending.current`, reverts the draft and calls `setEditing(false)`, and dispatches nothing. Only `open()` (line ~1000) dispatches `{ kind: "editing" }`, which is the one event `reduceEdit` turns into `{ status: idle }`.

**And they stack.** Because nothing retires a refusal, a second failed edit draws a second red panel over the first. Screenshot `sandbox-refusal-lastrow-light-1440.png`: the `label` not-null refusal (5 lines, from a cleared `label`) and the `observed_on` date refusal (2 lines) are on screen simultaneously and overlap, the second printed across the first. Neither is readable.

## Leg 2 — the refusal panel has no boundary, and eats the values it floats over

**Expected** — LOOK_AND_FEEL: "**1px hairlines, never shadows.** Structure comes from rules and fills. There is no elevation in this app." A floating panel is elevation by position, so a hairline is the only thing that can bound it. The app already knows this: the edit cell's **hint** popover, rendered from the same component a few lines away, is `... rounded-control border border-hairline bg-surface px-1 py-0.5 ...`.

**Found** — the refusal popover is `... rounded-control bg-surface px-1 py-0.5 ... text-broken` (no border), positioned `absolute left-full ml-2`. It is `bg-surface` floating over a table that is also `bg-surface`, so it has no edge at all: it covers the row hairlines it crosses and truncates neighbouring values mid-word. In `sandbox-stale-refusal-light-1440.png` the `is_flagged` value reads **`fal`** — the rest of `false` is behind an unbordered red panel belonging to a different row. One component, two spellings of the same floating box; the doc's whole reason for existing is that two builders produce the same-looking app.

Provenance checked before filing: `git log src/components/EditableCell.tsx` returns ticket-bearing commits only (ba74f57 BUG-0105, e1f75bf BUG-0104, 36209d7 BUG-0101, 2e9e1e3 BUG-0086, 6cf73c7 BUG-0098, 77ede05 BUG-0075, …). No human-lane divergence; this is a violation, not a reconciliation.

Not a duplicate of BUG-0098 (which added the second half of the refusal's *words* and is closed), nor of BUG-0086/0101/0104/0105 (which settled where the box is *positioned* and that it stays inside the table's clip — and it does: both refusals above measured inside the container box y=142 h=222). This is how long it lives, and whether it has an edge.

Evidence: `agenticflow/tracker/evidence/M2/designer/sandbox-stale-refusal-light-1440.png`, `sandbox-refusal-lastrow-light-1440.png`, `sandbox-refusal-notnull-light-1440.png`.

## Acceptance criteria
1. Escape retires the refusal. After a refused save, pressing Escape leaves the cell at rest with its old value **and no `role="alert"` node beside it** — the same end state as a cell that was never edited.
2. Leaving the cell retires it too: blur, or opening a different cell, clears the refusal of the cell being left. At most **one** refusal is on screen at any moment, on any record page.
3. A write still in flight is not spoken over: the existing rule ("a status is only ever replaced or retired by the edit that produced it", BUG-0075) holds — a `saving` status is not cleared by Escape, and a stale edit's clearing event does not retire a newer edit's statement.
4. The 1.5s confirmation clock is unchanged: `saved` still appears in healthy green and retires on its own after `CONFIRMATION_MS`, measured at ~1.5s on the walk.
5. The refusal panel carries a **1px hairline border**, the same spelling as the hint popover rendered by this component (`border border-hairline`), so it has an edge against the `bg-surface` table it floats over. No shadow, no new radius: `rounded-control` (4px) as now.
6. The refusal still says both halves in the two faces BUG-0098 settled — the database's refusal verbatim in mono, then the fix in the app's voice at the `body` step — and still measures inside the table's bordered container at every row including the last (BUG-0101/0104/0105 unregressed).
7. Human-check: on `/records/walk_sandbox/00000000-0000-4000-8000-000000000001` at 1440x900, refuse a save on `label`, press Escape, then refuse a save on `observed_on`: exactly one red panel is on screen, it has a visible edge, and no value in any other row is covered by it. (human-checkable)
8. `npm run lint` and `tsc --noEmit` clean; the targeted offline files green; the edit live suite green.
