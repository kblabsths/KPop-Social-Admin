# Micro labels uppercase machine identifiers: DATA_CONFLICT OPEN, ENTITY_LINK FOLDED, TICKETMASTER STUCK RECORDS

## Description
Found on the M1 endgame designer walk (2026-09-03), walk instance :8771 against staging.

Voice copy bar 5 names this exact string as its example: "Machine identifiers (**`data_conflict`**, `admin_locked`, `event_performers`, `wont_fix`) render verbatim in mono and are never prettified into Title Case prose."

The queue-health cards on `/queues` build their `micro` labels by concatenating a queue name with English, and the `micro` step is uppercase sans, so the identifier's case is rewritten on screen:

- `DATA_CONFLICT OPEN`, `DATA_CONFLICT FOLDED`, `DATA_CONFLICT OPEN AGE`
- `ENTITY_LINK OPEN`, `ENTITY_LINK FOLDED`
- `/sources`: `TICKETMASTER STUCK RECORDS` (a source name, same treatment)

The page already does it right one line above: the subsection heading renders `data_conflict` verbatim, lowercase, in mono `data` — so the same screen shows the same identifier two ways, three pixels apart.

This is the collision of two of the file's own rules (the `micro` step is uppercase; identifiers are verbatim mono), and the page has already demonstrated the way out: keep the identifier out of the sans label, the way the subsection heading does.

Evidence: `agenticflow/tracker/evidence/designer-walk-m1/queues-light.png` (the queue-health cards under the `data_conflict` heading), `sources-light.png`.

Smallest finding of the walk; filed because copy bar 5 names the string, not because it hurts.

**What this adds that its siblings do not.** BUG-0045 removes two prose sentences' ticket id; BUG-0046 fixes the count sub-lines under the figures. This one is the `micro` eyebrow label ABOVE the figure — a third string on the same card, cited to a different bar (copy bar 5, not 6), and it also reaches `/queues`, which neither sibling touches.

## Acceptance criteria
No `micro` label on any page contains an uppercased machine identifier. Where a card belongs to `data_conflict` or `entity_link`, the identifier appears verbatim in mono — as the subsection heading already renders it — and the sans label carries only the app's own words ("Open", "Folded", "Open age").

Source names get the same treatment: `ticketmaster` is not uppercased into a sans label.

Bucket, shape and status BADGES are unaffected — they are already mono `data` and already verbatim.

`tests/offline/queues/page.test.ts` and `tests/offline/sources/page.test.ts` assert no rendered `micro`-class element contains an underscore.

Human-check: on `/queues`, the string `data_conflict` looks the same everywhere it appears on the screen. (human-checkable)
