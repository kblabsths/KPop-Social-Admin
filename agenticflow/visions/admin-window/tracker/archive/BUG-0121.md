# The queues detail page's empty state cards set review_items in sans — the face BUG-0120 fixed one route over

## Description
Measured on the QA pass of admin-window/BUG-0120, 2026-09-09, on a production build (`next start`, port 8781) against staging, 1440x900, light and dark, console clean.

**Expected** — LOOK_AND_FEEL Voice bar 5: machine identifiers "render verbatim in mono and are never prettified into Title Case prose". `review_items` is a table name — the machine's word — and BUG-0112/BUG-0120 settled that a table name in this app's prose gets the identifier-in-prose spelling. Anchors: `src/app/queues/[reviewItemId]/page.tsx:180-183` (`NOT_AN_ID`, `${T.reviewItems}` interpolated into a plain string), `:602` (`holds={`row with that id in ${T.reviewItems}`}`). `Empty`'s `holds`/`filledBy` are already `ReactNode` since admin-window/BUG-0120 (`src/components/ui/empty.tsx:15-38`), so this route can wrap without touching the primitive — the fix is this file alone.

Scope note: `review_items` is not an English word on this screen, so there is no second-fixture trap of BUG-0120's kind here. `T.reviewItems` is the name the code already uses; wrap that one word, change nothing else. `review item` (two words, prose) is the app's own noun and stays sans.

Pinned red before filing: `tests/offline/review-item/page.test.ts`, describe "a table name in a queues empty state card" — two `it.fails` xfails, watched failing as plain `it`s with `expected [] to deeply equal [ [ 'type-data' ] ]` on both.
