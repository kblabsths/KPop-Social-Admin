# /cycles spells a raw ?source= into the runs window line as bare text, so a bidi control in the URL reverses 87 characters of the app's own prose

## Description
Found attacking admin-window/BUG-0147 on the landed run branch (e4538f5). BUG-0147 closed `?cycle=` on this page through an allowlist (`canSpellAskedCycle`); its builder named `?source=` as the same class left open, but named only the BOXED half. The unboxed half is worse and is what this ticket is: the RENDERED reversal BUG-0147 filed, alive on the same page, one facet over.

Expected (ARCHITECTURE.md §7, common violation 15, the rule earned by BUG-0123 -> BUG-0127 -> BUG-0136 -> BUG-0137 and applied to `?cycle=` by BUG-0147): "Text this app did not author never sits inside a sentence this app wrote" — foreign text reaches app prose either THROUGH AN ALLOWLIST or IN ITS OWN BOX.

Found: the `?source=` value reaches the runs window line's app-authored sentence as BARE TEXT — no allowlist, no isolate, no box. `runsScope(runs.data.source)` returns the template `` `from ${source}` `` (src/components/cycles/adapter-runs.tsx:73) and hands it to `WindowLine` as `scope` (src/components/cycles/adapter-runs.tsx:283), where `population()` interpolates it into plain prose (src/components/ui/window-line.tsx:335-336, :358). A `<p>` of plain text is not a bidi isolate, so an unterminated U+202E's scope is the paragraph.

MEASURED IN CHROMIUM (playwright, agenticflow/.venv-tools), production build of the landed tree against staging (ref ubfjjqlvnpnoborczbdb.supabase.co), this lane's own bind-probed port 8832 (child pid 57783, SIGTERM'd, exit 143; port re-probed free), viewport 1440x900, BOTH colour schemes — byte-identical in light and dark. `GET /cycles?source=%E2%80%AEbandsintown`, every character of `p[data-window="runs"]` collected by Range rect and sorted by (round(top), left):

  logical (what the page wrote):
    The adapters' newest runs, newest first - a window of at most 200, not a count of the runs from <U+202E>bandsintown that exist. The window did not fill: the read happened and found no runs from <U+202E>bandsintown at all.
  visual (what the operator reads):
    The adapters' newest runs, newest first - a window of at most 200, not a count of the runs from .lla ta nwotnisdnab<U+202E> morf snur on dnuof dna deneppah daer eht :llif ton did wodniw ehT .tsixe taht nwotnisdnab<U+202E>

87 characters of the app's OWN words — " that exist. The window did not fill: the read happened and found no runs from  at all." — are reversed by a value that came from the URL. Control on the same run, `?source=bandsintown`: logical and visual are identical strings, prose in order.

Over HTTP on the same production build, `GET /cycles?source=%E2%80%AEbandsintown` -> 200, **6 bidi controls OUTSIDE `<script>`** in 392559 bytes of markup (every `?cycle=` probe in the same walk measured 0 — that is BUG-0147 working and this ticket must not undo it). `data-dropped-params` is absent, so the page passes the sentence rather than reporting the facet dropped.

The facet's OTHER sentence, `p[data-source-facet]` (src/components/cycles/adapter-runs.tsx:88-101), has the box — `<Identifier>` renders `<span dir="ltr">` (admin-window/DEBT-0011) — and the same measurement shows the reversal contained to the value's own span there, the app's prose in order. That arm still carries the control in `data-source-facet` and in the text an operator COPIES OUT, which is exactly the limitation BUG-0137 and BUG-0147 named when they chose the allowlist over the box.

Repro (offline, exact, on the landed tree): in `tests/offline/cycles/page.test.ts`, the strict pin "never lets a ?source= bidi control into the sentences the page wrote" (in `describe("a ?source= link arriving from the Sources page")`), flipped from `it.fails(` to a plain `it(`. It fails at the first case with `U+202E U+0062 U+0061 ... : expected true to be false` (watched red before filing: 1 failed | 123 passed). As landed the pin is `it.fails` and the file is green; the day the hole closes, the XPASS turns the file red and sends the reader here.

Two honest arms, and the ticket should not guess silently:
(a) BUG-0147's answer, which §7 states as the rule: an allowlist on the raw `?source=` characters, and a value outside it earns no narrowing sentence and is reported on the shared dropped-parameter line. Note `?source=` is not merely SPELLED, it is SENT — `readRuns` does `.eq("source", source)` — so the allowlist question and the narrowing question are the same question here, which `?cycle=` did not have to answer.
(b) Box every occurrence (`<Identifier>`/`<bdi>` inside the window line's scope clause). Cheaper, but `WindowLine.scope` is typed `string | null` and consumed as text by `besides()`/`narrows()` string-splitting (src/components/ui/window-line.tsx:300-320), so an element cannot travel through it without changing that contract — and it still leaves the copied-out text reversed, which is (a)'s whole reason.

P3, the same price BUG-0147 carried and for the same reasons: the value is attacker-supplied only via a URL the operator themself pastes, on an admin surface behind `admin_allowed_emails`; no privilege boundary is crossed and nothing is written. It is a truthfulness defect on two sentences of one page — the fifth of its family. `/cycles` is the only route that renders `AdapterRuns`; `tests/offline/runs/page.test.ts` renders the same page.

Either arm satisfies it: an allowlist on the raw value, with an unadmitted value earning no sentence and being reported on the shared dropped-parameter line; or every occurrence in its own bidi isolate AND no control left in the text (including the data- attributes an operator copies).
