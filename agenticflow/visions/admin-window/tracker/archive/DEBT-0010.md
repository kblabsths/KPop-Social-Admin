# Two exported narrowedTo with different meanings, and one isNarrowed whose two arities answer two different questions — the narrowing vocabulary has no owner

## Description
M2 structure walk finding (architect, 2026-09-09), measured on run/admin-window.

§11 says contract vocabulary is the app's vocabulary, in code as in copy. The narrowing vocabulary — the single most-touched idea of M2, the root of nine bugs (0109/0114/0118/0123/0124/0128/0129/0131/0133) — has two words doing two jobs each.

**`narrowedTo`, exported twice with unrelated types:**
- `src/components/ui/window-line.tsx:279` — `(readonly (string|null)[]) => string|null`. Joins several narrowing PHRASES into a scope sentence, with `besides()` as its inverse. Re-exported from the `@/components/ui` barrel (`index.ts:29`).
- `src/lib/db/runs.ts:198` — `(string|undefined) => string|null`. Canonicalises the `?source=` FACET for a query; a blank narrows nothing.

Both are imported by a page, and by adjacent pages: `src/app/cycles/page.tsx:38` takes the `lib/db/runs` one, `src/app/claims/page.tsx:28` takes the `components/ui` one. A reader moving between the two pages sees the same identifier mean 'a sentence fragment' and 'a query value'. Nothing catches an import from the wrong module except the type checker, and only because the shapes happen to differ.

**`isNarrowed`, exported twice with two different definitions, and one of them means two things depending on arity:**
- `src/lib/claims/filters.ts:132` — `(filter) => boolean`, 'is any facet set'.
- `src/lib/review/queue-filters.ts:302` — `(filter, within = {}) => boolean`. With `within` it means 'narrowed RELATIVE to this block's own scope' (the question BUG-0129/0131 exist to answer); with the default it collapses to the claims meaning. **No production call site uses the default** — `queues/page.tsx:347` and `queue-filters.ts:355` both pass `within`. The only callers of the one-argument form are `tests/offline/queues/filters.test.ts:85,102,143`, which grade a meaning the app never asks for. A default parameter that exists only for its tests is how a predicate gets widened by whichever question broke last — the cost ARCHITECTURE Common violations row 15 names in its ruling.

No behaviour is wrong today. This is the naming and shape debt underneath the M2 bug tail, filed so the next ticket on a narrowing surface reads one vocabulary instead of four.

Dependency: BUG-0141 (in flight) writes `src/lib/review/queue-filters.ts`, `src/lib/claims/filters.ts` and `src/app/claims/page.tsx`. This lands after it.

## Acceptance criteria
1. No identifier is exported twice from `src/` with two different meanings. Each of the two `narrowedTo` functions carries a name that says which job it does — the phrase-composer and the facet-canonicaliser are not the same word — and every import site is updated. Which name each takes is the builder's call; the constraint is that a grep for either name returns one declaration.
2. `isNarrowed` in `src/lib/review/queue-filters.ts` no longer carries a default `within`, so its one signature asks its one question. Its callers are unchanged (both already pass `within`); the tests that relied on the default either pass `{}` explicitly at the call or are rewritten to grade `isBlockNarrowed`, which is the question the page actually asks.
3. The two `isNarrowed` declarations (claims and queues) either share one name because they genuinely share one meaning, or are named apart. Do not merge the functions: their facet sets differ and DEBT-0008 is separately settling the two-fact rule.
4. Behaviour is identical on every surface: the window lines, scope sentences, bucket captions, empty-state arms and `?source=` narrowing on `/cycles` render byte-for-byte what they render today. This is a rename, not a rule change.
5. `npm run lint` and `tsc --noEmit` clean; the offline suite green.
