# Browse's Sources column names superseded and sourceless provenance decisions

## Description
Browse reads `field_provenance` as if it were a current-state table, one row per field. It is not.

**Authority.** `contracts/data-model.md`, "Per-field provenance": "the `field_provenance` table is an append-only decision log, one row per canonical write ... **The latest row per fact identity is the current provenance; the rows before it are that fact's decision history.** Rows are never updated or deleted. On an unset row ... `observation_id` and `source_id` are **null**". The schema agrees: scraper migration `20260818000000` line 3550 `COMMENT ON TABLE field_provenance IS 'The decision log ... Append-only ...'`, line 4470 the only key is `provenance_id`, line 5089 trigger `field_provenance_reject_rewrite BEFORE DELETE OR UPDATE`; scraper migration `20260901000005` lines 82-88 `alter column source_id drop not null` with the comment "null on a verdict unset". contracts/admin-observability.md section 4 asks for "the source(s) **behind the row**".

**Found.** `src/lib/db/browse.ts:139-154` (`provenanceFor`) projects only `entity_id, source_id` — it selects neither `field` nor `applied_at`/`provenance_id`, so it structurally cannot tell a current decision from a superseded one — and `src/lib/browse/rows.ts:132-142` (`joinBrowseRows`) set-unions every `source_id` for the entity. `EventProvenanceRow.source_id` is typed `string` at `src/lib/browse/rows.ts:44`, against a nullable column.

**Repro A — a superseded source is named as behind the row.**
One event; the fact identity (event, `title`) decided twice, append-only: `retired_feed` won it at 2026-01-01, `ticketmaster` won it at 2026-08-01.
- Expected: Sources cell = `ticketmaster`.
- Found: Sources cell = `retired_feed, ticketmaster`.
Pinned by `tests/offline/browse/views.test.ts` > "the join" > "names only the source behind the current value, not a superseded one" (measured: `expected [ 'retired_feed', 'ticketmaster' ] to deeply equal [ 'ticketmaster' ]`).

**Repro B — a verdict unset (`source_id: null`) becomes a phantom empty source.**
One event with one unset decision (`source_id` null) and one `ticketmaster` decision.
- Expected: `BrowseRow.sources` = `["ticketmaster"]`; Sources cell = `ticketmaster`.
- Found: `BrowseRow.sources` = `[null, "ticketmaster"]` — a `null` inside a `readonly string[]` — and the rendered cell carries an empty segment.
Pinned by `tests/offline/browse/views.test.ts` > "the join" > "contributes no source name for a decision that names no source" (measured: `expected [ null, 'ticketmaster' ] to deeply equal [ 'ticketmaster' ]`).

**Repro C — both, at the rendered surface.** `tests/offline/browse/page.test.ts` > "the page's rows" > "does not name a superseded source, or a decision with no source": Expected Sources cell `ticketmaster`, Found `bandsintown, ticketmaster,` (note the trailing empty segment from the null source).

**Impact.** This is the one column whose purpose is spot-verification — "which source told us this". It currently answers with the union of every source that has ever won any field on the row, plus a blank for every verdict unset. On a mature database the wrong answer grows monotonically, because the log only ever appends.

**Note for the fix.** No current-provenance view exists in the scraper schema (checked: the only views are `event_listings`, `catalog_completeness_summary`, `group_completeness`, `idol_completeness`, `*_follower_counts`), so the latest-per-fact-identity reduction is Admin's to do: select `field` and an ordering key (`provenance_id` is uuid_v7, i.e. time-ordered, or `applied_at`), keep the latest row per `(entity_id, field)`, and drop rows whose `source_id` is null. Do not widen scope beyond that.

**The pins are strict-xfail.** They are committed as `it.fails(...)` so the run branch stays green; the reason names this ticket. **Flip all three back to `it(...)` as part of the fix** — with the pins left as `it.fails` a correct fix turns them red, which is the signal working as intended, not a second bug.
