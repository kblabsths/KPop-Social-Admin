# STACK.md 5's production-like walk row is not runnable as documented: the step-1 prefix binds to 'npm run build' only, so 'npm run start' launches with no database and the wrong origin

## Description
Expected (agenticflow/docs/vision/STACK.md 5): 'Everything below is verbatim and runnable from the repo root', plus the bullet added by BUG-0039 — '**Both walk rows in the table above take the same step-1 prefix** — the production-like row (`npm run build && npm run start`) exactly as much as `npm run dev`.' A walker composing the table's production-like row with step 1's prefix must get a database-backed walk instance, same as the dev row.

Found: the composition the doc instructs is a no-op for the server that actually runs. A command-prefix assignment binds to ONE simple command, so in `A=1 npm run build && npm run start` the started server inherits neither the mapped SUPABASE_* names nor AUTH_URL. The doc gives no verbatim production-like launch line — the dev row's fenced block is the only one — so the literal substitution is the only reading available, and it fails silently at startup.

MEASURED 2026-09-03 on run/admin-window at aeb54d6, in an isolated git worktree (own .next; the dispatcher's 8771 instance was never touched — it stayed HTTP 200 throughout and I bound only 8779/8781, both freed afterwards). No value printed anywhere; .env was never opened, catted or grepped.

REPRO (from a fresh shell where STAGING_SUPABASE_URL / STAGING_SUPABASE_SERVICE_ROLE_KEY / SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY are all UNSET — verified with the doc's own presence idiom):

1. Compose step 1's prefix with the table's production-like row, verbatim, on a free port:
     ( set -a && source .env && set +a && \
       SUPABASE_URL="$STAGING_SUPABASE_URL" SUPABASE_SERVICE_ROLE_KEY="$STAGING_SUPABASE_SERVICE_ROLE_KEY" \
       AUTH_URL="http://localhost:8781" npm run build && npm run start -- --port 8781 )
   -> builds, starts, /api/health 200.

2. GET / and /sources with a cookie minted by `node tests/walk/session-cookie.mts`:
   -> HTTP 200, but EVERY panel renders the not-provisioned refusal 'SUPABASE_URL is not set / Reload to try the read again.' Zero staging rows. / is 16,221 bytes, /sources 16,107 bytes; occurrences of 'ticketmaster' in the markup: 0.

3. GET / with NO cookie on the same instance:
   -> HTTP/1.1 307, location: http://localhost:3000/login?callbackUrl=http%3A%2F%2Flocalhost%3A3000%2F
   AUTH_URL never reached the server, so the walk is redirected to a port nothing is listening on — the exact ':3000 chase' 5 calls 'not optional'.

CONTROL — the dev row, same fresh shell, same worktree, verbatim from 5's fenced block (port 8779 substituted):
     ( set -a && source .env && set +a && SUPABASE_URL="$STAGING_SUPABASE_URL" SUPABASE_SERVICE_ROLE_KEY="$STAGING_SUPABASE_SERVICE_ROLE_KEY" AUTH_URL="http://localhost:8779" npm run dev -- --port 8779 )
   -> /, /cycles, /queues, /claims, /sources, /browse ALL HTTP 200 with real staging rows: / is 51,963 bytes (14 'ticketmaster' hits), /cycles 462,075 bytes (26), /browse 176,418 bytes (80), /claims 2,871,345 bytes; visible text shows resolver cycles ('10h ago succeeded') and the sources registry (test_harness, test_harness_control, test_harness_ticketmaster, ticketmaster). Zero 'SUPABASE_URL is not set' panels. The dev row is sound; only the production-like row is broken.

MECHANISM (no secrets, reproducible standalone):
  bash -c 'PROBE=bound true && python3 -c "import os;print(os.environ.get(\"PROBE\",\"<absent>\"))"'   -> <absent>
  bash -c 'PROBE=bound python3 -c "import os;print(os.environ.get(\"PROBE\",\"<absent>\"))"'           -> bound
The prefix is consumed by the first simple command. `set -a` does not rescue it: .env carries the STAGING_* pair, not SUPABASE_URL/SUPABASE_SERVICE_ROLE_KEY (5's own bullet says so), so the started server has SUPABASE_URL undefined; and .env's own AUTH_URL (name listed in .env.example as http://localhost:3000) is what next-auth then resolves the origin from.

FIX (doc only, same scope as BUG-0039): give the production-like walk its own verbatim fenced block in 5 step 1 in which the mapped names and AUTH_URL sit on the SAME simple command as `npm run start` (repeat the prefix on both halves, or export the mapped names once inside the subshell before running build and start). The table row alone is not runnable and the 'same step-1 prefix' sentence is what makes it look like it is.
