# The over-cadence line says 'never finished' of a cycle the same page renders as still running

## Description
Measured 2026-09-09 while attacking BUG-0110's landed fix on `run/admin-window` (b34e18a).

BUG-0110 made the Cycles-in-window sub-line name its excluded set. The clause is built from `duration.unmeasurable` (`src/components/cycles/cycle-health.tsx:88-91`) and calls every row in that set a cycle that **never finished**. `duration.unmeasurable` is every row `secondsBetween(started_at, ended_at)` cannot measure (`src/lib/gauges/gauge.ts:367-375`) — which is wider than the dead.

**Expected** — LOOK_AND_FEEL, The Voice, "one name per concept, everywhere": the app pins one word per cycle state, and `STATE_WORD` (`src/lib/cycles/state.ts:130-137`) gives them — `running` -> "still running", `died` -> "died". The scraper's own migration `20260901000001` states the distinction on this exact column: "Null while the cycle is still running; the row is inserted at start, so an OLD row with a null here is a cycle that died". `src/lib/cycles/state.ts:16-21` records why this is load-bearing here: admin-window/BUG-0055 was filed because "/cycles' rows said `died` where its own health panel said `unfinished`, over the same four cycles on the same screen". And BUG-0110's own criterion 4: "The count of unfinished cycles in this line is the **same** number the outcome distribution's `died` row and the duration note already render — the page cannot show three counts of one set."

**Found** — with a window holding three finished cycles and one cycle inserted 2 minutes ago with no `ended_at` (a cycle in flight; cadence is 15m), the one card row renders both of these at once:

    CYCLES IN THIS WINDOW
    4
    0 of 3 finished cycles ran longer than the 15m cadence; 1 never finished

    Cycle outcomes:  succeeded 3 | failed 0 | skipped 0 | still running 1 | died 0 | (unrecorded) 0

The sub-line pronounces the cycle dead; the panel under it, from the same read, says it is still running and that nothing died. Criterion 4's equality fails outright on a mixed window: 1 finished + 1 running + 1 died renders "; 2 never finished" against a `died` row of 1.

Two further rows fall in the same set and get the same verdict:
- a row with a **non-null but unparseable** `ended_at` — it recorded an end — renders "1 never finished" while the outcome panel counts it `unrecorded` (the em dash);
- any window whose newest cycle is mid-execution, which at a 15-minute cron is a normal state, not a corner.

Not visible on staging today: my independent read of `resolution_runs` over the rendered 7-day window returned 65 rows, 61 outcome-bearing, 4 with no end and **all 4 older than one cadence** (died), 0 running — so the rendered "0 of 61 finished cycles ran longer than the 15m cadence; 4 never finished" is correct there, and BUG-0110's criterion 1 is met. The defect is in the general case, which criterion 4 names and the fix's fixtures avoid (the builder's own handoff flags it: "'never finished' means no measurable duration, so a still-RUNNING cycle counts in it too ... that is why my fixtures use only died rows for the panel cross-read").

**Repro (offline, no database):**
1. `cd "kspace Admin"` on `run/admin-window`.
2. `./node_modules/.bin/vitest run --project=offline tests/offline/cycles/page.test.ts -t "in-flight"`.
3. The strict pin `it.fails("does not pronounce a cycle it is rendering as in-flight one that never finished (admin-window/BUG-0116)")` (tests/offline/cycles/page.test.ts) passes today because the assertion inside it fails; flip it to a plain `it(` and it reports: `AssertionError: 0 of 3 finished cycles ran longer than the 15m cadence; 1 never finished: expected true to be false`.

The neighbouring always-green case, "excludes the cycle that is still in flight, and counts it once", establishes the fixture's facts independently: the running row is the only row rendering no duration, the sub-line's three counts are `[0, 3, 1]`, and the outcome panel counts 1 under the word the table gave that row.

**What the fix has to decide (not mine to choose).** Two honest shapes, and the ticket's criteria pull toward different ones:
- **Reword.** The excluded set is "recorded no end" — the phrase the duration note two panels down already uses, and exactly what `unmeasurable` means. One count, no verdict, satisfies BUG-0110 criteria 1-3 and the Voice bar. Does NOT satisfy criterion 4's literal equality with the `died` row.
- **Split.** Name the excluded set and how many of it died: "...; 2 recorded no end, 1 of them died". Satisfies criterion 4 literally, at the cost of a longer line on a card the rule allows exactly one sub-line.

The pin above passes under either — it forbids the claim class ("never" + finish/complete/end), not a spelling, and its discriminator case ("guards the claim a cycle never ends, in any spelling, and nothing weaker") proves it clears "recorded no end", "has not finished" and "died".

When the fix lands, flip the `it.fails` back to a plain `it(` — the convention this file already uses (see its admin-window/BUG-0067 note).
