# The signal item's two dispositions: fixed, and wont_fix with its required note

## Description
**SPEC F10 / spec §7, the signal item** — today's only real one: the `entity_link` source-pattern item, the single row staging holds. A signal takes no verdict; it closes with a **disposition**:

- **`fixed`** — the breakage was addressed elsewhere, on its own surface (a tier move, a source pause, a dial change). This app does not perform that fix and offers no control for it; it records that it happened.
- **`wont_fix`** — the condition stands, and **the note is required**. The form refuses without one and NAMES the reason. The form's refusal is courtesy: `decisionRefusals` refuses it too, and `settle_review_item` raises on it. Three guards, deliberately, and the ticket's tests prove the first two here.

Either way the item settles and the `verdicts` row carries the disposition.

**This is the one shape that is walkable on staging**, so its live grading is real rather than vacuous — but the walk writes nothing: with `settle_review_item` absent, the live suite grades the not-provisioned state, which is the honest oracle (DECISIONS 2026-09-02: a live oracle names the page's state kind before it compares a number).

**The absence is the normal case and is graded FIRST.** `verdicts` and `settle_review_item` do not exist on staging and will not until Ben installs the handoffs — that is the database `main` deploys against for the whole of M2. Build and grade the not-provisioned path before the happy path, and never offer a control that would call a missing function.

**No Admin-side workaround for the absent function may be written** — spec §10's one forbidden move: no queued write, no pending-overrides table, no retry buffer, no flag-guarded direct write.

## Acceptance criteria
1. With `verdicts` present (stub) and the signal fixture: the close slot contains exactly two controls, `fixed` and `wont_fix`, and no others; both machine identifiers render verbatim in mono (§11), never prettified to "Won't fix".
2. `wont_fix` with an empty or blank note is refused BY THE FORM, the refusal names the reason on screen, and the recording stub records ZERO calls — the payload is never sent.
3. `fixed` submits with a null note and succeeds; `wont_fix` with a non-blank note submits; each is exactly one call carrying one typed decision, `review_item_id` set and `value` null.
4. With `verdicts` absent: neither control renders, the not-provisioned card names the missing object, and the item's summary, severity, age and `folded_count` ("asked again ×N") render exactly as M1 shipped them.
5. The live suite for the review-item detail asserts the STATE KIND before any number, and grades the staging signal item's page as `not_provisioned` in the close slot while the rest of the page is `ok` — never inferring absence from "no rows rendered" (§10).
6. `npm run lint`, `tsc --noEmit`, the targeted offline file and the review-item live suite are green.
