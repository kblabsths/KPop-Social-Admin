# '0 ran longer than the 15m cadence' stands bare beside four cycles that never finished — the Zeroes bar, on the card the doc quotes

## Description
Measured on the M2 endgame walk, 2026-09-09, on `/cycles` at 1440x900.

**Expected** — LOOK_AND_FEEL, Interaction principles, Zeroes: "a zero states what it excludes whenever the excluded set is not empty — **'0 of 65 finished cycles ran longer than the cadence; 4 never finished'** — and never stands bare beside the rows it silently drops. The line names the excluded set and how many rows are in it; whether the figure is good news stays the operator's call, never the app's." The bar quotes the sim who earned it: "'0 ran long' sitting next to four corpses is the sort of reassuring sentence I've been burned by before."

**Found** — the Cycle health gauge's first card, verbatim on screen today:

    CYCLES IN THIS WINDOW
    69
    0 ran longer than the 15m cadence

and, in the same window, the outcome distribution below it reads `died  4`, and the note under the duration percentiles reads "4 of these cycles recorded no end, so they are counted as unmeasurable rather than as a duration of zero."

So the excluded set is four cycles, it is not empty, the page knows its size, and the zero does not name it. The doc's example sentence — "0 of 65 finished cycles ran longer than the cadence; 4 never finished" — is this exact card with this exact data: 69 in the window, 65 with a measurable duration, 4 without.

The qualification exists but is ~500px lower, under a different table, after three other cards. A reader who takes the card at face value reads "nothing ran long" from a figure computed over 65 of 69 rows.

`src/components/cycles/cycle-health.tsx:102` builds the line as a bare template — `` sub={`${count(health.overCadence)} ran longer than the ${cadence} cadence`} `` — with no reference to `health.unmeasurable`, which the same object already carries (the note below it renders from that count).

TASK-0038 wrote this bar into LOOK_AND_FEEL on 2026-09-09 and changed no `src/` file; nothing has built it since. It is the sibling of the palette bar filed as BUG-0106 — both were written for the endgame to enforce.

**Swept for others, and there is only this one.** Every other zero on the six pages already names its set or has an empty excluded set: `WRITES / 1,710 applied, 0 escalated, 49 created`; `RE-REJECTED CLAIMS 0 / Values a human already adjudicated out, pushed again`; `SOURCES RE-PUSHING ADJUDICATED VALUES 0 / of 0 with any claim adjudicated in this window`; `data_conflict FOLDED 0 / of 0 items read here, 0 folds in all`; `UNSET BY A HUMAN DECISION 0 / Decisions that name no claim, so they carry no wait to measure`; `/claims`'s zero buckets, whose table note says "A bucket with no claims is a real zero."

Provenance checked before filing: `git log src/components/cycles/cycle-health.tsx` returns one ticket-bearing commit (0543d42, DEBT-0004). No human-lane divergence; violation, not reconciliation.

Evidence: `agenticflow/tracker/evidence/M2/designer/cycles-light-1440.png`.

## Acceptance criteria
1. The Cycles-in-window card's sub-line names the excluded set and its size whenever that set is non-empty. The excluded set is exactly the rows the over-cadence figure could not be computed over — `duration.unmeasurable`, the same field the duration note two panels down renders — and the line names it by what is true of EVERY row in it: it recorded no end. On today's staging window it reads "0 of 61 finished cycles ran longer than the 15m cadence; 4 recorded no end".
2. When the excluded set **is** empty (every cycle in the window recorded an end), the line stays as it is now: no clause is added to say nothing.
3. The line says what is excluded and how many; it does not say whether the figure is good news. No "healthy", no "all clear", no reassurance — the operator's call, per the Zeroes bar.
4. **The line makes no claim about the OUTCOME of the rows it excludes.** It does not say they never finished, never completed, never ended, died, crashed or failed. That is the architect's ruling of 2026-09-09 and it replaces the old criterion 4, which demanded the excluded count equal the outcome panel's `died` row: `duration.unmeasurable` is a strict superset of the dead (a cycle in flight and a row with an unparseable end are both in it and neither died), so on a mixed window the old 4 and criterion 1 could not both be satisfied. What must agree is this: the count in this line is the SAME number the duration note renders, from the one read of the one field, so the page cannot report one set as two numbers. It is not required to equal `died`, and after this fix it must not be readable as if it were.
5. **One name per concept** (the Voice bar, and the reason `src/lib/cycles/state.ts` exists — BUG-0055, BUG-0074). The words this line names the excluded set with are the words the page already uses for that same set, in the duration note under the percentiles; the state vocabulary `STATE_WORD` publishes (`still running`, `died`, and the shared absence dash for unrecorded) stays where it is, on the surfaces that classify a row by its state. The card does not gain a second, shorter vocabulary for cycle states, and it does not split the excluded set into per-state counts: the stat-card rule allows exactly one sub-line, and the outcome panel three cards down is where the states are counted.
6. The figure itself is unchanged (`69` on the walk's window), stays at the `figure` step in mono, and the sub-line stays one `data` line of sub-detail on the stat card.
7. The strict pin QA left on the run branch — `it.fails("does not pronounce a cycle it is rendering as in-flight one that never finished (admin-window/BUG-0116)")` in `tests/offline/cycles/page.test.ts` (commit 4242769) — is the red-to-green target: it is a plain `it(...)` and green when this lands, and no `it.fails` marker is left XPASSing in that file (the file's own convention, its admin-window/BUG-0067 note). Its neighbouring always-green case, "excludes the cycle that is still in flight, and counts it once", stays green unchanged. The pin forbids a CLASS of claim rather than a spelling, so it grades criterion 4 without pinning the app's words.
8. Human-check: on `/cycles` at 1440x900, reading only the Cycle health card row and nothing below it, it is clear that four cycles are outside the "ran longer than the cadence" figure, and nothing on that card says what became of them. (human-checkable)
9. `npm run lint` and `tsc --noEmit` clean; the targeted offline files green; the cycles live suite green.
