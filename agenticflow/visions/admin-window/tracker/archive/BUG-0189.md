# The queue-health live case takes its ABSENCE from the markup, so a not-provisioned page passes it vacuously

## Description
**Module:** `tests/live/queues.live.test.ts:449`, the queue-health gauge case —

    const counted = window.present ? await windowCounts(window) : "absent";

**The defect.** That line derives an ABSENCE from the MARKUP: no `[data-window="queue_health"]` line rendered, therefore `review_items` is declared absent. `gradeSurface` then reaches rule 5 (`tests/live/parity.ts:804`, `if (counted !== "absent" && !(await objectIsAbsent(input.object)))`) with `counted === "absent"` and short-circuits — the test's own read of `review_items` is never issued, and `not_provisioned` is returned as a pass. The case's remaining assertions are all behind `if (state !== "ok" || counted === "absent") return;`, so a `/queues` that renders the gauge not-provisioned while `review_items` exists passes this case with ZERO database reads of its own. That is precisely the class admin-window/BUG-0037 and BUG-0062 were filed for, on the one surface where the guard against it was written out.

**The rule it breaks** (`agenticflow/docs/vision/ARCHITECTURE.md` §10, live-state rule 3): *"`not_provisioned` is a pass only when the test's own read of that same object gets the absence code (`PGRST205`/`42P01`). It is never inferred from 'no rows rendered'."* A missing window LINE is the same inference as missing rows — a fact of the render, not of the database.

**Measured on run/admin-window (architect, 2026-09-11):** `grep -rn 'present ?' tests/live` returns exactly ONE line, this one. Every other absence in the twelve live files comes from the test's own read — `countOrAbsent`, `objectIsAbsent`, or the `PGRST205`/`42P01` codes read off an error. `tests/live/queues.live.test.ts` does not import `objectIsAbsent` at all. The suite is green today: `npm run test:live -- tests/live/queues.live.test.ts` = 14 passed, 9.8s.

**The fix shape (ruled, architect).** The gauge's `counted` is produced by a READ, never by a markup predicate, in the shape the sibling case already uses — `tests/live/cycles.live.test.ts:313-320`:

    counted: async () => {
      if (!window.present) {
        return (await objectIsAbsent(T.reviewItems)) ? "absent" : 0;
      }
      return windowCounts(window).then(...)  // the window the page states
    },

i.e. hand `gradeSurface` the thunk it already accepts (`SurfaceGrade.counted`, `tests/live/parity.ts:738` — run only once the surface is known not to be in its ERROR state), and when the page published no window line, ask the DATABASE whether `review_items` is absent. Where the line IS present nothing changes: both edges still come off the line the render published, `windowCounts` is unchanged, and the window-LENGTH assertion (180 days end to end) stays conditional on the line being there, because a page that published no window states no interval to grade.

**Not in scope:** `windowCounts` and every parity comparison below the grade (they are correct and graded green today); the other eleven live files; `src/`, which this ticket does not touch — no product behavior is claimed to be wrong, the ORACLE is. Do not add a `whileStill` retry: this case is deterministic for the reason stated in its own comment and in the DECISIONS.md entry of 2026-09-11 (`review_items.status` is not written by anything in this build).

**Note for the M3 structure walk, not this ticket's work:** this fix makes THREE hand-written copies of `(await objectIsAbsent(X)) ? "absent" : 0` in the live tier (cycles, sources, queues). A shared helper in `tests/live/parity.ts` is deliberately not in scope — `tests/live/sources.live.test.ts` is inside TASK-0073's touch scope and a fold into all three files would collide at landing. Count it at the walk (ledger row 9's class).

## Acceptance criteria
The queue-health case establishes an absence only from its own read. When `/queues` publishes no `[data-window="queue_health"]` line, the value handed to `gradeSurface` as `counted` comes from a read this test issues against `review_items` — `"absent"` only if that read gets `PGRST205`/`42P01`, and a NUMBER otherwise, so a page rendering the gauge not-provisioned over an existing table fails the case at parity.ts's rule 5 instead of passing it. No expression in `tests/live/queues.live.test.ts` derives `"absent"` from a fact of the markup.

The shape is the sibling's, not a new one: `gradeSurface` is handed the thunk form of `counted` it already accepts, spelled as in `tests/live/cycles.live.test.ts:313-320`, and `objectIsAbsent` is imported from `./parity` and called with `T.reviewItems`.

Everything the case already proves still holds, unchanged: where the window line IS present both edges are still read off it, `windowCounts` is unmodified, the 180-day end-to-end assertion stays conditional on the line's presence, and every per-slice open-count parity assertion below the grade is byte-identical. The file gains no `whileStill` retry and no product file is touched — `git diff --name-only` for this ticket names `tests/live/queues.live.test.ts` and nothing else. `npm run test:live -- tests/live/queues.live.test.ts` stays green at 14 passed (9.8s measured on run/admin-window before the fix).
