# Sources narrowed to one source reports the FLEET's unattributed-rejection count as that source's

## Description
Expected (contracts/admin-observability.md sections 4-5, the per-source settled-values gauge, and this page's OWN stated rule at src/app/sources/page.tsx:475-479 in RejectionSection — 'The figures answer the question the URL asked. Narrowed to a source with nothing adjudicated in this window, that is an empty scope — a real zero over the rows read, not the fleet's total wearing one source's name'): with /sources?source_id=<A>, every figure the Settled values section reports is over source A's rows.

Found: the closing sentence of that section reports two FLEET-WIDE totals under the narrowing. src/app/sources/page.tsx:552-566 reads gauge.unattributed and gauge.unnamedSources straight off SettledValues — both are computed across every source in the window (src/lib/gauges/settled-values.ts:120 'Sources whose sources row did not come back' and :127 'Rejections carrying no rejected_by at all', accumulated at :169-176 over ALL rejections, before any per-source grouping). Only the two GaugeCards above them are scoped (via the local 'scope' at :541-545). So an operator narrowed to ticketmaster reads a count of rows that belong to bandsintown.

Repro (offline, no database):
1. cd '/Users/ben-m4/Desktop/Coding/KPOP/kspace Admin'
2. ./node_modules/.bin/vitest run tests/offline/sources/page.test.ts -t "keeps a stranger"
3. The test renders /sources?source_id=<ticketmaster> twice: once with only ticketmaster's rejections in the window, once with one extra rejection belonging to BANDSINTOWN whose rejected_by is null. It compares the Settled values section's own words (window line removed, since it carries the render instant).

Watched failing as a plain it() on run/admin-window @ 5b42bc8:
  AssertionError: expected 'Settled valuesRe-rejected claims in t...' to be '...' // Object.is equality
  Received differs from Expected by exactly: ' 1 rejection carries no reason at all, so it is counted in neither column.'
i.e. a bandsintown row, alone, added a number to a page narrowed to ticketmaster. The unnamedSources clause on the next line has the same shape and the same defect.

Reachable from real data, no malformed row needed: observations.rejected_by is nullable and written by convention rather than by a trigger (kspace Scraper migration 20260901000003) — the module's own docstring says so — and the narrowing is a one-click path (the source chips on this page, and the Claims page's sourceHref link /sources?source_id=<id>).

Fix: scope both clauses to the same 'scope' the cards use, or report them per source. Do NOT fix it by deleting the sentence — an unattributed stamp and an unnamed source are real facts the operator needs; they just have to be that source's. Then flip the pinned it.fails at tests/offline/sources/page.test.ts:604 back to a plain it(). The assertion is behavioural (a stranger's row must not move a narrowed source's figures) and pins no wording.
