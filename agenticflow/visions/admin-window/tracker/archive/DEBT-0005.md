# The /cycles lead renders error_summary unclamped, so a long producer string can push the newest cycle back below the fold

## Description
BUG-0040's residual, carried by both its builder and its QA and unticketed until now (M1 endgame, architect's residual pass 2026-09-03).

BUG-0040 put a 'Newest adapter run' lead above the cycles table so the newest run and the newest cycle are both above the fold (Feel bar 1). The lead renders the run's `error_summary` verbatim, with no clamp, in a cell measured at 151px wide. Measured by the QA walk: the lead row sits at y=108-140 and the first cycle row at y=281-306, against a 900px fold. An `error_summary` beyond roughly 700 characters wraps the lead tall enough to push the newest cycle below the fold — re-breaking half of the criterion BUG-0040 exists to satisfy, on a page that is otherwise correct.

Unreachable today, which is why this is P3 and not a bug: staging's longest `error_summary` is 58 characters and the producer's own column comment promises 'never the whole trace'. That promise lives in the scraper repo and is not something this repo can enforce, so the page's layout currently depends on another repo's discipline. Clamping is cheaper than depending on it.

Why not left as a note: a Feel-bar-1 criterion that holds only while foreign data stays short is a criterion nobody can re-verify. One clamp makes the fold property a fact of this page.

Not in scope: the cycles TABLE's own error column (it is one row among many and pushes nothing), and any change to the lead's other cells. `error_summary` is producer text — it is never re-worded, only clamped, and the full value stays reachable.

## Acceptance criteria
`lib/format.ts` — the one place a value becomes display text — exports a clamp used by the /cycles lead, so a long `error_summary` renders at a bounded length with the full value still reachable on the element (a `title`), never re-worded and never dropped: a clamped string is visibly clamped (an ellipsis), and a string under the bound is returned byte-identical. An offline test renders the /cycles lead with a 2,000-character `error_summary` and asserts the lead's own markup is bounded, and that the existing fold pin still holds (`rowOrder` over the 200-row `fullCycleWindow` fixture: the lead precedes every `[data-cycle]`, with `lead.markers === 1`). The live oracles for /cycles and /runs are unchanged and green: this changes rendered TEXT for one over-long value only, and every `data-` attribute the page carries stays as it is.
