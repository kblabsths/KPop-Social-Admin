# A probe directory left by a KILLED vitest run is never swept, and a later run that draws its pid grades the corpse as its own probe

## Description
Found attacking DEBT-0018 on the landed tree (run/admin-window @ e40c473, primary checkout, offline vitest + eslint, no device, no network, 2026-09-11). DEBT-0018's own criteria are green (the concurrent pair passes 5/5 here); this is the hazard the same change opened on a DIFFERENT trigger — a run that DIED rather than two runs that are both alive.

**Expected** (`tests/offline/db/layering.test.ts:72-76`, `isForeignProbe`'s docstring): "True for a probe under the shared parent that THIS run did not plant — another concurrent run's, **or one left by a run that died**."

**Found — two measured consequences of one root cause.** A run's probe directory is named from `process.pid` ALONE (`tests/offline/db/layering.test.ts:68-69`, `tests/isolated/probe-race.isolated.test.ts:60`), and since DEBT-0018 each `finally` removes only THAT directory while the shared `src/.probes` parent is deliberately never removed. So a run killed mid-scan leaves a probe directory that NOTHING ever sweeps — `.gitignore:75` hides it from `git status`, and `tests/offline/toolchain.test.ts`'s real-tree case now excludes the whole probe AREA, so no guard sees it either. Before DEBT-0018 every scan's `finally` did `rmSync("src/.probes")` (`git show 7c142c3^:tests/offline/db/layering.test.ts` lines 219, 228 — `probeDir` WAS the shared parent), so the next run swept any corpse; that self-healing is what this change removed.

(1) **pid reuse makes the corpse this run's OWN probe, and the credential rule reports it.** pids are recycled; a later vitest worker fork drawing the dead run's number computes the same `CREDENTIAL_PROBE_DIR`, so the corpse is not foreign and is GRADED — and a probe holds `process.env.SUPABASE_SERVICE_ROLE_KEY` on purpose.
  MEASURED: with probe directories planted across a band of not-yet-allocated pids, the worker fork drew 60860 and `./node_modules/.bin/vitest run --project=offline tests/offline/db/layering.test.ts` went **3 failed | 30 passed (33)**:
    - `credentials > reads the service-role key in the db client alone`
    - `credentials > reads no other SUPABASE_ credential outside the db client`
    - `the credential guard itself > is blind to another run's probe, and leaves it where it found it`
  each with `expected [ 'src/.probes/credential-guard-60860/__credential_guard_probe__.ts', 'src/lib/db/client.ts' ] to deeply equal [ 'src/lib/db/client.ts' ]` — a false red in a lane that planted nothing, wearing the most alarming possible shape (a service-role-key violation).

(2) **`npm run lint` reddens FOREVER in that checkout.** ESLint 9 flat config has no dot-directory skip (`package.json:9` — `\"lint\": \"eslint\"`), so it lints `src/.probes/**`. The leaf guard writes `const { T } = require(\"@/lib/db/tables\");` to its probe as one of its must-flag fixtures (`tests/offline/db/layering.test.ts`, \"reddens the leaf assertion when a NON-leaf import is added\"), which is exactly what a run killed in that loop leaves behind.
  MEASURED on this tree, with that one file present at `src/.probes/leaf-import-guard-424243/__leaf_import_probe__.ts`:
    `npm run lint` -> `1:15  error  A ` + "`" + `require()` + "`" + ` style import is forbidden  @typescript-eslint/no-require-imports` , `1 error, 1 warning`, **exit 1**.
  `npm run lint` is in `ci_command` and in nearly every ticket's check block, and nothing in `git status` or in the suite points at the gitignored file causing it. This needs no pid collision at all — one killed run is enough.

**Fix shape (not binding):** (a) give each probe directory entropy as well as the pid — the repo's own idiom `source-tree-${process.pid}-${randomUUID()}` (`tests/offline/toolchain.test.ts:303`), which DEBT-0018's own description cites as the precedent to follow; a corpse at `credential-guard-<pid>` is then foreign to every run.
