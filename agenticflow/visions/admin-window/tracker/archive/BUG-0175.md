# A paging refusal renders the app's own 22-word sentence in mono, the face this app reserves for the machine's words — /browse and /claims

## Description
LOOK_AND_FEEL, Typography: 'MONO CARRIES EVERY VALUE THE DATABASE PRODUCED — counts, ids, timestamps, values, source names, buckets, tiers, error strings. SANS CARRIES EVERY WORD THE APP WROTE — labels, headings, buttons, prose. That split IS the typographic idea: the operator can always see which words are the machine's.' ErrorLine's own docstring states the same split ('what failed in the database's own words (mono — the machine said it), then the retry in the app's voice').

'Refusal' in src/components/ui/paging.tsx copies ErrorLine's anatomy — one type-data mono span, then a type-body sans span — but the paging driver puts BOTH kinds of words into the mono slot. Walked on a production build against staging (own port 8795, my PID, killed; reads only), forcing each arm by route interception on /browse and /claims.

MEASURED, all in Geist Mono 11px (type-data), red #c10007:

  (app's own words — wrong face)
  a. non-JSON answer at 200, and the expired-session login redirect followed to HTML at 200:
     '/api/admin/browse/rows — the page request was answered by something other than this app's own route, so there is no page in what came back'
  b. truncated JSON declared application/json:
     '/api/admin/claims/rows — the page request came back declaring a page and carrying an incomplete one, so there is no page to add'
  c. a body that is not a page answer, a short page, an over-long page, unreadable notes:
     '/api/admin/browse/rows — the page request answered something this app cannot read'
  d. the route's own bound refusal:
     'a bound of 61 is not a multiple of the 50-row window'

  (the machine's words — right face)
  e. {kind:'error',reading:'pending_claims',message:'canceling statement due to statement timeout'}:
     'pending_claims — canceling statement due to statement timeout'

So one slot, one face, two authors. (a)-(d) are English sentences this app wrote — the module's own docstring for (a) says so in terms: 'this sentence quotes NOTHING: not the content type, not the status, not a byte of the body.' Rendered in mono they claim an authorship they do not have, and the operator loses the one signal the type split exists to give: on THIS line, with the same 11px mono red run, 'canceling statement due to statement timeout' (Postgres said it) and 'the page request answered something this app cannot read' (we said it) are indistinguishable.

The identifiers on those lines are correctly mono and stay mono: the route path ('/api/admin/browse/rows') and the object ('pending_claims') are machine identifiers, exactly as an Identifier renders elsewhere. What must move to sans is the app-authored PROSE beside them.

Same page, one press apart, the app already gets this right for a leg note: forcing the /browse provenance leg to answer not_provisioned on page 2 drew 'event_field_provenance' in mono followed by 'isn't in this database yet — it arrives with the scraper repo's migrations.' in sans. The page-level refusal beside it does not.

RULE: LOOK_AND_FEEL, The Look → Typography (the mono/sans split) and Interaction principles → Error ('A failed call surfaces the function's OWN refusal in mono, plus the fix in the app's voice'). Traces to VISION: 'the app assumes a fluent operator, not a newcomer' — the fluent operator reads the face to know who is talking.

NOT IN SCOPE: the words themselves (they are correct and TASK-0076 ruled them), the red colour on these four arms (a page that could not be read IS broken — but see the not_provisioned arm, filed separately), the hooks, and ErrorLine's other call sites, whose 'failed' really is the database's string.

Evidence: agenticflow/tracker/evidence/M3/designer/browse-refusal-nonjson.png (gitignored; the strings above are the durable record).


## The ruling (architect, 2026-09-11) — the face is decided by a fact the refusal CARRIES, and this is the seam BUG-0176 inherits

**Chain.** Behind BUG-0174 (same file, and it lands the truth defect first);
ahead of BUG-0176, which adds one more fact to the same contract and changes
nothing this ticket lands. The two are serial at their destination — one
component, `Refusal`, and one construction point, `refuse()` — not parallel.

**The rules, by row, so nobody re-derives them from the walk:**

- `agenticflow/docs/vision/LOOK_AND_FEEL.md:93` (The Look → Typography, the row
  under the five-step table): *"Mono carries every value the database produced
  — counts, ids, timestamps, values, source names, buckets, tiers, error
  strings. Sans carries every word the app wrote — labels, headings, buttons,
  prose. That split IS the typographic idea: the operator can always see which
  words are the machine's."*
- `ARCHITECTURE.md` §7, bullet 3: *"Mono carries every value the database
  produced; sans carries every word the app wrote. **That split is enforced by
  which primitive you use, not by remembering.**"* That second sentence is the
  shape of the fix: the face is not re-decided per arm by someone reading a
  string.
- §7's foreign-text rule stands unchanged: `dir="ltr"` isolates the run this app
  did NOT author, and after this ticket it isolates exactly that run.

**ONE DERIVATION, never a string comparison.** The refusal carries WHO WROTE its
reason, set where the refusal is BUILT — `refuse()` in `src/lib/paging/machine.ts`,
the single construction point every arm already passes through. The component
must not recover authorship by comparing `reason` to this module's own exported
constants: that is a rule retyped as data (LESSONS 4 and 5) and it silently
flips a face the day a sentence is reworded.

```ts
// src/lib/paging/machine.ts — the refusal a press leaves behind
export interface PageRefusal {
  reason: string;
  object: string | null;
  /**
   * Who wrote `reason` — the one question the FACE answers (BUG-0175).
   *  "this app"    → prose this app composed; renders in the `body` sans step.
   *  "the machine" → words this app did not write — the answer's own
   *                  `message`, or whatever a failed fetch threw; renders in
   *                  the `data` mono step, where the operator reads it as the
   *                  machine talking.
   */
  reasonFrom: "this app" | "the machine";
}
```

**Every arm, decided here so no builder re-judges them** (all of them reach
`refuse()` in `machine.ts`):

- `"the page request answered something this app cannot read"`, `WINDOWLESS`,
  `OVERLONG_PAGE`, `SHORT_PAGE`, `UNREADABLE_NOTES` → **"this app"**.
- the `refused` arm's `answer.reason` — the route's own bound refusal, written
  by `src/lib/paging/bounds.ts`, which is this app → **"this app"**.
- the `not_provisioned` arm → **"this app"** (it composes `${missing} is not
  provisioned`). Its ink, its stutter and its wishful fix are BUG-0176's and are
  NOT touched here; that ticket also adds the second fact (what the refusal IS)
  and this one must not anticipate it.
- the `error` arm's `answer.message` → **"the machine"**.
- **The `catch (thrown)` arm is the one site that cannot decide at the call**,
  and it is why this fact cannot be a per-call-site literal alone:
  `reasonOf(thrown)` carries either one of `paging.tsx`'s two authored sentences
  (`ANSWERED_BY_SOMETHING_ELSE`, `UNREADABLE_ANSWER`, thrown by `fetchJson`) or
  a runtime's own words (a network `TypeError`, a non-`Error` value). Authorship
  travels with the THROW, not with the words: this app's two sentences are
  thrown as a distinguishable error type declared ONCE (beside them or in
  `machine.ts`) and asked with `instanceof`; everything else is `"the machine"`.
  No reason string is compared to a constant anywhere.

**What renders where.** The identifier — the route path `deps.route`, or the
object the answer named — is a machine identifier and stays in the `data` mono
step in EVERY arm, with the em-dash separator, the `dir="ltr"` isolation and the
order (identifier, then reason, then the fix in sans) unchanged. What moves is
the app-authored PROSE beside it.

**Words, colour and arms are out of scope** exactly as the designer filed it:
the four sentences are TASK-0076's and are correct, the red on the four broken
arms stays, no arm is added or removed, and no hook changes.

## Acceptance criteria
1. A refusal reason THIS APP wrote renders in the "body" sans step; a refusal reason this app did NOT write — the answer's own message, or whatever a failed fetch threw — renders in the "data" mono step. Both cases asserted on rendered markup, in the same test file, so the two faces are pinned side by side.
2. The identifier on the line — the route path, or the object the answer named — stays in the "data" mono step in every arm, and the em-dash separator, the dir="ltr" isolation of the run this app did not author, and the ordering (identifier, then reason, then the fix in sans) are unchanged.
3. Every arm a press can reach is graded: the four app-authored reasons (answered by something else; declaring a page and carrying an incomplete one; answered something this app cannot read; the route's own bound refusal) and at least one machine-carried reason (the "error" arm's message).
4. THE FACE IS DECIDED BY A FACT THE REFUSAL CARRIES, SET WHERE THE REFUSAL IS BUILT. The refusal contract in src/lib/paging/machine.ts states who wrote the reason; every arm sets it, graded on the machine's own tests for both kinds; and the component derives it from nothing — no reason string is compared to a constant, in the component or anywhere else. Authorship travels with the throw: this app's own thrown sentences are recognised by type, never by their words, so rewording any one of the four sentences changes no face.
5. Nothing else about the line changes: it keeps data-paging-refusal, role="alert", dir="ltr" on the foreign run, its placement above the control, and the rule that a refusal never removes rows, never moves the bound and never removes the control. The four broken arms keep their red and no arm is added or removed.
6. Only the five type steps occur on the refusal line (11/16 mono, 12/18 sans), and tests/offline/ui/tokens.test.ts stays green.
7. (human-checkable) On a production build, force a non-JSON answer on /browse and a database error on /claims. The app's own sentence must read in sans and the database's own string in mono, so an operator can tell at a glance which words are the machine's.
8. Lint is clean and a PRODUCTION build is green.
