# one-place.test.ts bans the domain's own vocabulary: narrow the M2-close pin to the write, not the word

## Description
**Architect ruling, 2026-09-02 (ARCHITECTURE §10 + Common violations class 4).** `tests/offline/review/one-place.test.ts`'s "declares no settle or verdict function under src" matches ANY declaration whose name contains `settle` or `verdict`:

```ts
const settleOrVerdict =
  /(?:function|const|let|class)\s+\w*(?:settle|verdict)\w*|settle_review_item|\.rpc\(/i;
```

That is a ban on the app's own vocabulary. `settled` is a `review_items.status` value (migration `20260901000002`); "settled values" is a spec §5 gauge name; `verdict` is an `observations.rejected_by` reason (`src/lib/gauges/settled-values.ts:65`); `verdicts` is a table in `tables.ts`. It has already cost two pieces of correct work: TASK-0007 renamed its `…SettledValues` exports to `…RejectionStamps` to get past it, and BUG-0012's `isVerdictUnset` hit it. It only passes today by accident of which declaration keywords are listed — `interface SettledValues` and `type ReviewStatus = "open" | "settled"` survive because `interface` and `type` are not in the alternation. TASK-0010 renders "settled items browsable" next; the first `const settleCount` reddens a guard that has nothing to say about it.

**What the guard is FOR is already covered, structurally, in one other file.** `tests/offline/edit/config.test.ts`, "the write surface of the whole repo", asserts on code lines: no `.insert(`/`.upsert(`/`.rpc(` anywhere under `src`, `.delete(` nowhere in the data or route layers, `.update(` **only** in `src/lib/db/records.ts`, and `settle_review_item|admin_locked|apply_resolution` nowhere. A settle path cannot be built without breaking that file. Do not duplicate any of it here (ARCHITECTURE §10, one owner per structural guard).

**The fix.** Replace the `it("declares no settle or verdict function under src")` case with the two shapes that file does NOT cover, and nothing else:

```ts
it("builds no write path toward the M2 close", () => {
  // Narrowed 2026-09-02 (architect ruling, admin-window). The old predicate
  // banned any declaration NAMED settle*/verdict*, which is the domain's own
  // vocabulary — `settled` is a review_items.status value, "settled values" is
  // a spec §5 gauge, `verdict` is an observations.rejected_by reason. It cost
  // TASK-0007 a rename of correct code and BUG-0012 a second one. What must
  // not exist is a WRITE toward the close, not a word.
  //
  // The mutation surface itself is pinned once, in
  // tests/offline/edit/config.test.ts ("the write surface of the whole repo"):
  // no .insert/.upsert/.rpc anywhere, .update only in src/lib/db/records.ts,
  // and settle_review_item nowhere. These are the two shapes it does not cover.
  expect(filesWhereCodeMatches(/["']use server["']/)).toEqual([]);
  expect(
    sourceFiles().filter((file) => /^src\/app\/.*(settle|verdict)/i.test(file)),
  ).toEqual([]);
});
```

Both measured green on today's tree: no `"use server"` module exists under `src/` (the only directives are `"use client"`), and no route or page path contains either word. The second half is what a settle control would most plausibly arrive as in M1 — a server action, or a `settle`/`verdict` route — and neither is reachable from the write-surface guard alone.

Leave the other case in that describe block ALONE: "mentions verdicts under src only as the table name in tables.ts" is code-line-based, has no vocabulary collision (it pins the plural table name, and `tables.ts` is the one legitimate home), and is the permanent not-provisioned probe's guard. Leave the kind-mapping and severity-score cases alone too.

Update the file's header docstring so the next reader knows the third bullet now means "no write path toward the close" and where the mutation surface is owned.

## Acceptance criteria
The declaration-name predicate is gone from tests/offline/review/one-place.test.ts and is replaced by the two assertions above — no "use server" module under src, and no route or page path named settle/verdict — with the reason recorded in the test's own comment. Nothing from tests/offline/edit/config.test.ts's write-surface block is duplicated here. The other cases in the file are unchanged: the kind mapping lives in one module, no severity score or rank, and 'verdicts' appears under src only as the table-name entry in tables.ts.
