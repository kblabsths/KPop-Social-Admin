# LESSONS — the bug classes of M1+M2+M3, for the builder starting a ticket (rewritten whole each close; 45 M3 bugs classified 2026-09-11)

1. **An inline status is a component, not four lines you write again** (11 M2: BUG-0086/97/98/101/102/103/104/105/107/111/119 — one surface took six). Anything showing a transient status owns four properties together: CONTENT (the database's words AND the app's fix, never steered by what the operator typed), PLACEMENT (inside the clipping container it grows in, on any field, wrapping a long unbroken token), LIFETIME (cleared by Escape, blur, the next edit and a later success, through the page's ONE refusal slot), and a LOCK (every control inert while the write is in flight). Read `EditableCell.tsx` and reuse its clock, its slot and its layout rule before you build a fifth one.
2. **A sentence claims only the scope its read had — and on a paged surface a PRESS is a read** (16 M2/M1 + 16 M3, the largest class of the campaign: BUG-0168/72/74/78/80/83/86/91/92/93/94/97/98/201/202/204). Say the narrowing out loud before you write the query: a count over a filtered set takes a filtered count; a window figure says the window filled or did not; a zero says what would fill it. Three M3 corners nobody briefed: a server-rendered sentence describing rows a client press then changes is a CONSTANT over changing state — the sentence belongs to the paging state, not to the server render; a clause naming a subject ("under the filters above") claims that subject removed rows, so it needs that subject's own effect established, never merely its presence; and an unpaged fallback arm ("50 claims below") is still a claim — grade every arm, including the one you did not change.
3. **An empty surface is explained from TWO facts, and emptiness is answered per ELEMENT** (5 M2 + 4 M3: BUG-0129/31/33/35/42, BUG-0169/97/203/206). Facts: (1) can a facet of this URL remove a row of this kind at all, (2) does this surface hold any row with no facet. And the figure-versus-block split, ruled 2026-09-11: a FIGURE states its real zero in every counted state; a BLOCK that renders rows draws its Empty card instead of a row of zeros; the surface's empty-window sentence is said ONCE, by the window line, never restated by a card inside it. Comparing two PAGES' answers to emptiness is how the fourth bug of this class gets filed.
4. **Compare on a normalized form; never enumerate the spellings you thought of — and identity is a DECLARATION, never a text match** (9 M2 + 3 M3: BUG-0081/83/89/90/95/127/136/137/40, BUG-0207/0212/0213). A blocklist patched for blank, then invisible, then nonspacing keys is the shape; so is a guard that asks "is this line ours?" by matching a corpus of our own paste blocks — it counted our own installed handoff as a collision, then missed the sibling's own raise idiom, then called the sibling's next legitimate code a claim on ours: three rounds, one file, one day. Canonicalise where the value is DERIVED from the request, once, and compare canonical to canonical; across a repo boundary compare declarations both sides spell (code → meaning), not similarity.
5. **A shared spelling gets imported, never retyped** (5 M2: BUG-0099/108/113/115/117). One ticket fixed the link spelling on three surfaces and the next found 132 more, because the rule lived in prose and three files retyped it. If two surfaces need the same guard, format, face or affordance, it is one exported thing with one test — and check what your markup RENDERS, not what it declares: a `<Badge>` inside an anchor re-inks the words and paints over the underline.
6. **An identifier has one face, a domain noun has one word, and the MONO face belongs to the machine's own words** (5 M2 + 5 M1 + 4 M3: BUG-0100/112/120/121/122, BUG-0175/184/196/200). Machine identifiers render verbatim in mono through the shared primitive; never prettified, never uppercased, never a bare uuid where a name or a link belongs. The M3 corner: the app's OWN sentences — a refusal, an em dash, a 22-word explanation this repo wrote — never wear the face reserved for what the database said, and an account that composes both must say which half is which.
7. **Absence has exactly one rendering, and it is the app's** (5 M2 + 8 M1: BUG-0085/92/126/132/134). Every nullable value goes through `lib/format.ts`'s dash — never a blank cell, never a hand-typed em dash beside it, never a dash the block neither owns nor explains. "Absent" and "not drawn" are different facts and the page says which. Render each page once against a null/empty fixture.
8. **A guard proves itself on two fixtures, and the failing one must be the shape that OCCURS** (4 M2 + 10 M1 + M3's guard chain). Ship one input it MUST flag and one it must NOT — a guard that never saw a passing spelling passes vacuously, and `undefined` and `null` are two inputs. BUG-0212's lesson on top: the pinned failing fixture used the one grammar the neighbour never writes, so the guard passed for the shape that does not occur and missed the shape that does. **The guard that counts is on the server**: a route accepting a free-text value for a reference fact is guarded only by courtesy if the check lives in the component.
9. **An artifact a human will run — or INSTALL — you have run, and installed against** (4 M2 + 6 M1 + BUG-0207). A handoff, a migration, a doc recipe, an ACL grant: replay it against the real state before you hand it over, and then ask what your own suite does the day the human installs it. Ours turned `npm test` red for every builder precisely because the campaign's handoff landed next door — a guard that cannot tell its own delivered artifact from a stranger's claim fails at the moment of success.
10. **`npm test` is not the bar** (3 M2 + 5 M1: BUG-0094/138/139, DEBT-0002). `ci_command` runs offline+isolated only. If your diff touches a page, a shared render primitive or a `lib/db` read, drive it over HTTP against a production build and run that page's `tests/live/*.live.test.ts` — offline stubs cannot see a dropped column, a client-boundary 500, fourteen sequential round trips, or a real `PGRST205` (BUG-0210: a HEAD count carries no body, so the absence code never arrived and the page printed a developer sentence at the operator). A ticket in `src/app/**` or `src/components/ui/**` carries the TARGETED live file in its checks, never the whole tier.
11. **One fact, one derivation — and one reading per repeated URL key** (2 M2 + 1 M1 + 2 M3: BUG-0106/116/74, BUG-0201/0202 residuals). When two surfaces or two lines describe the same row they read one module's derivation, never each their own. Same rule on the request: `?cols=&cols=banana` meets a page that JOINS repeated values and a dropped-params line that judges the FIRST one, so the surface narrows by a value no sentence explains. Canonicalise the facet where the facet is owned; every consumer reads that.
12. **A check you author, you have RUN on the tree it will run on — and it is ONE LINE** (7 across M1/M2 + 3 M3). `npm test -- <path>` cannot pass here (BUG-0142): name the binary and the project, `./node_modules/.bin/vitest run --project=offline <path>`. Three M3 additions, all measured: the `## Checks` fence is split ONE COMMAND PER LINE, so a multi-line heredoc becomes N broken commands and the receipt is RED whatever you delivered (TASK-0078, BUG-0209); receipts run in a DETACHED WORKTREE AT HEAD, so a check naming a gitignored evidence path can never be green (TASK-0062); and a test file you COMMIT is TypeScript like any other — run `./node_modules/.bin/tsc --noEmit` before you push, because nothing else here sees a type error under `tests/` and a QA pin committed straight to the run branch passes no gate at all (BUG-0195). Prefer presence-of-the-fix over absence-of-the-defect, and read the number a count check returns before you write it down.
13. **State the BAR positively, or the class costs one ticket per property** (9 M3 on one derivation — BUG-0170/173/179/181/182/185/187/196/200 — plus the 3-round guard chain). Seven consecutive lanes each anchored one more question to `src/lib/db/result.ts`'s account derivation: a document, then a body we serialised, then an envelope with no message, then a pretty-printed document counted per line. Every one was a true finding and the chain still ran a whole milestone, because the ticket said what must not happen instead of what must. Before you fix the instance, write the property that makes the next instance impossible — "the account renders exactly the database's words, once, in the machine's face, whatever shape they arrive in" — and put THAT in the criteria.
