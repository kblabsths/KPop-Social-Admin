# LESSONS — the M1+M2 bug classes, for the builder starting a ticket (rewritten whole each close)

1. **An inline status is a component, not four lines you write again** (11 M2: BUG-0086/97/98/101/102/103/104/105/107/111/119 — the milestone's biggest class, and one surface took six of them). Anything that shows a transient status owns four properties together: CONTENT (both halves — the database's words AND the app's fix, and the fix never steered by what the operator typed), PLACEMENT (inside the clipping container it grows in, on any field, wrapping a long unbroken token), LIFETIME (cleared by Escape, blur, the next edit and a later success — from wherever focus is, through the page's ONE refusal slot), and a LOCK (every control inert while the write is in flight). Before you build a fifth one, read `EditableCell.tsx` and reuse its clock, its slot and its layout rule.
2. **A sentence claims only the scope its read had** (9 M2 + 7 M1: BUG-0109/10/14/18/23/24/25/28/30). Say the narrowing out loud before you write the query: "877 claims match these filters" over a read nothing narrowed, a facet's oldest run called the whole table's floor, a lede claiming every claim is below. A count over a filtered set takes a filtered count; a figure over a window says the window filled or did not; a zero says what would fill it. If the sentence names a relationship between two figures, one read must actually establish it.
3. **An empty surface is explained from TWO facts, never one** (5 M2 + BUG-0141 in flight: BUG-0129/31/33/35/42, ARCHITECTURE §4.3). "Nothing here yet" and "nothing matched" never share a rendering, and the URL alone cannot tell them apart: you need (1) can a facet of this URL remove a row of this kind at all, and (2) does this surface hold any row with no facet. Blaming the nearest filter for a zero it did not cause took four consecutive tickets on one page. Grade every facet, not the one that broke.
4. **Compare on a normalized form; never enumerate the spellings you thought of** (9 M2: BUG-0081/83/89/90/95/127/136/137/40). A blocklist patched three times for blank, then invisible, then nonspacing keys is the shape; so are a percent-encoded table name, an uppercased uuid, and a join keyed on `venue` vs `venue_id`. Canonicalise where the value is DERIVED from the request, once, and compare canonical to canonical. Foreign text reaches an app sentence through an allowlist or its own bidi-isolated box, never by scrubbing — and a predicate answering two different questions gets widened by whichever one broke last, so give each question its own.
5. **A shared spelling gets imported, never retyped** (5 M2: BUG-0099/108/113/115/117). One ticket fixed the link spelling on three surfaces and the next found 132 more, because the rule lived in prose and three files retyped it. If two surfaces need the same guard, format, face or affordance, it is one exported thing with one test — and check what your markup RENDERS, not what it declares: a `<Badge>` inside an anchor re-inks the words and paints over the underline.
6. **An identifier has one face and a domain noun has one word** (5 M2 + 5 M1: BUG-0100/112/120/121/122). Machine identifiers render verbatim in mono through the shared primitive (DEBT-0011 — until it lands, say in your criteria which face you use); never prettified, never uppercased, never a bare uuid where a name or a link belongs. And the glossary owns the nouns: a claim is not an "observation", a fact is not a "record".
7. **Absence has exactly one rendering, and it is the app's** (5 M2 + 8 M1: BUG-0085/92/126/132/134). Every nullable value goes through `lib/format.ts`'s dash — never a blank cell, never a hand-typed em dash beside it, never a dash the block neither owns nor explains. An empty set still renders its labelled figure as a real `0`. "Absent" and "not drawn" are different facts and the page says which. Render each page once against a null/empty fixture.
8. **A guard proves itself on two fixtures** (4 M2 + 10 M1: BUG-0079/80/87/91). Ship one input it MUST flag and one it must NOT — a guard that never saw a passing spelling passes vacuously, and `undefined` and `null` are two inputs. **The guard that counts is on the server**: a route accepting a free-text value for a reference fact is guarded only by courtesy if the check lives in the component. Ban the write, never a word the domain owns.
9. **An artifact a human will run, you have run** (4 M2 + 6 M1: BUG-0082/84/88/93). A handoff, a migration, a doc recipe, an ACL grant — replay it against the real state before you hand it over. A grant that never revokes what it inherits, door numbers the sibling already raised, an SQL clause that adopts any row in the ledger, a replay harness that ignores what it should flag: every one of these reads correct and none was executed.
10. **`npm test` is not the bar** (3 M2 + 5 M1: BUG-0094/138/139, and DEBT-0002). `ci_command` runs offline+isolated only. If your diff touches a page, a shared render primitive or a `lib/db` read, drive it over HTTP against a production build and run that page's `tests/live/*.live.test.ts` — offline stubs cannot see a dropped column, a client-boundary 500, or fourteen sequential round trips. Count the round trips your page issues; a read that answers questions the URL did not ask is the third bug of that class.
11. **One row, one verdict — derive the state once** (2 M2 + 1 M1: BUG-0106/116, BUG-0074). A cycle reporting errors called "succeeded" in healthy green, and an over-cadence line calling "never finished" a cycle the same page renders as still running. When two surfaces or two lines describe the same row, they read the same derivation from one module — never each their own.
12. **A check you author, you have RUN on the tree it will run on** (7 across both milestones: ARCHITECTURE Common violations row 4 ×4 — absence pins keyed on a word, red on correct work — plus row 5 ×2, checks pinning a module-path spelling instead of the landed export; and BUG-0142). `npm test -- <path>` cannot pass here: npm appends the filter to the second of two chained projects, and the isolated project matches nothing (BUG-0142, measured). Name the installed binary and the project: `./node_modules/.bin/vitest run --project=offline <path>`. Prefer presence-of-the-fix over absence-of-the-defect, and read the number a count check returns before you write it down. And a test file you COMMIT is TypeScript like any other — a QA pin included: run `./node_modules/.bin/tsc --noEmit` before you push, because on this stack nothing else sees a type error under `tests/` (lint 0, `npm run build` 0 since Next never type-checks `tests/`, vitest green because it transpiles without checking) and a pin committed straight to the run branch passes no gate at all (BUG-0195: three TS2345s rode the run branch through four commits and one land).
